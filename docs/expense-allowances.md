# 行程定额补贴

补贴日额来自管理员发布的费用制度。申请人填写起止日期，系统按包含首尾日的自然日计算金额，保存计算公式、制度选择、匹配规则和事实来源。实际企业标准及事实源仍由 E03 验收；测试中的 100 或 120 元每日均为合成数据。

## 配置与填报

在“费用制度”规则中选择显式费用类别和原币，启用“按行程自动计算定额补贴”，填写大于零的每日金额。所选类别只能允许 DAY 单位。补贴不能与单价限额、票据时限、舱位限制或禁止报销混用，可以要求事前申请。草稿保存、三版本核对及发布复用现有配置管理。

同日出行计一天，跨月、跨年和闰日直接按日历日期计算，不使用小时差或时区换算。一次补贴行程须完整落在命中规则的生效日期内；跨区间需拆成多行。同一单据内同类别补贴日期不能重叠。普通 DAY 费用仍按原费用规则处理。跨单重复及拆单风险由 F04 独立完成。

申请人在费用行填完类别、城市、日期及币种后取得本人适用规则。补贴天数、金额、可抵扣税额以及 DAY 单位由系统确定；补贴不关联发票，可抵扣税额为零。页面显示日额、天数、公式和制度版本。结束日期必填。修改行程后重新计算，单笔分摊随之更新；多笔分摊保留人工调整并要求总额平衡。

填报提示使用已有 `/finance/expense-policy-guidance`，增加可选 `endedOn`。缺少结束日期时可以展示已匹配规则，但不产生金额。页面仅采纳当前上下文的结果；保存请求不提交客户端计算依据。真实保存重新取得权威规则并核对金额、数量、税额和发票，不以浏览器只读状态代替服务端约束。

## 职责与版本

`ExpenseAllowanceRule` 拥有自然日公式，`ExpenseAllowanceBasis` 保存完整等式与发布回执，`ExpenseLine` 约束本行计算一致性。费用内容检查同类别日期重叠。领域层不依赖 HTTP 或外部财务调用。

`ExpenseAllowancePreparation` 在数据库事务外读取员工和城市的可信匹配结果；`ExpenseDraftService` 在短事务内复核本人、配置选择、事实有效期和目标摘要。所有草稿写入与制度发布共用配置锁，包括原本没有补贴制度的草稿，避免准备期间首次启用新制度而漏校验。幂等成功重放返回原结果，不重新请求财务事实。

正式预检再次核对已保存补贴的制度、规则、日额、完整日期以及财务评估金额。发布选择变化后必须重新计算，返回 `ALLOWANCE_RECALCULATION_REQUIRED`；外部评估不能提高补贴总额或产生可抵扣税额。更改后的内容仍须重新预检和提交。

计算依据随 `expense_report_revision` 和审批轮次快照留存，无新增数据库迁移。撤回、修改行程、重提产生新版本；旧轮次按原日额和原日期展示，不依赖当前制度。旧普通费用及旧制度 JSON 保持可读，未配置补贴的规范化制度正文保持原摘要。

## 验证

F03 本地完整验收已完成，实现提交 `bc4620b`，见[完整证据](evidence/expense-allowances-complete-20261003.json)。320 项 Java、1,109 项前端测试与构建通过；OpenAPI 333 个操作、670 个模型和 123 份请求样例通过。实际 119 份响应和 23 份请求通过契约验证。

实际 PostgreSQL 安装包验证金额、数量、税额、发票和币种篡改拒绝、可信来源替换、幂等重放及员工读取隔离；换版后的旧计算阻断，撤回修改并重提保留上一轮原金额和制度。真实页面完成行程重算、只读金额与税额、分摊更新和保存，桌面及 390 像素窄屏通过。重启后两轮计算、预算确认及页面保存的 480 元保持；9 张旧费用单的原存储字节保持，7 份新业务版本保留各次计算。

管理保存的真实 HTTP 验收曾发现严格输入模型漏加补贴字段，先用最小测试稳定复现，再补齐输入映射；未知字段和金额类型约束保留。
