# 报销填报与正式提交页面

更新：2026-09-28。本阶段完成本地填报与审批发起链路，后续结算仍在实施。

费用工作台可以填写新的报销；本人草稿、退回和撤回单据从费用详情继续编辑，沿用原流程版本。编辑器选择已发布且允许新发起的版本，并核对完整费用字段契约；通用表单版本不能被误用为费用流程。法人、类别、单位、城市、成本中心和项目来自当前员工财务目录，目录过期或不可用不填写猜测的替代数据。

费用行支持原币含税额、税额、数量、日期、成本分摊、发票和事前批准引用；整单支持借款抵扣。金额始终用十进制字符串，分摊以整数分校验。移除行不重新编号。资金引用从本人接口按页读取，不开放任意员工查询；仅选择当前法人已验原件、开放批准行及相同本位币的已放款借款。本单已有引用保留给后端预检重新核验，页面余额不被解释为正式预留。

## 职责与恢复

`ExpenseWorkspace`、`ExpenseDetail` 调用 `ExpenseEditor`，费用行输入和资源选择分别由 `ExpenseLineEditor`、`ExpenseFundingPicker` 管理。`ExpenseSubmission` 使用已保存双版本发起持久预检，展示实际任职、会计日、查询目标、脱敏账户及金额预览；明确确认后才调用专用正式提交接口。跨聚合占用、冻结及审批状态仍属于已有后端应用服务和领域模型。

费用输入只保存在按身份与编辑入口隔离的页面内存中，切换页面可继续填写；不写浏览器持久存储。保存使用平台原请求幂等恢复，只有身份、原路径和原正文一致的回执才推进草稿基线。版本冲突保留输入并停住再次写入，用户明确选择后才能读取服务器版本替换本地内容。预检结果未知时通过最新任务状态恢复，不自动发起新检查；正式提交结果未知时仍恢复原操作。

草稿已经预编号为第 1 轮；退回或撤回后再次提交才增加轮次。预检 READY 还必须匹配当前双版本、下一轮、所选任职、法人、会计日期和有效期，提交动作执行前再次检查时效。正式提交的服务端仍重新校验全部事实。财务目录或请求失权、身份切换、超时和迟到响应不会回填旧数据。

`precheck-options.latestPrecheckId` 由服务端按 `attempt_no` 倒序查到本人当前报销的最新任务。历史列表沿用 UUID 游标分页；它的第一项不能代表最近一次预检。只读选项和任务读取之间若出现新检查，任务可用性校验仍会阻止旧检查被使用。新增字段向后兼容，不需要迁移。

## 验证

前端 69 项范围回归通过，包含 18 项填报消费者与边界测试；构建及静态 OpenAPI 校验通过。后端预检 16 项及 OpenAPI 5 项通过，预检同范围 16 项在 PostgreSQL 17.11 通过，范围重叠不相加。Java 作者和解析检查通过；前端构建仍有既有单个包超过 500 kB 的提示。

实际浏览器创建 `UI-CREATE-003`，差一分钱的分摊被阻止；导航离开后恢复未保存内容；保存、预检、取消确认、修改后旧预检失效、首次正式提交、撤回、修改并第二次正式提交均已完成。最终实际 HTTP 12 次读取检查确认仅有一个第二轮业务待办、第一轮撤回快照保留、最新检查为第 3 次、当前金额预算确认。小屏 CSS 500 像素、文档宽 500 像素、弹窗宽 476 像素，没有横向溢出，最终浏览器控制台无错误。

本阶段先失败再修复的消费者边界：

- READY 计算缓存未随时钟失效：确认期间到期测试曾发送一次提交，修复为零次，并设置界面到期失效。
- 发票缺少占用归属时，两个未定义值相等造成误选：必须存在当前报销标识及匹配占用归属。
- 测试草稿错误地使用轮次 0：改用真实轮次 1 后首次提交测试失败，修复首次与重提的区别；浏览器同步验证。
- 历史 UUID 列表被当作最近检查：实际浏览器展示第 1 次而非第 2 次，增加本人最新任务指针；反向 UUID 的后端失败回归及 PostgreSQL 验证通过。
- 空项目字段被服务端省略后，下拉框没有选中项：真实 DOM 断言失败，修复空值回显后显示“不指定项目”。
- 仅填写业务编号时退出提示遗漏：先失败的草稿状态测试后统一未保存状态判断。

机器证据见 [填报验收](evidence/expense-origination-20260928.json)。验收使用本机合成财务网关；未把它计为企业接口验收。引用选择器有组件场景覆盖，当前浏览器数据库没有已验发票、已批准额度或已放款借款，尚未作为带资金引用的浏览器端到端证据。下一阶段继续个人票夹上传与验票、资金来源发起和实际结算。
