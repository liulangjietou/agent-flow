# 业务写请求的幂等协议

前端可能已经发出申请或审批，但因断网没有收到响应。乐观版本能够拒绝重复写入，却不能向用户说明上次操作是否成功。幂等协议为同一次操作保存请求摘要和已提交的响应，重试只回放原结果。

## 接口范围

以下 9 个业务写接口必须携带 `Idempotency-Key`：

- `POST /api/v1/applications`
- `PUT /api/v1/applications/{id}`
- `POST /api/v1/applications/{id}/submit`
- `POST /api/v1/applications/{id}/withdraw`
- `POST /api/v1/tasks/{taskId}/actions`
- `POST /api/v1/process-definitions`
- `PUT /api/v1/process-definitions/{id}`
- `POST /api/v1/process-definitions/{id}/publish?expectedRevision=...`
- `POST /api/v1/process-templates/{templateKey}/copy`

登录、注销以及只读的流程校验和模拟不属于这 9 个业务写接口。外部集成调用方需要同步增加请求头；缺失或格式不合法会返回 400，不会自动生成服务端随机键来掩盖契约缺失。

键长 1—128，字符范围为 ASCII 字母、数字、`.`、`_`、`:`、`-`。推荐客户端为一次新操作生成 UUID；同次重试保留原键，新操作使用新键。

## 重放与冲突

键在租户内唯一。服务端绑定认证操作人、角色摘要、HTTP 方法、实际资源路径、原始查询字符串和原始请求体字节。JSON 空白、字段顺序、未知字段或显式 null 的变化也属于不同请求；发布版本位于查询字符串，同样参与校验。

成功后的相同请求返回当时保存的状态码和 JSON 正文，并用 `Idempotency-Replayed: true` 标识重放。响应是当次操作结果，可能早于资源当前状态；查询资源最新状态仍使用 GET。首次成功响应标识为 false。

同租户换用户，或换接口、资源、查询参数和请求体复用原键，返回 `409 IDEMPOTENCY_KEY_REUSED`，不泄露缓存响应。相同用户的权限角色发生变化时禁止回放；未登录、失效会话先由认证层拒绝。跨租户使用相同键互不影响。

JSON 解析和入口字段校验先于幂等执行；坏 JSON、无效字段仍按入口错误返回，不通过幂等命中绕过校验。只有成功响应被保存。业务拒绝、版本竞争失败、依赖错误等失败不会成为可回放的成功记录。

响应保留窗口为首次执行开始后的 24 小时。过期键返回 `409 IDEMPOTENCY_KEY_EXPIRED`，不自动重新执行；调用方应先查询原资源、核对结果，再决定新的业务操作。当前不自动删除过期记录，因此不能把本阶段视为已经交付完整的留存清理治理。

## 事务与职责

幂等协议属于 API 基础设施。控制器显式调用幂等执行器，业务状态规则继续由原聚合负责，权限和跨资源编排继续由原应用服务负责。

幂等占位、申请/定义修改、Flowable、轮次、审计和响应序列化保存共用一个本地事务。任一步骤失败时整体回滚，原请求可继续重试。HTTP 只发送事务内已经序列化的 JSON，不在业务提交后再生成响应内容。

同键并发依赖数据库唯一约束。竞争失败后先退出事务，再读取已提交的胜者结果，避免在 PostgreSQL 已中止的事务中继续查询。只识别幂等占位自身的唯一冲突；业务号、流程版本冲突继续遵守原领域与并发规则。

重复提交先查询原响应，不重复启动流程；已完成的任务即使不在活动任务表中，也可向原操作人回放本次结果，不再次审批。不同幂等键仍必须通过原 `expectedVersion` / `expectedRevision` 检查。

## 前端恢复

前端为业务写请求管理当前页面内的待确认操作。网络失败、服务端 5xx 或成功响应未能完整读取时保留原请求和键，不自动重试审批。用户恢复时发送原请求；结果尚未确认时不能用修改后的内容替换它并另发一次写入。

恢复成功后更新原申请或流程定义，再由用户继续下一步操作。保存后发布、创建后提交分别有独立请求键，不能因为第二步未确认就重做第一步。

模板复制也保存原请求和响应；复制出的流程草稿、来源记录和幂等响应在同一事务提交。恢复复制只打开原草稿，不再生成副本，也不会自动发布。

待确认正文只保留在当前页面内，不写入持久化浏览器存储。刷新或关闭页面可能失去恢复上下文；离开前会提示，重新进入后应先从申请记录、流程列表及审计核实当前状态。生产级离线操作日志仍需后续设计。

## 验证

后端新测试覆盖接口重放、并发、权限和请求绑定、失败回滚、过期边界；原业务回归显式为每个独立写操作提供不同的键。前端针对未确认请求、改变内容、用户隔离和分步操作恢复运行自动化测试。

最终执行结果、数据库和浏览器证据以本阶段验收记录为准。
