# 借款还款通知

F17 的原还款查询、明确登记、查询触发复核及原消息详情已接通。本阶段完成本地实现与范围验证，F17 整体仍为 OPEN。验证记录见[阶段证据](evidence/repayment-notifications-20261003.json)。

## 调用链和责任

财务通过原借款的还款接口发起查询，后台工作器读取收款及对应借款冲减分录。`AdvanceRepaymentService` 编排原放款、原还款与最新查询的比较；`AdvanceRepaymentCheck` 保存本次查询状态和它实际触发复核的原还款编号。借款余额、查询、还款登记与规范资金防重凭据仍由各自领域和仓储负责。

查询事实保存后发布 `AdvanceRepaymentChanged`。明确登记在借款修订、查询消费、原还款及资金凭据保存后发布事件。通知、外发意向和原财务动作共享事务；任一步失败整体回滚。查询导致既有还款冻结时，冻结、原查询复核依据和通知也一起保存。

通知区分查询不可用、来源变化、查无、待确认、收款撤销、触发原还款复核和明确登记。正常确认的查询保持安静，查询不会自行冲减欠款。外部原件仍显示 CONFIRMED，但资金、会计分录或版本与原还款冲突时，也必须通知复核要求。

## 原查询与历史依据

`reviewRepaymentId` 保留本次查询实际触发的原还款复核关联。后续复核解除冻结后，旧查询仍保留当时事实，不再根据当前借款是否冻结推断。该字段只允许出现在已完成查询中，带有复核要求的查询不能用来新增还款登记。旧 JSON 缺失字段时恢复为空，不反推过去未记录的复核关系；无需新增 SQL 表结构。

`GET /api/v1/notifications/{id}/repayment-target` 只读取本人原消息，不接受额外查询参数，也不发起银行查询、登记、复核裁决或标记已读。原登记按自身编号恢复被消费查询与登记前后的借款修订，并重放领域变更验证实际归属。后来的还款、占用和复核决定不能替换历史登记版本。

接收人是原申请人和本次查询的实际财务。创建和外发领取复核当前人员及原法人任职；详情再检查原轮次字段权限和当前财务角色，管理员不能绕过敏感字段。去重键为 `repayment:<原查询编号>:<事实种类>`，重复事件和 HTTP 原键回放不重复通知。

消息与详情不包含金额、公司账户、外部收款编号、会计分录或办理许可。页面分别展示消息发生时事实、原查询状态、收款原件、实际登记及当时触发的复核。身份切换、失权、超时和卸载清除旧内容并阻断迟到响应，只提供重新读取与原轮次导航。查无原件允许零版本，其他结果须正版本；历史登记保留浏览器毫秒截断边界，不提供续期或新登记许可。
