# 原付款安全结束与重新授权

更新：2026-09-28。本阶段在隔离工作树实现财务安全结束原付款，以及按原批准金额和原收款账户重新授权。旧命令、回执和修订全部保留；账户变更的重新复核、已到账／退回争议裁决继续实施。合成资金系统验收不代表真实银行联调。

## 调用链与职责

财务页面在原轮次付款状态中读取 `actions.retire`，明确填写原因后提交 `RETIRE`。入口复核财务角色、当前法人任职及原轮次完整字段权限，幂等回放同样复核权限。应用服务按申请、财务聚合的既有顺序加锁，再比较授权及执行版本。

`PaymentOperation` 判断是否具备结束依据，并使未发送队列或账户复查领取失效。`PaymentAuthorization` 保证只能结束已登记执行的第二版，且申请人、原出纳不能作此决定。服务在同一事务内停止执行、结束授权、释放业务占用、保存关联修订和写入审计。实际资金 HTTP 不在此事务中。

## 允许结束的事实

| 原执行事实 | 财务安全结束 |
| --- | --- |
| `QUEUED`／`CHECKING`，发送次数为 0，无任何资金回执 | 允许；先转为 `VOIDED`，清除调度与租约，使迟到复查无法发送 |
| `VOIDED`／`EXPIRED`，发送次数为 0，无任何资金回执 | 允许；保留原停止事实 |
| 原资金系统的 `FAILED`，没有冲突回执 | 允许；保留原失败回执及执行版本 |
| 曾发送后查无，包括查无后重排队、停发或到期 | 不允许；查无不能保证迟到请求不会受理 |
| 发送中、查询中、未知、到账、退回或对账冲突 | 不允许；继续占用业务单据，不能换号付款 |

`FAILED` 的外部契约是原命令的永久终态拒绝：资金系统必须保留原编号及摘要，迟到请求或重复调用也不能再受理为另一付款。网络故障、缓存未命中及暂时未查到均不符合这一事实。真实接入时需要验证该语义；本阶段没有银行取消接口，也不会根据人工说明制造银行失败事实。

结束后的授权为第三版 `RETIRED`，原执行不能再查询或重发。授权的不可变条款、原财务决定和出纳命令不改写。页面显示结束操作者、时间、依据和执行版本；出纳最小视图不包含财务自由文本说明。

## 新授权与账户边界

安全结束本身不授权、不付款。重新授权复核实际批准、当前业务双版本、原挂账凭证和当前财务任职；再次取得业务唯一占用。新授权仍等待独立出纳选择出款账户，执行前重新检查本人账户及出纳目录。旧授权永不复用。

本阶段重新授权仍使用原批准轮次冻结的本人账户。员工已维护新账户时，执行会拒绝旧账户；不会直接把主数据变化当成财务同意换账户。新的账户复核与授权绑定是下一阶段，不通过修改旧轮次、旧凭证或旧命令实现。

成功重开的付款按新命令形成实际借款余额或报销核销及付款凭证。集成测试覆盖失败原交易结束、新授权、独立出纳执行、报销结算及归档，旧失败原交易保持不变。已到账或退回的原交易不走这条结束路径，不能借此删除既有资源核销。

## V51 与验证

V51 扩展授权状态和第三版修订，新增 `payment_retirement`。结束事实按租户和授权唯一，同时引用第三版授权修订和结束所据的执行修订；缺失、跨租户及重复证据被数据库拒绝。读取时进一步交叉校验 JSON、关系列、原命令与执行事实。证据写入失败会回滚队列停止、授权结束和审计。

迁移不改写旧授权、旧命令及其历史。H2 和 PostgreSQL 的历史内联检查名称不同，迁移从约束目录识别待替换的取值范围；PostgreSQL 列出的非空检查显式保留。首次 PostgreSQL 验证因这一目录差异拒绝迁移，修正后验证通过，并增加非空约束回归。
