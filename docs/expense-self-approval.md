## 发布与轮次规则

费用报销定义须在开始节点明确选择“申请人转本次任职的直属主管”，对应 `expenseSelfApproval=ESCALATE_SUPERVISOR`。后端只允许结构化费用报销表单启用这一策略；普通表单、未知值和人工节点上的同名配置在校验时拒绝。未启用的既有发布版本保留原选人语义。快速设计器与完整设计器使用同一配置组件，切换视图、导入导出和版本比较保留该设置。

正式提交在同一事务内固定本次任职及每个人工节点的原候选。业务候选包含申请人时，只沿选定任职上溯一级，保留原候选、替代人员、直属主管任职、目录修订和发布／规则版本。多任职不会改用另一个兼任关系；重复替代人先去重，再固定会签分母。缺少合法直属主管、关系环路或上级停用时返回 `APPROVER_NOT_FOUND`，申请轮次、财务状态和流程任务一起回滚。

在审期间组织关系变化不会更换本轮已固定的候选，后续节点仍使用本轮证据；当前审批资格仍会重新检查。撤回后重新提交产生新轮次，才按新的组织关系解析，旧轮次审计保留。

## 财务职责与查询一致性

财务签收、审核和复核保留人工办理，不由此策略自动通过或改派主管。申请人始终被排除；本单实际业务审批人与财务办理人双向互斥，覆盖并行激活和财务之后的业务节点。明确签收纸件也记录实际财务办理人员，不以尚未点击同意为由忽略该事实。

办理、转交、委派、加签和待办读取共用职责判断。并行任务创建后，如果另一分支的实际办理使某个原候选失去资格，原候选历史仍保留，但该人不能继续读取或办理相冲突的待办。工作台在 SQL 计数与游标分页之前排除这些任务，避免页内过滤造成空页、漏项或错误总数。

每个实际激活并发生上溯的节点追加 `SELF_APPROVAL_ESCALATED` 审计，保存原候选及最终有效名单；未激活分支不伪造已发生的上溯事件。申请历史、管理员审计检索及导出声明均支持按此动作筛选。上溯是选人事实，不产生人工批准结论。

## 根因与验证

原费用夹具一直使用与申请人不同的主管，通用职责测试又明确预期“排除后无人则阻断”，因此没有覆盖费用自审批替代。先用真实已发布费用流程复现有有效主管却提交返回 422，再实现费用策略与提交轮次冻结。

补充验证又复现两处缺口：并行决策后的财务待办仍显示给冲突候选；已入库的上溯动作在公开审计筛选中返回 400。分别修正当前权限与分页查询、审计参数白名单和三处 OpenAPI 枚举。三次失败均为业务断言失败，原日志和 XML 保留。

最终 Java 范围为 11 个实际执行测试类，共 87 个不同的类名／方法名组合，失败、错误和跳过均为 0。其中费用提交选择执行 12 个用例，包含 8 个新规则用例和 4 个原链路回归；其余覆盖规则校验、定义发布、代理读写、待办分页及公开契约。分页验证同时包含全被排除的总数 0，以及排除旧冲突任务后，两页各一条且总数保持 2。
