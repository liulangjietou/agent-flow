# 借款到账结算

更新：2026-09-28。借款付款成功后，已接通实际借款余额生成、重复确认、旧成功交易恢复及退票/冲突冻结。报销资源核销及零应付已接通，见 [报销结算](expense-settlement.md)；付款凭证和归档继续实施。

## 调用链与事务

`PaymentOperationService.finish` 保存成功回执并同步发布状态事件；`AdvanceDisbursementService` 加入原事务读取实际借款申请，调用 `AdvanceRequest.paidAdvance`，通过 `EmployeeAdvanceRepository` 保存余额与创建证据。任一消费者或余额写入失败，成功确认一起回滚，随后查询原交易，不新建付款。

申请实体负责原批准、轮次、双版本、金额、收款账户与授权时序的一致性；应用服务负责付款、申请和余额三个聚合的编排。实际借款使用原申请业务标识，数据库原有主键和外部放款引用唯一约束防止重复。重复到账比较不可变放款事实，不覆盖余额的后续预留、冲销和冻结。

结算不要求当前审批状态仍为已批准。已经发送后才收到成功回执的真实款项，仍根据原批准依据入账；当前撤销或授权到期不能抹掉到账事实。新发送及重发继续使用原付款前校验。

## 日期、恢复与争议

到账日取成功回执的完成时间，按原轮次冻结的法人时区转换；还款日保留原约定。原模型错误地要求还款日不早于到账日，旧测试只覆盖提前到账。延迟放款回归先失败，再删除这一错误约束；逾期判断同时要求查询日不早于实际到账日。

付款后台每次有界检查已成功但尚无余额的借款，使用原申请锁重新读取持久付款并补建。补建不读取账户目录、不查询银行、不重新付款。现有余额 JSON 缺少新增争议标记时按原未冻结状态读取，金额及版本保持。

银行退票或回执冲突不删除余额、预留及已冲销记录，而标记 `PAYMENT_REVIEW`，可用金额显示为零。该借款不能增加预留、迁入下一轮或继续核销，原预留仍可减少和释放。普通成功查询不会解除冻结；人工争议裁决和退款调整尚未提供，不能以改写旧余额代替。
