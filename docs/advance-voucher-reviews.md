# 原借款凭证与余额冻结

更新：2026-09-29。V60 修复原借款挂账或付款凭证已经冲销、存在争议时，已到账借款仍可继续使用的问题。先以两条失败的集成测试复现：100 元放款、25 元还款、20 元预留后，原凭证冲销仍返回 55 元可用；修复后可用额为零，原账完整保留。

## 调用链与职责

调用方是原凭证查询、独立财务裁决和实际放款确认。`AdvanceVoucherReviewService` 在原业务事务内消费 `VoucherOperationChanged` / `VoucherDisputeResolved`，用原付款授权绑定两类凭证，再由 `EmployeeAdvance` 保存逐张冻结。下游还款确认、费用新增预留和结算沿用借款实体的限制；页面和 OpenAPI 统一增加 `VOUCHER_REVIEW`。

- `REVERSED` 和 `RECONCILING` 分别冻结对应原凭证；重复事件不增加余额版本。
- 普通过账查询不能解冻。只有独立财务明确采用原凭证有效过账的裁决，才能解除该凭证的冻结。
- 付款、逐张凭证和逐笔员工还款的复核分别保存。解除其中一个来源不影响其他来源。
- 冻结禁止新增占用、预留迁移、结算和新增还款确认，允许降低或释放已有预留。
- 实际放款本金、已核销金额、原还款及退回、银行退回、未还款、原预留均不因冻结被改写。
- 原凭证先发生争议、银行随后返回成功时，新借款余额在同一事务继承该冻结。凭证已进入再次查询、暂时处于 `UNKNOWN` 时，也从尚未被有效过账裁决覆盖的历史修订中找回冻结。

跨聚合的原凭证归属、锁顺序及持久化编排放在服务层，借款实体只管理自身冻结和使用规则。恢复继续使用现有原轮次字段权限、当前财务任职及原付款出纳分离约束；本次没有新增放宽权限的入口。

## 升级与界面

V60 在服务启动前从原付款授权及不可变凭证修订补录尚未解除的冻结。已经明确裁决恢复的旧凭证保持原状；恢复后再次发生的争议重新冻结。迁移保留旧 JSON 原文，仅为需要冻结的借款追加新余额版本及 `VOUCHER_REVIEW_UPGRADE` 审计修订，不修改旧凭证、资金、占用、还款或决定。

借款详情和费用资金目录展示“凭证待核对，暂停使用”，可用额为零。财务仍可读取原还款、原放款及其各自复核记录。完成原凭证裁决后，刷新还款记录读取当前余额；其他冻结尚未解除时，页面继续显示暂停使用。
