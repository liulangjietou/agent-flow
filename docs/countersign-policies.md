# 任一人通过与比例会签

更新：2026-10-01。ANY 与 PERCENT 已完成本地后端、设计器、任务办理、消息、实际数据库及浏览器验收。全平台其余范围以[当前剩余清单](remaining-local-work.md)为准；真实企业环境和远端 CI 未计入本地结果。

## 规则与配置

人工节点 `properties.approvalMode` 支持四种方式：

| 方式 | 所需实际同意人数 | 人员责任 |
| --- | --- | --- |
| SINGLE（旧定义缺省） | 一人处理原候选任务 | 保持既有单人审批 |
| ALL | 当前必要人数全部同意 | 支持[明确加减签](countersign-membership.md) |
| ANY | 节点激活名单中的一人 | 名单与门槛固定 |
| PERCENT | 激活人数 × 配置比例，向上取整 | 名单与门槛固定 |

PERCENT 必须显式填写 `approvalPercentage`，为 `"1"` 至 `"100"` 的整数字符串。不接受小数、空值、空白、表达式或其他方式残留的比例，不默认填入 50%。例如三人、50% 需要两人，67% 需要三人；六人、50% 需要三人。

```json
{"assigneeRule":"role:FINANCE","approvalMode":"PERCENT","approvalPercentage":"67"}
```

节点实际激活时从同租户有效目录去重、冻结真实名单和人数门槛，每人一张独立待办。名单为空回滚本次推进；后续目录变化和新发布版本不修改在审节点。达到门槛后由引擎结束剩余待办，保留取消历史，不为未处理者记录批准意见。达到门槛前任一驳回或退回终止整轮；并发决定只有先成功提交者生效，另一方刷新现态。重提使用新轮次重新激活。

ANY/PERCENT 不支持加减签、领取、释放和转交，避免改写固定分母或责任。委派只能协助并回交，回交不计为同意，最终决定仍由原责任人作出。无关并行节点仍须独立完成，某个会签达标不会释放其他分支。

## 调用链与职责

调用方为两种设计视图和任务动作接口；下游为定义校验、有效人员目录、Flowable 多实例、申请版本、审计和站内消息。影响新节点发布、激活、多人竞争、委派、提前完成、旧全员节点继续办理和历史读取。

定义领域的 `ApprovalPolicy` 负责模式、比例和整数取整；`CountersignProgress` 表达实际进度与责任动作约束。发布适配器仅将已校验枚举和整数写入固定表达式，用户不能提供任意引擎表达式。运行适配器把实际名单和门槛保存到当前多实例根执行的局部变量，Flowable 原生完成条件决定何时离开节点，不另建投票表或复制引擎任务状态。

任务应用事务共同保存实际动作、申请/轮次、审计、消息和幂等回执。达标前只采集同一节点其他真实待办的收件人，成功后仅通知本次结束的任务。消息写入失败时，已完成与已取消任务全部回滚。结束通知 `TASK_COUNTERSIGN_COMPLETED` 不代表收件人同意；该通知及原减签通知直接打开仍受权限检查的申请详情，不再请求已结束任务。

当前平台图禁止循环且未支持重复子流程激活；引入这些能力前，历史和收件范围必须进一步绑定具体节点激活，不能只按节点标识查找。

## 接口与页面

任务详情及兼容列表返回实际 `countersign`：

```json
{"total":6,"completed":2,"mode":"PERCENT","percentage":50,"required":3}
```

ALL 返回 `mode=ALL`、`required=total`，包含已明确增减后的必要人数；非比例模式省略 `percentage`。SINGLE 不返回会签进度。原操作权限、敏感字段投影、`expectedVersion` 及幂等恢复规则继续适用。任务已结束后的原成功请求仍可按原键回放相同回执，不创建第二条意见或通知。

设计器支持选择方式、比例原文校验、快速步骤/高级画布切换、撤销、保存发布、模板往返和版本比较。待办显示方式、已同意人数及服务端固定门槛，仅全员会签展示加减签入口。批准前可填写意见，并须明确确认；取消不提交。页面不会自行根据当前目录重算门槛。

## 已验证范围

- H2：领域 12 项、服务端相关 40 项，涵盖 12 项新策略集成及旧全员会签/加减签回归。PostgreSQL 17.11：同一新策略集成 12 项；另外运行领域 3 项和 H2 契约 6 项，范围重叠，不能合并为唯一测试数。
- 前端最终 68 项、类型检查和构建通过。通知入口缺口先以真实页面复现，再用实际 `openNotification` 的失败测试确认，修复后回归通过。
- 真实 HTTP 的响应按当前 OpenAPI 校验，数量见[机器可读证据](evidence/countersign-policies-20261001.json)。任一模式六张任务仅一份批准；比例模式六张任务需三份批准，实际历史分别保留五张、三张取消任务。
- 浏览器创建并发布 ANY → PERCENT 串联流程，验证空比例、小数拒绝、切换清除、两种设计视图保持值；实际完成首节点一份、后节点三份意见，申请批准。完成通知直接进入申请，操作审计只显示真实意见。
- 实际 500 CSS 像素下比例说明、确认和取消可用，页面没有横向溢出；已恢复默认视口。
- 原 V86 非空库升级保留原两张完成申请及三份附件；升级前新启动的旧 ALL 节点在新包中继续加减签及最终批准。PERCENT 已有两份意见时重启，原任务、门槛、版本及审计保持，随后第三份同意完成。结束后的 ANY 原回执继续回放相同结果。

未新增数据库迁移。新二进制兼容旧全员部署的两参数成员表达式；首次保存新模式或新通知后，旧程序不认识这些枚举，回退须使用匹配版本的数据备份。前后端应配套更新。本地 CI 配置已加入 PostgreSQL 策略回归；仓库无远端，未运行远程 CI 或创建 PR。
