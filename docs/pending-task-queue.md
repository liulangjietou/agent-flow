# 待办检索与分页

待我审批支持按单号、申请标题、任务名称搜索，并组合流程标识、申请人账号、金额范围、办理范围和处理期限筛选。列表按任务创建时间升序，较早进入待办的任务优先；同时间按任务标识升序。当前筛选总量与已加载条数分别展示。

列表只返回申请摘要，不含表单正文。打开任务后先按 ID 读取当前任务与版本，再按原授权读取申请详情；不能直接用旧列表提交动作。领取、释放、转交、委派、回交、批准等仍使用原应用服务、乐观锁、幂等和事务。消息中的待办入口也改为单项读取；任务已流转时回到原申请授权查询。

## HTTP 契约

`GET /api/v1/workspace/tasks` 返回 `{items, nextCursor?, total}`。支持参数如下：

| 参数 | 含义 |
|---|---|
| q | 单号、标题或任务名称包含匹配，忽略大小写；最多 100 字符，`%`、`_`、`!` 按字面量查询 |
| processKey | 精确流程标识；不同版本共同匹配，列表显示各自版本 |
| applicant | 精确申请人账号，不是当前审批人 |
| assignment | all 全部可办理，assigned 指派给我，unclaimed 待领取，delegated 待我回交；默认 all |
| deadline | all 全部期限状态，overdue 已超时，pending 未到期，unrecorded 未记录期限；默认 all |
| minAmount / maxAmount | 包含边界的规范十进制文本；不接受指数、NaN，最低不得高于最高 |
| limit / cursor | 默认 30、最大 100；游标绑定租户、账号、角色和全部筛选条件 |

拒绝未知参数、非法范围、错误游标和跨查询游标，返回 400 / INVALID_TASK_QUERY。游标用时间与任务标识定位，已加载任务完成后不因 offset 位移遗漏后面的任务。任务可能在分页期间新增、转交、完成；总数与各页不是冻结快照，刷新从首页读取最新结果。

`GET /api/v1/tasks/{taskId}` 返回原 TaskView 的实时授权快照。未登录 401，无操作权 403，不存在/结束/暂停 404。随后审批动作仍再次复核授权与版本。

既有 `GET /api/v1/tasks` 保留数组响应，避免破坏已有调用方；查询先限制租户变量，再执行原可操作性过滤。新 UI 不再使用这个全量兼容入口，集成调用方应使用有界分页入口。

## 权限与 DDD

调用链：PendingTaskQueue → PendingTaskController → PendingTaskReadPort → FlowablePendingTaskReadAdapter。入口只做参数解析，读端口输出业务摘要，引擎表结构仅存在于适配器中。

适配器针对当前 Flowable 7.2 的运行表执行参数化只读查询，在数据库中同时限定当前租户、根流程变量中的申请/租户/轮次、审批中申请、活跃任务，以及实际 assignee 或未指派任务的 candidate 用户/角色。管理员不会因此获得其他人的任务。候选用户与角色重叠不会重复返回；已指派任务不继续向候选组开放。无 APPROVER 角色的主体得到空队列。

使用真实任务事实，未新建任务状态副本，也不从站内消息或审计推测待办。引擎升级时需要重新验证该适配器的表结构与授权查询。H2 和 PostgreSQL 的真实任务集成验证已覆盖当前版本；这不是容量压测或任意引擎版本兼容承诺。

页面与总数已在读适配器中合并，正常非空页只联查一次；窗口计数发生在游标与展示截断之前，后续空页保留正确总数。回归与性能证据见[待办分页查询性能验证](pending-query-performance.md)。

## SLA 期限筛选

期限读取 Flowable 当前任务的真实 `DUE_DATE_`，与[已生效的任务期限规则](confirmed-rules-runtime.md)使用同一事实。服务端每个请求只取一次查询时刻：截止时间小于或等于该时刻计入“已超时”，大于该时刻计入“未到期”；NULL 仅计入“未记录期限”，不推定为未到期或未配置。客户端不能提交比较时刻。

同一请求的结果、窗口总数及后续空页补计数共用该时刻和全部授权条件。分页仍为实时队列，每个请求重新判断期限；跨过截止时间后应刷新首页，不能把各页理解为冻结快照。游标绑定期限条件，改筛选必须重新查询。默认 all 保留已有游标格式与上下文，兼容原调用方。

入口负责校验协议参数并捕获查询时刻，领域读端口表达期限筛选，Flowable 适配器负责参数化时间谓词；不新增任务状态副本或迁移。期限筛选不会完成任务、改变批准权限或重置期限。列表和看板共用筛选，编辑未提交条件不影响已加载结果；清空恢复全部期限状态。

2026-09-28 范围验证：最小测试先以未知 deadline 参数返回 400 复现缺失功能；补齐后 H2 后端 27 项、前端 31 项、类型检查/构建和 OpenAPI 契约通过。PostgreSQL 17.11 上的待办集成测试 12 项通过，包含截止时刻相等、后续空页、租户及当前可办理权限边界；这些范围与 H2 重叠，不累计为独立用例数。

独立 H2 运行时使用真实日历和任务创建产生期限，32 条任务到期后验证 30＋2 分页、未来期限 1 条、未记录期限 1 条；14 次 HTTP 验收请求通过，79 次测试数据准备请求单独记录。浏览器验证筛选、末页、未提交条件、看板和清空，无页面控制台错误，34 张申请均仍在审批中。证据见 [SLA 筛选验收](evidence/pending-task-sla-filter-20260928.json)。

## 金额读索引与升级

V12 为 approval_application 添加 `search_amount DECIMAL(56,18)` 及租户/状态/金额索引。该列是从原内容计算的查询索引，核算和审批仍以申请及其表单为事实源。申请仓储在原事务中同步写索引，补正清空或修改金额时也同步更新；它不保存另一套业务金额状态。

当前只识别 schema 声明为 NUMBER 的 `amount` 字段；无 schema 的旧申请只识别规范十进制 amount。TEXT 类型、缺失/空值、无效旧值保持 NULL，不按零处理，也不从明细合计猜测金额。查询设置金额范围时这些记录不匹配。仅增加列和索引，不重写旧正文、状态、版本、时间、轮次和审计。固定迁移实现不调用可能继续变化的运行时提取器。

列精度容纳现有表单最多 38 位有效数字、18 位小数，包括 38 位整数；JSON 摘要金额按字符串返回，前端不经过 Number 转换。当前尚无跨币种换算或财务核定金额语义，金额筛选不代表财务核算能力。

## 交互与回归

输入筛选后点击查询生效，分页始终使用已提交条件的副本。账号、条件、页面切换会取消旧请求并清空结果；迟到成功/失败不回填。分页失败保留已有结果和原游标，可重试；重复点击不会重复加载。只读请求有 12 秒时限，不进入写操作恢复队列。

首页不预先读取全部申请正文。申请记录进入对应页面后按当前授权检索摘要，打开详情才读取正文；见[参与者申请检索](participant-application-search.md)。

长任务列表使用独立滚动区。选择任务后详情滚动到可见位置并接收焦点，防止详情被几十行任务推到页面底部。窄屏仍可访问筛选和审批按钮。

浏览器回归步骤：

1. 准备 35 条以上待办，确认首页加载 30 条、总量独立显示，加载更多到末页。
2. 组合申请人和金额范围，确认总数和行内容一致；输入逆序金额区间，确认显示错误并可清空重查。
3. 从 30 条列表选择第一项，确认列表滚动区有界，详情可见并取得焦点；批准后总数减少，旧任务消息转到已批准申请详情。
4. 设置 400 毫秒网络延迟，连续点击两次刷新数据；旧请求取消不显示网络故障，最新请求成功后显示正常状态。恢复网络配置。
5. 切换到无关账号，确认结果和详情不残留；在窄屏确认没有水平溢出。

独立验收库执行 `python3 scripts/check-task-queue.py http://127.0.0.1:8082`。脚本创建独立随机流程与 36 张申请，验证 30＋6 分页、筛选、当前授权、单项读取、领取、委派、回交与批准，并保留其余待办供 UI 验收。不要将该写入型脚本用于生产库。

风险、组织筛选需要对应的真实数据源，当前尚未提供；抄送和受策略控制的批量处理仍在后续范围内。已交付的[看板视图](task-board.md)与列表共用本查询接口。
