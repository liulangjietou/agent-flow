# F04 跨单风险与合计金额路由

状态：领域计算、发布校验、持久化、提交事务与 Flowable 业务网关已接通，356 项相关回归通过；权限查询、设计器、页面及固定安装包验收仍待完成。用户已授权剩余任务按推荐方案实施；N、金额阈值和企业配置仍必须由管理员明确填写，不给既有流程补造默认规则。

原需求为 `05-费用报销领域设计.md` §5.3：同一申请人、同一类别、N 天内多张单合计超过金额矩阵阈值，标记 `SPLIT_SUSPECTED`，按合计金额选择审批层级。已接受的口径为提交时滚动 N×24 小时、当前有效轮次，并按租户、申请人、法人、本位币和类别隔离。

## 调用链与职责

调用方是 `ExpenseController` 的正式提交入口；`ExpenseSubmissionService.submit` 重验预检、冻结费用轮次、更新财务版本，经 `ApprovalApplicationFacade` 启动 Flowable，最后登记预算操作。费用资源、原件、预算与流程都在该本地事务中协调。跨单来源查询、冻结与运行绑定放在费用服务，纯金额和窗口判定放在费用领域模型。

`ExpenseFormContract.amount` 同时用于业务金额条件和财务核减后的复核条件；`ExpenseReductionService` 还会用新核定金额更新它。因此 F04 不替换该字段，而只在显式标记的业务排他网关求值时采用冻结的跨单路由金额。报销总额、税额、预算、凭证和付款继续使用本单财务事实。

既有提交已经持有租户 `expense_configuration` 行锁。跨单查询在此锁取得后执行，沿用这一提交串行点；不再添加另一套跨单锁。来源行以同一 SQL 读取的状态和财务版本为准，不对其他报销单逐一加锁，避免两个提交各自持有本单锁后互相等待。

## 规则与冻结口径

- 开始节点属性 `expenseSplitRisk` 明确为 `ENABLED` 或 `DISABLED`；缺少属性表示未配置。启用时必须填写 `expenseSplitWindowDays`、`expenseSplitThreshold` 和 `expenseSplitCurrency`，并选择至少一个业务网关。
- 软件支持 1 至 365 个滚动日；阈值必须为正数，并沿用系统现有 Money 支持的两位 ISO 币种范围。此范围是输入界限，不是企业规则的默认值。关闭时可保留一套完整合法参数，也可全部清空；不接受半套参数。
- 业务排他网关用 `expenseSplitRouting=AGGREGATE_AMOUNT` 标记，其条件须引用 `amount`。财务审核或复核之后可达的网关不能标记；普通财务条件保持原求值方法。关闭策略时标记不启用合计路由。
- 窗口以本轮费用冻结的提交时刻为准，范围为 `[时刻－N×24 小时, 时刻]`，包含下边界，排除未来时刻。来源只含其他报销单的当前 `IN_APPROVAL` 或 `APPROVED` 轮次；退回、撤回、驳回、撤销、作废及草稿不计入，重提不重复计入本单旧轮次。
- 使用来源当前有效轮次在查询时已核定的本位币含税金额，按类别汇总；保留其财务版本、原轮次及行号。零额行不增加跨单数量，不跨类别合并为一次命中。
- 至少两张不同报销单有该类别的正额，且类别合计严格大于阈值才命中。路由金额取“本单核定总额”和“所有命中类别的合计”中最大值，不将不同类别合计再次相加，也不降低本单原审批金额。
- 一次冻结最多容纳 1,000 张参与单据（含本单）；超过界限阻断提交，不截断来源后声称已完成检查。来源顺序固定为本单在前，其余按提交时刻和报销单编号排列，行号和类别排序固定。
- 来源后续核减、退回或配置换版不改写已经冻结的路由依据。下一次提交重新计算；财务核减仍可改变本单财务复核金额，但不能消除已冻结的业务路由依据。

## 存储与运行边界

在 `expense_report` 添加当前冻结轮次、冻结提交时刻、法人及本位币的查询投影。V116 从原 `state_json` 的当前轮次回填，不重写旧正文；新建、修改和恢复检查由同一仓储维护投影。按租户、申请人、法人、本位币与窗口查询当前有效来源，旧规则关闭的来源也参与新规则的经济事实比较。

另存每个报销轮次的不可变合计依据，关联原财务修订和已发布定义。提交在费用修订已写入、流程启动之前准备该依据，Flowable 只读取服务端同事务的准备记录；后续步骤失败则全部回滚。由于原审批轮次在引擎启动之后追加，主记录不能依赖尚未存在的轮次外键；持久记录必须绑定原报销、财务修订、预期轮次和定义，读取时再核对已提交轮次。已有来源的外键仍绑定实际原轮次和财务修订。

新 BPMN 仅对已启用且已标记网关生成专用条件调用；旧 BPMN 的两参数和三参数方法保持原语义。启动时校验金额、币种、定义、报销和原轮次绑定，缺少或错配的依据直接阻断，不能退回本单金额继续运行。

## 页面和权限

新增原轮次只读依据入口 `/api/v1/expense-reports/{id}/split-routing?roundNo=...`，以及费用详情中的状态和依据展示。必须先拥有本单原轮次完整费用明细权限。只要任一来源原轮次明细不可读，就只返回受限状态，不返回合计、来源编号、行号或数量；管理员没有额外读取权。计算服务可以使用服务端事实决定业务路由，页面不能借此扩大跨单读取权限。

两种设计器显式维护启用状态、窗口、币种、阈值和业务网关。导入导出、差异、模拟及模板使用相同配置；模板升级保持旧发布版本和在审轮次，示例默认关闭 F04。普通表单、AI 输出和浏览器正文都不能填写或修改冻结依据。

## 验收边界

需覆盖精确窗口、阈值相等、同单多行、多类别、租户/法人/币种隔离、撤回重提、并发提交、核减、回滚、敏感字段、旧数据和旧 BPMN。固定包使用真实本地 HTTP/Flowable 验证升级、重启、原审批接续及配套恢复。浏览器、PostgreSQL 和企业接入仍分别保留对应门禁；局部单元测试不等同于 F04 交付完成。
