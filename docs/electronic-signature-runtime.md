## 回调锁等待缺陷

第一次安装包运行发现，两个已验真的并发重复回调可能分别得到 204 和 409。控制器在进入服务前记录接收时刻，先到请求可能后取得数据库锁；此时其时间早于另一事务已保存的 `updatedAt`。原并发测试给两个调用传入同一时刻，因此未覆盖这一顺序。

先补两个最小用例，分别复现重复回调和新回调排在其他事务后取得锁的失败，再修改事务编排服务。锁内生效时刻以持久化 `updatedAt` 为下界；原始验真时刻仍保存在证据中。该处理属于掌握锁和持久状态的服务层，领域对象继续拒绝状态时间倒退，验签也不借此放宽未来回执的接受范围。

修复后的最终 Java 范围为 165 个唯一用例，全部通过，无失败、错误或跳过。它包含两个新增回归用例，不与前阶段 314 个用例或重复运行次数相加。

## 共享企业登录

使用同一安装包、独立合成 RSA／PKCE 身份源和 JDBC 共享会话，另完成 7 次应用启动、68 次业务 HTTP 交互及 3 次签署服务调用。员工仅有 EMPLOYEE，审批人有 APPROVER，管理员有 ADMIN／PROCESS_ADMIN；管理员同时是有效组织人员，敏感附件读取仍被拒绝。

- 待发操作创建后重启应用，原会话恢复并完成首次发送，远端仅提交 1 次，原件与结果分别下载。持久授权只关联会话内部 PRIMARY_ID，不保存可登录的 SESSION_ID。
- 主动注销删除原共享会话但保留授权历史；同一用户重新登录后，旧待发操作仍被取消，未调用服务方。
- 当前人员停用后，旧待发操作取消且发送尝试为 0。
- 关闭 JDBC 共享会话时，签署选项不可用，创建返回 503，未向服务方发送。
- 普通业务写入缺少 CSRF 令牌返回 403；已验真回调无需用户会话或 CSRF，仍可完成原操作。

最终记录的 63 份 JSON 响应、35 份 JSON 请求、4 次二进制下载、1 次无正文回调均符合契约；页面解析函数另核对 9 次读取和 3 份写回执。合成身份源和 HTTP 协议验收不代替浏览器或真实企业 IdP 验收。

## 证据与边界

一次恢复夹具最初直接比较 H2 结构导出的行顺序，将 CHECK／UNIQUE 约束语句换序误判为差异。全表数据摘要一致，之后用 H2 自身的 SQL 语句解析器比较完整语句及其重复次数，确认 2099 条结构语句一致；这是夹具修正，未修改生产实现。共享登录夹具也分别修正了源码启动的类加载方式、企业人员规则标识和管理员缺少有效人员绑定三处准备问题，未据此修改生产权限。首次失败、最小失败复现、最终通过日志、实际请求和响应以及原始配套备份均保留。

上述服务、身份与文件均为合成数据。真实供应商的身份、文件内签名、证书链和时间戳仍归 E10；真实企业 IdP 验收归 E11。浏览器与 PostgreSQL 验收尚未完成，既有访问限制未绕过，I02 保持 OPEN。原主工作区和运行进程保持，新增验收进程在结束后关闭；远端 PR／CI 随 V02 完成后进入 E15。
