# 待办看板

“待我审批”可在列表和看板之间切换。看板按真实办理状态分为待领取、已指派、待回交三列，列内沿用服务端的进入待办时间顺序。任务卡片保留申请人、标题、单号、流程版本、轮次和精确金额；受托任务额外显示回交对象。

## 使用与边界

- 列表和看板共用已应用的筛选、已加载页面和选中任务；切换视图不发起审批动作或重新读取整份申请正文。
- 看板数字表示各列已加载条数，队列总数仍使用服务端返回的筛选计数。第一页 30 条，继续加载后更新各列；尚有下一页时，空列提示不能据此认定没有此类任务。
- “指派给我”筛选沿用既有含义，包含指派给自己的受托任务。看板从中单独分出待回交，三列互不重复；回交完成后原审批人看到已指派任务。
- 点击卡片先读取最新任务权限、版本及申请，再进入已有办理界面。看板提供返回按钮，将键盘焦点恢复到原卡片；卡片已经离开队列时回到队列区域。
- 领取、释放、委派、回交和批准通过原服务端动作完成，成功后刷新当前查询。刷新从第一页开始，不把上一次加载的旧卡片留作办理依据。
- 无结果、读取失败与分页重试沿用待办查询机制。刷新失败清除旧卡片，分页失败保留原页及游标供重试。
- 视图选择仅保留在当前页面会话内，切换账号恢复列表。不会新增浏览器正文缓存或改变其他账号设置。
- 宽屏三列，较窄屏幕纵向排列；任务列内部滚动，保留明确列标题、键盘选择和焦点样式。卡片不提供通过拖动改变审批状态的操作。

## DDD 职责与调用链

`App.vue` → `PendingTaskQueue` → `PendingTaskQueueQuery` → 原 `GET /api/v1/workspace/tasks`；卡片点击继续走 `GET /tasks/{id}`、申请详情和 `TaskActions`。

三列仅投影 `assignee` 与 `delegationState`。`PendingTaskCard` 为两种视图共用展示，审批命令和权限不在卡片中判断。后端领域模型、Flowable 状态、授权、API、数据库迁移均没有改变，未增加新的任务状态或处理路径。
