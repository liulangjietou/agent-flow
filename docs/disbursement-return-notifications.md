# 借款放款退回通知

F17 的借款放款退回查询、明确裁决和原消息详情已接通。本阶段完成本地实现与范围验证，F17 整体仍为 OPEN。验证记录见[阶段证据](evidence/disbursement-return-notifications-20261003.json)。

## 调用链和事实边界

财务从原借款发起放款退回查询，后台工作器读取原银行放款及实际入款依据。`AdvanceDisbursementReturnService` 在查询状态持久化后发布 `AdvanceDisbursementReturnChanged`；明确裁决时先保存借款修订、查询消费、决定及入款防重凭据，再发布同事务事件。通知只投影已经保存的事实，与借款裁决、审计及外发意向共同提交或回滚。

查询不可用、来源失效、原件未核清、发现待登记退回以及明确裁决分别通知。后续[还款复核通知阶段](repayment-review-notifications.md)补充原查询的历史一致性结论：CONFIRMED 与既有退回记录冲突时通知重新核对；一致重复查询已登记退回时保持安静。排队、运行及正常一致的查询保持安静。发现退回原件本身不会减少欠款；明确裁决也可能确认没有资金退回，不能将所有结果写成回款成功。主动还款、还款复核及既有占用仍分别保留。

接收人是原申请人和本次实际核对财务；创建及外发领取都会复核当前人员和原法人任职。去重键为 `disbursement-return:<原查询编号>:<事实种类>`，重复事件和 HTTP 原键回放不重复通知。消息不包含金额、公司账户、入款流水或证明正文。

## 原查询与原决定

`GET /api/v1/notifications/{id}/disbursement-return-target` 仅接受本人消息编号，不允许额外查询参数。详情绑定原借款轮次、首次成功放款修订和本次查询；不会发起银行查询、修改借款、登记资金或标记已读。

仓储按原决定编号恢复被消费查询与裁决前后的借款修订，重放领域裁决验证实际状态变化。后续退回、主动还款及新的余额版本不能替代旧决定。旧待核对消息可以展示同一查询后来明确形成的裁决；失败和未核清消息仍保留各自查询状态。

申请人读取沿用原轮次字段权限，财务还须当前 FINANCE 角色和原法人任职，管理员不能通过消息绕过敏感字段。响应使用 `no-store`。页面分别展示消息发生时事实、当前原查询状态、原件有效窗口和真实裁决，只提供重新读取与原申请轮次导航。身份切换、失权、超时和卸载会清除旧内容并阻断迟到响应。

历史裁决保留微秒与毫秒精度边界：到期前完成的裁决不会因浏览器截断到同一毫秒而被误拒绝展示，读取也不会延长原件有效期或授予办理许可。
