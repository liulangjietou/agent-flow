# 结构化财务实施

2026-09-28 开始实施。依据项目原 `doc/05-费用报销领域设计.md` 及当前 `docs/remaining-implementation-plan.md`；D1–D6 和保守默认已经用户授权。此文是实际开发记录，不把未配置外部接口或未验收环境标记为完成。

## 事实源与调用链

费用报销页 → 费用核算应用服务 → `ExpenseReport`、发票、事前申请/借款余额 → 审批申请用例。`Application` 只拥有审批状态、轮次与任务，报销明细、含税金额、核定额和应付金额以 `ExpenseReport` 为准。结构化业务只通过自己的写入入口操作，通用表单入口须拒绝绕过财务校验。

外部预检、账户、汇率和发票查验在事务外获取；本地事务复核申请与财务版本、占用发票和余额、冻结快照、启动审批并写预算消息。预算冻结、凭证和支付由持久任务在事务外调用。外部状态未知时保留原幂等号并对账，不能盲目再次付款。

核减调用方是当前财务待办处理人。应用服务负责当前任务、申请状态、组织权限和职责分离；报销聚合保证只减不增、分摊平衡、税额不超含税额、冲销额不超过核定额，并追加差额记录。结算拥有独立状态和付款授权，采纳 Agent 摘要不参与这些状态转换。

受影响场景：草稿/补正、提交与重提、跨币种明细、重复发票、并发占用、预算冻结失败、签收、核减、零应付结算、外部账户变化、凭证失败、支付回调乱序、撤销与归档；通用表单及旧申请保持原事实。

## 金额与核减规则

金额采用非负定点十进制；按当前费用设计支持两位金额精度，入参超出精度直接失败，不静默四舍五入用户填写的金额。汇率仅在提交时应用，按行四舍五入至两位后汇总。币种必须显式匹配；汇率来源、日期和币种对随轮次冻结。

成本分摊先校验原币合计等于行申报金额。本币折算或核减后的金额按原始分摊权重使用最大余数法分配整分，并按原输入顺序打破余数相同的平局，保证分摊与核定行金额严格相等。

税额不内置推断税率或抵扣政策。原币税额必须不超过含税金额；可抵扣资格由版本化政策/查验事实提供。核减时财务明确核对核定税额，服务端要求金额和税额均不增加、税额不超过核定含税金额；不根据模型结果或通用比例宣称完成税务校验。

草稿明细允许多币种；冲销使用法人本位币。核减后冲销超过核定总额时，从已冻结的选择顺序末尾依次下调，保留每笔变化；对应余额预留和预算释放由应用服务同步编排。任何错误必须发生在聚合状态整体替换之前，不能出现前几行已经核减而后续一行失败的半更新。

## 已完成的财务基础与草稿 API

`Money`、`ExpenseLine`、`ExpenseReport` 现已实现两位金额、行汇兑、分摊守恒、费用/税额独立核减、借款冲销收敛及不可变轮次。核减不会改变提交时的费用、汇率、制度与账户证据。`EmployeeAccountSnapshot` 只保存外部引用、掩码和绑定摘要，不保存完整卡号。

V33 给审批申请增加不可变 `BusinessReference(EXPENSE, id)`，旧表单的绑定保持空，不根据历史流程名称猜测财务业务。数据库外键同时核对租户、申请、业务类型和报销标识；财务版本与审批版本分开更新，每次财务写入追加 `expense_report_revision`。申请与财务写入共用短事务，追加证据失败时整体回滚。

草稿入口为 `POST /expense-reports`、`POST /expense-reports/{id}/revise`，读取使用 `GET /expense-reports/{id}?roundNo=`。金额 JSON 为 `{"value":"10.00","currency":"CNY"}`，拒绝 JSON 浮点数、科学计数法和未知金额属性。普通申请的创建、编辑、提交、撤回及作废不能处理结构化费用，返回 `USE_BUSINESS_ENDPOINT`。

结构化费用定义必须包含 `expenseDetails`、`amount`、`currency`、`overPolicy` 四个必填字段。完整费用是一个敏感字段组 `expenseDetails`，必须声明敏感标记并由节点显式授权；隐藏或脱敏均不能通过费用 API 取回原文。管理员无明细豁免。`amount`、`currency`、`overPolicy` 只由已核定财务轮次派生，草稿不填猜测值。旧审批人只能按原轮次权限读取原财务快照，不能读取后续补正草稿。支付账户的内部引用和摘要不返回页面。

当前进度只包含财务模型和草稿基础：完整提交、外部查验、资源占用、预算与结算守卫以及业务页面仍按上表继续接入。读取权限测试中的冻结事实是测试夹具，不是查验或正式提交能力。
