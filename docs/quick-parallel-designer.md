# 快速步骤中的并行审批

流程管理员在快速步骤的“＋”中选择“添加并行分支”，即可生成两个审批分支及配对的全部汇合节点。可继续增加分支、配置审批人、嵌套条件或并行块，无需先进入高级画布连接每一条线。所有并行分支都执行，全部完成后继续；左右顺序只用于展示。

## 编辑行为

- 点击分支块可增加分支、查看删除范围或删除整块。点击分支标题可调整展示顺序或删除该分支，至少保留两条路径。删除后可撤销。
- 分支内审批沿用单人审批与全员会签配置。并行线不显示条件、默认分支或条件优先级按钮。
- 支持成对嵌套，以及同一网关先汇合再拆分。删除后半块保留前半块的汇合责任；共用后续节点不属于某一分支的删除范围。
- 多入口汇合之前不提供公共插入按钮，避免新增步骤绕过等待。可以在某条分支内或汇合之后插入。
- 在并行汇合前插入条件时，自动添加独立的条件汇合，使被选中的一条路径继续进入并行汇合。否则把条件的每条出路直接接入并行网关，会等待永远不会被选择的路径。
- 删除兼有条件合流作用的审批步骤时，保留一个条件汇合节点；审批行为被删除，必要的合流仍在。
- 快速步骤和高级画布使用同一份图、属性、条件与撤销历史。切换模式不改图、不增加修订号。断线、交叉共享、不配对或不支持的图保持原样并提示进入高级画布处理。
- 新建节点仍须配置审批人和业务条件，服务端继续负责保存和发布校验。已发布版本只读，必须复制为草稿后编辑。

## 调用链与职责

`App.vue` → `QuickDesigner` / `QuickSequence` → `quickDesigner.ts` → 原定义保存、校验、模拟与发布接口。快速编辑只在图副本中计算一次结构变更，没有新增一套持久化流程模型。

`DefinitionValidator` 允许多入单出的排他网关作为条件汇合，出线必须无条件且非默认；单入单出的伪分支仍拒绝。`ParallelStructureValidator` 继续验证并行分支归属，不允许用条件汇合代替并行等待。`DefinitionSimulator` 与 `BranchCoverageAnalyzer` 不把纯条件汇合当作新的条件判断。

领域层没有引入 Flowable 类型。基础设施沿用原生 `exclusiveGateway` 和 `parallelGateway` 部署；权限、幂等、轮次快照、整轮退回/驳回/撤回均保持原链路。没有新增 API 或数据库迁移，数据库仍为 V23。
