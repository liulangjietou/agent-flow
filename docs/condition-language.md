# 版本化条件语言与设计器

条件属于流程定义的路由规则，由 `agentflow-domain` 解析成受限 AST 并求值。设计器校验、试算与 Flowable 运行共用此实现；服务器适配层只负责 JSON 版本绑定、权限和 BPMN 部署。

## 兼容边界

`graph.conditionLanguageVersion` 只接受整数 `1` 或 `2`，缺省为 `1`。旧库记录、旧模板、旧导入文件及旧 BPMN 的两参数调用继续使用 v1。字符串、小数、null、未知版本不能被强制转换成合法版本。

新建空白流程使用 v2。旧草稿点击“启用组合条件”时，客户端请求 `POST /api/v1/process-definitions/upgrade-conditions`，服务端先用 v1 解析原 AST，再生成等价 v2 文本。它需要 ADMIN 或 PROCESS_ADMIN 权限，返回 `Cache-Control: no-store`，不保存、不发布、不产生业务幂等记录。任一条件无效或转换超限时整体失败。客户端确认返回仍属于当前编辑快照后才应用，可撤销/重做，然后沿原有草稿保存与发布流程生效。

例如旧条件 `memo == a && b` 中 `a && b` 是一个字面量，升级为 `memo == "a && b"`；不能直接把原文按新版执行。已发布版本保持不可修改，创建新的草稿版本后才可升级。图版本随保存、模板导入导出、编辑历史保留，版本比较将其列为路由变化。

## v2 规则

- 比较：`== != > >= < <= EXISTS NOT_EXISTS`，继续受表单字段类型和选项白名单约束。
- 逻辑：`AND`/`&&`、`OR`/`||`、`!`、括号；优先级为括号、取反、且、或。关键字不区分大小写，布尔字面量使用 `true`/`false`。
- 属于：`category IN ["TRAVEL", "DAILY"]`。仅支持 SELECT 字段，列表非空，每个值必须存在于本版本表单选项。没有表单契约的历史流程不能使用 IN。
- 文本使用单引号或双引号；支持常见转义与 `\uXXXX`。数字可使用精确十进制文本；前端不转 JS 浮点数。禁止函数、脚本、模板表达式与分号，包括转义后出现的禁用内容。
- 未填写字段的普通比较为 false，`NOT_EXISTS` 为 true；`!` 对完整结果取反。因此 `!(amount > 5000)` 包含未填写金额的情况。需要排除时使用 `amount EXISTS && !(amount > 5000)`。
- 独占分支仍按保存的连线顺序选择首个匹配项；默认分支只在其他条件都不匹配时选择。

示例：

```text
(amount > 5000 && category IN ["TRAVEL", "DAILY"])
OR (urgent == true && !description NOT_EXISTS)
```

表达式最多 4000 个 UTF-16 字符、16 层嵌套（含取反）、100 个比较项、每个 IN 最多 50 项、字面量最多 256 个 UTF-16 字符。语法错误返回 `INVALID_CONDITION_AT:<edgeId>:<position>`，位置从 1 开始，以 UTF-16 字符计数；缺少末尾符号时可指向长度加 1。界面展示字符位置并提供连线定位。

## 交互与验证

快速设计和图形设计共用条件编辑器。单一且/或条件组可以按字段编辑；SELECT 的“属于（多选）”使用复选框。括号、取反和混合连接符保留原表达式，不强行拆成平面列表。金额阈值保持字符串精度。表达式修改后，使用“校验流程”和“流程模拟”检查配置与分支结果。

自动测试覆盖旧语义升级、转义、精度、缺失值、优先级、复杂度限制、字段类型白名单、只读权限、严格版本输入、数据库回读、新版实际 Flowable 路由和历史两参数 BPMN。前端测试覆盖 IN 回显、复杂表达式保留、版本透传与导入导出。

浏览器验收步骤：

1. 打开旧草稿，点击“启用组合条件”；撤销后旧提示恢复，重做后新版条件恢复。
2. 选择含 SELECT 字段的分支，将判断改为“属于（多选）”，勾选两项；切到表达式核对 IN 文本，再切回字段配置核对复选项。
3. 输入括号、且/或混合及取反，验证原文保留；输入 `amount >` 后校验，核对错误位置与连线定位。
4. 保存、重载并导出再导入，确认版本和原条件文本保留；发布后只读且执行结果与模拟一致。

数字区间覆盖与重叠分析现已实现，见 [分支覆盖说明](branch-coverage.md)。可视化嵌套条件组和任意脚本仍未包含。
