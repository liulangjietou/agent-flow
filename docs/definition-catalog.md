# 流程目录

进入“流程管理”，点击“流程目录”，按名称或流程标识搜索草稿和发布版本，再打开目标记录。默认加载 30 条，点击“加载更多流程”继续读取；显示的是已加载数量，不是全库总数。

可组合流程状态、准确流程标识和发布版本。版本必须配合准确标识使用；选择草稿或清空标识时，版本条件清空。修改筛选后，页面明确提示下方仍为上次查询结果；再次查询后才生效，追加读取始终沿用已提交的条件。

打开记录时重新读取完整配置，避免从旧列表恢复过时的草稿。当前存在未保存修改时，先选择继续编辑或放弃修改并打开；读取失败保留当前设计。发布版本继续只读，编辑、发布和新建权限沿用原规则。

## 查询契约

`GET /api/v1/process-definitions/search`，必须登录，响应为 `Cache-Control: no-store`。

| 参数 | 规则 |
|---|---|
| q | 名称或标识包含匹配，不区分大小写，最多 100 字符；`%`、`_`、`!` 按字面量处理 |
| status | `DRAFT` / `PUBLISHED`；流程管理员省略时查询两者，普通账号始终只见已发布版本 |
| processKey | 精确流程标识，最多 128 字符 |
| version | 发布版本，1—2147483647；必须同时指定 processKey，不能与 DRAFT 组合 |
| limit | 默认 30，范围 1—100 |
| cursor | 相同查询返回的 nextCursor，绑定租户、账号、角色及筛选条件 |

`ADMIN` 和 `PROCESS_ADMIN` 可查询当前租户的草稿与发布版本；普通账号显式请求草稿返回 403。客户端不能传 tenantId 或排序覆盖查询边界。未知参数、非法筛选或失效游标返回 `400 INVALID_DEFINITION_QUERY`；未登录返回 401。

响应为 `items` 和可空的 `nextCursor`。每项仅含 `id / key / name / status / version / revision / createdAt / updatedAt`，不含流程图、表单配置或其他租户数据。按 `created_at DESC, id DESC` 定位下一页，单次 SQL 最多读取 limit + 1 条，无全库 COUNT 或逐条聚合装载。创建时间不随保存和发布改变；查询不构成跨页冻结快照，状态或名称在翻页期间变化可能影响匹配，新建记录通过重新查询获取。

## 职责与兼容

调用链为 `DefinitionCatalog → DefinitionCatalogController → DefinitionCatalogPort → JdbcDefinitionCatalogAdapter`。Controller 在入口校验角色和参数；领域端口描述查询模型；基础设施执行带租户谓词的绑定参数 SQL。目录属于只读模型，不向流程定义聚合加入列表分页职责。打开记录复用已有定义详情接口、授权和未保存确认。

V18 只增加 `(tenant_id, created_at DESC, id DESC)` 索引，不修改流程、审批或历史数据。旧 V17 迁移测试改为明确迁移到 17，独立 V18 测试验证新增索引、旧行和迁移历史保留。

账号变化、关闭目录及新查询会取消旧请求，迟到结果不能回填。查询设置 12 秒超时；首次失败清空旧结果，追加失败保留已有结果与游标供重试。打开完整配置也有超时保护。

本次替换设计器的长下拉列表。首次使用引导、发起申请、版本比较等页面仍依赖旧的全量定义读取，因此不代表全站已经消除全量加载，也不代表完成生产容量验收。停用/归档、组织初始化、附件、Agent 和财务规则另行开发。
