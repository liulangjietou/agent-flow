# 付款授权与执行持久状态

更新：2026-09-28。本阶段完成领域模型、数据库 V45 和仓储验证。真实批准来源编排、岗位授权入口、后台执行器、页面及到账结算仍在接续开发；此阶段没有开放付款 API，也没有调用银行或生成借款到账余额。

## 调用链与职责

财务授权服务从实际批准的借款或费用轮次、原收款账户和已过账凭证派生 `PaymentAuthorization`。付款正额来自挂账凭证的净应付，不接受客户端金额。申请人、财务授权人和出纳必须是三人；出纳登记只接受该出纳当前目录中的账户，并固定一条以授权号为编号的 `PaymentCommand`。实际岗位、敏感字段读取权限、原业务版本及当前账户须由应用服务重新核验，领域对象自身不是权限凭据。

授权模型负责自身状态和不可变条款；执行模型负责检查、可能发送、恢复及外部事实演进；仓储负责租户、版本、原始输入、关系约束和逐版审计快照。跨聚合真实来源、网络读取和资金发送由后续应用服务及事务外执行器承担，不能放在实体或 JDBC 事务中。

## 授权与执行规则

授权固定租户、用途、申请／业务编号、轮次、两套版本、实际应付、本人收款账户快照、挂账凭证命令摘要、财务目标、过账引用和外部版本。重新核验凭证时同时比对金额、身份和业务绑定；只核对编号或摘要不足以证明恢复后的条款未改变。查询中、冲突、失败或已冲销的凭证不可用于新付款。

授权有效区间为 `[authorizedAt, expiresAt)`，最多二十四小时，应用配置可以进一步缩短。授权不会自动续期。未执行时可带原因作废或到期；执行登记一经保存不能再次换出纳、账户或延长原窗口。零应付不创建付款命令，留给实际资源核销与归档处理。

| 当前状态或事件 | 行为 |
| --- | --- |
| QUEUED → CHECKING | 只领取账户复查，还没有资金副作用 |
| CHECKING 读取失败或租约过期 | 重读原出纳的目录和原收款账户，不生成银行失败事实 |
| CHECKING → SENDING | 重新核验原账户版本、法人、币种及出纳；持久化选择账户的有效证据后才允许外发 |
| SENDING 超时、异常或租约过期 | UNKNOWN，后续只查询原授权及原命令摘要 |
| UNKNOWN → QUERYING | 即使授权到期也继续追踪原交易，不重发付款 |
| 权威 NOT_FOUND | 停止自动调度；显式恢复才可重发原编号，仍受原有效期约束并重新检查账户 |
| SUCCEEDED | 金额、币种、账户、原命令及回单全部匹配时，才可作为首次本地结算依据 |
| REVERSED | 保留退回回单和退回完成时间，不能重复形成到账结算或静默删除既有核销 |
| 乱序、同版本矛盾或状态倒退 | RECONCILING，保留先前到账事实、最高外部版本和矛盾事实；再次查询不会自动消除矛盾 |

每次真正调用前仍检查租约、授权和短期账户证据。检查与可能发送使用不同持久状态，因此崩溃恢复不会把账户读取失败误判成未知银行付款，也不会把可能已支付的交易当作首次发送。外部资金系统仍须原子复核其自身账户、权限、批准与凭证条件；只读预检不能消除跨系统变化窗口。

## V45 与恢复

新增 `payment_authorization`、`payment_authorization_revision`、`payment_operation`、`payment_operation_revision`。授权通过租户、业务、申请、轮次与挂账凭证外键关联。有效授权及已登记执行独占整张业务单据，不能通过另一审批轮次换号重付；只有未执行的作废／到期授权释放占用。

授权登记与原命令队列在同一事务保存。命令、目标、出款账户及授权条款参与比较更新；迟到执行者不能覆盖新版本。每次更新与对应版本快照同事务追加，历史写入失败会整体回滚。读取时同时验证领域快照、摘要与关系字段，跨租户读取为空，持久数据不一致拒绝恢复。

## 验证

领域授权 8 项、执行状态 11 项；仓储 5 项、V44→V45 升级 1 项。包含既有凭证、账户及支付端口的 H2 范围回归共 75 项通过；仓储与迁移 6 项在真实本地 PostgreSQL 重跑通过。范围有重叠，不相加为独立用例总数。Java 作者检查 604 个文件、1072 个类型通过。

新增授权恢复负例最初稳定失败：原实现仅核对凭证标识及摘要，变更恢复条款中的金额、租户或业务绑定仍可匹配。此前测试只走正常创建路径。补齐真实凭证财务字段的交叉核验后，范围回归通过。
