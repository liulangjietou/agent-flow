# 外部组织同步

I01 当前只完成同步协议、领域状态与持久化基础。本地组织管理功能继续由原入口使用；同步尚无可用的管理接口或页面，任务仍为 OPEN。基础实现提交为 `7cbb27278549cc7073afe4c6a2fce68c2389817b`。

## 调用链与职责

- 调用方：后续的组织管理页面和租户管理员同步接口。
- 下游：可信组织来源、原 `OrganizationService` / `OrganizationRepository`、组织选人及责任解析。
- 业务影响：后续发起与选人的组织事实可以变化；已经固定的审批轮次和责任快照保持原值。

批次、来源游标和稳定映射的状态约束放在组织领域。JDBC 仓储负责租户外键、版本比较、轨迹写入和事务参与。来源调用与组织变更的编排属于后续应用服务；任何网络调用都应在组织事务之外。

## 已实现的约束

一个租户只注册一个可信来源。来源返回相对于上次本地已应用版本的显式变更：`afterRevision` 必须匹配当前游标，非空变更的 `revision` 必须前进。空变更允许确认当前游标或推进到新版本。记录缺失表示未变；停用必须明确提供 `active=false`。

协议只包含法人、部门、岗位、人员和任职事实。来源标识按对象类型精确匹配，不根据显示名称或大小写归一化推断身份。人员主体保持原值；本地认证身份和系统角色不由同步创建或授予。单批最多 5,000 条事实，严格 JSON 正文最多 4 MiB，拒绝未知字段、重复键、尾随文档以及数字和布尔值的字符串替代。可空引用字段必须显式出现。

批次经过 `QUEUED → FETCHING → RECEIVED → APPLIED`。读取失败进入稳定的 `FAILED`；管理员可取消未应用批次。领取时固定原租约，到期或取消后不接受迟到结果。`RECEIVED` 仍占用当前租户的活动批次位置，避免待核对事实被新读取覆盖。重试创建关联原失败或取消批次的新批次。

收到数据不推进来源游标。只有具名人工应用成功后，才能在同一事务保存组织修改、原组织审计、批次状态、映射历史和来源游标。仓储要求已有事务；锁顺序为组织目录、来源、批次。稳定映射记录上次应用后的本地修订和来源版本，不能改绑到另一个本地对象。仓储核对映射目标的租户、类型和实际修订。

V109 增加来源、批次、状态轨迹、稳定映射和映射历史五张表，不改变原组织表结构。

## 当前验证

六个明确选择的测试类共执行 102 个唯一用例，失败、错误和跳过均为零：领域 47、严格协议 24、JDBC 持久化 23、迁移 1、原组织集成回归 7。加强 UTF-8 字节上限断言后，单独重跑协议类 24 个用例；当前清单替换该类旧报告，不重复相加。

持久化验证覆盖真实并发排队和领取、迟到结果拒绝、租户隔离、映射修订一致性及历史恢复。测试在同一真实 JDBC 事务中组合原组织服务和同步仓储，验证后续映射历史写入失败时，组织事实、审计、批次、映射和游标全部回滚。该测试组合不代表同步应用服务已经实现。

H2 的 V108 → V109 非空迁移验证保留五张已填充的组织及审批表和旧 Flyway 历史，五张新增表为空，重复迁移执行数为零。这是测试进程中的迁移验证，尚未进行固定安装包升级、进程重启和配套恢复验收。

详细范围、实际 Surefire 报告摘要和文件哈希见 [基础验证记录](evidence/organization-sync-foundation-20261004.json)。
