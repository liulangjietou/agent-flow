# 外部组织同步

I01 已完成同步协议、持久化基础、预检和人工应用，并接通可信来源 HTTP、持久工作器及 11 个管理员接口。系统检查、管理页面和固定包完整验收尚未完成，任务仍为 OPEN。基础实现提交为 `7cbb27278549cc7073afe4c6a2fce68c2389817b`，预检与应用实现提交为 `1a1b1fcaf1f742be34a30393707b7b3a0d29611e`。

## 调用链与职责

- 调用方：`OrganizationSyncController` 的租户管理员入口，以及待接通的组织管理页面。
- 下游：可信组织来源、原 `OrganizationService` / `OrganizationRepository`、组织选人及责任解析。
- 业务影响：后续发起与选人的组织事实可以变化；已经固定的审批轮次和责任快照保持原值。

批次、来源游标和稳定映射的状态约束放在组织领域。JDBC 仓储负责租户外键、版本比较、轨迹写入和事务参与。`OrganizationSyncService` 编排排队、领取、取消和结果接收；`OrganizationSyncWorker` 在领取和接收事务之间调用 `HttpOrganizationSyncSource`。网络等待不持有组织锁。`OrganizationSyncApplicationService` 独立编排人工预检和组织提交，工作器不持有该服务。单笔组织维护与同步投影通过 `OrganizationRelations` 使用同一套关系规则。

## 已实现的约束

一个租户只注册一个可信来源。来源返回相对于上次本地已应用版本的显式变更：`afterRevision` 必须匹配当前游标，非空变更的 `revision` 必须前进。空变更允许确认当前游标或推进到新版本。记录缺失表示未变；停用必须明确提供 `active=false`。

协议只包含法人、部门、岗位、人员和任职事实。来源标识按对象类型精确匹配，不根据显示名称或大小写归一化推断身份。人员主体保持原值；本地认证身份和系统角色不由同步创建或授予。单批最多 5,000 条事实，严格 JSON 正文最多 4 MiB，拒绝未知字段、重复键、尾随文档以及数字和布尔值的字符串替代。可空引用字段必须显式出现。

批次经过 `QUEUED → FETCHING → RECEIVED → APPLIED`。读取失败进入稳定的 `FAILED`；管理员可取消未应用批次。领取时固定原租约，到期或取消后不接受迟到结果。`RECEIVED` 仍占用当前租户的活动批次位置，避免待核对事实被新读取覆盖。重试创建关联原失败或取消批次的新批次。

收到数据不推进来源游标。只有具名人工应用成功后，才能在同一事务保存组织修改、原组织审计、批次状态、映射历史和来源游标。仓储要求已有事务；锁顺序为组织目录、来源、批次。稳定映射记录上次应用后的本地修订和来源版本，不能改绑到另一个本地对象。仓储核对映射目标的租户、类型和实际修订。

V109 增加来源、批次、状态轨迹、稳定映射和映射历史五张表，不改变原组织表结构。

## 可信来源与工作器

默认不启用外部组织同步。每个租户在部署配置中明确提供一个来源，没有默认租户回退，也不接受管理请求传入来源地址、令牌或超时。示例中的环境变量由部署方提供：

```yaml
agentflow:
  organization-sync:
    enabled: true
    worker-enabled: true
    poll-delay-ms: 1000
    tenants:
      example-tenant:
        source-key: corporate-hr
        endpoint: ${ORGANIZATION_SYNC_ENDPOINT}
        token: ${ORGANIZATION_SYNC_TOKEN}
        timeout-seconds: 15
```

企业入口使用 HTTPS 和 Bearer 令牌；地址不能带用户信息、查询参数或片段。基础路径只接受 `/`、英文字母、数字、下划线和连字符。明文 HTTP 只允许字面回环地址 `127.0.0.1` 或 `[::1]`；无凭据的回环夹具还必须显式设置 `allow-unauthenticated-loopback: true`。启用后的无效配置在启动时失败，错误文本和配置对象字符串不输出地址或凭据。

适配器只发送 `GET <endpoint>/changes?tenantId=...&sourceKey=...&afterRevision=...`，没有请求正文，不发送本地人员、审批或财务事实。返回必须为 HTTP 200、`application/json` 和严格 UTF-8，不能使用重定向。超时配置范围为 1–60 秒，覆盖完整响应流；单次请求还受原批次剩余租约限制。响应流超过 4 MiB 时立即取消，不等待远端结束或把超量内容完整读入内存。

外部协议第 1 版的根字段必须全部提供：`contractVersion`、`tenantId`、`sourceKey`、`afterRevision`、`revision`、`units`、`people`、`appointments`。三类事实使用外部稳定标识：

| 事实 | 必须提供的字段 |
| --- | --- |
| 单元 | `externalId`、`kind`、`name`、`legalEntityId`、`parentDepartmentId`、`active`、`headAppointmentId` |
| 人员 | `externalId`、`subject`、`displayName`、`active`、`approvalEligible` |
| 任职 | `externalId`、`personId`、`departmentId`、`positionId`、`active`、`supervisorAppointmentId` |

没有值的可空引用仍须写 `null`；管理 API 返回的是已解析的类型化引用，结构与外部协议不同。来源不能夹带登录凭据或系统角色。租户、逻辑来源和起始游标必须精确匹配原请求。

目标摘要固定租户、协议版本、逻辑来源及基础地址。令牌轮换不改变逻辑目标；来源标识或地址变化会使旧批次失效。排队、外发前、接收结果、预检和应用分别核对当前目标。读取过程中配置变化产生稳定的 `SOURCE_CHANGED`，不能把旧响应当成新来源事实。

独立单线程调度器按固定延时扫描持久队列，每轮最多领取十个候选；多进程竞争由组织目录、来源和批次锁解决。后台不会自行创建新批次，也不会自动应用已接收事实。租约固定为领取时的配置超时加五秒余量，不能由重建工作器续期。执行中批次到期后只记录 `SOURCE_TIMEOUT`，不重发；后续读取必须由管理员显式重试。`worker-enabled: false` 停止自动轮询，持久状态和管理员入口仍保留。

## 管理接口与恢复

接口前缀为 `/api/v1/organization/synchronization`，全部要求当前租户 ADMIN。权限校验先于成功响应的幂等回放；写入继续使用原 `Idempotency-Key`、OIDC CSRF 和当前身份绑定规则。只读接口不初始化目录、注册来源或探测远端，响应禁止缓存。

| 方法与相对路径 | 作用 |
| --- | --- |
| `GET /` | 配置状态、已注册来源版本、已应用游标和活动批次标识；不返回地址或令牌 |
| `POST /batches` | 确认 `targetDigest` 与 `expectedSourceVersion` 后排队；首次来源注册使用版本 0，返回 202 |
| `GET /batches` | 批次分页索引；只接受单值 `page` 和 `pageSize` |
| `GET /batches/{id}` | 原请求、来源事实、状态、人工决定与实际采用计划标识 |
| `POST /batches/{id}/retry` | 确认原终态版本和当前来源版本后追加新批次；保留 `retryOf`，返回 202 |
| `POST /batches/{id}/cancel` | 具名取消排队、读取中或待核对批次；当前来源停用或变化后仍可取消 |
| `POST /batches/{id}/preflight` | 保存完整核对计划，返回计划标识和 `ready`；冲突计划可保存但不能应用 |
| `POST /batches/{id}/apply` | 通过原批次版本和服务端 `planId` 明确应用；不接收客户端重新提供实体字段 |
| `GET /plans/{planId}` | 当前鉴权下读取原计划、前后值、选择和冲突 |
| `GET /batches/{id}/transitions` | 按已读取版本返回连续轨迹前缀，避免并发追加导致混合历史 |
| `GET /batches/{id}/plans` | 分页列出全部具名预检，旧计划不会被后续核对覆盖 |

新命令使用独立的严格解析规则，拒绝未知字段、重复键、尾随正文、数字枚举和标量类型替代。人工选择仅包含 `kind`、`externalId`、`localId`、`expectedRevision`。分页从 0 开始，单页默认 20、最多 50，最大页号 10000；不接受租户或来源覆盖参数。

写回执只缓存批次标识、版本、状态或计划标识，不缓存完整人员正文。结果未知时使用原身份、原幂等键和原始请求恢复；来源停用后原成功回执仍可恢复，当前权限被撤销则不能回放。历史正文须重新通过当前管理员权限读取。收到事实不表示已经应用，202 也不表示读取已完成。

## 预检与人工应用

预检固定收到的批次、来源版本和当前目录修订，保存具名操作者、明确选择、实体前后值及每条事实的阻断原因。V110 新增完整计划和实际采用计划的关联表。计划只追加；历史详情读取当时保存的内容，不用最新姓名或来源事实替换旧记录。

已有来源映射保持原本地身份。未绑定人员或任职遇到相同主体／任职组合时，预检要求管理员明确采用已有对象；不会按姓名合并。选择必须携带当前实体修订。已被另一来源标识绑定的对象不能再次采用，跨租户对象不可见。来源事实不得修改人员主体、法人归属或原任职身份。

本地修订偏离上次同步基线时，默认阻断。管理员重新核对并明确选择当前实体及其修订后，才能采用来源值。当前实现支持明确采用来源值或取消批次；没有隐含的“保留本地并自动跳过来源变更”分支。无冲突计划也需要显式应用；预检本身只写计划，不修改组织或推进来源游标。

应用入口重新核对目录、来源和批次版本，拒绝过期或有冲突的计划。新单元先按法人和部门依赖创建基础记录，任职创建后再补齐负责人和主管引用；全部中间状态都在同一事务内。最终组织审计、批次状态、稳定映射历史、实际采用计划和来源游标一同提交或回滚。相同来源值只确认映射，不制造组织修订。

主管及负责人任命检查只在关系新增或变更时执行；停用保留原关系及已保存的计划历史。部门层级、法人和任职引用继续按最终状态检查，当前审批资格仍由原组织读取链路判断。

## 当前验证

HTTP、工作器与管理员入口阶段最终八个明确选择测试类共执行 **145 个唯一用例**，失败、错误和跳过均为零：来源 HTTP 24、管理接口 37、原子应用 35、同步仓储 23、OpenAPI 7、原组织管理和审批 18、OIDC 组织完整旅程 1。此数不累计首轮的 118，也不与前一阶段 152 条相加。

真实回环 HTTP 来源覆盖固定目标和游标、无请求正文、不跟随重定向、严格 UTF-8、响应流大小、完整响应超时和凭据轮换。MockMvc 管理接口与同一持久工作器贯通排队、接收、预检、人工应用、取消和重试；实际捕获的 **112 个接口响应和 37 个成功写请求**通过 OpenAPI 校验，涉及全部 11 个操作和 8 种 HTTP 状态。接口契约总表与 Spring 路由及请求记录字段一致。

并发与失败验证包括：读取中取消无需等待组织事务、第二个工作器不重复发送、外发前取消／目标变化／原租约到期检查、读取中停用或切换目标拒绝旧事实、当前管理员权限先于幂等重放、租户隔离、来源注册失败整体回滚、过期来源版本及活动批次冲突。历史读取保持已读版本前缀，并拒绝缺失或不一致的轨迹。重新构造仓储后原租约保持，但这不等同于真实进程重启验收。
