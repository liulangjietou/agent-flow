# 持久化发票查验

个人票夹可以发起、查询独立的验票尝试。原件上传、票面查验、报销占用是三个独立状态；本次实施不自动提交报销、释放占用或确认付款。

调用链为本人票夹 → `InvoiceVerificationController` → `InvoiceVerificationService` → `InvoiceVerificationJob` / `Invoice` 与 JDBC 仓储；后台 `InvoiceVerificationWorker` 在事务外读取原件，再通过 `InvoiceVerificationPort` 调用租户财务网关。领域对象维护状态与租约边界，应用服务协调原件、发票版本和事务，存储层提供跨进程互斥及审计。

## 本人操作

| 方法及路径 | 行为 |
| --- | --- |
| `GET /api/v1/invoices/{id}/verification-options` | 当前发票版本、可用性、实际目标及其指纹、已确认法人 |
| `POST /api/v1/invoices/{id}/verifications` | 幂等保存一次任务；请求含 `expectedInvoiceVersion`、`legalEntityId`、`targetDigest` |
| `GET /api/v1/invoices/{id}/verifications/{jobId}` | 当前任务状态、输入/结果版本、时间和稳定失败分类 |
| `GET /api/v1/invoices/{id}/verifications` | 本张发票历史；`limit` 1–100，默认 25；`beforeId` 接上一页游标 |

POST 必须带 `Idempotency-Key`，返回 202 和任务 ID。202 只表示任务保存成功，页面必须查询任务结果。相同请求重放原回执，不重新查验，也不因为网关后来停用而重新执行；新尝试使用新的幂等键。请求中的额外字段明确拒绝，不能附带票面结论、外部地址或原件内容。

所有入口都要求同租户、本人归属，管理员没有他人票夹豁免。任务 ID 还必须属于路径中的发票。列表只允许数量和游标参数，不接受任意员工或租户过滤。响应为 `no-store`，不返回凭据、外部错误正文或原件字节。

选择法人不构成票面真实性证明，由真实网关返回成功或拒绝。已确认票面不能通过另一法人重新查验替换；票号、金额、税额、开票日期和原件摘要也不能被后续响应换掉。详细网关协议见 [财务只读网关](finance-gateway.md)。

## 执行和结果

排队时冻结员工、法人、原件 ID/摘要、发票版本及目标指纹；任务不保存原件字节或凭据。目标指纹绑定租户、协议版本和规范化地址，凭据轮换不改变指纹。没有本租户配置时拒绝排队；目标改变后，已排队任务成为 `TARGET_CHANGED`，不能把旧授权原件发到新目标。

每张发票最多一个 `QUEUED` / `RUNNING` 活动任务。领取和完成都在短事务中锁定同一发票行，网络和文件读取在事务外执行。读取原件时重新核对实际字节摘要，损坏文件不能外发。默认单进程一个独立调度线程，每批最多十项；其他进程通过数据库行锁与活动唯一键协调。

任务状态为：

| 状态 | 含义及发票变更 |
| --- | --- |
| `QUEUED` | 已保存，未执行；保留原发票结论 |
| `RUNNING` | 已领取，租约为配置的网关超时加 30 秒结果提交余量 |
| `SUCCEEDED` | 可信结果与发票下一版本及财务审计同事务提交 |
| `REJECTED` | 真实业务拒绝；无效、取消、买方不符更新查验失败；法人不可用只拒绝请求 |
| `UNAVAILABLE` | 没有可信结论；配置、网络、协议、原件、版本或租约问题，不改写发票结论 |

真实无效结论保留已确认票面及当前占用；不能通过查验释放或重新分配已经报销的票。系统不可用不伪造“发票无效”。历史成功事实仍保留不代表后续提交预检可以忽略本次依赖失败，提交必须另行核对当前事实和时效。

结果提交再次检查租约、目标、原件状态和发票版本。排队或外发后，占用或其他财务操作改变发票版本，原任务以 `INVOICE_CHANGED` 结束。晚到结果不能覆盖超时、新任务结果或已改变的发票状态。

## 重启与运维

排队任务重启后可以领取；已领取任务不自动重发。租约到期记录 `TIMEOUT` 终态，用户明确发起新任务才会再次发送原件。终态不可重置，每次任务保留排队、领取和完成三个版本。

财务网关默认停用，启用及租户目标配置见网关文档。`AGENTFLOW_INVOICE_VERIFICATION_WORKER_ENABLED=false` 只暂停后台领取；已保存任务、输入和租约继续保留。恢复领取后首先按原租约处理过期运行，不延长租约。关闭整个财务网关也会关闭自动调度，重新启用后恢复上述处理。

V36 增加任务与版本历史，不重写 V35 原件和已有财务版本。复合外键同时约束租户、发票、本人、原件 ID/摘要及真实存在的输入财务版本；唯一活动键在终态释放。任务随现有数据库备份保存，原件仍使用 V35 的数据库与文件配套备份，不能只备份数据库后声称可恢复查验。

## 本地证据

领域状态、调度隔离、目标绑定共 19 项；H2 任务集成及 V35→V36 迁移 12 项；PostgreSQL 同范围 12 项；财务资源、票夹、网关和 OpenAPI 回归 34 项通过。跨数据库范围有重叠，不累加为唯一测试数。OpenAPI 对应 112 个操作、186 个 schema、38 个请求示例。

新增请求未知字段测试先失败于返回 202。原因是平台既有 JSON 默认忽略额外字段，旧网关严格解码测试只覆盖外部响应。修复在新写入 DTO 边界明确拒绝额外属性，保持其他接口既有兼容策略。

打包服务的 PostgreSQL/实际 HTTP 重启证据见 `evidence/invoice-verification-20260928.json`。全部票据、法人、账户和网关都属于合成本机验收；尚未完成真实企业税务查验或票夹页面验收。
