# F05 事前额度控制

状态：按已授权规则实施中。来源为原费用设计 §6.1，用户已授权后续推荐及“超容差须说明和独立追加审批”。本地继续开发，不再次请求方案批准。

## 业务规则

每个费用类别可明确配置 `STRICT`、`TOLERANCE` 或 `NONE`。`STRICT` 阻断超过已批准额度的累计占用及净核销；`TOLERANCE` 明确配置比例，在批准金额乘以 `1 + 比例`、向下取整到分的阈值以内不增加额度例外审批，超过阈值须逐行说明并经过独立的事前额度例外审批；`NONE` 不以计划金额阻断，但仍完整登记预留、核销、冲回和核减。所有模式都保留申请人、法人、币种、来源行、关闭状态和并发版本约束。

比例沿用现有受支持范围 0–100%，最多六位小数，不提供企业默认比例。历史类别没有此配置时保留原严格控制；历史批准行即使已有非零容差，也保留其原硬上限，不自动变成可超支模式。

配置保存在已有管理员类别修订中，类别保存形成新的生效修订。事前计划预检固定类别修订和每行完整控制配置，提交时在配置锁内复核；批准后控制依据固定到 `ExpenseRequest.ApprovedLine`，不随类别改版、停用或重新启用而改变。新控制依据同时固定类别身份，后续报销不能用其他类别的计划行获得较宽松的模式；旧无类别依据的额度继续原规则，不补造历史事实。

`TOLERANCE` 的阈值按同一批准行的净核销加全部有效预留计算，而非每张报销单各自享有完整容差。预检只计算候选结果，不占用额度。提交在锁定资源和核对预检版本后再次计算，冻结本轮使用金额、阈值、提交后总占用及超出额。并发改变使旧预检失效；不能先展示未超额，再静默提交成例外。

关闭计划仍禁止新增或增额；原占用可核减、释放、核销和按现有规则跨补正轮次迁移。原核销及独立冲回身份保留，不能借 NONE 或容差重新核销旧轮次。财务核减可以降低金额，但不倒改已冻结的审批依据或省略已进入的例外审核。

## 职责与链路

- 类别配置 → `ExpensePolicyConfiguration` → `ExpensePlanCheckEvaluator` → `ExpensePlan.freeze`/`ExpensePlanRound` → `ExpensePlan.approvedRequest`，负责冻结可信控制来源。
- 费用预检/提交 → `ExpenseSubmissionResources` → `ExpenseRequest` → `ReservedAmount`，负责完整金额账本、同一来源行的累计控制及关闭不变量。
- `ExpenseSubmissionService` 在同一提交事务保存控制事实，并将服务端派生的 `priorRequestOverTolerance` 交给原流程；客户端不能声明该值。
- 审批图校验和实际任务授权共同保证独立额度例外节点在财务复核之前完成；查询仅从原轮次冻结依据读取，保持 `expenseDetails` 的当前敏感权限。

现有 `ReservedAmount` 同时服务借款，不能为了 NONE 伪造巨大上限或解除借款限制。为这个真实的新用例增加明确的 `REFERENCE_ONLY` 上限语义，默认及旧 JSON 仍为硬上限；每个业务聚合恢复时校验应有语义。借款始终要求硬上限。参考余额最低为零，并单独提供超出额；页面不能将参考余额当作 NONE 的实际可用额度。

## 审批边界

新增受控布尔路由字段 `priorRequestOverTolerance`，保留原四字段费用定义读取。只有需要该控制的新版定义才增加此字段；其值由提交资源计划产生。增加明确节点职责 `PRIOR_REQUEST_REVIEW`，必须能够按既有字段权限完整读取费用明细，并在所有超容差路径上先于财务复核完成。金额在阈值以内可走原普通路径。没有满足该约束的发布定义时，超容差提交失败，整笔事务回滚，不能只提示风险后继续普通审批。

额度例外为独立节点，不能由已有单价超标节点、纸件签收或财务复核节点兼任。沿用本项目已经确认的发起人回避、重复审批与任务转交规则；不能因为增加节点扩大任何人的明细读取权限。旧发布定义、旧在审轮次不自动插入节点，也不补写新控制事实。

## 兼容与页面

旧 JSON 缺少新属性时，原配置、轮次、批准额度和金额账本可严格恢复；没有新控制的旧记录序列化不新增默认属性，不修改原修订、上下文或摘要。旧硬限额不能被新枚举降级。新依据要求字段成组完整，未知模式、无效比例和不一致的账本语义直接拒绝。

管理页提供类别控制模式及明确比例；计划与批准额度显示冻结来源和阈值。报销选择器显示模式、参考剩余额度和超出额，NONE 明确显示不按额度阻断。预检说明与审批明细显示实际累计依据及需要追加审批的行；身份或轮次切换清理迟到结果，未知写入继续恢复原键。
