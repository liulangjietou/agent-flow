# Agent 执行与人工复核

状态：本地开发与合成环境验收完成，2026-09-28；真实模型服务联调单独验收。

## 调用链与职责

当前可决策审批待办 → Agent 输入目录 → 审批人显式选择来源 → 幂等创建运行及持久任务 → 后台领取、复核原任务和版本 → 事务外模型 HTTP → 保存带来源摘要的建议 → 当前有效审批人采纳修订或拒绝。审批申请状态始终由原审批用例管理，摘要采纳不会批准申请。

审批授权继续使用 `FlowableTaskFacade` 的候选/指派、租户、当前轮次和人员资格边界。输入投影使用提交时表单与字段权限。跨审批、组织、队列和模型的编排在 Agent 应用服务；运行状态仍由已有 `AssistRun` 聚合推进；模型协议属于基础设施适配器。

## 输入及执行规则

只有当前允许批准的审批人可以发起或复核。申请人、历史审批人和管理员身份本身不产生此权限。调用方须给出待办标识、申请版本和显式来源清单；服务端从真实申请构造内容，不接受客户端上传模型提示或正文。

提供标题、非敏感且可见原值的普通字段及明细列；隐藏、脱敏、敏感字段与附件均不提供模型来源。表单之外的任意扩展值不自动发送。最多 64 个来源、合计 64 KiB。输入内容和摘要与运行一起冻结，模型引用必须匹配来源标识及 SHA-256；网页、文件路径、工具调用和模型指令不执行。

模型服务由部署配置指定，默认关闭。启用时要求真实端点和模型；HTTPS 或本机回环 HTTP，禁止重定向和 URI 内嵌凭据。使用 OpenAI 兼容 Chat Completions JSON 输出，服务端继续验证长度、结构、引用和结束原因，兼容协议不表示已完成任何真实厂商联调。

持久任务记录冻结执行目标摘要，重启后配置变化不向新地址发送旧输入。后台领取后释放事务再执行有时限的 HTTP；多工作者靠行锁和租约确保同一运行只有一个执行者。任务已转交、已结束、申请版本改变或人员停用则不再发送。执行前检查使用发起时经过认证的角色快照及当前组织/任务事实；企业身份源撤销需通过既有身份治理使平台角色或人员失效。

运行超时、进程中断导致租约过期时记录稳定失败类型，不自动重复不确定的远端调用。重新生成创建新运行，重新核对任务、版本及所选来源；旧运行、原模型文本和复核轨迹保留。读取新运行按实际输入逐项核对当前访问者的当轮字段权限；旧运行缺少可信输入清单时保持全输入可读限制。

## 协议依据

[OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat/create) 与 [JSON 输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)。JSON 模式仅保证 JSON 形式，业务契约与来源必须由平台校验。

## 验收记录

- 默认 H2：领域 14 项、服务端范围 60 项；覆盖运行查询、真实模型 HTTP、超时、严格结构、伪造证据、当前权限、并发、过期结果、来源投影和契约。
- PostgreSQL 17：执行集成 12 项、V31→V32 升级 1 项。保留历史运行及轨迹、不补造外发授权；重复升级为空操作，外键拒绝跨租户任务。
- 前端 49 项，包括选择目录、切换身份立即清空、晚到响应、人工草稿和原请求恢复；生产构建通过。
- OpenAPI：98 个操作、147 个 schema、34 个请求示例。Spring 真实路由与请求/响应 DTO 对照通过。
- 独立 PostgreSQL、打包 jar 和回环合成模型：31 次实际 HTTP 请求通过。浏览器使用独立申请，只选 `form:reason`，实际接收来源同样只有这一项；手动编辑并采纳，原模型文本仍保留，申请版本仍为 2，批准按钮仍需单独执行。
- 部署入口 4 项密钥读取测试及生产模型 Compose 叠加配置校验通过；没有传输真实业务材料或模型凭据。

测试范围有交集，以上数量不能相加为唯一业务场景数。红灯回归先复现最长合法表格路径误拒绝、租约结束后接受晚到成功、身份切换未立即清空、错误 URI 空指针、调度器替代默认执行器，数字被宽松转为文本的模型输出，以及旧展示运行阻挡新授权运行，再修正根因。

## 部署与运行

默认 `agentflow.assist.enabled=false`。普通 Java 部署通过 `AGENTFLOW_ASSIST_ENABLED`、`AGENTFLOW_ASSIST_ENDPOINT`、`AGENTFLOW_ASSIST_PROVIDER`、`AGENTFLOW_ASSIST_MODEL`、`AGENTFLOW_ASSIST_API_KEY` 和 `AGENTFLOW_ASSIST_TIMEOUT_SECONDS` 配置；超时 1–120 秒，默认 45 秒。`AGENTFLOW_ASSIST_WORKER_ENABLED=false` 可停止新任务轮询，持久任务与历史仍保留。启用后每秒扫描最多 10 项，模型使用专用单线程池；普通调度和 Flowable 继续使用原自动配置。

生产 Compose 叠加 `compose.assist.yml`，模型 API key 放到受控文件，`AGENTFLOW_ASSIST_API_KEY_FILE` 只保存路径；入口拒绝空文件、不可读文件以及正文/文件双配置，不打印凭据。先用维护身份执行 V32 迁移，再滚动启动服务；历史 Agent 记录不会自动调用模型。端点必须是可信部署配置，前端只能确认指纹，不能改地址。示例 `model.example` 不是可调用服务。

输入目录显示已验证的目标主机、模型及提供者，并返回目标指纹。排队时必须提交同一个指纹；目标变化要求重新选择内容，不能借用旧授权。新模型密钥轮换不改变目标指纹。跨实例应统一模型目标和时间同步；不确定执行不自动重发，只记录租约超时。

合成夹具先运行 `python3 scripts/assist_model_fixture.py --port 18219`，演示服务模型端点设置为 `http://127.0.0.1:18219/v1/chat/completions`、模型名设置为 `loopback-synthetic-model`、提供者为 `loopback-fixture`。夹具不读取真实凭据、不记录正文，只能用于合成材料。

协议复验脚本：`python3 scripts/check-assist-execution.py http://127.0.0.1:18210 --exercise`，仅允许显式回环演示地址，要求已启用配套合成模型（期望响应模型标识 `loopback-synthetic-model-v1`），保留合成申请。真实凭据、真实模型质量和企业环境验收仍未完成。
