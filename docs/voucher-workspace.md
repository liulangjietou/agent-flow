# 凭证状态与财务操作

更新：2026-09-28。本地已完成借款与报销的凭证状态、重新准备、原操作查询和权威查无后的原编号重发。实际付款、资源核销和归档继续实施；凭证已过账不表示资金已到账。

## 调用链与权限

借款或报销明细中的 `VoucherStatus` 读取 `GET /api/v1/applications/{id}/vouchers?roundNo=...`。`VoucherAccess` 复用申请可见性和相应业务的本轮完整敏感明细投影。本人可读状态；其他人员仍需本轮字段权限，管理员没有旁路。服务端不返回账户引用、账户摘要、财务目标、会计科目、完整命令或远端原始响应。

财务操作另要求 `FINANCE` 角色且不能是申请人本人。流程必须明确给实际财务参与者本轮明细权限；仅拥有财务角色不会自动读取全企业单据。操作入口在幂等回放前也检查实时权限，停用人员不能通过旧请求键获得旧回执。

`VoucherActions` 负责跨申请、财务聚合和凭证的编排：取得申请及业务锁、再次检查权限、核对审批与财务版本、调度原服务、记录操作者／财务角色／原因／前后状态。实际状态转换仍由准备和凭证领域对象承担，网络调用继续由事务外后台任务完成。

## 操作契约

`POST /api/v1/applications/{id}/vouchers/actions` 使用 `Idempotency-Key`，只接收动作、轮次、双版本、原操作编号／版本和说明。金额、账户、科目、ERP 成功声明等未知字段返回 400。202 只表示调度与审计已经持久化。

| 动作 | 条件与结果 |
| --- | --- |
| `PREPARE` | 当前轮次仍已批准，双版本一致；后台重查期间及映射。任意原凭证已登记后不能通过新准备产生另一个编号。 |
| `QUERY` | 有原凭证且未被领取、未等待首次发送；核对凭证版本后安排原编号查询。允许对历史或已撤销轮次核对既有外部事实。 |
| `RESEND_ORIGINAL` | 当前批准及财务事实未变，原操作为权威 `NOT_FOUND`、最高外部版本为零、无冲突且未过原发送期限。仍发送不可变原命令。 |

查询使用同一数据库快照，所有响应 `Cache-Control: no-store`。可空字段显式保留 `null`，与 OpenAPI 3.1 和页面回执校验一致。页面核对业务、类型、轮次、双版本和准备／凭证关联，不能把迟到或错误绑定的响应显示为本轮事实。

## 页面与恢复

准备状态与 ERP 过账分栏展示；已有凭证号只来自已接受的外部事实。冲突时保留旧凭证信息并明确提示不能作为新付款依据；查询次数不等于发送新凭证次数。

财务先选动作、填写原因，再确认。选择、取消和刷新不会写入。网络未知结果留在现有“未确认操作”中，恢复只使用原键和原正文；恢复完成后必须重新读取当前状态才能再次操作。确认重发时再检查原期限；账号、轮次或版本切换立即清空旧结果，超时后的迟到读取不能恢复旧数据。
