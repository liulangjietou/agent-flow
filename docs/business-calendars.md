# 工作日历与到期时间试算

管理员可从侧栏“工作日历”建立和维护真实日历，配置时区、每周工作时段和日期例外，查看不可变修订并试算到期时间。本阶段不改变实际审批任务的期限，不发送超时提醒，也不输出 SLA 违约指标；后续任务期限将引用明确日历修订并保存计算结果。

## 使用方法

1. 以当前租户 ADMIN 登录，填写日历标识、名称和 IANA 时区。标识以字母开头，允许字母、数字、下划线与连字符，租户内唯一，保存后固定。
2. 逐日添加工作时段，空白日为休息。可主动点击“填入工作日示例”，填入周一至周五 09:00—12:00、13:00—18:00。该按钮仅提供编辑示例，不代表企业制度或法定安排。
3. 为节假日和调休添加日期例外；例外覆盖整天规则。没有时段表示休息，有时段表示该日实际工作窗口。系统不自动导入或推断法定节假日。
4. 保存得到 v1；每次修改保存产生新修订，保留原规则、原作者与时间。历史版本只读，可“使用此版创建新修订”，不会覆盖旧版本。
5. 在试算中填写日历当地开始时间和工作分钟。结果显示所用版本、日历时区的时间及 UTC 时间。未保存修改时暂停试算，避免把草稿误认为已生效规则。

同日最多 8 个不重叠时段，格式 HH:mm，结束允许 24:00；跨午夜按相邻两天拆开配置。每份日历最多 500 个日期例外，日期不能重复，至少有一个工作时段。时长为 1—527040 个工作分钟，开始年份 0001—9998，最多向后查找 3660 天，结果不得越过四位 UTC 年份边界。找不到足够工作时长时明确报错。

工作时间沿真实时间轴累计：午休、周末和休息日不计入。夏令时跳过的钟点不产生虚构工作时间；回拨时落在规则内的重复窗口分别计时，两个窗口之间的非工作时间不计入。开始钟点不存在时必须重新选择；出现两次时必须明确选择第一次或第二次。计算依据为服务端 Java 时区库；浏览器不支持某个时区别名时退回明确的 UTC 展示。

## 并发、恢复和权限

所有管理、历史和试算接口仅允许当前租户 ADMIN，租户及修改人来自认证上下文。跨租户资源与不存在资源统一返回 404。权限在幂等回放之前核对，读取响应禁止缓存。

创建、保存修订要求 `Idempotency-Key`，与业务写入共同提交。修改请求必须带已核对的 `expectedRevision`；服务端乐观锁冲突返回 409，不自动覆盖他人的修改。当前指针和新历史版本共同提交，历史写入失败会回滚指针。

草稿按租户和账号保留在当前浏览器页面内存中，切换页面后可恢复；刷新或关闭页面不会永久保留草稿，离开时会触发浏览器未保存提醒。保存结果未知时锁定新写入，使用原正文、版本和键恢复；确认结果仅更新相同原请求的草稿，不覆盖后续编辑。保存成功后仍需在任务配置阶段显式选用该日历，当前没有自动生效到审批任务的行为。

## DDD 调用链与存储

`BusinessCalendars.vue → BusinessCalendarController → BusinessCalendarService → BusinessCalendar / BusinessDeadline / BusinessCalendarRepository`。

聚合 `BusinessCalendar` 负责固定身份、修订前置条件及状态变化；值对象 `CalendarRules` 负责不可变规则、日期替代和时区窗口转换；纯领域服务 `BusinessDeadline` 负责工作时间累加。应用服务编排事务和仓储；JDBC 适配器实现租户查询、当前指针 CAS 与历史追加。领域层不依赖 Flowable、Spring MVC 或 JSON；接口层负责 ADMIN 与分页入口约束，复用统一 `JsonUtil` 和写请求恢复协议。

V14 新增 `business_calendar` 和 `business_calendar_version`。后者以日历与修订为主键，并使用租户与日历复合外键；不改动旧申请、轮次、评论、审批审计或 Flowable 任务，也不补造默认日历。版本历史本身保留修改人和时间，本阶段没有另写审批 `audit_event`。

| 方法和路径 | 用途 |
|---|---|
| GET /business-calendars | 目录，按业务键升序，afterKey 翻页 |
| POST /business-calendars | 新建首版，需要幂等键 |
| GET /business-calendars/{id} | 当前完整规则 |
| PUT /business-calendars/{id} | 保存新修订，需要幂等键和 expectedRevision |
| GET /business-calendars/{id}/versions | 修订倒序，beforeRevision 翻页 |
| GET /business-calendars/{id}/versions/{revision} | 固定历史规则 |
| POST /business-calendars/{id}/calculate | 只读试算，需要 revision，不使用幂等键 |

路径统一加 `/api/v1` 前缀。两个分页接口默认 30、最多 100，末页续页字段明确为 null。完整请求及响应见随包 OpenAPI。
