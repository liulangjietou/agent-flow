# 本人关闭已批准事前额度

更新：2026-10-02。F06 已完成本地开发及验收，实现提交 `414b5d7`。关闭入口位于「财务申请 → 事前批准额度」，由原申请人填写原因并确认。管理员或财务角色不会扩大对他人额度的关闭权限。

关闭停止新增或增加占用，保留已批准申请、历史计划、全部原预留和原核销。已有预留仍可减少、释放、迁移至补正轮次或结算，迁移同样不能增额。关闭后的未用金额显示为「未用余额（已停用）」，不被记为消耗，也不自动释放原报销的资金占用。此入口不提供重新开放。

## 调用与职责

`ExpenseWorkspace → ExpenseRequestClose → POST /api/v1/expense-requests/{id}/close → ExpenseRequestClosureService → ExpenseRequestRepository / ExpenseRequestClosureAudit`。

- 控制器校验整数版本、明确文本原因和未知字段；不接受请求指定租户、所有者或关闭状态。数字、布尔值不会被隐式转换成原因或版本。
- 应用服务取认证身份，确认本人归属后锁定报销占用共用的 `finance_resource` 行，再重读最新额度。领域对象执行版本与关闭规则，仓储保存相邻版本，审计记录操作人、原版本和原因。
- 资源更新、规范化占用、版本记录、审计及成功幂等回执在同一事务提交。审计失败时全部回滚；等待并发占用结束后发现旧版本时返回冲突，不覆盖新余额。
- 关闭不调用外部财务端口，不改变原申请审批状态。审计使用 `ExpenseRequest / EXPENSE_REQUEST_CLOSED`，管理员检索只返回事件元数据，不复制原因或余额。

## API 与页面恢复

请求必须携带 `Idempotency-Key`。请求正文只有两个字段：

```json
{"expectedVersion":2,"comment":"本次采购完成，停止新增费用"}
```

首次成功及原请求重放都返回五字段回执：`requestId`、`applicationId`、`version`、`closed`、`eventId`。成功版本为原版本加一，原键重放返回首次回执，即使后来原占用已结算而资源版本继续增加。平台的原请求有效期、身份和角色绑定仍适用。

非本人或其他租户返回 404；旧版本返回 409；用新请求再次关闭已关闭的当前版本返回 422。页面要求先展开确认区、填写原因，再明确确认；取消和空原因均不发送关闭请求。身份、额度版本变化或组件卸载会清除原因并丢弃迟到响应。

页面在清除原请求前检查目标标识、相邻版本、关闭事实及回执结构。连接中断、12 秒等待超时或损坏的成功响应均保留原键，通过「恢复上次操作」确认结果；恢复后重新读取额度。明确冲突后须刷新并重新确认，不能带旧版本重发。
