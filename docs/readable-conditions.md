# 条件中文说明与字段插入

流程管理的快速步骤、条件分支列表、高级画布连线和条件编辑面板共用中文条件说明。字段采用本版本表单名称，枚举采用选项名称，布尔值显示“是/否”。数字阈值保持原始十进制字符串，不经过 JavaScript 浮点数转换。

例如：

```text
amount > 5000 OR urgent == true AND reason EXISTS
金额 大于 5000 或 （紧急 等于 是 且 事由 已填写）
```

括号、且/或优先级和取反关系保留；`!(amount > 5000)` 显示为“不满足：（金额 大于 5000）”，不会错误改写成“小于等于”，因为取反还可能包含未填写值。旧语法中 `reason == a && b` 的 `a && b` 仍解释为完整文本。

画布截断长说明，悬停可看完整说明与原始表达式；快速分支卡片最多显示三行，编辑面板显示全文。自动布局按实际显示的标签长度安排间距，不改变条件文本或分支执行顺序。修改字段或选项名称会更新说明，但不会改写表达式中的标识或取值。

## 表达式编辑

切换到“表达式”，将光标放在目标位置或选中要替换的文字，再点击字段按钮；按钮同时显示名称和标识。插入保留前后原文、空白和精度，按需要补充分隔空格，并恢复光标位置。支持键盘聚焦字段按钮后激活。插入会进入原设计器撤销记录；只读流程不能插入。

光标或选区端点位于引号内部时拒绝插入，避免把字段标识误当成文本值；旧语法不将 `O'Reilly` 等无引号正文中的撇号当作引用起点。新语法插入后不能超过 4000 字符。此操作只插入字段标识，不代替运算符和值的配置；随后通过“校验流程”检查完整条件。

## 职责与兼容

- `conditionSyntax.ts` 只为前端提供 v2 只读语法树；平面/嵌套条件回显与中文说明复用它，不求值、不授权、不发布。
- `conditionBuilder.ts` 保留旧版平面转换和共用字段规则；`conditionGroups.ts` 提供 v2 的[嵌套条件编辑](visual-condition-groups.md)，不参与业务求值。
- `conditionPresentation.ts` 根据本版本表单生成说明和插入结果；未知字段、非法类型、无效语法、超限或缺少表单时保留原文，不显示猜测的业务含义。
- 保存与发布继续发送原表达式，服务器领域解析器仍是校验、模拟和运行的依据。没有增加 API、数据库迁移或新的条件语言版本。
- 前端及 Java 领域测试共同读取 `agentflow-domain/src/test/resources/condition-presentation-cases.json`，核对固定语义树，覆盖优先级、转义、取反、成员条件和拒绝项。

## 浏览器复核步骤

1. 打开已有条件的草稿，分别在快速步骤和高级画布查看中文说明；悬停长标签，核对完整说明及原文。
2. 修改表单字段/枚举选项名称，核对说明更新，表达式标识和选项值不变；撤销后名称与说明一同恢复。
3. 切到表达式，选中一个字段后点击另一个字段按钮，核对替换范围、光标及撤销/重做；再用键盘激活字段按钮。
4. 在引号内点击插入，核对错误提示与原文保留；使用旧条件 `reason == O'Reilly AND ` 时，在末尾插入应正常。
5. 输入不完整条件，核对原文显示及服务端报错；打开已发布版本，字段插入应不可用。
6. 在窄屏检查字段按钮换行、长标签截断与全文核对入口。
