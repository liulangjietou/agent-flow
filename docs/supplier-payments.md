# 供应商付款与原应付结算

## 当前实施范围

采购审批和本地应付占用已完成。供应商付款继续按独立资金链路实施，现已实现批准来源、独立财务授权、原 ERP 应付预留命令及恢复状态机、固定目的地的 HTTP 适配器，以及 V68 持久授权、队列、修订和后台恢复。尚未接入公开财务办理入口、银行付款和 ERP 结算，不能将内部领域与队列验证视为整条付款链路验收。

实际调用链为：已批准采购申请 → 独立财务授权 → 原 ERP 应付预留 → 出纳付款 → 独立 ERP 应付结算。原采购的发票、应付挂账及预算确认保持，不重新创建员工报销或消费采购预算。

## 已落实的规则

- `ApprovedProcurementPayment` 绑定真实批准版本和同一轮仍保留的本地应付占用。未批准、外租户、其他申请或已释放占用不能形成来源。
- 本次金额取自批准内容。最新应付版本和已付余额可以变化，但剩余未付额须足够；供应商、完整账户快照、合同、订单、验收匹配、原挂账凭证、原预算确认、到期日和逐行发票事实必须保持。
- 财务授权最多 24 小时。申请人、授权人和出纳必须是三个不同主体；岗位、当前任职和字段权限由后续应用入口核验，领域记录不自行授予角色。
- 新建外部预留的窗口是授权到期、ERP 快照到期、观察时间加五分钟三者的最早值，排他到期。授权有效不能延长旧余额的使用时间。
- 原授权号为预留幂等号。SHA-256 摘要以四字节大端 UTF-8 字节长度逐项编码，固定完整原批准快照、当前复核应付、目标、金额和授权。金额、数量采用精确十进制；票号使用规范字符串，保留前导零。
- ERP 必须在一次原子操作内核对原应付版本与可用额，建立持续保留的原应付预留，重复编号且摘要相同只返回原结果。重复编号且摘要不同必须拒绝。
- `HELD` 只表示 ERP 已预留。发送窗口或本地授权到期不能自动释放它；结束必须经过后续有明确原交易依据的结算或安全释放。

## 恢复与协议

首次发送由 `QUEUED` 领取为 `RESERVING`，持久标记可能外发。超时、租约到期、无效响应或笼统失败进入 `UNKNOWN`，后继只能领取 `QUERYING`。查询不受新发送窗口限制，并且不携带可新建预留的完整明细。

`NOT_FOUND` 只能来自权威查询，并停在待明确处理状态。显式重试沿用同一命令，仍受原短期发送窗口限制。已受理或已预留后出现查无、版本倒退、改变原预留凭据或其他矛盾时进入 `RECONCILING`，保留原事实和矛盾事实；后续普通查询不能自动解除争议。

新端口：

| 操作 | HTTP 路径 | 身份与用途 |
| --- | --- | --- |
| 原应付预留 | `/supplier-payable-hold-command` | 固定原授权号作为请求编号和 `Idempotency-Key`，数据为 `command` 与 `commandDigest` |
| 原预留查询 | `/supplier-payable-hold-query` | 新传输请求号，无幂等写入头；数据只有原 `authorizationId` 与 `commandDigest` |

两者沿用财务网关固定租户目的地、严格信封与精确金额、有界响应、事务外调用、禁止重定向和自动传输重试。已保存目标变化时拒绝调用，不改查其他 ERP。`REJECTED` 必须是带原命令身份的预留观察结果；普通信封拒绝不能证明这个幂等命令没有产生外部预留。

预留回执固定正额、账户摘要、原预留号、建立时账本版本和建立时间；观察时间可通过再次查询刷新。首次预留时间必须位于原发送窗口且不得早于本地队列保存时间。领域日志不展开供应商、票号、金额、账户或人员。

## 本地验证

2026-09-29：领域 30 项、网关与已有采购/支付协议 32 项通过，共 62 项。覆盖真实批准绑定、余额边界、三方分离、有效期、命令摘要、未知恢复、明确重试、版本冲突以及真实回环 HTTP 超时和查询。新增恢复边界先得到 2 项失败，再修复并通过；测试记录见 [证据](evidence/supplier-payable-hold-contract-20260929.json)。

回环测试采用应用相同的 `NON_NULL` JSON 形状，验证完整命令及队列/领取状态可以往返恢复。无数据库迁移，现有验收服务继续运行 V67。企业 ERP 的真实原子预留和持续保留语义需以实际接口验收，当前测试未声明完成该项。

## V68 持久授权与预留恢复

授权与初始队列同事务保存，真实审批必须仍为 `APPROVED`，申请版本、采购版本、冻结内容、申请人及活动本地占用均重新核验。所有编排沿用审批申请、采购聚合的锁顺序。数据库复合外键绑定原占用归属和实际采购修订，唯一键阻止对同一已批准申请建立两个预留身份。

`supplier_payment_authorization` 保留原授权，`supplier_payable_hold_operation` 保留固定命令及当前状态，`supplier_payable_hold_revision` 追加每次领取、故障、查询和回执。更新同时比较版本、原命令原文和摘要，命令不能在重试时改写。修订追加失败会回滚当前状态更新。

`ApprovedSupplierPaymentSources` 编排跨聚合的实际批准来源，`SupplierPayableHoldService` 只做短事务；`SupplierPayableHoldWorker` 在领取提交后调用网关。新发送重新检查财务在原法人的任职，批准或人员失效则保存 `VOIDED`；已进入可能发送状态后继续原查询，不因人员停用、来源变化或授权到期而删除未查清的预留。

后台在 `agentflow.finance-gateway.enabled=true` 时启用独立调度；`agentflow.supplier-payments.hold-worker-enabled=false` 可停止领取而保留任务。默认租约 90 秒，范围 15–300 秒；默认轮询间隔 1000 毫秒。后台只消费已保存授权，不从批准状态自动产生财务授权。

2026-09-29：H2 最终领域 19、数据库与采购审批 38 项通过；PostgreSQL 相关领域 18、真实 PostgreSQL 48 项及 H2 OpenAPI 契约 5 项通过，范围有重叠，见[持久化证据](evidence/supplier-payable-hold-persistence-20260929.json)。包括真实并发授权/领取、迟到结果隔离、事务回滚、原文恢复、旧库 V67→V68 保留原表，以及事务外网关故障后只查询原命令。

V68 尚未升级现有长期验收库或替换运行服务。当前同一批准申请的原授权保持独占，下一步补安全结束和重新授权，再开放财务与出纳入口；未知或已预留授权不能直接解除独占。
