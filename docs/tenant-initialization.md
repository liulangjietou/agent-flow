# 租户初始化向导

状态：后台编排阶段完成；页面、真实运行与重启验收仍在开发。本工作包继续保留在剩余清单中。

## 调用链与职责

调用方为管理员首次使用页面。服务端从可信认证上下文取得租户、稳定主体和 ADMIN 权限，页面不能创建登录凭据、指定另一租户或授予系统角色。系统角色由平台既有用例和身份映射提供，向导展示内置角色与当前已验证身份，不重复创建权限定义。

初始化应用服务组合组织、日历与本人通知偏好用例；它拥有租户初始化事实，不接管组织关系、日历规则或消息发送。下游使用现有同租户仓储、组织目录锁、日历版本和通知绑定。组织、日历、本人偏好、初始化记录、审计及成功幂等响应共用事务。没有模型或外部网络调用。

受影响场景为首次新租户、已有目录/日历的租户、重复提交、并发初始化、状态过期、后台失败及响应丢失。旧租户不自动初始化，不覆盖现有法人、人员、日历或其他人的通知偏好。

## 实施规则

- 名称由管理员填写，租户标识和管理员主体来自登录。创建一组明确命名的法人、部门、岗位和管理员任职，或采用本人已有的有效任职；已有人物记录不隐式改名、启用或提升审批资格。新人物的审批资格只承接已验证的 APPROVER 权限。
- 页面核对当前组织修订，提交时锁定目录再核验；重复初始化拒绝创建第二套对象。原幂等请求只回放原结果，不重新修改组织、日历或偏好。
- 工作日历支持创建和采用已有精确修订。创建时显式确认时区、工作时段；不生成企业节假日或费用制度。初始化保留原日历版本，后续管理产生新修订。
- 站内消息沿用平台基础渠道。本人可明确选择已受控绑定的邮件或企业 IM，提交同时核验个人偏好版本和绑定摘要；只修改本人偏好，不发送测试消息或回补旧通知。配置存在不代表真实递送通过。
- 初始化记录保留操作者、时间、原组织任职、日历版本和通知选择，并追加统一操作审计。完成后继续已有模板、设计和第一条真实流程引导。

企业身份的可信映射仍由部署管理员/IdP 配置。向导完成表示当前认证租户已完成上述本地初始化，不表示创建了企业 IdP 账号、真实外部服务已联通或整个企业上线验收完成。

## 验收要求

覆盖新建与采用已有配置、同租户权限、角色不可伪造、并发与重复请求、来源修订、完整事务回滚、原键恢复、追加审计、旧库升级和重启保持；页面覆盖草稿、账号切换、错误恢复、明确确认和窄屏。随后通过真实界面从初始化继续发布并运行首条请假流程。
