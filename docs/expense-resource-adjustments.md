# 已核销报销的独立资源调整

当前完成全额取消的领域模型、资源冲回计划、旧资源快照兼容，以及 V65 的持久准备、明确授权、预算 outbox、独立调整、后台调度和资源反向明细原子落库。公开接口和页面仍在接续；现有验收服务保持 V64，本阶段不代表完整办理已经可用。

## 调用链和职责

调用方是拥有原轮次完整财务字段及当前法人财务任职的独立财务人员。应用服务锁定原申请和报销，装配已持久化的结算、预算消费、凭证冲销及银行退回事实，准备新的开放会计期间，然后明确授权一条独立预算冲正命令。预算网关成功后，应用服务在同一短事务保存全部本地资源反向计划和调整完成状态。

`ExpenseResourceAdjustmentBasis` 核对各项财务依据是否属于同一笔完整取消；`ExpenseResourceAdjustment` 分别保存预算冲正和资源完成事实。发票、事前申请与借款各自改变自身状态；`ExpenseResourceReversal` 只在不可变输入副本上计算跨资源计划。数据库锁、当前身份、真实外部调用与原子保存归应用层。

受影响场景包括全部银行付款退回后的原报销取消、全额借款冲销形成的零应付报销取消、资源冲回失败的人工重试，以及旧发票和余额快照恢复。暂不把部分退回解释成按比例取消费用；部分报销调整继续作为后续范围。

## 财务依据

- 必须已经消费原报销资源，原 `CONSUME` 预算命令确实 `APPLIED`，原结算保持待处理。原预算分摊、业务版本、轮次、员工、法人和含税金额同时固定。
- 原 `EXPENSE_ACCRUAL` 凭证必须已登记另一张完整反向凭证。它负责撤销费用、税额和借款冲销；不能只凭原凭证显示“已冲销”就释放资源。
- 正额付款必须全部实际退回，采用已有银行入款及原员工应付贷方的逐笔登记。原支付命令、成功回单、金额及原员工应付科目不得替换。申请人和原付款出纳不能授权调整。
- 正额付款还须保留已过账的原付款凭证，其应付借方与原挂账及退回贷方属于同一科目。付款凭证未知、争议或正在冲销时暂不接受。
- 如果付款凭证也已明确冲销，冲销中的全部应付贷方必须与银行退回登记是同一张凭证、同一分录、金额、科目、记账日和过账时刻；另一批退回贷方不能再重复抵销原付款。系统不额外自动创建付款冲销。
- 零应付报销不创建虚构的付款或银行退回。全额核减至零的旧单没有本次正额取消的依据。
- 新预算冲正固定原成功版本、原目的地及独立授权。预算成功只进入资源待处理状态，不能直接宣称本地调整完成。

## 资源事实

金额账本在原 `consumptions` 外追加 `reversals`，每一项引用调整编号、原报销轮次、原金额及完成时刻。净核销等于原核销累计减独立冲回；原核销不删除，已冲回的旧归属仍不得再次预留。同一笔原核销只能完整冲回一次，其他报销的预留原样保留。

事前申请原批准额度和关闭状态不变。借款冲回增加原未还金额，原放款、实际还款、真实退回以及各项独立冻结不变；冻结借款即使增加未还额也不因此恢复可用。

发票记录原核销归属和调整编号后退出有效占用，回到待查验。票面身份、金额与原件摘要不变；必须取得不早于调整时刻的新查验结果才能再次占用，旧查验不能直接恢复可报销。原件和原归档继续保留。

已核减至零并释放的引用不参与反向计划。多个报销行使用同一事前额度时，计划保留每次版本转换。任何缺失、跨法人/员工、错误金额或已冲回资源会使整个计划失败，不改变输入资源。

## 验证边界

领域测试验证财务证据绑定、零应付、重复冲回、资源原子计划、冻结保留、重新查验、来源篡改及预算/本地资源分步完成。实际仓储兼容测试移除旧 JSON 中不存在的冲回字段后重新读取，确认原核销、票号占用和关闭状态保持。

V65 新增持久准备及修订、独立调整及修订、预算冲正 outbox 及修订、安全结束记录、规范化资源冲回明细。原结算、预算消费、银行退回和冲销记录使用同租户外键固定。准备就绪时没有写命令；明确授权后才生成固定期限命令，调整与命令共同提交。资源完成必须有精确的原报销资源集合，只有预算成功不能直接标记完成。

安全结束只接受从未外发或明确拒绝且没有冲突的预算命令。原授权、停止命令及结束前后修订保留；未知和查无不能释放同报销占用。停止与释放任一失败则一起回滚。

已用实际报销、预算消费、付款、退回、凭证冲销登记测试仓储事务，并补充登记永久有效性的失败回归：登记核对可能比原凭证本地观察更新；永久引用以登记时实际本地修订为下界，继续核对同一原过账，不能误用新登记时的证据新鲜度规则。

资源写入现已核对本次调整的真实预算成功、精确原核销及前后完整聚合状态。每次修订只能追加一笔原核销冲回；其他字段和旧冲回历史不能同时篡改。独立明细固定前后相邻修订，原金额核销行保留，已消费发票只有持久冲回证明才能删除当前占用键。

资源执行与调整完成使用一个短事务，任一资源失败全部回滚。较新的同一原凭证确认可以支持本地恢复，但不能替换原金额、原过账、退回明细或预算成功。资源执行阶段的 178 项服务端范围和 43 项领域范围通过；其中 7 项聚焦完整取消的事务、原件保留、重复执行及失败恢复。

后台编排阶段在 PostgreSQL 上通过 49 项领域与 171 项服务端范围，包含 10 项新增完整流程测试；范围与早期阶段有重叠。读取会计期间不发送写命令；本人最新准备只能明确授权一次，授权、预算命令和审计共同提交。首次发送前重新核对财务依据、原授权人任职及原网关目的地，变化即停止新写入；已经发送而未知的命令仍查询原结果，不受后来授权过期或任职失效影响。

权威查无结果也不自动重发，原授权人只能在原有效期内明确重发同一个命令。资源失败保留预算成功，人工恢复不重复冲正预算。已完成调整再次查询预算会进入复核，确认同一成功事实后可明确恢复完成标记，原资源明细不再执行。安全结束与后台首次领取共用原报销锁，只有其中一方能够生效。

调度器使用独立线程；`agentflow.expenses.resource-adjustment-worker-enabled` 可关闭调度而保留持久状态，轮询间隔由 `agentflow.expenses.resource-adjustment-poll-delay-ms` 配置，默认 1000 毫秒。网关关闭不阻止已经确认预算成功的本地资源完成。V65 目前在 H2 和 PostgreSQL 测试库迁移，公开办理和原有验收库升级仍待接续。
