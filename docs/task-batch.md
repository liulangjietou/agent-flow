# 批量领取与释放

更新：2026-10-01。已完成本地代码、范围测试、真实 PostgreSQL HTTP 和浏览器验收，见[验收证据](evidence/task-batch-20261001.json)。本功能使用既有单笔任务命令，没有新增批量接口或数据库迁移。

## 调用链与职责

待办队列打开 `TaskBatchPanel`，选择当前已加载的任务，最多 20 项。`TaskBatch` 逐笔调用 `GET /api/v1/tasks/{taskId}`，核对申请绑定、允许动作和当前版本。用户填写说明并确认后，页面顺序调用既有 `POST /api/v1/tasks/{taskId}/actions`。

页面负责固定选择清单、确认和逐笔结果；`PendingWrites` 保存原命令和幂等键。服务端 `TaskController`、`FlowableTaskFacade` 继续负责同租户权限、当前任务资格、申请锁、版本、事务及审计。选择清单不是权限依据。领取和释放只变更任务归属，不形成审批结论，不提供批量批准、转交或委派。

## 办理边界

- 列表只提供候选摘要；核对阶段没有写请求。刷新、分页和切换展示方式不会给原清单追加任务。
- 确认绑定逐笔读取的版本，所有任务使用本次填写的 1–500 字说明。一个任务发生版本冲突或明确拒绝，不回滚其他已成功任务，也不刷新版本自动重试。
- 响应未知、认证失效、CSRF 失败或无效成功回执时，立即停发后续任务。恢复只发送已保存的原任务、原正文和原幂等键；剩余任务需重新选择和确认。
- 关闭面板或切换账号取消旧读取；离开期间已有写请求可以完成，但不会继续发送后续任务，旧结果不会进入新账号。
- 批次记录留在本次页面面板中；持久证据是每笔服务器审计。全局恢复槽沿用既有页面内存机制，刷新或关闭整页前应先核实业务现态。

## 无效成功回执修复

原请求层只判断写响应是否为 JSON 对象，领取／释放收到 HTTP 200 `{}` 时也会清除恢复槽。旧测试覆盖网络响应丢失，未覆盖内容损坏。新增最小测试先复现此问题，再在 API 回执边界校验任务、动作、`IN_APPROVAL` 状态及唯一的版本增量。空壳、串任务或错误版本不能算成功，原幂等键保留；单笔与批量入口共用该校验。

## 本地验收

- 前端 68 项范围测试通过，覆盖批次状态、真实组件模板、单笔任务、待办查询、原请求恢复和实例运维回归；类型检查、生产构建和静态 OpenAPI 检查通过。
- 实际页面完成三笔领取、三笔释放，以及一笔真实版本冲突后另外两笔成功。故意把第二笔释放的成功响应替换为空对象后，第一笔成功、第二笔待恢复、第三笔未发送；恢复原请求后再单独确认第三笔。
- 共核对 25 份直接 HTTP 响应和 42 份浏览器代理收到的服务器响应，均符合契约；其中一份向浏览器故意注入的空回执按预期不符合契约并触发停发，不能算作合法浏览器回执。
- 三笔申请均保持第 1 轮 `IN_APPROVAL`、版本 6，最终未领取。每笔仅有两次领取、两次释放的审计，共 12 条；原键恢复不增加审计或版本。
- 实际 500 CSS 像素宽度下，页面滚动宽度为 500，无横向溢出。源库 221 张表、1,059 行及三份原件保持；目标库全部旧行仍在，最终 1,231 行，无原件变化。

## 已有流程失败恢复核对

“其余明确失败恢复”现按实际可发布节点逐项核对完成，避免把已验收能力继续作为未定义待办。

| 故障场景 | 已有恢复方式与边界 | 依据 |
| --- | --- | --- |
| 定时等待推进失败 | 原事务回滚，保存原失败等待；管理员提供原因与版本重试原任务，仍受当前轮次、暂停和原到期时间约束 | [定时等待](timer-waits.md)，`TimerWaitService.retry`、`TimerWaitIntegrationTest` |
| 外部事件处理失败 | 保留原签名收件、来源、契约与目标；管理员具名恢复原件，消费时再次复核信任配置与原等待 | [事件收件](event-inbox.md)，`EventInboxService.retry`、`EventInboxIntegrationTest` |
| 提交、审批、子流程启动或业务收尾失败 | 同步命令整体回滚；修复依赖后重新核对原业务操作。结果未知时通过页面原请求恢复，不把失败转成审批成功 | [子流程](subprocesses.md)，`FlowableTaskFacade`、`SubprocessPublicApiIntegrationTest`、前端原请求恢复测试 |

发布校验继续拒绝任意 `SERVICE_TASK`，原生异步执行器保持关闭；当前没有额外开放的任意作业或跳节点恢复入口。Webhook、财务原号执行、模型失败仍按其各自既有规则和外部接入工作包处理。已授权的高级流程本地范围至此收尾；通知协作和真实企业接入继续实施。
