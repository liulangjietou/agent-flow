# O01 业务操作追踪补齐

来源：原 02 §10（观测）。V03 实际追链确认，错误响应随机 UUID 与请求无关联，审批 Webhook 使用审计 eventId 代替请求 traceId；现有测试仅断言 traceId 非空。

调用方：HTTP 入口（包括认证、CSRF、CORS 失败）→ 认证主体 → 控制器和错误处理；审批应用服务 → JDBC 审计适配器 → Webhook outbox → 短事务领取 → 事务外 HTTP。受影响场景为请求排错、同事务多个审批事件、幂等重试及投递恢复；业务状态、授权和重试语义保持。

请求追踪应放在安全链之前的 Web 入口，认证后的租户由真实主体补充，不能相信客户端身份或 trace 请求头。异步关联在持久化边界保存，worker 从原记录恢复；日志不得包含请求体、令牌、外部响应或异常正文。不得把线程 MDC 当成跨重启持久化。

- [x] 先通过真实请求/认证和审批 outbox 复现无法关联。
- [x] 请求 header、统一错误、MDC 和精简完成日志共用服务端生成 traceId，清理线程上下文；CORS 可读取响应追踪头。
- [x] 审批审计/outbox 保留来源 traceId，Webhook 重试从原记录恢复并发出不含业务正文的追踪头。
- [ ] 核对业务号、引擎实例/任务和其他 Agent/worker 的持久化关联，补齐遗漏后再宣称整体条款完成。
- [ ] 范围回归、固定包运行、证据归档和本地合并；PostgreSQL、真实外部接入仍保留门禁。

当前分阶段实施，API 与 Webhook 通过不等于所有后台链路已覆盖。

请求/Webhook 阶段：134 项范围测试通过，固定包 6 次启动、187 次 HTTP（其中新包响应 178 次均具追踪头）、3 次实际接收；280 表升级和独立恢复、接收后强退及原事件重试通过。归档下载线程另有先失败后通过的验证。见[阶段证据](../../evidence/operation-tracing-request-webhook-20261007.json)。其余 Agent/worker 与业务标识继续实现，O01 保持 OPEN。

Agent 阶段：六类队列表在原创建事务保存来源 traceId，工作器在领取前恢复、结算后清理，共用模型 HTTP 客户端发送 X-Trace-Id。V122 只新增可空诊断列，不回填旧 HTTP 来源，不修改领域快照、发送同意或状态摘要。6 项断言先失败后通过；范围去重 307 项通过（仓储夹具复验见证据）。固定包 7 次启动、12 次真实模型接收，六类旧任务升级及新任务排队后强退恢复、原键重放和独立备份恢复通过。见[Agent 阶段证据](../../evidence/operation-tracing-agent-20261007.json)。O01 的其余 worker 与业务标识继续实现。
