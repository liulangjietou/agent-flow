# 轮次流程图

申请详情新增“流程图”页签，按提交轮次查看实际引擎流程、当前节点、历史节点与会签剩余待办。支持轮次切换、节点详情、缩放、适应和键盘滚动。没有提交轮次时展示空状态；读取失败清除旧图并允许重试，旧账号或旧轮次的迟到响应不回填。

## 读取边界与职责

调用方是申请详情 `ApplicationRecord` → `RoundDiagram` → `GET /api/v1/applications/{id}/rounds/{roundNo}/diagram`。接口先调用 `ApprovalApplicationFacade.get` 复用租户和参与关系授权，再读取指定提交快照，由领域端口 `RoundDiagramPort` 连接 `FlowableRoundDiagramAdapter`。事务采用可重复读，在同一数据库快照中读取申请、轮次和引擎事实。

领域端口只描述安全读模型，不依赖 Flowable；基础设施核对实例的系统租户、申请、轮次变量、引擎租户、定义 key/version，以及申请保存的引擎定义 ID。使用历史实例的精确定义获取拓扑，不查询最新草稿，不用同 key/version 的全局模板替代租户流程。全局来源只允许内置费用报销 v1。用户只能读取原本有权查看的申请，不通过该功能获得审批、评论或流程管理权限。

- `ACTIVE`：引擎当前活动或真实待办所在节点；`activeTasks` 是实际剩余任务数量。
- `LEFT`：存在历史活动且已不再活跃；退回、驳回、撤回导致离开也属于这一状态，不能解释为通过。
- `NOT_REACHED`：未记录到达，不据此补造历史。
- `firstEnteredAt` / `lastLeftAt` 来自本轮活动历史。会签仍在运行时可以已有部分结束记录，UI 明示这一点。
- 连线 `TAKEN` 表示本轮引擎存在 `sequenceFlow` 历史；`NOT_RECORDED` 表示未记录，不能解释为从未执行。接口同时返回记录数量 `traversalCount`、首次与最近流转时间。无时间证据时省略时间字段。
- 仅匹配已授权申请的精确实例、定义 ID、引擎租户、活动类型与连线 ID。不根据两个端点都已到达推断路径，也不使用当前表单重新计算历史分支。
- UI 用深色实线与箭头表示已记录流转，浅色虚线表示未记录；可展开“流转记录”查看连线名称、默认分支、次数与时间。记录按首次时间排列，同一时间的排列不代表执行先后。
- 条件表达式、收件/审批规则、表单值不进入此接口。

缺少提交快照、引擎历史、定义或绑定不一致返回 404；不以当前数据补画历史。当前不展开外部子流程，不支持历史被清理后的自动重建。只读查询设置 `Cache-Control: no-store`；正整数轮次是唯一参数，未知查询参数返回 400。没有数据库迁移、业务写入和新的消息。

## 2026-09-23 连线流转增强

原测试只验收节点状态与拓扑。本阶段先增加连线断言，确认 4 个用例因缺少连线状态失败后再实现。新增回归涵盖两个端点都已离开但默认连线未执行、退回重提的轮次隔离、会签部分完成与驳回、默认路径、撤回、缺失/错误类型/异租户历史，以及引擎级重复流转的次数和时间范围。位置调整仅用于集成测试制造真实重复证据，没有增加生产操作入口。

验证脚本要求显式 `--exercise`，拒绝默认主环境 8080/8180 与非本机入口。它保留七份合成申请，比较图查询前后的申请、轮次、时间线与审计完全一致。
