# 表单字段关系选人

更新：2026-10-01。本地开发、范围回归、独立 PostgreSQL 运行、真实页面及两次重启验收已完成，见[验收证据](evidence/form-assignees-20261001.json)。本能力补齐组织审批工作包中的最后一项已确认缺口；完整平台目标仍有其他工作，见[剩余清单](remaining-local-work.md)。

## 使用方式与业务规则

流程管理员在表单中创建**顶层、必填、单选字段**，通过组织目录添加人员、部门或岗位选项，再在人工审批节点选择“表单字段”和对应关系。快捷设计与高级画布共用配置。关系包括所选人员、所选部门负责人、所选部门成员、所选岗位成员。

选项保存本租户组织对象标识和发布时的名称。发布逐一核对全部选项的类型、归属及可用性，不能用任意账号文本或表达式代替组织对象。目录接口仅供管理员及流程管理员使用，返回选项名称、类型、人数和负责人可用状态，不返回账号与任职明细，响应禁止缓存。

提交时按该轮表单值解析**所有人工节点**的字段关系，包括尚未命中的分支，固定原始审批人及组织修订号。任何关系无有效人员时，整次提交回滚，不创建半个轮次。已提交后更换部门负责人或增减组织成员，不会替换本轮原名单。撤回或退回后重新提交时，按新一轮的输入和当时组织关系重新确定名单，历史轮次保持。

节点激活仍会核对冻结人员的有效状态和审批资格。资格已失效时阻断推进，不能静默删人降低会签责任。职责分离继续从原名单中排除申请人或前序实际批准人，任一人、全员、比例会签继续使用已有实际激活人数规则。快照缺失或规则不匹配时直接报错，不回退到当前组织目录重新选人。

固定版本子流程在创建自己的轮次时，根据已映射的子表单输入独立生成名单，不继承父流程的同名字段快照。已有账号、角色及发起任职规则保留原语义；抄送和超时升级不支持此字段规则。

## 实现职责

调用链为设计器 → 定义保存／发布 → 申请提交或子流程启动 → Flowable 人工任务／会签激活 → 原有职责分离与待办授权。

- `FormAssigneePolicy` 属于定义领域，负责固定关系语法和版本化字段约束。
- `DefinitionReferenceInspector` 在发布应用层核对外部组织引用；`OrganizationAssigneeResolver` 继续使用原本地目录的租户锁和资格规则。
- `FormAssigneeBindings` 编排提交快照及激活资格复核。Flowable 适配层仅持久保存并读取 `agentflowFormAssignees`，不接管组织业务规则。
- 前端复用原表单选项和目录查询组件的取消、身份切换及错误处理。未完成的字段配置保留在设计器中，不能静默替换为其他审批规则。

没有新增数据库迁移，仍为 V98。普通申请、会签、职责分离、子流程、定义发布、模板导入和历史候选展示均属于本次影响范围。历史版本没有字段规则时无需补造快照。

## 验证结果

新增领域用例首先在旧实现稳定失败，随后通过实现修复。Java 范围去重 172 项通过，包含领域 50 项、服务端 122 项；新增服务端 11 项又在 PostgreSQL 通过，属于重叠验证。前端相关 66 项、类型检查、构建及 OpenAPI 静态检查通过。静态检查覆盖 297 个操作、591 个模型与 113 个请求示例。

独立运行复制已验收的 V98 数据，在页面完成组织选项配置、两种设计视图切换、保存／校验／发布、申请提交、财务先审及原负责人批准。提交后先将负责人从 `manager` 改为 `bob`，并在后续节点激活前重启；原 `manager` 仍为候选，`bob` 读取该待办返回 403。第二次重启后，页面仍显示第 1 轮已批准及原候选名单。

实际 HTTP 补验撤回重提：旧轮冻结 `bob`，新轮冻结恢复后的 `manager`，旧快照未变。移除负责人后提交失败，草稿版本和空轮次保持；恢复关系后原草稿可提交。累计 108 份响应及 32 份成功写请求符合实际接口契约，其中 66 份响应来自浏览器，捕获缺口为零。过程中一次登录失效后经正常重新登录完成验证；未完成配置的自动保存被结构校验拒绝，补齐配置后可正常保存。

两次重启分别保持 228 张表的 3,637 行和 3,778 行，每次三份文件哈希均一致。13 条原在审任务保持，源 V98 数据库的 228 张表、3,550 行及三份文件未变。运行使用本地合成组织和账号，不代表真实企业目录同步或生产模型验收。会签、资格失效、子流程隔离等组合由 H2／PostgreSQL 集成用例验证，未逐一声称通过浏览器办理。
