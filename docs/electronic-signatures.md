## 调用链与职责

业务入口将从当前用户可读的已批准申请轮次发起，复用 `ApprovalApplicationFacade` 的申请授权、`ApplicationFieldViews.attachmentView` 的轮次字段投影及 `AttachmentService` 的冻结附件引用检查。隐藏或脱敏字段的原件不能因拥有管理员身份而发送给签署服务。

申请批准和签署授权分别处理。入口还必须核对可信签署配置的授权操作人、实际签署身份、配置版本及摘要，明确记录本次目的和发送授权有效期。不能从审批角色、显示姓名或请求中的任意账户推断印章使用权。

`SignatureRequest` 固定申请及流程版本、当轮原件引用和内容指纹、具名授权、签署人集合。`SignatureOperation` 管理自身状态。后续应用服务负责当前权限复核、短事务领取与比较版本、审计、调用外部端口及不可覆盖文件存储。领域层不访问数据库、文件系统或网络。

## 已实现的约束

- 同一授权对应唯一操作号。第一次领取后，超时、连接失败、回执丢失或查询未找到都只允许查询原号，不能重新发送原件。
- 只有发送前可以本地取消；首次领取达到授权有效期时直接到期。已发送的操作继续查询和收集结果，不因发送授权后来到期而丢失远端事实。
- 服务方回执绑定请求摘要、稳定修订号、原文件集合及全部签署人。旧修订回调忽略；同修订不同正文、服务方记录号变化或终态替换均拒绝覆盖。
- 回调可以结束当前领取。后续仓储必须比较领取版本，防止旧工作器覆盖已接受的回调结果；领域方法不能代替数据库并发约束。
- 服务方确认签署后先进入 `COLLECTING`，为结果预分配独立内容标识。下载恢复沿用该标识；只有存储层校验并保存全部文件后，才能进入本地 `SIGNED`。
- 原件内容标识不能用作签署结果标识，结果也不能缺少文件、混入其他文件或替换回执中的大小及摘要。

当前本地协议限定最多 10 份文件和 10 个签署身份，原件单份 16 MiB、合计 32 MiB；结果单份 32 MiB、合计 64 MiB。发送授权最长 24 小时，领取租约最长 5 分钟，后台退避范围 5 至 300 秒。签署方集合不表达签署顺序。

请求和回执摘要采用长度前缀的 UTF-8 编码，覆盖全部固定字段。摘要用于绑定和冲突检测，适配器仍必须独立验证回执真实性、文件签署证据和配置来源；已有消息 HMAC 或 OFD 签章图片渲染不能替代这一层。

## 状态与恢复

| 本地状态 | 含义 | 下一步 |
| --- | --- | --- |
| `QUEUED` | 授权已固定，尚未领取发送 | 首次发送、到期或本地取消 |
| `SENDING` | 首次发送领取有效 | 接收回执；丢失结果后查询 |
| `UNKNOWN` | 无法确认远端当前结果 | 查询原操作号 |
| `QUERYING` | 原号查询领取有效 | 保存已验证的服务方事实 |
| `PENDING` | 服务方确认处理中 | 继续查询原操作号 |
| `COLLECTING` | 服务方已签署，文件尚未全部保存 | 领取同一批结果文件 |
| `FETCHING_FILES` | 结果文件收集领取有效 | 保存并核验全部文件，失败时继续收集 |
| `SIGNED` | 已保存完整签署结果 | 保留原件、授权、回执和独立结果 |
| `DECLINED` | 服务方确认拒签 | 终态，不自动换号 |
| `CANCELLED` | 发送前本地取消或服务方确认取消 | 保留两种取消各自的依据 |
| `EXPIRED` | 首次发送前授权已到期 | 终态，不发送 |

`NOT_FOUND` 只表示本次查询没有查到结果；即使多次查无原号，也不能推断远端副作用不存在。该观察保存为失败类别，不覆盖已经接受的 `PENDING` 回执。

## 持久化与文件清单

V111 使用 `signature_operation`、`signature_source_document`、`signature_operation_revision` 和 `signature_result_file` 保存原操作、冻结原件、连续状态和结果文件。创建时锁定并核对当前已批准的申请版本及轮次；源文件同时关联当轮冻结字段引用和同租户、相同指纹的 READY 物理原件，子流程复制的授权引用不改变原内容身份。

同一申请轮次只能存在一个未结束签署。未知结果和正在收集文件都占用该位置；终态释放位置并保留原记录。新操作仍须重新经过明确授权，不自动将原授权变成再次发送。

状态更新比较原输入和前一版本，原授权及目标不能改写。签署成功回执、结果预留和历史在同一事务中提交；迟到工作器不能覆盖已接受的回调。每份文件的 READY 确认绑定有效下载领取及对应历史版本，部分保存后可以重开数据库继续收集。只有全部结果已在仓储登记 READY，才能提交本地 SIGNED。

结果文件加入 `stored_document_inventory`：预留项沿用 `UPLOADING`，保存后为 `READY`，列名及列类型保持旧备份契约。备份工具继续逐份核对真实字节；它不会仅凭 READY 元数据生成不存在的原文。

初次 JDBC 测试复现了 SQL `CHECK` 的空值语义和时间精度问题：三处空值需要显式拒绝；JSON 保留原始纳秒时间，数据库索引统一截到微秒，因此索引允许租约两端相等，实际正租约仍由领域状态校验。这四个复现用例已包含在最终通过的 72 个用例内。
