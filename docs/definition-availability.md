## 调用链与职责

- 流程设计器 → 版本治理接口 → `DefinitionAvailabilityService` → 定义聚合状态变更 → JDBC CAS 与追加操作记录 → 原写请求幂等响应。
- 新建申请 → 定义行锁 → 聚合发起状态守卫 → 原申请创建事务。
- 首轮提交 → 原申请聚合 → Flowable 适配器确定实际绑定来源 → 租户版本行锁和聚合守卫 → 引擎启动及原事务提交。
- 历史查询、版本比较、轮次流程图、正在运行的待办沿用原读取和办理链路。

开关属于流程定义的业务状态；合法转换和 revision 检查放在定义聚合。用例服务负责操作身份、审计与事务，JDBC 负责持久化和并发锁。引擎适配器只有在确认真实来源后才查询租户版本，避免把同名同号的租户版本开关错误应用到历史内置流程。

发布状态仍为 `PUBLISHED`，新增 `startEnabled`。停用不会篡改图、表单、发布版本或发布记录，也不调用 Flowable 实例挂起。恢复沿用原版本；草稿不支持此操作。修改 revision 后，旧页面请求返回冲突；相同目标状态的新请求也返回冲突，原成功请求则按原幂等键回放。

## 当前接口

- `POST /api/v1/process-definitions/{id}/availability`：正文为 `startEnabled`、`expectedRevision`、`reason`。原因要求 1–2000 字；操作人、权限与时间取服务端事实。需要 ADMIN 或 PROCESS_ADMIN、原 Idempotency-Key，以及企业会话模式的 CSRF 和页面身份绑定头。
- `GET /api/v1/process-definitions/{id}/availability-history`：仅流程管理员可读；默认 30、最多 100，使用 `beforeRevision` 继续按修订降序分页，返回 `items` 与可选 `nextBeforeRevision`。
- 定义详情和目录摘要返回 `startEnabled`；目录支持 `status=PUBLISHED&startEnabled=true|false`。历史阅读不因停用消失；新申请只选择当前允许新发起的版本，并在服务端再次检查。

旧成功写请求的幂等响应可能没有新字段。原响应保持原字节，页面显示“状态待刷新”并阻止治理动作，读取当前定义后再确认状态。不能把字段缺失解释为启用或停用。

## 数据与交互
