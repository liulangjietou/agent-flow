# 首次流程使用引导

交付时同时修复了旧 H2 文件关闭压缩后的数据回退，详见 [H2 关闭重开完整性](h2-restart-integrity.md)。

管理员首次进入当前浏览器账号时，默认打开“开始使用”。这里提供复制官方模板、新建可视化流程和只读样例预览三条路径；可以勾选以后直接进入工作台，随时从侧栏返回。偏好和选中流程按租户与账号隔离，仅影响当前浏览器。

本引导用于验证现有流程能力。租户、法人、默认角色、工作日历、通知渠道及企业身份/组织初始化仍未实现，不能把四步完成视为企业初始化或生产上线完成。

## 从配置到真实证据

1. **保存流程**：存在当前租户的已保存定义。模板复制或设计器实际保存后才完成；仅打开新建页面不算保存。
2. **发布版本**：所选定义已产生发布版本。发布仍使用原有校验、变更说明、并发版本与幂等规则。
3. **提交申请**：该流程精确版本存在提交轮次。发起入口预选该版本，重新加载后若版本已不可用则停止，不静默改成另一份流程。
4. **完成批准**：存在该版本已批准的轮次。退回、驳回、撤回、模拟或浏览样例均不能代替批准证据。审批仍由实际授权账号完成。

可以打开最近提交或最近批准对应的申请详情，核对表单、轮次、轨迹与审计。若旧申请缺少轮次快照，界面披露缺失量，仅显示可核对的事实，不能用当前申请状态补造旧记录。

未提交的申请草稿不计历史缺口；有准确作废审计证明从草稿直接作废的申请也不计。退回、撤回后作废仍保留真实旧历史缺口；无法核对的作废来源保守保留提示。见[草稿误报修复](known-draft-round-count.md)。

引导旁的环境检查调用现有系统自检服务。进入页面不预设检查通过；依赖失败、未知或未实现不会折算为就绪。每次返回页面需重新检查，显示实际检查时间。

## 实现链路

`FirstWorkflow.vue → api.firstWorkflow → FirstWorkflowController → FirstWorkflowReadPort → JdbcFirstWorkflowReadAdapter`。

新接口为 `GET /api/v1/system/first-workflow`：

- 仅 ADMIN；普通审批人及单独 PROCESS_ADMIN 不具有全租户申请读取权。
- 可选完整 UUID `definitionId`；省略时查询该租户最近更新的定义，排序含 ID 以稳定处理相同时间。空租户不返回 definition。
- 未知参数或非法 UUID 返回 400 `INVALID_FIRST_WORKFLOW_QUERY`；定义不存在和跨租户均返回 404。
- 只读可重复读事务，`Cache-Control: no-store`。返回摘要和轮次证据，不返回表单正文或会话数据。
- 提交与批准计数覆盖全部日期，但绑定认证租户、流程标识和精确发布版本。草稿没有发布版本，不继承同标识旧版本的进度。
- 不新增可手工勾选的完成状态表，不修改审批聚合、Flowable 状态或组织角色。跨上下文的展示查询在读适配器聚合，所有写操作仍进入原应用服务。

示例预览复用模板中心，以只读模式隐藏复制表单及副本操作，默认展开一份输入/预期路径示例。模板复制、打开已有版本与新建设计继续使用已有未保存修改确认。模板风险说明同步修正为“站内消息使用平台统一文案，邮件和 IM 尚未接入”，流程图、表单和审批策略不变。

## 验证

- Java 集成：真实退回、重提、撤回、批准；旧版本与新草稿/新版本隔离；无轮次快照和损坏跨租户绑定不补造进度；角色、UUID、未知参数和查询不写历史。
- 前端模型：账号/版本切换清除迟到结果；失败和超时不保留旧完成状态；浏览器存储拒绝访问时仍可打开页面；偏好隔离；API 认证和取消。
- 浏览器：空库四步待完成；模板预览不会改变进度；复制/发布/提交/实际批准后逐步更新；申请详情；只读样例、未保存修改保护、登录偏好、窄屏、失败重试与普通账号入口隔离。

在独立本机演示库执行，随机业务记录会保留：

```sh
python3 scripts/check-first-workflow.py http://127.0.0.1:8082 --exercise
node agentflow-web/scripts/check-openapi.mjs http://127.0.0.1:8082 --exercise
```

验收服务应运行从构建目录复制到固定路径的 jar。不要在服务运行时覆盖该 jar；再次构建后，先正常停止旧进程，再使用新副本启动。此约束用于保护验收运行，不需要更改产品审批逻辑。
