# 付款授权与出纳工作区

更新：2026-09-28。本地已实现财务短期授权、独立出纳选账户与执行登记、原交易查询和明确查无后的原号重发。资金服务的成功回执已能展示；借款余额生成、费用资源核销和归档继续接入。

## 调用链与职责

借款或报销明细中的 `FinancePaymentStatus` 读取原轮次财务视图；`FinancePaymentActions` 锁定实际申请与财务单据，重新检查批准、凭证和双版本，从服务器冻结事实派生金额及收款账户。财务仅指定有效期和原因，不能改收款人、金额或代选出款账户。

`CashierWorkspace` 按当前有效法人任职分页。`CashierPaymentDetail` 单独读取资金目录，必须手工选中脱敏账户并确认；入口仅在幂等事务内保存账户引用和版本。后台在事务外重新读取账户证据，再锁定原业务并检查批准、凭证、授权期限与人员，原子登记不可变付款命令。资金调用仍在事务外执行。202 表示已登记，READY 表示已生成执行队列，只有有效成功回执才显示到账。

跨聚合校验、登记和同事务审计属于应用服务；授权与执行状态变更继续由领域对象负责。前端提示不承担资金正确性或权限检查。

## 权限与接口

财务入口沿用本轮完整敏感字段权限，并要求非申请人本人、明确 FINANCE 角色及当前法人任职。出纳要求明确 CASHIER 角色及当前有效法人任职，只提供付款所需最小信息，不授予完整申请读取权。申请人本人及授权人不能执行付款；只有原出纳可以重发原命令。管理员无隐含出纳角色或敏感字段旁路。

V47 从原授权条款回填法人索引，损坏、错租户或非规范标识不推断权限。法人范围在 SQL 分页前应用，游标也必须处于当前范围。读写及幂等回放前重新检查权限，停用人员不能利用旧请求键取得回执。

| 接口 | 行为 |
| --- | --- |
| `GET /applications/{id}/payments` | 受控状态，包含授权前服务器应付金额 |
| `POST /applications/{id}/payments/authorizations` | 明确期限、原因与显示版本，创建短期授权 |
| `POST /payments/{id}/finance-actions` | 未执行时作废，或查询原交易 |
| `GET /cashier/payments` | 当前法人范围的付款目录 |
| `GET /cashier/payments/{id}` | 付款、账户复查与资金回执状态 |
| `GET /cashier/payments/{id}/accounts` | 事务外读取账户选项，等待前后复查授权 |
| `POST /cashier/payments/{id}/actions` | 登记执行、查询或原出纳明确重发原命令 |

路径前缀为 `/api/v1`。响应禁止缓存，未知请求字段被拒绝；页面不持有完整账号、绑定摘要或资金目标。未知结果不提供直接重发；即使授权已过期或批准已撤销，原交易仍可对账。

## 页面恢复与验证

页面区分授权、账户复查与银行结果，保留成功回执及冲突/退票提示。恢复沿用原请求键和正文；恢复后须重新读取当前状态才可操作。身份、业务绑定或轮次变化会清空旧结果，超时返回不能恢复旧选项。
