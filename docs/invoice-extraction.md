# 票据抽取与本人确认

2026-10-02：已进入领域与模型适配开发，尚未完成持久任务、公开 API、页面及完整运行验收。票据抽取仍属于剩余工作，不把下述范围测试计为整个功能完成。

验收基线包含原产品目标，以及费用报销领域设计 `doc/05-费用报销领域设计.md` §4.1、§16：XML 结构化解析优先，识别结果带置信度和证据位置，必须由申请人确认。当前 XML 文本模型适配是兜底能力的基础，结构化优先路径仍待完成。

## 职责与调用链

个人票夹入口将先核对同租户、同本人及原件 READY 状态，再调用 Agent 协作域的独立抽取用例。内容适配器经 `InvoiceOriginalFiles` 读取并校验完整原件，模型适配器只在事务外向已确认目的地发送内容。`InvoiceExtractionRun` 保存原件身份、摘要、实际页数、提示版本、模型目的地指纹、运行结果及本人的人工修订。

这段状态逻辑放在 Agent 协作域，因为它描述建议的生产和复核；原件归属、上传完整性与正式税务查验继续分别属于票夹和发票领域。`CONFIRMED` 仅表示本人确认了选中的候选值。后续应用服务将独立持久化该记录，不调用 `Invoice.verified`，也不授予批准、核销或付款权限。

## 已实现的领域约束

- 固定发票 ID、原件 ID、SHA-256、格式、字节数和实际页数；最多 10 页，原始字节沿用票夹 20 MiB 上限。页数必须由内容适配器读取，不能采用客户端或模型自报页数。
- 11 个封闭字段：票号、代码、开票日期、买卖方名称和税号、币种、不含税金额、税额与价税合计。缺少依据的字段省略，空结果如实表示未识别。
- 票号保留前导零，金额使用字符串保留精度与红字负号；不会为使算术相符而修改票面候选值。金额、日期和币种的格式检查不证明票据真实。
- 每项建议绑定原件及真实页码，最多 4 份摘录、每份 512 字符。摘录属于模型声称的依据，仍须本人对照原件。
- 每项候选保留 LOW／MEDIUM／HIGH 置信度，明确属于模型自评，不能展示成实测准确率或真实性保证；缺失或超出枚举的值拒绝。
- 本人明确选择并可编辑部分建议；模型原值与人工值分别保存。其他人、管理员、重复目标、额外目标或已变更来源不能确认。
- 排队、运行、完成、失败、确认、放弃按版本单次推进；超时或终态后的晚到结果不能重新启动。重建持久状态必须通过合法动作校验。

## 当前内容适配范围

| 原件 | 当前实现 | 边界 |
| --- | --- | --- |
| PNG、JPEG | 原始图片字节通过内联 data URL 发送；解码前检查尺寸，随后检查可读性 | 单边最多 12,000 像素、总计最多 2,000 万像素；没有外部图片 URL |
| XML 模型兜底 | 遵循原声明编码读取正文、元素名和属性，再作为纯文本发送 | 禁用 DTD、外部实体和外部资源；文本最多 64 KiB，超限失败；模型摘录必须存在于发送文本；结构化优先路径待完成 |
| PDF、OFD | 待实现 | 不在当前适配器能力清单中，不能当作文本或图片静默发送 |

图片请求采用 Chat Completions 的 `image_url` 内联图片格式，协议依据为 [OpenAI 图片输入文档](https://developers.openai.com/api/docs/guides/images-vision)。XML 内容以文本块处理，不能据此认为模型文件接口原生支持 XML；该接口的文件类型限制见 [OpenAI 文件输入文档](https://developers.openai.com/api/docs/guides/file-inputs)。最终配置的模型仍需实际图像能力与质量验收。

模型只接收原件引用和白名单字段，不发送归属人、租户、文件名或文件系统路径作为请求元数据。图片本身的全部字节会外发，公开入口和页面必须明确说明发送范围，默认不勾选；尚未开放这些入口。模型只能返回封闭候选结构，额外动作、未知字段、数值类型票号、伪造原件、不存在页码和 XML 虚假摘录均拒绝。
