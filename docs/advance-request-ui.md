# 员工借款申请页面

更新：2026-09-28。本阶段在借款后端基础上完成独立填报、账户预检、提交、撤回补正、历史轮次与批准展示。付款、凭证和归档继续开发；本地合成财务验收不代表企业接口或真实放款验收。

## 调用链与职责

费用工作区的“我的借款申请”读取本人申请目录，填报页通过 `advance-requests` 保存用途、法人本位币金额和归还日，再由持久预检核对所选任职与本人财务账户。页面只接收脱敏账号，不能输入或提交完整账户、批准结果或已到账余额。审批工作台和申请记录均使用借款专用详情，历史入口明确指定轮次。

`AdvanceDrafts` 按身份和单据隔离内存输入及待恢复请求。创建、修改只返回最小保存回执；页面必须重新读取服务器版本后才开放预检与提交。响应丢失时沿用已有原请求恢复机制，核对路径、原始请求体、身份和单据绑定，避免创建第二张借款单。读取失败保留已保存编号，可显式重新查询。

字段编辑权、任职、流程版本、账号与预检时效均由后端最终核对；前端负责反馈和防止过期结果继续展示为可提交。预检轮询有界，切换身份或单据后丢弃旧响应。撤回补正创建新轮次，旧轮次金额、日期、任职和脱敏账户保持。

## 本地验收

- 借款页面 23 项自动测试；包含费用计划、填报、资源、附件及原请求恢复的范围回归共 118 项通过，范围有重叠。前端类型检查与生产构建通过，保留原有大分块警告。
- 测试先复现目录刷新与“读取已保存内容”重叠时中断目录请求并残留加载状态。原测试分别覆盖读取成功，未覆盖共享取消器的并发入口；修复后两入口互斥，负例与范围回归通过。
- PostgreSQL V42 的实际页面创建 `UI-ADVANCE-001`：500 CNY、2026-10-10 归还，指定任职预检后提交第一轮；撤回后改为 450 CNY、2026-10-12，再次预检并提交第二轮。历史页仍展示第一轮原约定。
- `manager` 在实际待办页面核对第二轮并确认批准。申请人看到第二轮已批准及等待结算提示；批准前后 `employee-advances` 仍为空。借款审批不会伪造付款或可冲销余额。
- 实际 HTTP 检查无关人员返回 404，受敏感字段约束的管理员返回 403；当前与历史响应均无完整账户引用或账户摘要。
