# 费用相邻重复审批：固定包运行验收

F12 的后端、设计器、模板和当前可执行的 H2 运行验收已完成，任务仍为 OPEN，等待浏览器与 PostgreSQL 补验。没有将合成财务服务当成真实企业联调，也没有在本阶段推送或创建 PR。

## 安装包与真实调用

基线为 `1a62061` 的费用模板 v2 固定包，当前为 `25fc140` 的费用模板 v3 固定包。两者 SHA-256 均重新核验；独立文件 H2 保存了非空组织、旧定义草稿、已发布定义、业务草稿和在审申请。

脚本通过认证 HTTP 创建组织、发布实际费用模板副本、预检和提交报销、读取待办并审批，不直接改写业务或引擎表。财务主数据、制度和预算来自独立本机合成 HTTP 服务。模板配置使用合成人员建立明确重复的业务审批人，原金额网关和财务阶段保留。

## 通过的行为

- 升级后，原定义、业务草稿和在审状态保持；v2 中同一人员的部门节点仍需人工审批，并可继续完成财务审批。v3 模板目录拒绝过期的 v2 复制请求。
- v3 提交后修改组织关系，再对运行包强退。重启仍使用原轮次冻结的主管；主管批准后，部门节点受控自动通过，财务签收保留人工。
- 60,000 元报销的两个并发审批请求分别返回 200 和 409。主管只批准一次，部门和高管各自动通过一次，申请版本准确增加 3。
- 自动通过后撤回重提，第二轮仍先创建真实主管任务；第一轮自动审计保留，第二轮自动动作使用第二轮源任务，不复用旧轮次的批准事实。
- 第二次强退后，申请版本、自动审计和待签收任务编号保持。重放已完成源任务不能再次推进。
- 独立备份恢复逐表核对 253 张表、789 行记录。恢复前后的 5 条自动审批原始凭据一致；恢复后继续办理另一张在审单，新增第 6 条凭据，仍指向被冻结的本轮实际审批人及源任务。

6 次包启动均已结束，本轮创建的运行进程已核对停止。原运行进程与主工作区保持。

## 契约与恢复证据

257 份实际 HTTP 响应和 53 份成功请求通过当前 OpenAPI 校验，涉及 24 个操作；这些数量包含重复读取，不代表 257 个独立业务场景。6 个不同自动审批事件的结构化原始数据核对了规则版本、发布定义、轮次、前驱节点、源任务及实际人员。

恢复结构比较覆盖 1,981 条完整 SQL 语句，保留列与表的归属、默认值、约束、序列及账号权限。首次直接比较仅因新数据库生成不同 SA 密码盐而失败；随后使用 H2 原生 `NODATA NOPASSWORDS` 在闭库副本和独立恢复库上导出，使用明确的合成账号完成认证，并核对与最初两份结构等价。没有放宽表或约束检查，也没有修改原数据库。

本场景附件数为 0；此次证据只证明空附件目录的配套恢复，不替代已有附件功能的验收。原数据库和合成财务回执在独立恢复办理后保持不变。
