# 费用风险提示

用户已授权“按照未完成的内容全部开始，此项目都按照你的建议来开发”。后续推荐的业务规则按该授权推进；真实企业参数和外部验收继续以实际来源与运行证据为准，不把尚未答复的旧问题当成重复授权门槛。

A04 的目标是审批界面中选择来源、运行模型、保存风险提示并由当前有效审批人复核。目前领域事实、持久执行、六个公开操作及审批页面已接通；真实 Flowable/API 范围、页面组件及固定安装包的 H2 升级、进程重启、配套恢复已经验证。浏览器与 PostgreSQL 补验仍待完成，任务保持 `OPEN`。

## 调用链与职责

费用审批页面通过 `ExpenseRiskController → ExpenseRiskService → ExpenseRiskAccess` 读取目录和编排复核。来源边界通过现有申请读取、任务决定权和字段投影逐单核验所选轮次，再查询所选行引用的查验票据和明确指定的日历；不自动扫描整个企业费用。

`ExpenseRiskEvidence` 位于费用领域，计算可核验的局部观察。`ExpenseRiskSources` 将已授权事实转换为发送目录并校验显式选择。`ExpenseRiskInput` 保存本地身份、轮次、版本和事实摘要；适配器只发送其中选定的来源和观察类型。`ExpenseRiskRun` 保存自己的执行和人工复核状态，不修改审批申请、预算、核定额或付款。

## 来源与解释边界

| 观察 | 可核验事实 | 不能据此认定 |
| --- | --- | --- |
| 同日费用 | 相同发生日、类别、原币的所选费用行及合计 | 重复报销、违规消费 |
| 跨单费用 | 所选对照单中的同类别、同币种金额和实际日期范围 | 已命中企业拆单窗口、已越过审批阈值 |
| 非工作日 | 明确选择的工作日历中，日期覆盖优先于周规则 | 法定节假日、缺少日历时推断周日应休息 |
| 发票连号 | 已成功查验且当前有效的规范票号，在类型、代码和宽度一致时数值连续 | 同一开票方、造假、重复报销 |

对照范围限同申请人、同法人，并逐单校验原轮次读取权限。每次最多选择 20 份单据、合计 200 行，最多确认 20 条观察；发送来源不超过既有 64 项和 64 KiB 限额。超限直接要求缩小选择，不悄悄截断。

完整费用明细属于敏感字段组。该专用路径要求当前主单决定权和每份来源的完整明细读取权；普通通用摘要的敏感字段排除规则不变。管理员和财务角色不能因此获得新的跨单读取权。历史正文也逐单检查当下的原轮次字段权限。

操作者必须明确选择单据范围、票据查验覆盖以及至少一条观察。服务端不补选未确认的正文。来源只包含选择内序号、日期、类别、原币申报额、票数和派生观察；人员标识、实际单据标识、账户、附件、完整票号、原自由文本和日历备注不发送。

没有观察时不请求模型凭空生成风险。部分票据缺失、查验失败、过期或归属不符时，覆盖信息明确保留未参与比较的部分，不能将“没有发现连号”解释成全部票据已查验或全部费用无风险。

## 版本、模型与人工复核

本地上下文绑定每份申请版本、费用版本、原轮次、所选行、原费用及票据状态摘要，并绑定日历身份、修订及规则摘要。即使重新查验后可见观察没变，原票据版本变化也要求重新确认。日历摘要使用固定星期顺序，不依赖不同进程中的 Map 遍历顺序。

模型请求复用现有配置、固定目的地摘要、有界响应和事务外 HTTP 客户端。模型只能逐项解释已选观察，输出解释、证据局限、人工核对步骤和精确来源摘要；未知观察、变更类别、遗漏所需来源、伪造摘要、额外字段、工具调用或截断输出都被拒绝。

运行状态为 `QUEUED → RUNNING → COMPLETED/FAILED`，完成后可记录 `ADOPTED/DISMISSED`。租约只能首次领取时固定，超时运行不重发；晚到结果不能覆盖失败。采纳要求当前输入完全匹配，只记录选定解释及人工意见。具体任务资格和来源权限由应用服务每次重新检查，不能凭领域聚合中的字符串身份绕过。

## 持久队列与后台执行

V115 新增运行、来源索引和转换审计三张表，沿用原费用、费用版本及提交轮次的外键。同一主单只允许一条活动运行；创建时 SQL 再核对每份来源版本，状态转换、来源写入和转换审计共同提交或共同回滚。

预览摘要绑定当前操作者、任务和完整来源目录。排队先逐单授权，再按申请标识排序锁定来源，重新读取并核对摘要；发生变化要求重新预览。持久记录只保存发起时的登录引用，后台通过现有延迟认证服务恢复仍有效的原登录，不借用调度线程的角色或其他人的登录。

领取事务只固定一次租约。发送检查在独立短事务中重新核对原登录、当前决定权、每份原轮次字段权限、票据、日历和目的地。权限异常退出该事务后，工作器另开事务保存失败；数据库异常不会伪装成权限撤销，原运行由租约到期结束。HTTP 在领取和发送检查事务结束后执行，工作器拒绝被外层事务包裹。

原请求者的登录结束不阻止其他当前有效审批人复核已完成结果。采纳仍要求所有来源相同；来源变化后可由具备当前决定权和全部原文读取权的人记录放弃。模型停用不撤销已保存历史的读取或人工复核能力。采纳和放弃只追加风险复核轨迹，不写审批、费用、预算或付款。

## 公开接口与审批页面

以下路径均位于 `/api/v1/expense-reports/{id}/risk-explanations`，读取和成功回执禁止缓存：

| 方法与后缀 | 行为 |
| --- | --- |
| `GET /calendars?roundNo=&taskId=&afterKey=` | 当前决定人读取本租户日历摘要，每页最多 30 项；同时要求主单原轮次完整费用明细权限。 |
| `POST /input` | 预览明确选择的单据、原轮次和行号；这是只读请求，不建立运行、不分配幂等键、不调用模型。 |
| `POST /` | 携带范围、目录摘要、目的地摘要和逐项选择的来源，幂等排队，返回 202。 |
| `GET /?roundNo=&page=&pageSize=` | 读取主单原轮次历史，页大小最多 50；只返回运行摘要。 |
| `GET /{runId}` | 逐单重新授权后返回原解释；分别表达当前能否复核和能否采纳。 |
| `POST /{runId}/review` | 以原运行版本幂等记录采纳或放弃；成功回放仍重新检查全部原来源读取权。 |

请求只接受声明字段，拒绝未知属性、重复查询参数、重复单据/行号与超限范围。非法 JSON 形状和查询返回 400；已解析来源位置违反领域规则沿用 422。复核成功后旧任务结束，原键仍可读取已经保存的同一回执，但不会再次写入轨迹。

`ExpenseRiskScope` 负责范围选择，复用本人可访问申请检索，在读取完整原轮次费用后才加入对照单；不能因管理员或财务角色扩大明细权限。主单和对照单的费用行、日历默认不选。`ExpenseRiskPanel` 负责来源逐项确认、历史展示与人工复核；金额和审批操作仍属于原费用组件。两者的忙碌和未提交选择共同纳入原费用操作锁。

更改范围使原目录失效；请求超时、账号或任务变化后，迟到正文不能回填。已知失权时清除对照正文、日历与未提交选择。模型及来源文本由 Vue 转义展示。前端核对响应状态、正整数版本、原轮次、所有观察和精确来源摘要，损坏成功回执仍保留原请求字节与原幂等键，通过页面既有“恢复原操作”入口回到同一记录。

## 当前验证范围与剩余工作

基础阶段的范围测试覆盖本地计算、来源选择与脱敏投影、严格 HTTP 模型输出以及复核状态。该阶段的来源编排测试对既有授权端口使用桩，不证明真实任务、角色撤销、跨轮权限、并发事务或数据库恢复已经验收；154 项范围用例通过，其中 74 项为新增风险能力用例，见[基础验证证据](evidence/expense-risk-foundation-20261004.json)。两次夹具错误及修正前日志单独保留，不作为产品回归缺陷计数。

后续后端范围已通过 129 项去重用例，见[持久执行证据](evidence/expense-risk-execution-20261004.json)。其中持久化 25 项、执行链 31 项使用实际 Flyway、H2、JDBC 和 Spring 事务，覆盖非空 V114 升级、并发、审计回滚、服务对象重建、权限异常事务结算、超时和原输出保留。其余用例覆盖来源、领域、HTTP 模型适配器、调度以及既有原登录服务。该数字与前述基础范围存在重叠，不能相加。

上述后端执行链测试对来源与决定权使用受控桩；服务对象重建不是操作系统进程重启。该阶段的断言编译歧义、模型桩重设和调度夹具缺少事务管理器均已修正并复跑，原始失败日志保留。

接口与页面阶段通过 66 项 Java 范围测试、85 项前端范围测试、类型检查、生产构建及 OpenAPI 检查，见[接口与页面证据](evidence/expense-risk-api-ui-20261004.json)。其中 12 项集成用例走实际报销创建、预检、提交、预算确认、Flowable 待办、真实认证及 MockMvc 入口，财务与模型使用本机合成 HTTP 服务；22 项新增页面/协议用例包括原恢复入口、跨账号响应隔离和模板转义。66 项与前述后端范围有重叠，不相加。契约包含 391 个操作、830 个 schema，既有操作和类型内容逐项保持。

接口与页面阶段稳定复现并修正三处问题：日历末页空游标被全局空值策略省略；未知状态与缺少版本同时出现时被 `undefined` 相等误接纳；来源选择期间失权未清除已选对照正文和日历。前后测试及源码哈希均保留。H2、MockMvc 和 Vue 渲染器的通过不代表真实浏览器、PostgreSQL 或企业模型效果已完成。

固定安装包阶段使用提交 `080f7458105f0911aab2976e0c98ec282517edf5` 对应 V115 包，并以保存的 V114 包通过公开接口创建两张已冻结预算的在审批报销单、三张已查验发票及原件。268 张旧表除 Flyway 迁移记录外逐行摘要保持，新增三张风险表。合成 OIDC 身份源使用真实授权码、PKCE、RSA/JWKS 和 JDBC 会话，重启没有重新登录替换原授权。完整证据见[固定包运行与恢复验证](evidence/expense-risk-runtime-20261004.json)。
