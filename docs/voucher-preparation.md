# 最终批准后的自动凭证准备

更新：2026-09-28。V44 已接入真实最终审批：借款批准和报销财务批准完成时，同事务登记一条凭证准备任务。后台准备与内部重试已接通；面向用户的状态、重试及原操作查询已完成，见 [凭证工作区](voucher-workspace.md)。

## 链路与事务

`FlowableTaskFacade.APPROVE` 完成最后一个任务、保存批准状态和借款批准依据后调用 `VoucherPreparationService.approved`。普通表单、事前申请及中间审批节点不进入准备。重复请求沿用既有幂等响应，同轮不会生成第二条初始准备。

准备任务固定租户、申请／业务编号、审批轮次、审批和财务版本、申请人、请求者及财务目标。审批事务不访问 ERP；准备任务或审计写入失败时，实际任务、提交轮次和借款批准一起回滚，避免批准已结束但任务丢失。

后台领取事务重新取得申请和财务聚合锁，从实际仓储派生金额、记账日期、成本分摊、税额和冲销，再释放锁。期间与科目查询均在事务外执行；已有 [会计端口](accounting-ports.md) 拒绝未来、过期、跨法人、不完整或改变原日期的响应。外部查询期间不阻塞申请行锁。

最后短事务再次校验同一批准版本与真实来源，登记 [原凭证操作](voucher-operations.md)，并把准备改为 `READY`。准备编号与凭证编号相同；外键同时约束租户、申请、轮次与类型。凭证登记或准备审计失败都会整体回滚。准备 `READY` 只表示凭证进入队列，不能当作已过账、已付款或已归档。

## 状态与恢复规则

| 情况 | 保留结果 |
| --- | --- |
| 等待后台领取 | `QUEUED` |
| 正在查询 ERP 依据 | `RUNNING`，带固定租约 |
| 原凭证已登记 | `READY`，引用相同编号的凭证 |
| 期间关闭、缺少科目或预算未确认 | `BLOCKED`，稳定业务错误码 |
| 网络失败、目标变化、未配置或准备租约过期 | `UNAVAILABLE` |
| 原批准或财务版本变化 | `VOIDED` |
| 已批准报销全部核减为零 | `NOT_REQUIRED`，仅免于生成零金额凭证 |

纸件和预算守卫在派生费用金额前后按实际事实复核；`NOT_REQUIRED` 也不能绕过本轮纸件及预算要求。后续资源核销、预算结转和归档仍需独立完成。

ERP 未配置也允许批准事务登记任务，后台把它转为可见的 `NOT_CONFIGURED`。配置修复后，显式重试生成新的只读准备尝试，原失败输入不改写。活动准备不重复入队，已经登记任何实际凭证时禁止重新准备另一个编号；后续须处理原凭证本身。期间关闭时不把记账日自动改到下月。

准备超时不自动重复读取。迟到结果只结束为不可用，不能登记实际凭证。凭证自身的未知结果和恢复继续由原操作查询处理，不能混同准备重试。

## 配置与验证

`agentflow.vouchers.preparation-worker-enabled` 默认 `true`；关闭后保留任务。`preparation-lease-seconds` 默认 150，范围 15–300；`preparation-poll-delay-ms` 默认 1000。准备使用独立单线程调度，每批最多十项，跨进程由申请锁和领取版本协调。即使财务网关关闭，准备调度也可以记录未配置结果，且不会外发。

H2 范围 79 项、PostgreSQL 17.11 范围 55 项通过，测试范围有重叠。覆盖实际借款最终审批、补正新轮次、队列失败的完整审批回滚、实际报销核减后凭证、零金额免凭证、预算变化守卫、事务外查询、目标变化、重试历史、凭证与准备原子落库、迟到租约及 V43→V44 原数据保留。

最初的新端到端夹具把过账时间设为刚创建命令的一秒后，真实协议正确拒绝未来回执。修正合成夹具后通过，生产时间校验保持严格。Java 作者和解析检查通过：588 文件、1034 命名类型。

本地 ERP 为合成 HTTP 服务，企业接口和生产接入仍未验收。记录见 [凭证准备证据](evidence/voucher-preparation-20260928.json)。
