# 电子签操作页面

申请详情的“电子签”页提供当前轮次授权和历史操作读取。调用链为 `ApplicationRecord` → `SignaturePanel` → 现有身份绑定 API 与请求恢复队列 → [签署应用接口](electronic-signature-api.md)。页面负责选择、核对、确认和读取代次；业务权限、原件完整性、领取与状态迁移仍由服务端负责。组件只呈现公开事实，不读取签署账户、服务凭据或原始回执。

## 授权与取消

当前申请及轮次均已批准、申请版本可准确表示、当前账号有可用签署资料且原件可读时，显示授权表单。原件从冻结且已投影的附件字段和明细附件列取得，再分批复查元数据权限；普通文本、隐藏值和额外字段不能变成原件。最多同时读取四份元数据，失权的原件不显示，服务故障不会伪装成空列表。

原件和签署资料均不预选。用户填写用途和 1 至 1440 分钟首次发送期限，核对所选文件、固定资料版本、轮次和截止时间，再勾选确认发送。最多 10 份原件，单份 16 MiB、合计 32 MiB。确认后改变身份、来源版本、轮次或填写内容会使旧确认失效；过期确认不能发送。浏览器不能准确表示的申请版本禁止新授权，签署操作和资料的长整数版本始终保留字符串。

未发送操作仅在当前详情允许取消时提供单独确认，携原编号和原版本执行。已发送、未知或收集结果的操作不会显示可取消入口。表单有修改或操作执行中时，父弹窗的历史切换、普通关闭和关联导航保持锁定；用户可以明确放弃填写，执行中不能借此中断确认并误认为未发送。

## 原请求恢复与记录

创建和取消复用现有原请求恢复队列。写入最多等待 12 秒；超时、网络中断或不完整回执不能推断失败，也不能释放原恢复位置。恢复继续使用原正文和原幂等键，迟到成功不自动替代用户恢复。有效回执先校验操作编号、状态和字符串版本，之后才清除待恢复请求。

父页面恢复成功后刷新同一申请，并记住原操作位置及已知轮次。这个页面内位置只保留一项，不持久化文件正文或凭据，也不会触发第二次授权。其他未知操作存在时仍可读取记录，新授权保持禁用。

读取使用独立代次、取消信号和总时限。身份、来源或轮次变化会清除旧详情、选择及下载地址，迟到正文不能填回新上下文。权限过滤可能产生带下一游标的空页，页面保留继续加载入口；重复游标、跨页重复操作和畸形响应显示读取错误。

## 原件与签署结果

详情并排展示原件和签署结果。`COLLECTING`、`FETCHING_FILES` 只表示结果正在保存，不提供结果下载；全部文件已保存的 `SIGNED` 才出现下载入口。原件使用原附件授权接口，结果使用签署下载接口，每次服务端重新检查当前文件权限和完整性。

页面核对返回字节数，正文不完整、身份变化或旧请求迟到时不创建保存动作；对象地址在下载后或组件卸载时释放。页面状态不代替真实供应商证书、文件内部签名和时间戳验证。

## 本阶段验证边界

2026-10-04，27 个签署用例及 134 个相关回归用例共 161 项通过，包含真实编译模板、真实 API 序列化、原键恢复和父弹窗绑定。类型检查、Vite 构建以及 384 个操作、812 个结构的 OpenAPI 校验通过。首次授权用例的失败来自测试替身无法复制响应式对象；独立探针和真实序列化链路已区分该夹具错误。标题关闭按钮遗漏签署状态则已先由真实模板用例复现，再修正。

详见[页面验证证据](evidence/electronic-signature-ui-20261004.json)。自定义渲染器不等于浏览器验收；后续[固定安装包运行](electronic-signature-runtime.md)已覆盖公开 HTTP、共享原登录、强退和完整恢复；浏览器和 PostgreSQL 补验尚未完成，I02 保持 OPEN。构建仍提示既有应用包大于 500 kB，不据此宣称性能通过。
