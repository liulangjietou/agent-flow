# 独立冲销通知

F17 已接通独立冲销的准备异常、执行结果与安全结束通知，以及消息中心的原记录详情。覆盖员工借款挂账、报销挂账和付款凭证的独立冲销。人工核对外部冲销的另一条流程、业务结算和其他财务恢复来源仍待补齐，F17 保持 OPEN。

## 调用链与职责

调用方是原申请的独立财务办理入口和 `VoucherReversalExecutionWorker`。下游由 `VoucherReversalPreparationService` 保存准备状态、`VoucherReversalExecutionService` 保存原命令状态，随后仍由既有原凭证查询与业务复核处理账务结果。安全结束沿用 `VoucherReversalRetirementService` 的持久结束记录和 `VoucherReversalRetired` 事件。

准备和执行服务在原保存入口发布状态变化事件；通知服务负责接收关系、最小文案与去重。领域模型仍负责状态判断，通知不修改凭证、银行资金、预算或费用资源。站内消息和外发意向加入原业务事务，回滚时一起撤销；事务内不调用外部通知渠道。

## 原身份与事实

消息键为 `reversal:<原准备及命令 UUID>:<事实>`，每个接收人的同类事实只保存一次。授权后的命令沿用原准备编号；新准备或新命令不能替换旧消息。安全结束必须来自独立结束记录，不能从 `VOIDED` 或 `FAILED` 推断。

| 状态 | 通知语义 |
| --- | --- |
| 准备不可用、依据变化 | 尚未登记本次命令，不能称为 ERP 冲销失败 |
| 就绪、授权、发送或查询中、正常受理中 | 不制造异常或成功通知 |
| 未知、执行租约到期 | 结果暂不明确，继续按原编号查询 |
| 原依据变化、发送依据过期 | 停止尚未开始的新发送，不能推断原凭证已恢复 |
| 权威查询查无 | 系统没有自动重发，后续依既有显式办理规则处理 |
| 回执冲突 | 保留此前已接受的会计事实，进入原记录复核 |
| 已过账、明确拒绝 | 仅描述本次反向命令结果，原凭证和业务状态分别核对 |
| 安全结束 | 保留从未发送或确认过账前拒绝的依据，不表示已冲销或已退款 |

原申请人与原准备经办人构成固定参与关系。安全结束的实际经办人只加入结束通知，不能因此收到此前的准备或执行消息。通知不广播给当前所有财务角色。生成与外发时重新核验人员有效性，财务参与人还须保留原法人有效任职。

## 原记录读取与页面

`GET /api/v1/notifications/{id}/reversal-target` 仅定位当前用户自己的原消息，拒绝查询参数并返回 `Cache-Control: no-store`。服务按原编号读取准备、执行与结束记录，校验首次接受的原凭证、原业务、轮次和命令关联，再通过 `VoucherAccess.read` 检查当前原轮次财务字段权限；管理员角色不能绕过。

响应只提供状态、原编号、日期、稳定原因与已接受凭证号，不包含反向分录、账户、理由材料、连接目标或办理动作。旧冲销结束后仍可读取原执行与结束记录，即使另一冲销已绑定同一原凭证。页面将“本次冲销记录”和“原凭证当前绑定”分别展示。

消息中心点击“查看原冲销”才读取详情。只提供重新读取、查看原申请轮次与收起；不提供发送、重发、授权或结束按钮。重新读取立即清除旧内容，身份切换、超时、失权和卸载使迟到响应失效。响应解析拒绝身份替换、错误状态、附加动作及非对象的可空嵌套记录。

## 验证与边界

145 项不同 Java 用例、115 项前端用例通过，类型检查与构建通过；OpenAPI 校验覆盖 347 个操作、695 个 schema、125 个请求示例。

证据见 [本地代码与组件验证](evidence/reversal-notifications-20261003.json)。验证覆盖原消息去重、准备与执行分离、租约未知、查无、冲突、过账、独立结束、后续新尝试、参与人与任职、当前字段权限、业务事务回滚和外发前原轮次复核。借款挂账及付款凭证使用实际借款业务夹具验证。

本阶段使用 H2、受控财务回环、Spring MockMvc 和实际 Vue 组件的宿主渲染测试。类型、构建和 OpenAPI 契约另行校验。固定安装包、非空运行升级、重启恢复、真实浏览器及 PostgreSQL 新范围验收仍待完成；既有浏览器管理策略和数据库镜像 I/O 阻碍保持原状。
