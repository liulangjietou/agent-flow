# 集成投递概况

管理员在“集成投递”查询后，可查看完整范围内的全部投递、待投递、投递中、等待重试、已送达和停止投递数量。点击状态卡片直接筛选下方明细。数字来自服务端聚合，不以页面当前加载的 30 条估算总量。

## 统计口径

- 范围由已查询的目的地标识和申请标识确定，始终覆盖当前认证租户；状态筛选和翻页不改变概况范围。
- 每个事件投向一个目的地计一条。同一事件投向两个目的地是两条；自动尝试和人工重新排队不会增加投递条数。
- 统计每条投递的当前状态。失败后重新排队会从“停止投递”转入“待投递”，不表达历史失败次数或累计失败率。
- 历史目的地即使已停用、移除或没有当前配置，原投递仍参与统计。是否可人工重试继续由原目的地和版本守卫决定。
- “已送达”只表示接收服务返回 HTTP 2xx，不能作为外部预算、付款、入账等业务已成功的证据。“停止投递”也不证明外部服务从未收到事件。
- 空范围显示零；加载或读取失败不显示旧数字或把未知结果显示为零。

查询时间标记为聚合读取开始时间，明细和概况独立读取，不共享数据库快照。后台投递过程中两者可能短暂不同，重新查询取得最新状态。页面不自动轮询；人工重试成功后重新读取概况、明细列表和所选记录。

编辑未提交的筛选时，页面提示仍为上次结果，状态卡片暂时不可点击。非法申请标识清空结果；账号切换、离开页面、读取失败和超时都会丢弃旧概况，迟到响应无法恢复其他账号的数据。

## API 与职责

`GET /api/v1/integrations/webhooks/overview`，仅当前租户 `ADMIN`。

只接受 `target` 和 `applicationId`，与投递检索同义；拒绝 `status`、`limit`、`cursor`、租户覆盖或其他未知参数，返回 `400 INVALID_WEBHOOK_QUERY`。未认证为 401，普通用户和仅有 `PROCESS_ADMIN` 的用户为 403。成功响应 `Cache-Control: no-store`。

```json
{
  "queriedAt": "2026-09-24T00:00:00Z",
  "total": 40,
  "pending": 20,
  "inFlight": 3,
  "retryWait": 5,
  "delivered": 7,
  "failed": 5
}
```

调用链为 `WebhookDeliveries.vue → WebhookController → JdbcWebhookStore.overview`。Controller 负责入口授权与条件白名单；基础设施用一次 SQL 聚合读取投递事实，不读请求体、尝试正文或签名配置，不联查当前目的地目录。当前状态仍由 `DeliveryProgress` 领域行为推进，本次不引入第二份状态存储、不新增迁移，也不改变投递重试或人工重试权限。

概况仅涵盖已有 Webhook 投递。邮件、企业 IM、SLA 告警、外部业务回调对账及生产容量验收继续属于未完成范围。
