# 供应商付款通知

F17 的供应商付款阶段已接通登记前检查、银行结果和争议处置的最小通知、当前权限详情及消息页面。本阶段完成范围验证，F17 仍为 OPEN：其他财务异常来源和完整安装包、恢复及环境验收尚未完成。

## 原记录与职责

调用链为 `SupplierPaymentExecutionService / SupplierPaymentService / SupplierPaymentDisputeService → 已保存状态事件 → SupplierPaymentNotificationService → JdbcInboxRepository`。付款状态由原领域模型决定，服务在原事务保存后发布事件；通知层决定最小文案、原接收人及去重身份。站内消息和外发意向与原状态同事务提交，事务内不调用外部通知渠道。

供应商付款允许一次登记检查停止后，在同一授权下重新选择账户。通知事件键因此固定为 `supplier-payment:<原授权 UUID>:<原出纳请求 UUID>:<事实类型>`。读取时同时核对两个规范 UUID、消息种类、原申请和轮次。银行事件使用实际登记该命令的唯一请求，不使用工作区的“当前占用或最近请求”查询。

同一次选择在登记前检查与银行发送前检查出现相同事实时，每个接收人只收到一次通知。不同选择分别保留；同一交易的不同事实也分别保留，例如成功后发生资金退回。正常排队、复核、银行处理中和主动查询不生成异常消息；查询失败、结果未知和回执冲突不能写成银行失败或成功。

## 接收与读取

- 接收人仅为原采购申请人、原财务授权人和该原请求的出纳。原供应商名称和银行账户不是组织身份，不作为外发地址。
- 原参与人必须仍在可信组织目录中有效；财务和出纳还须保留原法人的当前有效任职。最小消息不复制金额、采购正文、账户、指令摘要或银行回单。
- 本人偏好、收件绑定及同意代次沿用既有通知链路。外发领取与重试再次检查原参与关系和当前任职；原出纳失去法人范围时，意向被抑制，未开始外发。
- `GET /api/v1/notifications/{id}/supplier-payment-target` 只允许原消息接收人读取，不接受查询参数，响应为 `Cache-Control: no-store`。
- 申请人和原财务通过原采购轮次字段权限；财务还需当前 `FINANCE` 角色与法人任职。原出纳通过显式 `CASHIER` 角色与法人范围。管理员没有敏感字段读取旁路。
- 消息详情复用最小供应商资金投影，资金动作许可全部为 `false`。投影工厂仅负责字段组装；通知与出纳入口分别先执行自己的权限和来源核验。

已停止的原请求即使后来出现另一笔登记，也仍显示原请求及“尚未登记银行指令”，不会混入后来那次银行结果。只有原请求仍占用原授权时，原出纳才获得跳转原付款工作区的入口；详情及办理接口仍重新检查权限。申请人和财务进入原申请轮次。

## 页面行为

消息中心把员工和供应商付款交给同一个受控详情组件，各自调用独立只读接口。供应商事实展示组件复用于出纳工作区与消息详情，银行成功和应付结算分别说明。只有明确点击才读取或导航；读取不付款、不标记已读。

身份切换、失权、超时和失败清空旧详情并取消请求，迟到响应不能恢复旧资金记录。原供应商授权即使不在目录第一页，也可通过受控消息入口定位。已停止的旧选择没有跳转到后来请求的按钮。

## 验证范围

证据见 [供应商付款通知阶段](evidence/supplier-payment-notifications-20261003.json)。

- 314 项不同的 Java 用例通过：领域 31、真实采购财务流程 61、相关持久化 123、员工付款回归 62、通知回归 30、接口契约 7。
- 71 项前端用例通过，执行实际 Vue 脚本和模板、页面导航及出纳目录；覆盖原请求绑定、停止选择、银行成功与结算区分、当前权限失效、迟到响应和只读调用。
- 类型检查、Web 构建、344 个 OpenAPI 操作及 689 个 schema 检查通过；构建仍有既有包体积提示。Java 注释检查覆盖 1,532 个文件、2,942 个命名类型，无缺失或解析错误。
- 首个失败用例证明“银行已成功但原三名参与人无消息”。关联回归中，新写的 `PENDING` 测试回执遗漏协议必需的交易号，网关正确判为无效响应；仅修正夹具并加强已接受 `PENDING` 的断言，没有放宽生产校验。

最终 Java 计数采用通过的测试用例身份去重；失败夹具及较早重复执行不叠加。此阶段使用 H2、合成财务网关和 Spring MockMvc；页面验证不是实际浏览器验收。没有新增迁移，也没有推送或创建 PR。固定安装包、非空升级、重启与恢复、浏览器及 PostgreSQL 新范围仍需接续验证；真实企业渠道和资金系统另属外部验收任务。
