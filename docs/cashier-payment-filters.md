# 出纳付款目录筛选

F16 的法人和已固定出款账户筛选接入现有员工借款／费用报销出纳目录。按用户对后续推荐的既有授权，付款到期日由财务在每次付款授权时明确填写并固定，历史未设置单列；该字段仍未实施，本任务保持 OPEN。

## 事实与职责

调用链为 `CashierWorkspace` → `CashierPaymentController` → `CashierPaymentWorkspace` → 付款授权仓储。工作区入口解析有限查询参数，仓储在分页前应用当前法人任职与筛选条件；列表、总数和游标核对复用同一参数化查询范围。出纳权限继续要求明确 CASHIER 角色及当前有效人员、法人、部门、岗位和任职。

法人来自原授权的冻结收款人事实。账户来自账户复查通过后固定进原付款命令的 `Execution.debitAccount`，没有固定命令时归入“未固定出款账户”，包括正在复查或复查失败的选择。查询不会调用资金目录，也不会推测尚未选择的账户。

V114 增加 `debit_account_key` 派生索引。账户身份按租户、固定资金目标、法人、币种和原账户引用的长度编码计算摘要；不以名称、掩码或资料版本区分同一账户。这样，相同引用在不同目标、法人或币种下仍是不同筛选项。页面只取得内部筛选键和历史脱敏展示，不得到原始引用或资金目标。

新执行登记与索引更新在同一事务完成；严格读取将索引与原命令交叉核对。历史迁移读取固定 JSON 格式，不依赖以后变化的领域构造器，不修改授权、命令、修订、期限或执行状态；损坏或不一致的旧事实不补造账户归属。

## 查询契约

`GET /api/v1/cashier/payments` 保留 `limit`、`beforeId`，增加：

| 参数 | 含义 |
| --- | --- |
| `legalEntityId` | 规范 UUID，与当前任职法人取交集；无权法人返回空结果。 |
| `debitAccount` | 省略表示全部；`UNASSIGNED` 表示未固定出款账户；否则为选项接口返回的 64 位小写筛选键。 |

结果包含 `items`、`nextBeforeId` 和同条件的 `totalCount`。总数不包含游标限制；翻页不会将“余下数量”误当成全部数量。旧游标不属于当前筛选时拒绝请求；角色、租户或任职变化也重新检查。

每个出纳条目增加可空的 `debitAccount`，包含筛选键、法人、币种、历史名称和脱敏账号。它不会出现在申请人和财务共用的 `PaymentView` 中，也不扩展出纳的完整申请读取权。

`GET /api/v1/cashier/payments/filter-options` 接受 `limit`、`legalEntityId` 和 `afterAccountKey`。响应分别提供当前任职法人、已固定账户选项和 `nextAfterAccountKey`。同一账户的不同资料版本合并为一项，展示最近授权对应的脱敏记录。账户选项独立分页，不截断后宣称完整目录；无权范围和失效游标不能用于探测其他法人的账户。

两个接口的 `limit` 默认 25、最大 100；未知参数、非规范标识及无效分页边界直接拒绝。所有响应禁止缓存。筛选不修改授权有效期，不授予付款权限；批次和单笔执行仍按原规则重新检查批准、金额、收款人、出纳分离和账户证据。

## 当前验证状态

法人和账户筛选已贯通后端、实际 Vue 模板与公开 OpenAPI。后端范围验证通过 85 条唯一用例（含 7 条新增），前端范围验证通过 80 条（含 10 条新增），类型检查、Vite 构建和 OpenAPI 校验通过；构建仍提示产物超过 500 kB 警告阈值。前端测试使用自定义渲染器，不是浏览器验收。

固定包的 H2 实际财务链路已验证：三个法人中的 7 笔借款／报销付款授权由公开业务入口产生，V113 → V114 升级保留 267 张既有表的 810 行原字段数据；升级前已有 5 个固定付款命令。筛选与总数、账户版本合并、任职撤销、跨范围游标和管理员无隐式出纳权限均通过。付款网关已接受命令后强退应用，重启沿原交易查询恢复，命令发送次数保持 1，原账户键和幂等响应不变。

独立恢复逐表核对 268 张表、969 行数据及 2101 条完整结构语句；恢复后旧授权继续完成付款，原数据库数据保持不变。5 次应用启动共记录 324 次业务 HTTP 响应、102 次合成财务服务调用；324 个响应和 97 个请求通过各自打包版本的 OpenAPI 校验，35 次读取通过实际前端解析器。

另一个独立恢复实例将实际 Vue 筛选模板及 API 模块连接后端，通过 8 项交互检查、19 次 HTTP 读取（17 次成功、2 次角色拒绝）。该检查使用自定义渲染器并替代了付款详情子组件，仅证明筛选交互与 API 联动。所有 6 个成功运行实例均已停止。

付款到期日推荐规则已获既有授权；该字段的实现与验收尚未完成，因此 F16 保持 OPEN。既有浏览器及 PostgreSQL 限制保持，不能用 H2 或组件测试替代其验收。
