# 快速流程设计器

流程管理默认打开“快速步骤”：从上到下安排审批，在“＋”处插入审批或条件块，在分支卡片中配置判断条件。可随时切换“高级画布”。两种视图使用同一个流程定义、同一组节点与连线，保存、自动保存、撤销、模拟、版本比较和发布沿用已有链路。

## 操作与边界

- 审批步骤支持名称、指定账号或角色、单人审批/全员会签；可交换相邻审批、删除步骤并接续前后流程。
- 条件块支持嵌套、增加/删除分支、调整条件判断顺序和默认分支。按列表顺序先满足先走，“其他情况”在全部条件不满足时进入。
- 删除分支前显示包含的步骤数量；删除整个条件块会移除其中的分支步骤，接回共同后续。共同后续只显示一次，不能作为某一分支的私有步骤被误删。所有结构编辑都可撤销。
- 没有共同汇合点、各分支分别结束的流程也可展示与编辑。包含断线、回环、交叉共享或不支持节点的图显示原因并提供高级画布入口，保留完整原图。
- 新插入节点需要补齐审批人与条件；界面不会自动选择审批人或生成业务阈值。校验和发布由原服务端负责。
- 保留存量节点标识、属性及高级画布位置；新节点可在高级画布使用“自动布局”重新安排。切换模式本身不保存、不改规则、不改变已有申请的版本。
- 已发布版本和无管理权限的账号只能查看。新版本需先复制为草稿。

条件可以按表单字段选择判断方式与取值；旧版使用单组配置，v2 支持[可视化嵌套条件组](visual-condition-groups.md)，每组选“全部满足”或“任一满足”，可以对子组和判断取反。数字保持十进制字符串，不经 JavaScript 浮点数。文本值始终使用完整引用，因此 `O'Reilly AND OR` 不会拆成多个判断。服务端不支持的脚本、分号、模板表达式及不能安全引用的输入会提示并保留原条件。

v2 混合 AND/OR 按优先级显示为嵌套组；未知字段或无法完整识别的表达式保留原文，继续使用表达式模式。只有显式编辑才会序列化，切换查看不会改写原文。没有表单字段时仍使用表达式。编辑视图保留输入中的空格，提交阶段才执行既有规范化。

## 职责与调用链

调用方 `App.vue` → `QuickDesigner` / `QuickSequence`；字段编辑共用 `ConditionEditor`。`quickDesigner.ts` 只负责图的结构投影与不可变编辑，依据最近共同后继确定分支归属；`conditionBuilder.ts` 与 `conditionGroups.ts` 只转换可安全表达的字段条件和分组。

父组件持有唯一的设计、权限/请求锁和撤销历史。结构命令先在副本执行，成功后作为一次变更进入已有保存链路；条件编辑直接更新这份设计，不保留一份待“应用”的隐形规则。下游继续调用定义的保存、校验、模拟和发布接口，领域校验及 Flowable 运行方式没有改变。没有后端代码、API、迁移、审批权限或 Agent 行为变更。
