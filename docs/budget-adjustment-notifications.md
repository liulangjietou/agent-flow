# 预算调整业务通知

F17 的预算调整台账复核、原指令结果、安全结束与本人原消息详情已接通。本阶段完成本地实现及范围验证，F17 整体仍为 OPEN。完整记录见[阶段证据](evidence/budget-adjustment-notifications-20261003.json)。

## 调用链与职责

财务控制器和 `BudgetAdjustmentFinanceActions` 提供明确动作，两个后台工作器分别读取台账和执行原指令。预算领域保留原批准、台账复核、具名授权、回执、冲突及安全结束的约束；应用服务在持久化后发布 `BudgetAdjustmentReviewChanged` 或 `BudgetAdjustmentOperationChanged`。

通知、外发意向与原财务事务一起提交或回滚。安全结束原队列先停止发送，再保存实际结束决定，最后发布结束事件，避免同一决定产生两条含义不同的停止提醒。普通后台因来源变化停止发送，仍有自身通知。

台账读取不可用、条件不满足和来源停止分别通知；正常读取和可供授权的证据保持安静。执行通知区分未知、查无、拒绝、生效、冲突、到期、停止和安全结束。外部受理中以及财务主动发起原号查询不额外制造异常提醒，查询动作本身不能宣称预算已生效。

## 原事实与当前权限

去重键是 `budget-adjustment:<REVIEW 或 OPERATION>:<原编号>:<事实种类>`。同一来源的同类事实只通知一次；新的复核或新授权使用独立编号。

`GET /api/v1/notifications/{id}/budget-adjustment-target` 只接受本人原消息。访问服务从持久批准修订验证原申请、原轮次和原法人身份。操作消息的事实及发生时刻必须存在于同一指令的持久历史；读取失败消息不会挂到后一次成功复核，新的预算指令也不会替换旧消息来源。历史“未知”消息可以展示同一原指令后来取得的明确结果，同时保留消息发生时的事实。

接收人来自原申请人、本次实际财务；安全结束还包含实际作出决定的财务。创建及外发领取重新核验当前人员与原法人任职，详情进一步沿用原轮次字段权限，管理员角色不能绕过敏感字段。响应使用 `no-store`，额外查询参数被拒绝。

详情仅含来源编号、状态、版本、时间、稳定异常分类、原观察、冲突观察及真实安全结束依据。额度、台账、外部引用、命令摘要和办理许可不进入消息。读取不访问外部财务系统，不执行指令，也不标记消息已读。

## 页面与验证

消息中心增加“查看预算调整”。页面分别展示消息当时事实和当前原记录，保留原观察与冲突观察，只提供重新读取和原轮次导航。身份变化、失权、超时和卸载清除旧内容并拒绝迟到响应；未确认写入阻止改变导航。

113 项 Java 用例通过（领域 28、服务端 85），其中新增 9 项通知集成用例和 3 项领域用例。真实认证、Flowable、数据库及明确标识的回环合成财务服务共同验证原号恢复、权限、历史证明、重复事件、幂等回放、通知失败回滚和失权投递拦截。

20 个前端文件的 220 项用例通过，其中新增通知用例 10 项；类型检查、生产构建、357 个操作 / 730 个 schema / 125 份请求样例的 OpenAPI 校验及作者检查通过。新组件最初有旧标签名称残留，类型检查发现后已修正，原始诊断保留。构建保留已有的大体积资源块提示。
