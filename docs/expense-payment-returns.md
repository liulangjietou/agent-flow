# 报销原付款退回

V64 为已经有成功付款的报销提供累计银行退回查询与独立财务登记。原付款、已核销发票、事前额度、借款冲销、预算消费及既有归档继续保存；实际退回形成独立账本，并让本报销保持待处理。后续资源调整、重新付款需要单独业务流程。

## 调用链与职责

页面从费用明细的结算区进入，调用 `ExpensePaymentReturnController`。`ExpensePaymentReturnService` 负责当前财务权限、同一报销锁、查询租约、独立确认及原子持久化；`ExpensePaymentReturns` 保存累计资金事实及版本，保证已登记原件和首次登记归属不可改写。`ExpensePaymentReturnSources` 从原结算、首次成功付款修订和原挂账科目映射派生请求，当前账户、科目映射变化不能替换历史来源。

后台先保存请求和租约，事务外调用 `ExpensePaymentReturnPort`，再在短事务接受结果。原付款状态对账、凭证争议裁决、结算恢复和新归档都受独立退回冻结约束。查询入口不发出付款、退款、冲销或预算命令。

## 事实及业务规则

- 只接受 `EXPENSE_REIMBURSEMENT` 正额原成功付款；全额借款抵扣等零应付结算没有银行退回入口。
- 每笔退回同时包含公司银行实际入款和 ERP 已过账员工应付贷方分录。分录科目必须等于原挂账快照的员工应付科目，金额与币种必须和入款相等。
- 部分退回要求原交易仍成功；全额退回要求原交易修订增加、状态为撤销，并有等于原付款的全部独立入款。银行状态本身不能替代入款。
- 新累计依据必须保留此前所有财务已查询到的入款和分录，包括尚未登记的依据。低版本、同版本矛盾、遗漏旧原件、超额、重复流水或分录均不能登记。
- 原件有效窗口最多五分钟，一次最多一百笔。客户端不能填写付款金额、银行账户、科目或来源摘要。
- 查询不明或出现新增、不一致原件时先冻结。只有明确查明原付款仍有效且从未实际退回时，财务确认才可解除本模块冻结；完整原批准、付款、凭证和预算守卫继续检查。
- 已发生实际退回后，登记不会解除待处理状态。原发票不会自动开放，预算不会自动释放，借款抵扣不会自动返还。

## 权限和并发

读取沿用原审批轮次的完整费用字段权限。管理员没有敏感字段豁免。操作要求当前法人范围内有效财务任职，申请人和原付款出纳不能办理；幂等回放前也重新授权。候选原件仅展示给查询人，已登记的历史按原轮次权限读取。

结算版本、独立账本版本、查询编号及版本一起参与乐观校验，报销锁串行化登记。查询租约为九十秒，过期执行者不能覆盖新状态。一次查询只能消费一次；决定、查询消费、账本修订、结算冻结、入款防重和审计同事务提交，任何一笔冲突都会整体回滚。未确认的网页写入沿用原请求正文及幂等键恢复。

`finance_receipt_credit` 统一限制法人内资金流水和 ERP 贷方分录，覆盖员工主动还款、原借款放款退票及报销退回。V64 从旧 `advance_receipt_credit` 回填，原业务表及旧外键保留；每行恰有一个业务来源。

## 接口

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/expense-reports/{id}/payment-return?roundNo=1` | 读取原付款、已登记累计退回、自己的候选和登记历史；不发起外部查询 |
| `POST /api/v1/expense-reports/{id}/payment-return/checks` | 保存只读查询，输入结算版本、退回版本及说明 |
| `POST /api/v1/expense-reports/{id}/payment-return/registrations` | 核对后登记已展示的结果、查询版本、材料编号及说明 |

两个写入口需要 `Idempotency-Key`，返回 202 表示请求已接受；响应均 `no-store`。完整字段和错误契约以 `agentflow-server/src/main/resources/api/openapi.json` 为准。

财务网关固定操作名为 `expense-payment-return`，按原授权目标发送标准租户、请求编号和版本信封；此读取请求不带外部写入幂等键。`Request` 包含原命令、首次成功观察和原员工应付科目；`Receipt` 包含 `UNRESOLVED / CONFIRMED / PARTIALLY_RETURNED / RETURNED`、累计修订、观察和截止时间、当前原交易观察以及累计 `returns`。每笔原件由 `funding` 与 `posting` 组成，银行流水与 ERP 凭证/分录分别追溯。

## 本地验证

领域、网关、H2、PostgreSQL、公开接口及 Vue 组件已有范围回归。验证覆盖累计和全额退回、同源和全局防重、事务回滚、并发登记、租约过期、权限撤销、幂等回放、原件新鲜度、原归档和资源保持、未知网页写入恢复，以及结算与归档面板刷新。不同测试范围有重叠，不相加为独立用例数。

本地验收通过实际应用 HTTP、PostgreSQL 旧库升级及浏览器页面连接合成银行和 ERP 服务。具体计数与可复核结果见 [验收证据](evidence/expense-payment-returns-20260929.json)。企业银行、ERP 联调及生产验收仍需真实配置与目标环境。
