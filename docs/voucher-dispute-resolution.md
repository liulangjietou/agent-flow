# 原凭证争议裁决

更新：2026-09-29。本阶段在隔离工作树完成本地实现及验收，数据库新增 V55。ERP 为回环合成服务，企业 ERP 联调仍单独验收。

## 业务边界

财务只能明确采用原凭证操作最近一次已持久化的终态：`POSTED`、`FAILED` 或 `REVERSED`。普通查询继续保留冲突，不能自动解除争议。候选必须满足以下条件：

- 原轮次完整财务字段可读，操作者当前具有财务角色及原法人有效任职；申请人不能裁决，付款凭证的原出纳也不能裁决。
- 候选查询未超过五分钟，外部版本等于已见最高版本，观察时间不能早于已接受事实。
- 原过账操作号保持。曾接受过账或冲销时，凭证号、期间、日期、借贷总额和过账时间必须保持。
- 历史任何修订曾出现过账或冲销，包括后来被覆盖的冲突候选，不能再采用失败结论删除该事实。
- 请求绑定展示的申请、财务和凭证三个版本，只能选择已展示终态及填写人工核对编号、说明。不能提交新凭证号、金额、账户、期间或分录。

V55 的独立裁决记录关联同租户、同操作、连续的争议前后修订；一个争议版本只能裁决一次。原命令、目标、历史观察及裁决保留。本阶段不发送新的付款或凭证，也不改变原发送编号。

## 调用链与职责

`VoucherStatus` 展示旧事实、当前对账候选和上次裁决。财务确认调用 `POST /api/v1/applications/{id}/vouchers/{operationId}/dispute-resolutions`，三类凭证共用这一入口，原挂账与付款凭证页面继续分别读取。

`VoucherDisputeService` 负责实时字段权限、组织任职、职责分离和业务锁。`VoucherOperation` 决定候选能否成为本操作的终态；`VoucherDisputeResolution` 约束裁决凭据与连续修订。仓储在一个事务内追加操作修订、裁决、下游状态和审计，任一步失败全部回滚。幂等回放之前再次检查权限，撤销任职后不能重放过去的敏感结果。

付款与挂账争议出现第二个真实恢复场景后，由 `ExpenseFinancialDisputeRecovery` 统一复核同一报销的全部原始来源。它只读取原预算操作：未消费时恢复待核销，已消费时接续预算实际状态。已有发票、事前额度和借款消费不会重做，已生成档案和原件不会改写。付款仍处争议或其他批准、会计依据不成立时继续冻结。付款凭证裁决只恢复适用归档条件，不重新结算或付款。真实冲销继续等待独立调整。

借款挂账裁决不修改真实到账余额或已确认还款。验收使用原来已还清的 300 元借款，裁决前后仍有 100 元现金和 200 元银行还款，已还 300 元、未还 0 元；借款台账、原付款状态、两笔还款和所有凭证输入的数据库摘要完全相同。

## 页面与失败恢复

候选和原已接受凭证分开显示，确认表单只允许填写核对编号与说明。证据过期需要重新查询 ERP；双击确认只有一个意图，网络结果未知进入全局原请求恢复。切换身份、轮次或版本清空旧页面，迟到响应不回填。

本阶段先用最小测试复现“确认时权限被撤销，页面仍保留旧敏感状态”，再修正为收到 403/404 后立即清空凭证、确认表单和材料。此前测试只覆盖读取及身份切换，未覆盖写入时撤权；新增用例稳定呈现失败并在修复后通过。
