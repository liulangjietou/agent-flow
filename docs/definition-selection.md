# 按需选择流程版本

发起申请、首次使用引导、版本比较、待办和审批运营使用可搜索的流程选择器。每次先加载 30 条摘要，可继续加载；名称或标识、准确流程标识和发布版本可以组合查询。修改条件后需重新查询，追加页面沿用已经提交的筛选。

Web 不再调用旧的 `GET /api/v1/process-definitions` 全量接口，也不在 App 中保存所有定义的流程图和表单。服务端保留该接口供已有客户端兼容；本次没有改变接口权限、审批状态或数据库结构。

## 各入口如何读取

| 场景 | 数据读取与行为 |
|---|---|
| 恢复设计器 | 优先读取记住的单个定义；偏好返回 404 才读取一条摘要并选择初始配置。网络、权限或服务器错误不会静默换版本 |
| 发起申请 | 选择器仅提供已发布摘要，选中后读取一份完整配置；初始选择最多读取一条摘要。引导指定的 ID 失效时明确失败，不换成其他版本 |
| 首次使用引导 | 摘要选择器只传 ID，进度继续由原引导接口按该 ID 核对；仍可自动选择最近更新的流程 |
| 版本比较 | 显式选择同一准确流程标识的发布基线，按需读取其图和表单供差异文案使用；不会再从全量列表自动选择最高版本 |
| 待办和运营筛选 | 选择任一发布版本后填入流程标识，仍查询该流程所有版本；运营页面可继续填写准确版本。也保留手工输入标识 |
| 模板文件导入 | 按目标标识进行有界摘要检查；同名提示不依赖某页缓存。修改标识即清除旧提示，失败明确显示无法核对 |

`DefinitionPicker` 复用目录查询状态，`DefinitionSelection` 管理单个完整配置的读取。职责属于前端应用编排，不把分页或界面选择写进领域聚合。

## 版本与恢复保护

切换账号、选择或关闭页面会取消旧读取；迟到成功和失败不能覆盖当前配置。读取有 12 秒超时。申请配置未取得时不显示业务表单或提交按钮，避免把读取失败误当作旧版无 schema 表单。

恢复创建结果时，界面显示原申请的流程标识和版本，表单来自申请保存的快照；恢复不会自动提交。之后点击“重试提交草稿”只提交原申请，不依赖新读取的定义，也不更换版本。
