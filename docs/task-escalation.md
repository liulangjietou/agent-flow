# 审批超时升级提醒

2026-10-01 已完成本地后台、设计器、模板往返、实际计时与两次重启验收。升级是协调通知，不会自动批准、驳回、转交或增加表单与附件权限。邮件和企业 IM 的接通及实际递送仍按各渠道单独验收。

## 调用链与职责

- 调用方：快速步骤和高级画布在人工节点上明确配置升级规则；原生任务创建事件绑定规则；后台调度扫描到期任务；管理员从根申请暂停、恢复或终止。
- 下游：已发布定义和本轮发起任职 → 原工作日历修订及组织目录 → 任务本地时间与名单快照 → 站内通知和现有外发意向。查询与打开申请继续经过原权限服务。
- 受影响场景：普通审批、会签及并行任务、父子流程、组织停用、转交与委派、暂停恢复、撤回及终止、旧版本和多实例并发调度。
- 领域规则放在 `TaskEscalationPolicy`；日历计算沿用 `BusinessDeadline`。目录解析、事务与父子锁属于应用编排。Flowable 适配层保存原任务的到期和投递事实，调度器只负责有界扫描，不拥有审批结论。

## 明确配置与原任务事实

人工节点必须已有完整审批期限，然后同时提供以下属性；旧节点缺少这两项时保持不升级。

| 属性 | 约束 |
| --- | --- |
| `escalationWorkingMinutes` | 从原审批期限开始追加的工作分钟，规范正整数，1–527040 |
| `escalationRecipientRule` | 当前租户有效的字面量人员、组织或任职主管规则；实际名单为 1–100 人 |

设计器不预填等待时长或收件人。发布重新核对目录；收件人缺失返回 `ESCALATION_RECIPIENT_UNAVAILABLE`。模板完整保留原值；目标租户缺少收件对象时可导入待修正草稿，但不能发布。快速步骤、高级画布、撤销、保存与发布使用同一份节点配置。

每张实际任务创建时，从该任务绑定的发布版本读取升级规则，固定工作日历、到期时间、目录修订与实际名单。动态主管使用原审批轮次选择的任职；根流程预检同时检查固定版本后代的任职要求。名单解析失败回滚本次任务创建。

到期时只检查原名单中账号当前是否有效，不按新组织关系替换人员。原名单全部无效时暂不发送，后续扫描可以复核；部分仍有效时向有效人员发送一次，此后重新启用的人员不会补发。转交、委派和回交沿用原任务期限与名单；多张并行或会签任务各自计算。

## 暂停、并发与权限

暂停分别保留审批期限和未升级任务的升级期限。恢复按原日历接续各自剩余工作时间：审批已经超时，并不表示额外升级等待也已经耗尽。已超时的审批期限保持原事实，不能据此重新计算完整升级宽限期。已经发出的升级不重置、不补发。

根申请与原任务按统一顺序加锁，锁后重新检查本轮、任务和父子运行状态。暂停、结束、撤回或终止后，先前扫描到的任务也不能继续发送。通知、实际通知名单与完成标记同事务保存，任何写入失败全部回滚；事件按原任务固定，多实例竞争只有一次效果。

升级收件人收到申请名称、编号、节点和固定协调文案；不收到表单正文、评论或附件。通知不建立抄送关系，也不改变审批人、申请版本或读取权限。消息中心展示“审批超时升级提醒”，使用普通申请入口；无原权限时仍不可读取申请，不能将提醒作为新的待办。

## 运行与兼容

升级调度沿用 `agentflow.sla.reminders-enabled` 和 `agentflow.sla.reminder-delay-ms`，默认每 30 秒扫描，每页最多 100 张任务，具有独立游标。单笔失败或原名单暂不可投递不会阻塞下一页；扫描失败保留游标，扫到末尾后重新复核旧候选。

本增量没有新迁移，仍为 V93。时间、名单和完成事实使用 Flowable 持久任务变量；新发布规则不补到旧版本申请或旧任务，重启不重新计算期限。

完整证据见 [SLA 运行证据](evidence/task-escalation-runtime-20261001.json)。领域 26 项、H2 服务端范围去重 47 项、PostgreSQL 命令 22 项（21 项集成和 1 项调度）、前端范围去重 50 项通过；跨数据库和阶段测试有重叠，不相加。类型检查、构建、290 个操作的 OpenAPI 校验与实际 HTTP 响应验证通过。

先复现原校验忽略升级属性，以及暂停后升级时间未接续，再实现规则与独立期限。测试覆盖固定日历与名单、并发一次、事务回滚、原收件人停用、父子暂停和终止、旧版本隔离及有界调度。模板下载和重新导入、两种设计视图、撤销、发布只读及实际 500 CSS 像素通过。

运行使用原邮件验收库的独立副本：225 张表、1,365 行和 3 份文件。第一次重启完整保持当时 1,764 行；第二次重启发生在恢复后的升级等待中，按保存的原到期时刻仅发送一次。原版本和撤回申请没有升级，暂停期间不升级；并行两张任务分别产生一条通知。全部源业务行与文件保留，只有引擎内部标识预分配值正常前移；原服务和源库未改动。实际运行未修改数据库时钟或手动伪造到期时间。

本次验证站内升级和现有外发意向；验收服务关闭外发工作器，没有据此宣称真实 SMTP、企业 IM 或最终递送完成。
