# 科目映射版本管理

更新：2026-10-03。对应原费用设计 §10.1、§12.6 和任务 F02。已完成领域模型、会计网关契约、V104 管理存储与 9 个认证接口。准备任务绑定、管理页面及完整运行验收仍待完成，F02 保持未完成。

## 调用链与职责

调用方是 `VoucherPreparationWorker`：借款或费用最终批准、员工付款成功后，准备服务登记只读任务，工作器查询开放期间和科目映射，再由 `VoucherPreparationService.finish` 原子登记 `VoucherOperation`。外部查询在数据库事务外执行。

下游是 `GatewayAccounting` 和固定租户的 ERP 服务。ERP 仍负责科目是否有效、会计期间以及真实过账事实。平台管理配置指定应使用的科目和版本，不能仅凭管理员输入就宣称 ERP 已认可该科目。

受影响的业务包括员工借款挂账、费用挂账与员工付款凭证。费用核减、撤销和付款退回已从原凭证读取原科目，继续保留这一行为；重新发布不能重算历史分录。采购供应商结算的专用协议不改用此配置。

领域层维护草稿修订、发布版本、固定法人和币种、必要科目及不可变选择；应用服务负责当前操作者、仓储事务、类别版本和生效指针；网关在发送前核对固定租户与目标，并校验 ERP 回执。无需变更既有凭证用途或引入另一套结算流程。

## 已实现的领域与协议边界

- 一个配置业务键固定法人及币种。草稿修订可修改科目，不能把原键迁移给另一法人或币种。
- 发布物保留草稿修订、类别修订、ERP 目标摘要、发布人、时间、理由与完整正文。后续编辑和发布生成新对象，旧对象不可变。
- `EXPENSE` 按费用类别选择；`BANK` 按已授权出款账户引用选择；员工应收、员工应付及进项税保持现有用途。成本中心、项目和员工辅助核算仍来自原业务分录。
- 草稿允许暂时没有条目；发布必须有条目且不能包含未知或停用费用类别。非费用用途可在尚未建立费用类别时发布。
- 每次请求只携带实际所需的科目子集及完整配置摘要。缺少任一必要键即 `ACCOUNT_MAPPING_UNAVAILABLE`，没有默认科目或跨版本补齐。
- 管理映射写入 `AccountMappingPort.Request.managedMapping`。ERP 必须返回相同请求、相同配置身份、完全相同的科目代码和自己的来源版本、观察时刻与有效期。忽略管理配置、篡改代码或回显另一版本均不可用。
- 管理配置中的租户及发布目标须与本次调用一致，凭证的持久目标也必须相同。不一致返回 `TARGET_CHANGED`，不向外发送配置或凭证。
- 新凭证摘要在原字节序列末尾追加管理映射标识及六项选择字段。无管理映射时不追加；旧 JSON 不增加空字段，原摘要向量保持不变。新旧凭证均可按原操作查询。

自动准备在领取时读取同租户、法人及币种的生效指针，并将完整必要科目请求保存在准备状态中。未发布管理配置的范围继续由 ERP 管理映射；一旦存在管理发布物，缺少必要科目不能回退到旧模式。

本阶段 95 条相关测试通过，其中 16 条为 H2 持久化集成用例。新增模式的租户／目标隔离先出现 2 条失败，补齐发送前守卫后验证为零外发；正常管理映射、真实回环过账与查询、旧 JSON、原摘要向量及冲销回归通过。记录见 [领域与网关阶段证据](evidence/account-mapping-foundation-20261003.json)。

## 管理存储与接口

管理入口采用专用 `FINANCE_CONFIG_ADMIN` 权限，普通财务角色和单独的 `ADMIN` 均不能读取、写入或回放原管理成功请求。认证租户来自服务端上下文，客户端不能指定租户、发布人、发布时间、新版本或财务目标。

| 方法 | 路径（前缀 `/api/v1/admin/account-mappings`） | 语义 |
| --- | --- | --- |
| GET | 无后缀 | 本租户草稿摘要目录；支持法人、币种筛选与 `afterKey` 分页 |
| GET | `/current` | 必填 `legalEntityId`、`currency`，返回当前类别修订、生效修订及发布物 |
| GET | `/activations` | 必填同一范围，按 `beforeVersion` 查询生效历史 |
| GET / PUT | `/{key}/draft` | 读取或保存当前草稿，零修订表示明确创建 |
| GET | `/{key}/draft/versions/{revision}` | 当时的完整草稿定义、操作者与修改理由 |
| POST | `/{key}/publish` | 三版本确认后发布并切换本范围生效指针 |
| GET | `/{key}/versions` | 已发布版本摘要分页 |
| GET | `/{key}/versions/{version}` | 不可变发布正文 |

目录和历史默认每页 25 条，最多 100 条。列表只读取摘要列，不把全部科目正文装入列表查询。范围查询的法人编号采用完整小写 UUID，币种须是平台支持的两位小数币种。未知、重复或空参数不能被静默忽略。读取响应为 `no-store`。

两个写入入口复用原 `IdempotencyExecutor`：原账号、角色、方法、路径、查询与原始正文均绑定同一键，成功后回放原响应。认证和类型检查在回放前完成。输入拒绝未知字段、重复 JSON 键、尾随正文、整数截断及文本／枚举的隐式类型转换。

发布同时确认草稿修订、类别修订和该法人／币种的生效修订。生效指针按租户、法人和币种唯一；切换业务键也需确认原生效修订。当前 ERP 目标只从服务端读取；未配置目标时允许保存草稿，发布返回 `FINANCE_GATEWAY_UNAVAILABLE` 并回滚。发布只保存配置意图，不调用 ERP，也不证明科目已经通过 ERP 校验。

V104 新增范围头、草稿、草稿修订、发布版本和生效记录五张表。写入先复用 `expense_configuration` 的租户行锁，类别停用与科目发布使用同一个串行化边界。外键约束发布物的租户／法人／币种及原修订；无费用用途时允许逻辑类别零版，SQL 使用空引用，不虚构类别历史。新发布、草稿游标、生效记录、指针和幂等回执共同提交。

86 条相关用例通过，包含原费用配置和网关回归；其中 29 条接口与升级用例同时在 PostgreSQL 17 上通过。验证了两个业务键竞争同一生效修订只有一个成功，生效历史写入失败时所有配置及回执回滚，跨范围外键引用被拒绝，以及旧类别和财务样例记录在 V103→V104 升级后保留。详细记录见[管理后端阶段证据](evidence/account-mapping-management-backend-20261003.json)。完整安装包和页面仍待后续验收。

## 准备选择与登记复核

`AccountMappingPreparation` 在应用层协调发布查询和配置锁，领域 `VoucherPreparation` 保存领取选择及生命周期。准备服务沿用申请、财务聚合、租户费用配置的锁顺序。配置发布只取费用配置锁，不反向获取业务聚合锁；HTTP 查询在领取事务提交后执行。

选择写入 `state_json.mappingRequest` 及第二版修订，固定的 `input_json` 不变。无管理配置也保存完整请求，才能识别读取期间发生的首次发布。ERP 返回的请求必须与领取请求完全一致；最终登记事务取得同一配置锁后重新选择并比较。首次发布或换版先提交时，本次准备结束为 `ACCOUNT_MAPPING_CHANGED`，不留下可发送命令；显式重试才使用新配置。缺少必要键为 `ACCOUNT_MAPPING_UNAVAILABLE`，目标变化在读取前阻断。

取得配置锁后重新核对实际完成时间，锁等待不能延长准备租约。若等待耗尽租约，结果为 `LEASE_EXPIRED`，不登记凭证；过期判断先于实际凭证写入。

类别目录的后续修订不单独改写已发布映射。选择使用发布物冻结的类别修订及定义摘要；费用、税、借款抵扣和付款银行键仍来自真实业务分录，成本中心、项目和员工辅助核算保持原值。

如果凭证先登记完成，后续发布保留原命令和摘要，ERP 仍在过账事务校验原版本。历史查询、冲销和明确的原操作恢复不改写已登记命令。旧 JSON 缺少选择字段仍可读取；旧排队任务在新领取时绑定，旧执行中任务不能用未绑定的会计依据登记凭证，需要结束失败或等待租约到期后显式重试；旧终态与已登记凭证可继续查询。

本阶段不增加数据库列或修改旧输入 JSON。固定安装包的升级、进程重启及备份恢复验收仍须在完整 F02 验收中完成。

168 条范围测试通过，其中 33 条在 PostgreSQL 17.11 上复测通过，属于同一批用例的子集。覆盖借款挂账、实际报销类别／税／借款抵扣／应付科目、成功付款的授权银行科目，包含必要子集、原分摊不变、首次启用、换版、最终数据库锁竞争、等待耗尽租约、旧 JSON、明确重试、原命令后续过账与查询。最初两个映射接入用例以及锁等待过期用例均先稳定失败再修复。扩大付款回归另发现一个未随 FIFO 外键更新的旧数据夹具，修正缺失余额的模拟方式后验证恢复同时重建余额和顺序记录。详细记录见[准备接入阶段证据](evidence/account-mapping-preparation-20261003.json)。
