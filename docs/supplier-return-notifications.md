# 供应商回款通知

F17 的供应商银行回款查询、实际财务登记及原编号只读详情已接通。本阶段完成本地实现和范围验证，F17 整体保持 OPEN。完整验证见 [阶段证据](evidence/supplier-return-notifications-20261003.json)。

## 真实事实与职责

财务从原付款发起查询，工作器领取后只读取银行核对原件；明确登记由财务原入口执行。`SupplierPaymentReturnService` 在持久查询状态或实际登记后发布同事务事件，通知服务据此保存最小站内消息和外发意向。登记、资金入账、审计、幂等记录与通知共同成功或回滚。

查询不可用、来源变化、原件未核清以及明确发现资金退回分别产生提示。正常排队、读取中和成功但未见资金退回的查询保持安静。银行查询发现候选入款不能证明已经登记资金；实际登记的结果也可能是“确认未见资金退回”，因此登记消息不能统称为回款成功。

原申请人及本次查询的实际核对财务是接收人。服务先按当前人员及法人资格筛选；外发领取及重试再次复核原参与关系。稳定去重键为 `supplier-return:<原查询编号>:<事实种类>`，重复处理不会刷出重复消息。消息不包含金额、账户、入款流水或原始回执。

## 原查询与原决定

`GET /api/v1/notifications/{id}/supplier-return-target` 只读取本人消息的原查询，不接受替代付款、查询或租户参数。服务核对原银行首次成功修订、原采购申请及轮次，再恢复该查询实际消费的登记决定；后续查询和累计账本版本不能替换旧记录。

旧“待核对”消息可以显示同次查询后来实际完成的登记。旧失败查询没有登记时，即使后续查询已成功，仍只能显示自身失败。部分退回、全额退回及确认未见退回按原件分别展示；ERP 应付调整和本地账务完成有各自事实依据。

详情使用当前原轮次字段权限，管理员也受敏感字段约束。响应禁止缓存，不查询银行、不登记资金、不改变已读状态、不产生办理许可。页面仅提供重新读取与原申请轮次导航；身份切换、失权、超时、卸载和来源不一致清除旧结果并阻断迟到响应。

浏览器时间精度低于后端。已登记的历史记录在到期前数百微秒完成时，页面不能仅因截断到同一毫秒而拒绝展示；后端仍严格检查实际登记时效。
