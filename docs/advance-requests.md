# 员工借款申请

更新：2026-09-28。借款申请后端已实现；专用页面、实际付款和归档继续接续。

`AdvanceRequest` 保存借款用途、法人本位币金额、承诺归还日与每轮本人收款账户。`Application` 管理审批状态。最终人工批准只在申请内追加不可变的批准依据，不创建 `EmployeeAdvance`，也不产生支付授权或付款成功事实。现有 `EmployeeAdvance` 只表示实际到账、可供后续报销冲销的借款。

## 调用链与职责

1. 本人通过 `/api/v1/advance-requests` 创建草稿，`/{id}/revise` 以审批和借款双版本补正。结构化绑定为 `ADVANCE_REQUEST`，普通表单入口不能创建或直接提交这种申请。
2. 选择当前任职及已显示的财务查询目标，调用 `/{id}/prechecks`。任务持久保存双版本、轮次、任职、目标摘要、尝试序号和租约；同一单据最多一个活动预检。
3. 执行器在数据库事务外读取财务目录及本人账户。领域对象校验员工、法人、币种、账户有效期，以及法人本地提交日不晚于归还日。首期借款只允许法人本位币，不用未经约定的汇兑算法产生贷款金额。
4. 有效期取五分钟、目录有效期、账户有效期和法人下一日零点中的最早值。正式提交只接受最新且仍有效的预检，并重新检查原任职和双版本；冻结本轮后启动实际审批。
5. 所有人工审批节点须原样可读敏感借款明细，每条结束路径都须经过人工审核。这一共同规则由事前申请和借款共用 `HumanReviewContract`，业务保留字段由各自表单契约管理。
6. 最终批准事务保存申请结果及 `AdvanceRequest.Approval`，其中记录轮次、实际批准人、批准时间和最终申请版本。批准依据写入失败，申请状态、引擎任务和审批轮次全部回滚。后续结算才能使用这一来源，不以客户端的“已批准”标志替代。

领域对象负责金额、归还日、账户归属和冻结历史；应用服务负责权限、组织和外部财务查询，以及跨聚合事务。Flowable 只通过适配器触发批准记录。已批准借款约定不可再通过草稿修改、撤回或作废入口变更。

## 读取与恢复

本人仅在草稿、退回或撤回时编辑。重提重新预检，原轮次金额、归还日和收款账户保留。旧审批人不能读取补正草稿；显式查询历史轮次仍须通过字段权限，管理员同样受敏感组约束。历史轮次不会展示其他轮次的批准依据。

页面和预检预览使用独立 `AdvanceRequestRoundView`，只返回脱敏账号。支付用账户引用和摘要留在服务端；不能用通用 JSON 序列化整个领域快照作为页面响应。创建、修改和提交均返回最小回执，原请求幂等缓存不复制用途或账户。

排队任务可恢复领取，已领取后崩溃按原租约超时，不能自动重复外发。迟到结果不能覆盖终态；修改、任职或目标变化会令网络返回的事实失效。外部不可用与明确业务阻断分别保存，不持久化远端错误正文。

## 数据与验证

V42 新增借款申请、不可变修订、预检及预检修订表。业务类型、租户、申请、员工和预检引用版本由复合外键限定；V41 旧数据保留。当前新借款接口为 11 个操作，契约总计 147 个操作、248 个结构和 48 个请求示例。

自动验证覆盖领域及表单边界、真实 HTTP 目录和账户查询、两级实际 Flowable 审批、幂等重放、他人账户及过期账户、法人日期、补正和轮次读取、并发领取、网络等待中修改，以及最终批准事务回滚。共享的事前申请、报销提交、委派、会签和 OpenAPI 已纳入范围回归。H2 与 PostgreSQL 的结果分开记录，重叠用例不相加，见 [借款申请后端证据](evidence/advance-requests-20260928.json)。

合成财务端口用于验证协议和业务边界，不表示已经接入企业账户或已经付款。付款命令端口见 [支付系统端口](payment-system-port.md)，实际授权、执行、对账及到账余额生成继续开发。
