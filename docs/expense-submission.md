# 正式报销提交与审批控制

2026-09-28。本阶段完成正式提交、重提、纸件签收、财务同意守卫、撤回/作废及预算结果联动。外部事实仍由配置的企业接口提供；测试使用合成财务 HTTP，不能代替真实企业验收。财务核减已接通，见 [核减编排](expense-reduction.md)；费用业务页面和付款结算继续开发。

## 调用方与职责

本人费用入口调用 `ExpenseSubmissionService`。它协调申请、财务轮次、发票、事前额度、借款预留、引擎启动和预算命令，全部使用同一事务。实体仍负责自身核算、状态及版本约束；外部 HTTP 由已实现的持久执行器在事务外调用。

流程定义使用节点属性 `expenseStage` 明确职责：缺省或 `BUSINESS` 为普通业务审批，`RECEIPT` 为纸件签收，`FINANCE_REVIEW` 和 `FINANCE_RECHECK` 为财务审核/复核。节点名称不授予财务权限。设计器快速步骤和高级画布共同编辑此属性，导入的未知值保留供修正。

正式提交复核四个结构化费用字段。每条通往结束的路径必须经过财务节点；法人要求纸件时，每个财务节点之前须经过签收。必经控制放在并行分支共同路径，不能用某一条并行支路替代整单控制。签收、财务节点必须显式获得 `expenseDetails` 原文只读权限；隐藏或脱敏不满足要求。通用审批人的资格、当前候选和委派状态仍由共用的 `FlowableTaskAuthorization` 判断。

## 正式提交事务

1. 按申请、报销顺序锁定本人单据，检查申请/财务双版本及可编辑状态。
2. 读取指定预检，只允许本单最新的 `READY`；固定引用资源的锁，重新核对目标、任职、版本、原件查验回执及有效期。目录锁一直保留到提交结束。
3. 锁定绑定的已发布定义并检查版本可用及费用路径；从预检事实重新生成实际提交时刻的财务快照，不能把预览当成真实提交历史。
4. 计算并保存资源计划，每个中间资源版本追加审计；保存财务轮次后派生路由金额和超标字段，启动实际 Flowable 实例并冻结审批轮次。
5. 保存本轮控制和预算命令，再检查预检未过期。任何末尾失败均回滚财务、资源、申请、引擎、通知和预算登记，不留下半次提交。

V39 的 `expense_submission_control` 同时引用本人报销、实际 `approval_submission_round`、财务版本及同单预检。预检不可跨单或重复消费。纸件确认追加第二版本，保留任务、节点、处理人、说明和时刻；重提创建新的未签收控制，不复用旧纸件结果。

## 审批与终止规则

普通业务审批可以在预算执行中办理。签收节点的同意要求本轮纸件已明确确认；无需纸件的法人可以继续，不能补造签收事实。财务同意同时要求本轮纸件满足要求、预算没有待定操作、已确认预算完整分摊与当前财务版本一致。待归还的受托任务不能签收或直接同意。

预算确认 `BUDGET_INSUFFICIENT` 时，当前实际轮次自动退回申请人，终止实例并保存 `system:budget` 的申请审计、站内通知及已配置 Webhook 事件。其他拒绝保留实际分类并阻止财务同意，不伪称预算不足。事件与预算任务/台账终态同事务，不能先确认预算再丢失退回动作。

申请人仅在本轮尚未进入任何财务审核或复核任务时可以撤回。判断依据是当前审批轮次的实际任务历史；财务已经完成并流转到后续业务节点，也不会重新开放撤回。退回与撤回保留本轮资源供补正重提。重提按新费用整体迁移发票、额度及借款预留；预算调整失败仍保留最后已确认冻结。财务版本递增且审批轮次不倒退即可继续，拒绝的中间轮次不应阻止第三轮再次调整。

驳回与作废释放上一轮实际本地资源，不读取尚未提交的补正引用。预算已经确认冻结时登记释放；原操作未知时继续对账，确认后再安排释放。释放本身若被明确拒绝则保留结果供后续处理，不无限生成新的释放命令。审批通过后预算仍保持冻结、资源仍保持预留，尚不代表已经核销或付款。

## 接口

全部路径前缀 `/api/v1/expense-reports`，写入使用平台原请求幂等机制。回执仅包含标识、版本和状态，不缓存敏感费用内容；未知请求字段被拒绝。

| 路径 | 调用主体 | 正文 |
| --- | --- | --- |
| `POST /{id}/submit` | 申请人 | `applicationVersion`, `financialVersion`, `precheckId` |
| `POST /{id}/tasks/{taskId}/receive` | 当前签收节点可决策人 | 双版本及 `comment` |
| `POST /{id}/withdraw` | 申请人 | 双版本及 `comment` |
| `POST /{id}/cancel` | 申请人 | 双版本及 `comment` |

正式提交回执中的 `budgetOperationId` 表示已登记的持久操作，不表示外部已经冻结。`EXPENSE_BUDGET_NOT_CONFIRMED` 和 `EXPENSE_PAPER_RECEIPT_REQUIRED` 阻止财务放行；`BUDGET_OPERATION_PENDING` 拒绝覆盖未查清的上一操作。当前 OpenAPI 已对应全部实际路由和请求/响应字段。

## F10 预算保留期限（开发中）

本段为 2026-10-03 的增量实现说明。F10 尚未完成安装包、实际浏览器及重启恢复验收，仍计入未完成台账；上方历史阶段的测试数量不作为本次验证结果。

租户必须同时明确启用开关和保留天数，例如合成验收租户可配置：

```yaml
agentflow:
  expenses:
    budget-retention:
      tenants:
        demo:
          enabled: true
          retention-days: 3
```

示例中的 3 天只用于说明配置，不是企业默认值。没有配置或明确关闭时，不为本次退回或撤回生成自动释放期限。启用后按轮次实际结束时刻计算，每天为连续 24 小时；草稿修改和之后的配置变化不能延后或重算已记录期限。V105 只新增记录能力，不为旧退回单补造开始时间。已经捕获的期限继续有效；关闭租户规则只影响之后结束的轮次。

申请人撤回、审批人退回和子流程传播退回共用真实轮次结论事件。期限与结论在同一事务保存。到期服务和正式提交共用申请、报销锁，锁内重读当前轮次：已经重提则原计划失效；原预算命令尚待核对则继续等待；实际仍有冻结才登记既有预算队列的释放命令。排队、执行超时和查询中均不等于释放成功。原号查询确认后才写入完成状态；外部明确拒绝时保留失败原因，不自动换号重发。

预算已释放后的重提仍走正式预检、版本检查和资源占用链路。新轮次的冻结携带最后释放的版本和凭据，外部预算版本持续递增。释放命令尚未取得确定结果时，重提整笔事务回滚，不会留下半个新轮次。票据、事前额度和借款预留不受这项到期处理影响。

授权后的费用详情与历史轮次返回 `budgetRetention`，包含本轮固定期限和处理状态；管理员继续受敏感字段权限约束。页面分别展示待核对、释放处理中、已确认释放、被新办理取代及显式拒绝，不按前端时钟推定已经释放。

技术调度开关为 `agentflow.expenses.budget-retention.worker-enabled`，默认开启；每轮最多 50 条，按固定键翻页，延迟默认 10 秒，可通过 `delay-ms` 调整。暂停调度不改变已经保存的期限；恢复后继续按原记录处理。
