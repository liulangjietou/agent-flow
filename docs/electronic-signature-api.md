# 电子签应用接口

调用方包括已登录页面和电子签服务方回调。页面入口复用当前申请、冻结轮次和附件字段权限，下游为持久签署操作、原登录授权和后台工作器；回调经原始回执验签后进入同一事务服务。受影响的场景包括已批准合同的明确签署、未发送取消、重复请求、服务方回调与轮询并发、结果收集和受限文件下载。

控制器负责 HTTP 输入、错误分类和幂等约定；`SignaturePublicService` 负责公开投影与下载，避免内部账户、目标、登录引用和回执原文进入页面；跨申请权限、仓储和证据的原子更新保留在 `SignatureOperationService`。状态迁移继续由领域对象管理。

## 用户入口

| 方法 | 路径（均以 `/api/v1` 开头） | 行为 |
| --- | --- | --- |
| GET | `/signatures/options` | 当前账号可选择的资料名称、版本、部署可用性及固定限制 |
| GET | `/applications/{applicationId}/signatures` | 按指定 `roundNo` 分页读取当前可见操作 |
| POST | `/applications/{applicationId}/signatures` | 明确授权已批准轮次的固定原件 |
| GET | `/applications/{applicationId}/signatures/{id}` | 当前可读的操作、授权说明及文件摘要 |
| POST | `/applications/{applicationId}/signatures/{id}/cancel` | 原授权人取消尚未领取发送的操作 |
| GET | `/applications/{applicationId}/signatures/{id}/documents/{documentId}/content` | 下载已完整保存并重新校验的签署结果 |

公开契约见 [OpenAPI](../agentflow-server/src/main/resources/api/openapi.json)。写请求沿用 `Idempotency-Key`；企业模式还需要 CSRF 和页面身份绑定。版本以规范十进制字符串传输，不使用浏览器浮点数保存。入口严格拒绝数字版本，以及小数、文本或布尔轮次，不允许 JSON 反序列化静默转换来源。创建输入仅包含轮次、预期申请版本、资料键及版本、原附件引用、授权目的和截止时间；租户、操作者、实际签署账户和服务地址不能由页面指定。

首次创建需要当前已批准的申请及相同轮次、版本；所有原件必须属于该轮次冻结的 READY 引用且当前可读。物理文件预读发生在幂等事务外，实际后台发送前再次核对原登录、权限和来源。管理员受相同的敏感字段约束。批准申请不等于授权使用签名或印章。

成功重放先重查当前原件权限，再返回原来的最小操作回执，不重新执行授权。已有成功响应不因后来申请版本变化或存储暂时不可用而重新创建；权限撤销仍拒绝重放。取消只允许原授权人、当前可读原件和 `QUEUED` 状态；不能把结果未知或已经领取的操作当成未发送。

列表只接受单值 `roundNo`、`afterId`、`limit`，默认最多扫描 25 项、上限 100 项。每项分别检查全部原件权限。过滤后的空页仍可能带下一游标，客户端应跟随游标；游标不得跨申请或轮次。只读接口不会领取、续租或触发外部请求。

响应不返回服务方账号、端点、公钥、签名原文、认证引用或内部存储标识，并禁止缓存。下载始终使用附件方式、`application/octet-stream` 和 `nosniff`，每次复核当前权限以及实际大小和 SHA-256。服务方报告 `SIGNED` 后先收集文件；只有全部结果保存并确认 READY，才出现可下载的本地 `SIGNED`。原件与结果分别保存。

## 服务方回调

只有精确的 `POST /api/v1/integrations/signatures/callbacks` 使用回执签名认证。GET、尾斜杠、子路径及普通签署写接口继续由原用户认证和 CSRF 链处理；用户令牌不能替代回执签名。

请求必须携带唯一的 `X-Agentflow-Signature-Tenant`、`X-Agentflow-Signature-Operation` 和 `X-Agentflow-Receipt-Signature` 头。前两者仅定位原操作，仍须与签名正文和原请求完全绑定。正文为不超过 65536 字节的 UTF-8 `application/json`，不接受查询串、压缩体或重复认证头。未知长度正文同样有实际读取上限。

分离签名是标准 Base64 编码的 64 字节 Ed25519 签名。签名输入为 UTF-8 的 `agentflow-signature-receipt-1`、一个 LF 及未经重排的原始 JSON；信封与严格字段规则沿用 [回执证据格式](electronic-signatures.md#可信配置与原始回执证据)。先验签再解析，不能从正文获得替代公钥。

精确资料停用不会拒绝既有操作的事实。资料移除或原键被错误替换时，仅已有且重新验真的证据能够恢复原公钥；没有旧证据时拒绝认证，不切换新密钥或默认资料。存储损坏和数据库故障保留基础设施错误，不能冒充无效发送方。

状态、结果预留、原始证据和审计在同一事务内更新，锁顺序与工作器一致。首次发送前的回调和 `NOT_FOUND` 回调拒绝；重复及旧修订可安全确认，同修订不同事实和终态替换拒绝覆盖。回调结束原领取后，迟到工作器不能覆盖新事实。并发重复不重复增加修订、审计或文件预留。回调可能先记录接收时间、后等待数据库锁；锁内生效时间以已持久状态的更新时间为下界，避免较早请求较晚获得锁时被误判为时间倒退。原始回执验真时间仍按实际验真时刻留存，不随锁等待改写。

成功返回无正文的 HTTP 204，仅表示回执接收完成。结果文件尚可能等待收集，PDF/OFD 内部签名、真实证书和时间戳仍归 E10 验收。
