# 借款冲销 FIFO 建议

更新：2026-10-02。F07 已完成本地验收，实现提交 `2ab9a38`。按已通过预检的核定含税金额，为申请人展示按实际放款日期排序的冲销建议。建议仍需明确采纳，申请人可以调整。

## 调用与职责

`ExpenseSubmission → AdvanceOffsetSuggestion → GET /api/v1/expense-reports/{id}/prechecks/{jobId}/advance-offset-suggestion → AdvanceOffsetSuggestionService → EmployeeAdvanceRepository / EmployeeAdvance`。

- 预检服务校验原申请人、草稿可编辑状态、双版本、任职、最新检查、目标、有效期和原引用资源。管理员或财务角色不会扩大本人范围。客户端不能提供核定金额、申请人或排序参数。
- 仓储按租户、申请人、法人、本位币过滤，并以放款日期、UUID 文本升序进行每页 100 笔的游标查询。不能用工作台按 UUID 倒序的一页余额近似 FIFO。
- 借款实体负责可建议额度：当前可用余额加本报销单上一轮仍保留的预留；其他单预留、已冲销、净还款、银行退回均不能重复使用。付款、凭证或还款处于待复核状态时，连本单保留预留也不能推荐到新轮次。
- 服务层从有效预检取得核定金额，逐笔取剩余核定额与该笔额度的较小值，最多 50 笔。合计不超过核定额；达到 50 笔仍未覆盖的金额保留为应付，不宣称其余金额一定存在可用借款。
- 查询在最长 10 秒的 REPEATABLE_READ 事务中完成。授权校验沿用组织目录锁，PostgreSQL 不允许将该事务声明为数据库只读；查询不写入资金、草稿或审计。结束前再次检查预检有效期。

## 页面与正式提交

完成预检并选择匹配的任职、会计日期后，页面自动展示建议、放款日期、借款编号及可建议额度。查看建议不改变草稿，不占用资金。

申请人先核对，再确认替换当前冲销列表。确认时重新读取建议；借款版本或金额改变时更新预览，要求再次确认。身份切换、单据或预检版本改变、超时和过期都不能由迟到响应恢复旧建议。

采纳仅填写当前未修改的草稿，立即进入待保存状态并关闭原提交入口。可手动调整冲销金额；保存后必须重新预检。正式提交继续使用既有服务端资源校验和原子预留流程，建议不会绕过这些约束，也不会自动发起审批。

## V101 升级

新增 `employee_advance_order`，从 `finance_resource.context_json` 中的不可变法人、币种、放款日期和独立身份列建立索引。原余额、版本、金额占用、修订记录和文件不改变。新增借款与排序索引同事务写入，后续余额变更不改索引。

历史放款背景无法解析时中止迁移，不跳过该笔借款；否则最早借款可能被悄悄遗漏。新表使用财务资源复合外键，查询恢复实体时复核索引与原背景一致。
