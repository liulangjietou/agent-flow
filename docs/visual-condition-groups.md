# 可视化嵌套条件组

快速步骤和高级画布的条件配置现支持 v2 嵌套条件组。每组可以选择“全部满足（且）”或“任一满足（或）”，添加判断、添加子组，对整组或单个判断取反。删除子组会删除组内条件，按钮明确标识范围，可以使用设计器的撤销/重做恢复。每组至少保留一个条件。

例如：

```text
!(category IN ["TRAVEL", "DAILY"] OR urgent == "true")
AND amount EXISTS
AND !(amount >= "9007199254740993.123456789012345678" OR !description EXISTS)
```

界面按组显示且/或关系，金额保持十进制字符串。`!` 对完整判断结果取反，可能包含未填写字段；需要排除时添加“已填写”。它不等同于把“大于”改成“小于等于”。

## 编辑与兼容

- 打开已有条件、切换模式或查看说明，不改写保存的表达式。显式修改后使用现有 v2 语法序列化，子组保留括号，保存重载后仍可识别。冗余括号或双重取反可以等价归并，不承诺编辑后逐字符保留原文。
- 不增加新的条件语言版本，不把编辑用标识存入流程图。保存、自动保存、版本比较、校验、模拟及发布均沿原链路。
- 未知字段、非法类型、无效表达式或缺少表单时保留原文，提供表达式编辑。不会按猜测拆分。
- 暂时未填写的比较值或空 IN 列表可以保留在当前编辑状态中，切换查看表达式再返回不会清空。未完整条件不能通过服务端保存/发布；若自动保存报错，补齐后点击“保存草稿”恢复。手动修改成无法解析的表达式后不能切回旧编辑树。
- 旧版继续使用原平面配置，只有点击“启用组合条件”并通过服务端等价转换后才启用嵌套编辑；已发布版本只读。
- 最多 100 个比较项、4000 个 UTF-16 字符，生成表达式的括号与取反合计最多 16 层。超限时拒绝本次编辑并保留原状态。IN、字面量及字段白名单沿原约束。

## 职责与调用链

调用方 `App.vue` → `QuickSequence.vue` / 高级连线面板 → `ConditionEditor.vue`。两种视图共用 `ConditionGroupFields.vue` 递归呈现，旧版与新版共用 `ConditionRuleFields.vue` 的字段控件。

`conditionGroups.ts` 把已有只读语法树映射为临时编辑树，进行不可变编辑和序列化；它不执行条件、不保存业务数据、不改变分支顺序。父设计器仍持有唯一图状态和撤销历史。服务器领域 `ConditionParser` 是校验、模拟与 Flowable 执行的唯一语义依据。此阶段没有生产 Java 修改、接口变化或数据库迁移，符合既有 DDD 职责划分。
