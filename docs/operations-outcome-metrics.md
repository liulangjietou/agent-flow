# 审批运营结果指标

当前状态：2026-10-01 已完成本地接口、页面和独立运行验收。新增指标承接原产品目标中的 SLA 违约、通知失败和 Agent 人工采纳率，不改变审批、通知发送或人工复核行为。证据见[本次验收](evidence/operations-outcome-metrics-20261001.json)。

## 调用链与职责

运营页面 → 管理员只读接口 `/api/v1/operations/approvals` → `ApprovalOperationsReadPort` → JDBC 聚合。入口沿用当前租户和 ADMIN 授权、日期及组织筛选；读适配器在同一可重复读事务内汇总存储事实，不读取表单、通知正文或模型建议。比例计算属于运营读模型。无新增业务状态或外部调用。

三个指标都使用所选 UTC 提交日期内的轮次队列，流程版本和组织使用该轮冻结信息；显示这些轮次截至查询时的结果，后续结果可以在提交窗口之后产生。重提按新轮次分别统计。它们与不受日期窗口限制的“当前积压”分开展示。

## 统计口径

### 历史 SLA

- 以每个实际人工任务为单位，会签成员分别计数；结束任务必须能关联同租户、同申请、同轮次的引擎历史及本人真实 APPROVE／RETURN／REJECT 审计。
- 退回或驳回者计为已办理；同轮其他连带终止任务计为取消，不能把取消时间当作它们的审批时间。没有办理审计的普通结束任务单独披露为缺少办理记录。
- 分母为具备有效起止时刻及已记录期限的已办理任务，分子为结束时刻晚于期限的任务；等于期限不算违约。暂停后使用原任务已接续的实际期限，转交、委派和回交不创建新样本。
- 无法核实租户／申请／轮次引擎历史绑定的轮次另行披露，不能显示成有效零样本。
- 未记录期限、异常时间、取消、尚未完成及缺少办理记录分别计数，不进入比例分母。旧任务不根据当前流程配置补推期限；分母为零时省略比例，页面显示“—”。

### 外部通知

- 每条收件人／渠道投递为一个样本，重试及人工恢复不新增样本；分别显示受理、失败、待重试、未知、抑制、排队和发送中。
- “曾明确失败”通过追加投递历史的 FAILED／RETRY_WAIT 去重计数；恢复成功不抹掉该历史，重复失败不反复计数。未知结果单独披露，不认作明确失败或受理。
- 渠道受理不证明最终送达，不把收件地址、失败原因正文或个人偏好返回给管理员。

### Agent 人工采纳

- 分母为 ADOPTED + DISMISSED，分子为 ADOPTED；采纳包含人工修改后采纳，且不代表审批通过。
- 排队、执行中、失败、等待复核分别计数；不把尚未复核的建议当作拒绝，不将执行失败混入采纳率。
- 同一轮多次运行分别计数；不解析或返回上下文、模型文本、人工修订或复核意见。没有已复核样本时省略比例。

## 本地验收

- H2 范围 31 项通过，涵盖运营 11、OpenAPI 6、任务期限 7、升级提醒 7；PostgreSQL 的同组运营 11 项通过，跨数据库不累加。包含跨轮次、组织字面量、租户隔离、恢复后历史、零分母、边界时刻、真实会签退回／驳回和暂停恢复。
- 前端相关 7 项、类型检查、构建和 OpenAPI 通过；契约为 290 个操作、567 个模型、110 个请求示例。42 份实际响应通过契约，其中 1 份来自浏览器。
- 独立 PostgreSQL V93 副本通过实际 HTTP 创建一分钟日历任务。3 项办理中，2 项在期限内、1 项确认到期后办理，历史违约率 33.3%。3 次回环合成模型调用经实际人工复核，2 次采纳、1 次拒绝，采纳率 66.7%；模型未执行审批。
- 45 条原投递记录保持，新增流程产生 13 条未发送意向。页面分别显示当前失败 26、曾明确失败 32、未知 1、已受理 14；受理没有被显示为送达。真实企业模型和通知仍未验收。
- 浏览器核对三项结果、无样本“—”、实际 500 CSS 像素单列及无横向溢出。重启后演示会话需重新登录，重新登录后指标保持；最终控制台无警告或错误。
- 重启及连续查询保持 225 张表、2,150 行和 3 份附件；原库的 1,891 行及原件保持。没有新增迁移、回填旧期限或替换原服务。验收数据量不代表生产容量结论。

## 期限历史修复

真实会签退回／驳回先复现历史期限为空：原创建监听器直接设置运行任务，没有通知引擎更新已创建的历史任务；原测试只检查运行期限和批准后的历史，未覆盖终止路径。已改用公开 `TaskService.setDueDate` 在同一创建事务更新两者。暂停恢复继续使用原公开命令；旧历史未记录的期限保持缺失，不通过当前配置回填。
