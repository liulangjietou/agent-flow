# 财务工作区查询

更新：2026-09-28。此阶段完成工作区查询、本人列表、费用明细及审批操作页面；发起填报已接通，结算继续实施。

本人报销列表使用 `/api/v1/expense-reports`，按创建时间与编号倒序分页，允许状态筛选。租户和申请人来自当前身份，管理员也不能指定其他员工。列表只返回标题、编号、状态和双版本，不复制财务明细。

`/api/v1/expense-requests` 和 `/api/v1/employee-advances` 返回本人已批准额度、已放款借款与可用、预留、已使用余额。关闭的批准额度保留可见，以便补正时减少已有占用；不返回账户、付款引用或其他报销单的占用明细。游标必须属于当前本人和资源类型。当前按编号分页，不代表借款冲销的先进先出推荐。

`/api/v1/expense-reports/{id}/workflow` 先执行已有完整费用明细权限检查，再在一致性数据库快照内读取纸件签收、预算和当前任务的操作条件。隐藏或脱敏的审批人无法通过此接口绕过限制。传入 `taskId` 时必须是当前实际可办理的同轮任务；待委派办理期间不能收单或核减。

预算台账的 `FROZEN` 与 `confirmedCurrent` 分别表达“曾确认冻结”和“当前财务版本及分摊已获确认”。核减后，前者可以暂时保持，后者必须为假，直至调整命令获得外部确认。前端按钮只是提示，所有写入仍重新核验实际权限、双版本和预算。

V40 为本人费用、本人资金和报销预算操作查询增加索引。升级测试从 V39 保留两名员工的完整旧数据，检查分页顺序、本人边界和重复迁移结果。

验证：H2 范围 35 项通过（费用提交与查询 19、草稿权限 10、迁移 1、OpenAPI 5）；PostgreSQL 17.11 业务 19 和迁移 1 项通过；相邻资金仓储 10 项在 H2 通过。这些范围有重叠。静态 OpenAPI 为 125 个操作、213 个模型、44 个请求示例。查询后端机器证据见 [工作区查询](evidence/expense-workspace-20260928.json)。

## 工作区与审批页面

费用入口展示本人报销、事前批准额度和已放款借款，支持有界分页、状态筛选与重试。费用详情区分原始提交和当前核定，展示借款抵扣、应付余额、纸件、预算确认及核减记录；审批通过不表示付款完成。当前详情及按钮必须匹配同一单据、轮次和双版本，历史轮次只读。完整明细受限时，仅展示申请接口已经投影的可读字段。

签收、核减、撤回和作废均先打开可取消的确认表单；写入沿用统一原请求恢复机制。身份、任务或版本切换后清空旧表单和查询，超时或失权不继续展示旧财务数据。浏览器实际验证发现并修复三个消费者边界：核减后待办金额未随详情刷新、确认表单未接收键盘焦点、完整明细被拒绝时同时丢失了允许显示的摘要。前两个界面的数据与焦点问题分别有真实 DOM 失败断言和组件失败回归；第三个有真实受限审批人失败与通过断言。

本阶段前端范围 34 项通过，构建及静态 OpenAPI 校验通过。PostgreSQL 上打包后端的本机合成财务网关完成 24 次初始 HTTP 检查、16 次最终读取检查及额外浏览器操作：实际签收、批准收单、两次核减、预算确认、财务批准、本人及非本人权限检查。浏览器实测 CSS 500 像素宽度无横向溢出，控制台无错误。资金选择页只验证当前真实查询和空结果；没有把合成财务网关计为企业接口验收。详细证据见 [页面验收](evidence/expense-workspace-ui-20260928.json)。
