# 预算实际占用冲正

本阶段实现独立冲正命令、结果协议、可持久化执行状态和严格 HTTP 适配器。它是报销资源调整的前置能力；数据库编排、财务办理入口及资源调整页面仍在接续，现有验收服务保持 V64，不能将本阶段描述为完整业务办理完成。

## 调用链与职责

调用方是后续独立报销调整的财务授权服务。原已核销结算提供真实 `CONSUME` 命令及其 `APPLIED` 回执，期间准备使用既有只读会计期间端口。领域命令固定这些来源和本次授权；应用服务负责当前岗位、原单完整字段权限及数据库事务；网关在事务外发送或查询。

受影响场景为取消已核销报销后的预算实际占用冲正、发送超时和进程崩溃后的恢复，以及会计期间关闭时阻止新发送。普通冻结、调整冻结、释放冻结和消费协议继续保留。原预算消费台账不被改写成“没有消费”，新的冲正独立留证。

## 不变量

- 原命令必须为 `CONSUME`，成功回执匹配原租户、编号、摘要、精确分摊和递增预算版本。冻结成功或释放冻结的回执不能替代实际消费。
- 独立授权引用调整编号、核验材料、理由及财务身份。申请人不能授权自己的冲正。公开办理层继续检查当前法人范围及岗位分离。
- 财务明确选择新记账日期，开放期间覆盖该日期，法人和币种固定到原消费。发送窗口最多五分钟，期间证据到期同时阻止发送；不能在恢复时自动改期。
- 冲正结果必须采用原消费的下一预算版本、独立凭据、指定期间与日期，生效时间不能早于新授权。旧消费回执不能冒充冲正回执。
- 超时、连接失败和租约过期意味着未知。授权过期仍可查询原编号；权威查无等待明确重发，且只能使用未过期的原命令。曾经读到处理中再查无、迟到或矛盾回执进入人工核对。
- 外部必须在同一事务核对原消费仍生效、预期版本、期间和幂等编号，完整撤销原分摊的实际占用。同一原消费已有冲正时明确拒绝，不能用另一编号再次退还预算。

## HTTP 协议

| 固定操作路径 | 输入 `data` | 幂等头 |
| --- | --- | --- |
| `budget-consumption-reversal-command` | `command` 与 `commandDigest` | 命令编号 |
| `budget-consumption-reversal-query` | `operationId` 与 `commandDigest` | 无 |

沿用财务网关版本 1 信封、租户和请求相关号。写入相关号等于持久命令编号；查询每次相关号不同，业务操作编号不变。目的地摘要固定，配置改变时阻断，凭据可以轮换。适配器不自动重试写入，数据库事务内禁止实际传输。

`BudgetConsumptionReversalCommand` 包含 `id`、`adjustmentId`、`source`、`consumed`、`period`、`authorizedBy`、`evidenceReference`、`reason`、`createdAt`、`expiresAt`。分摊完整保留在原 `source.position`，客户端不能自行减少金额或更换成本对象。

稳定 SHA-256 摘要使用 UTF-8 字符串，每项前缀为四字节大端字节数，按以下顺序编码：协议标识 `agentflow-budget-consumption-reversal-1`、命令号、调整号、原命令摘要、原消费回执的操作号/摘要/状态/台账版本/凭据/生效时刻、期间请求的法人/币种/记账日、期间编号/来源版本/起止日期/观察时刻/截止时刻、授权人、材料、理由、创建时刻、授权截止时刻。日期采用 ISO 日期，时刻采用 Java `Instant.toString()` 的 UTC 表达。原命令摘要沿用既有预算命令算法。

返回 `BudgetConsumptionReversalObservation`，包含操作号、摘要、状态和观察时刻。`APPLIED` 必须另有台账版本、独立凭据、期间、日期和生效时刻；`REJECTED` 只带明确拒绝原因；`PENDING` 和 `NOT_FOUND` 不带成功字段，后者只允许查询结果。外层 `REJECTED` 不能冒充已确定无副作用的业务拒绝。

## 验证与边界

22 项预算领域范围测试及 26 项网关范围测试通过，范围有重叠。覆盖来源替换、原件摘要、日期和独立授权、逐字段响应损坏、写入字节和幂等号稳定、查询无写入幂等头、目标变化、事务内禁发、超时单次发送、过期后的查询、矛盾结果和租约恢复。此处均为本地领域与回环 HTTP 证据，持久调度和页面尚未验收。
