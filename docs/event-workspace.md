# 事件等待页面与本地验收

更新：2026-10-01。事件契约管理、设计器固定版本选择、参与者等待面板、管理员收件箱和原号恢复已完成本地开发与验收。配合[契约目录](event-contracts.md)、[原生等待](event-waits.md)及[签名收件](event-inbox.md)，本地事件等待链路已贯通。真实企业事件来源继续在企业接口工作包中独立验收。

## 调用链与职责

- 管理员从“集成投递 → 事件契约”发布、查看、停用或恢复明确版本。页面调用既有契约 API，服务端控制发布版本、独立启停修订、权限和事务历史；浏览器不管理来源凭据。
- 快速步骤与高级画布共用确切版本选择器，保存 `eventContractKey` 和 `eventContractVersion`。图模型负责无损保存，模板和版本比较保留相同引用；发布及发起仍由服务端复核原版本。
- 申请详情的轮次流程图读取该轮实际事件订阅。面板显示原等待编号、创建时间、契约版本和暂停／停用事实。人工刷新发现申请版本变化后，通知父页面更新申请与流程位置。
- 管理员从“事件收件箱”读取原记录与连续历史，仅对待检查记录填写原因后恢复。操作进入现有原幂等请求机制；回执异常时保留原请求，不换号重发。
- 申请历史与管理员审计将 `EVENT_RECEIVED` 显示为“事件已推进等待”，两处都能按该动作筛选；该系统记录与人工批准记录分别保留。

受影响场景是流程配置、历史版本发布、申请等待与后台消费、暂停接续、来源信任变化、原请求结果未知、身份切换及小屏浏览。页面只负责任务选择、明确确认与事实展示，业务迁移和权限继续由服务端负责。

## 页面规则

浏览目录、刷新或发布新版均不自动替换节点引用。用户必须明确选择一个已发布且可用的版本；旧引用失效时仍保留原值供核对。快速步骤、画布切换、保存重载以及文件模板导入保持原引用。

契约发布使用最新发布版本，启停使用该版本当前可用性修订。旧版与新版分别启停。所有写操作必须明确确认并填写原因，取消不会发送请求。目录、发布版本、启停历史、收件列表及处理历史使用各自游标。

收件恢复保留原事件、来源信任修订、契约和等待身份。成功回执只说明重新排队，随后读取原件确定当前结果。暂停中的申请仍等待明确恢复；终态记录没有重试入口。页面不提供外部事件签名或模拟批准按钮。

查询具有取消和超时边界，切换身份或卸载后丢弃迟到结果。写回执在清除幂等恢复槽前校验原对象、相邻版本和操作结果。写操作之后的列表、版本及详情刷新也逐步检查原身份，防止中途换账号后继续打开旧对象。

## 本地证据

[完整证据](evidence/event-workspace-20261001.json)记录了 146 项范围前端测试、类型检查、生产构建和 OpenAPI 检查。新增事件用例 20 项，覆盖实际组件确认／取消、精确引用、异常回执、分页与身份隔离。审计中文显示和筛选遗漏通过真实页面复现并补验；写入后刷新期间切换账号先有 5 个失败用例，再完成修复。不同阶段测试范围重叠，不累计为唯一用例数。

在保留的 V88 隔离库和签名来源夹具上，完成两次重启及两笔新增申请：页面发布两版契约，独立停用和恢复 v1；设计器选定 v1，切换画布、保存重载并发布；申请人在页面填报提交；签名事件各推进一次；财务账号在页面逐笔明确批准。另一笔通过来源信任变更隔离、取消确认、具名恢复及原暂停轮次接续，原等待编号始终保持。

73 份实际 HTTP 响应及 16 份浏览器写回执通过 OpenAPI 校验，25 份实际读取通过前端解析。管理员和参与者审计均筛出单条真实事件推进。契约启停历史实测 27 条，首屏 25 条、末页 2 条并可返回最新历史。等待、收件和契约页面在实际 500 CSS 像素下无页面横向溢出。171 张旧业务表的 3,673 行及 10 份附件保持原内容。

模板文件由实际保存的流程图经过生产序列化器生成，并通过浏览器文件选择器导入独立草稿，引用仍为 v1。浏览器下载事件未返回，本阶段不将点击下载等同于下载文件验收。企业来源、远端 PR 和远程 CI 尚未接入；本地验收不代表这些外部工作完成。
