# 报销电子档案

更新：2026-09-28。V50 完成报销归档的本地实现，覆盖真实本地结算事实、不可变清单、原件引用和授权下载。外部财务服务仍为合成环境。

## 调用链与完成条件

后台 `ExpenseArchiveWorker` 从已完成的 `ExpenseSettlement` 扫描候选，`ExpenseArchiveService` 在原申请和报销锁内读取候选清单，`ExpenseArchiveFiles` 在事务外逐个校验原件，再由服务锁后重读全部证据并封存。只处理本地事实，不发送银行或 ERP 命令，不再次消费发票、额度、借款或预算。

首次归档要求原批准及财务版本保持有效、纸件要求满足、资源结算完成且预算实际占用确认。正额付款要求原银行成功事实、挂账凭证和付款凭证；全额借款冲销只要求挂账凭证；全额核减不制造零额凭证或付款。

归档实体负责证据身份、金额、必需凭证和原件集合的一致性；应用服务负责跨仓储关联和锁后复核；文件服务负责字节指纹及传输。候选发生变化时本次不封存，下一轮重新检查。

## 固定清单与原文件

档案记录格式版本、封存时刻及下列内容：

- 原报销轮次、申报明细、制度和汇率、核定金额及全部核减。
- 原审批提交快照、冻结任职、审批及审计轨迹、纸件签收。
- 原结算、银行成功回执事实及回单编号、预算占用凭据。
- 挂账与必要付款凭证的原操作修订和 ERP 凭证号。
- 正式提交采用的发票查验凭据、原文件元数据、大小及 SHA-256。

发票后续重验或被其他报销引用，不替换本档案的提交时查验事实。清单不包含网关配置、外部凭据或完整付款命令。现有银行端口返回回执事实与回单编号，未返回银行原始回单文件；档案不会虚构一个银行 PDF。

`expense_archive` 只允许应用代码在未封存时更新检查原因，封存后没有更新或删除入口。`expense_archive_original` 外键保留原件元数据；物理文件继续使用既有不可覆盖目录和数据库/文件配套备份。归档记录不等于外部不可改写存储或电子签章。

ZIP 包按原存 UTF-8 字节输出 `manifest.json`、`manifest.sha256` 及 `originals/` 下的原文件。文件路径由服务端 UUID 和格式生成，不拼接上传文件名。每次下载重新核对原件，缺失或指纹不符返回失败。流式传输每次只持有一份原文件；传输中断留下的包不得当作完整档案。

## 权限、争议与恢复

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/expense-reports/{id}/archive?roundNo=1` | 最小进度、数量、归档时间、清单摘要及当前依据问题 |
| `GET /api/v1/expense-reports/{id}/archive/content?roundNo=1` | 下载保存的原档案 ZIP |

两项接口每次复核实际申请、轮次及完整字段读取权限，管理员没有旁路；未知查询参数拒绝，响应 `no-store`。读取完整包时在原文件校验前后均重新授权，不依赖前端按钮。档案原文不出现在状态接口。

归档后退票、凭证冲回或批准依据改变，只影响当前依据提示，原档案仍可由有权限的人员下载。清单不被重新生成，也不因此恢复旧发票、额度或借款余额。

执行器每批十单，使用轮转游标，缺件的前页不会阻塞后页。原因未变化不反复写入。缺件修复后自动重新校验，不提供强制归档。`agentflow.expenses.archive-worker-enabled` 默认开启，`archive-poll-delay-ms` 默认 15000；关闭调度保留原档案和读取入口。
