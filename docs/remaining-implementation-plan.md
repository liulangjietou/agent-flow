## 实施顺序与验收边界

按依赖顺序连续交付：抄送及轮次读取 → Agent 执行与复核 → 结构化财务 → 其他高级流程 → 外部通知与协作 → 企业部署和远端交付。六个工作包全部纳入同一目标；每个可独立验收的功能完成后保存本地提交，再接续下一项，不等待重复确认。

| 工作包 | 采用的规则 | 验收要求 |
| --- | --- | --- |
| 财务 | 接受原费用设计 D1–D6：覆盖填报至归档；预算、查验、汇率、账户、期间、凭证及支付通过外部端口；核减只减不增，增额及换对象退回；提交冻结法人本位币汇率；纸质签收按法人配置 | 金额、占用、冲销及结算各自领域状态和并发约束；实际适配器未配置时失败，不返回假成功；真实系统对账单独验收 |
| Agent | 配置可信的 OpenAI 兼容 HTTP 服务，默认关闭外发；当前审批人显式勾选其可读字段，敏感隐藏和脱敏原文不可发送；后台调用不持有数据库事务；结果等待当轮有效审批人复核，采纳不等于批准 | 真正 HTTP 适配器、持久队列、超时和失败恢复、来源绑定、实时权限复核、并发和失效输入、前端全链路；夹具与真实模型证据分开 |

| 远端交付 | 功能验证后使用个人身份提交，目标仓库确认可用后推送、开放 PR 和运行 CI | 无 Git remote 时保留本地提交及可执行 CI，不虚构远程结果 |

财务其余细则采用保守默认：路由使用核定含税金额；发票按租户查重，未完成真实查验不得提交；无匹配费用标准、税务口径、汇率或账户即阻断；不凭空填企业标准金额。财务审核及付款阶段不允许申请人撤回；付款授权绑定金额、账户和业务版本；回调须验签、幂等，未知结果先对账。拆单检测阈值、逾期借款控制和纸质制度显式配置，未配置的规则不伪称已生效。

事件采用已发布的白名单事件契约；定时器只推进指定等待节点；子流程绑定发布版本、输入映射与父子关系，不访问任意流程。运维只允许有审计和原因的暂停、恢复、终止及明确失败重试，不允许任意跳节点或伪造审批。暂停冻结剩余 SLA，恢复接续，不重算已消耗时间。

## 第一项：抄送调用链与职责

- 调用方：设计器创建 `COPY` 节点并设置收件规则、字段权限；提交或审批推进激活节点；消息中心打开抄送快照。
- 下游：当前租户组织目录 → 冻结收件事实 → 站内消息；查询只读取相同申请、相同轮次的提交快照，附件继续检查该轮冻结引用和字段权限。
- 受影响场景：审批前后抄送、多个节点抄送同一人、组织停用、退回补正重提、跨租户及敏感附件。
- 定义域负责节点结构和字段权限绑定；组织应用服务解析有效人员；Flowable 适配器触发服务；消息与收件记录加入原审批事务；专用查询入口投影快照。
- 抄送不加入普通申请参与者权限，不因此开放当前草稿、其他轮次、评论、Agent 原始记录或审批操作。收到旧轮次的权限不会自动延伸到新轮次。
- 接收人停用后立即失去读取能力；历史收件记录保留。节点成员数超过 100 时阻断，避免意外广播。收件事实按轮次、节点、人员唯一，重复执行不重复通知。
