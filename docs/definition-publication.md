# 流程发布说明与发布记录

流程管理员在设计器点击“保存并发布”后填写变更说明，确认后依次校验、保存草稿并发布。说明不能为空，最多 2000 个 UTF-16 字符；服务端检查原文长度后去除首尾空白，不截断。窗口支持返回编辑、Escape、焦点循环和窄屏布局。说明只作为发布请求保存，不冒充已保存的草稿字段。

发布成功后，设计器显示发布者、权限依据、时间、说明和发布时的校验摘要。图结构、审批人规则语法、受限条件是固定检查项；绑定表单时还记录字段与条件类型检查。摘要不代表组织人员存在或审批组有可用成员，也不代替业务制度审核。

## 契约和兼容性

`POST /api/v1/process-definitions/{id}/publish?expectedRevision=...` 要求 `Idempotency-Key`，新执行必须提供 JSON：

```json
{"changeNote":"请假超过五天增加复核，并补充申请原因提示。"}
```

操作者、租户和角色来自服务端认证上下文。客户端不能指定发布者或授权角色。响应继续返回原有流程定义结构。管理员角色仍为 `ADMIN` 或 `PROCESS_ADMIN`。

`GET /api/v1/process-definitions/{id}/publication` 仅流程管理员可读取，按当前租户查询。完整记录返回 `{recorded:true, publication:{...}}`；历史已发布版本无完整记录时返回 `{recorded:false, publication:null}`。草稿返回 422 / `DEFINITION_NOT_PUBLISHED`，跨租户返回 404，普通用户返回 403。

新发布缺少说明、空白或超长说明返回 422 / `INVALID_PUBLICATION_NOTE`，不会改变定义或部署引擎。新记录不会回填历史发布者、说明或校验摘要。旧版成功的无正文请求在原幂等记录未过期且认证上下文一致时仍可回放，回放不重新发布，也不生成虚构的发布记录。

网络结果不确定时，前端保留原说明、版本和请求键，关闭发布窗口后通过“恢复上次操作”继续确认。改变说明不能复用原请求键。重新加载页面会丢失当前内存中的恢复队列；持久化恢复队列不在本次范围内。

## DDD 与事务

- `DefinitionPublication` 表达不可变发布事实与说明规则；`DefinitionDraft` 继续拥有发布状态变更规则。
- `DefinitionApplicationService` 编排校验、版本分配、状态持久化、Flowable 部署和发布事实持久化。
- `DefinitionPublicationRepository` 只提供新增与按租户读取；JDBC 用唯一键阻止覆盖，复合外键约束定义所属租户。
- V9 增量创建 `definition_publication`，不修改 V1–V8、不补造旧记录。发布事实写入失败会回滚定义及引擎部署，发布事务成功响应也受既有幂等事务保护。

## 验证

后端包含发布者防伪、说明边界、不可变摘要、角色/租户隔离、历史缺失、旧请求回放、真实 Flowable 回滚与记录防覆盖测试。前端请求测试验证原说明随原请求恢复及 422 后修正重试。

运行 `python3 scripts/check-definition-publication.py http://127.0.0.1:8082` 可在独立环境验证六个并发请求只发布一次、记录查询与权限、说明不可改写。脚本会新增随机流程并保留数据，不应当作纯只读自检。

停用、回滚和停用后的退回/撤回重提规则仍在后续范围内，已有审批实例继续绑定原定义版本。
