# 财务核减应用编排

2026-09-28。当前财务审核、复核任务可通过独立入口执行核减。核减不创建审批轮次、不完成当前任务；付款、凭证、归档及费用业务页面继续开发。

## 调用链和权限

`POST /api/v1/expense-reports/{id}/tasks/{taskId}/reduce` → `ExpenseReductionService` → 共用财务任务授权 → `ExpenseReport.reduce` → 本地资源差额 → 申请与引擎路由 → 预算持久命令 → 任务审计及申请人通知。

签收、核减共用当前组织资格、实际任务归属、加锁后重新授权、双版本和委派检查。仅本轮固定的 `FINANCE_REVIEW`、`FINANCE_RECHECK` 节点可核减；管理员、普通业务审批人和待归还受托人不能借此改额。开始核减前，本轮纸件必须满足要求且预算须已确认当前财务版本。前一预算结果未知时先完成对账。

金额限制、税额、分摊、冲销和追加差额归报销实体；资源计划只在副本计算，应用服务负责同一事务。Flowable 适配器精确核对租户、申请、轮次及唯一实际实例，只更新 `formData`，不覆盖历史提交快照。

## 核减输入和联动

请求携带 `applicationVersion`、`financialVersion`、`lines`、`reasonCode`、`comment`。每行只允许 `lineNo`、`approvedGross`、`approvedTax`，金额必须是非负且最多两位小数的十进制字符串。币种取本轮本位币；禁止 JSON 数字、科学计数法、增额、新增行、换票据或分摊对象等附带字段。

原因枚举为 `INELIGIBLE_COST`、`OVER_STANDARD_NOT_ACCEPTED`、`INVALID_INVOICE`、`TAX_CORRECTION`、`OTHER`；补充说明始终必填。没有配置的核减比例阈值不伪称已生效。

- 核定含税金额降为零才释放该行发票；已在此前归零并被其他单据使用的发票不被本次触碰。
- 事前批准额度按本轮、本行精确下调；原账本与核减前金额不一致或已核销时阻断，不重造预留。
- 借款冲销额超出新核定总额时，从原选择末端下调，并同步降低借款预留。仍不代表已经冲销。
- 申请与财务版本各增加一次；当前路由金额改为新核定含税额，原超标审批标识和冻结制度事实保留。
- 预算登记 `ADJUST`，引用最后确认的外部台账版本。调整确认前再次核减和财务批准均被阻止；确认后可继续核减。
- 任务审计 `EXPENSE_REDUCE` 固定实际任务编号、节点、操作者和申请版本；差额、原因及原始金额保留在财务版本。站内通知只给申请人入口，不复制敏感明细。

实际核减、预留、申请路由、引擎变量、预算命令、任务审计和通知加入同一事务。末尾实例绑定异常全部回滚；不同幂等键并发核减同一版本只有一次成功，原请求重放不再追加差额或通知。
