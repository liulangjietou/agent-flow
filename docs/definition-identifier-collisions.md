# 流程标识冲突提前校验

2026-10-03 补充：流程、节点和连线的字符规则已统一提前检查，旧草稿修正与安装包升级接续通过，见[编号字符校验](definition-identifier-syntax.md)。下文保留 2026-09-26 重名检查阶段的范围和证据。

流程、节点和连线在生成的 BPMN 中共享标识空间。原实现分别检查重复节点和重复连线，没有检查不同元素之间重名，导致设计预检和草稿保存通过、发布时才由引擎抛出 XML 重复标识错误。

本次将重名检查接入预检、创建、更新和发布。设计器提供可定位的中文提示；修改流程标识会取消旧检查并重新校验，模板导入检查采用目标流程标识。无新增数据库迁移，不重命名已有节点，也不改写已发布版本。

## 调用链和职责

调用方包括流程设计器、模板文件预检及定义 API。`DefinitionController` 传入图、表单和当前流程标识，`DefinitionApplicationService` 在创建、更新与发布时始终取实际标识，交给领域层 `DefinitionValidator` 判断。只有校验通过才进入仓储和 `FlowableDefinitionDeploymentAdapter`。

唯一性是流程定义本身的约束，因此由领域校验负责，领域层不依赖 Flowable。界面不自行维护另一套校验规则，服务端写入口也不信任先前的预检结果。

受影响的业务场景为新建草稿、编辑旧草稿、模板导入和流程发布。旧版已经接受的冲突草稿仍可读取；拒绝保存或发布时，原内容、版本、修订号及引擎定义保持不变。

## 接口和修正方式

- 节点与连线重名：`NODE_EDGE_ID_CONFLICT:标识`。
- 流程标识与节点或连线重名：`PROCESS_KEY_CONFLICT:标识`。
- 原 `DUPLICATE_NODE`、`DUPLICATE_EDGE` 契约保持。比较区分大小写。
- `POST /api/v1/process-definitions/validate` 新增可选 `key`；旧调用方不传时仍检查图结构，不能据此推断某个目标流程标识已经通过。创建、更新和发布始终检查真实流程标识。
- 预检以 HTTP 200 的 `errors` 返回问题；创建、更新、发布返回 HTTP 422、`INVALID_DEFINITION` 和 `details.definitionErrors`。

未保存草稿可直接修改流程标识。已保存草稿的流程标识仍不可改；节点与连线重名可在高级画布删除冲突连线后重新连接。旧草稿若是流程标识冲突，可导出模板后用不同的目标标识导入新草稿；若必须保留原流程标识，则通过定义更新接口同时修正图元素标识及其引用。不会自动改写旧标识或关联历史申请。

模板检查在目标标识变化时保留已读取文件，但清空旧检查、取消未完成请求并忽略迟到响应。使用者需要重新检查；缺少审批人等原来允许导入后配置的问题继续沿用原规则，标识冲突不能放行导入。

本次覆盖标识冲突，不扩展为任意 BPMN 元素或完整 XML 标识字符集支持。
