# F15 费用财务报表

状态：实现中。依据费用领域设计 §17，继续用户已授权的推荐方案。F14 已合入本地 main `fb0a9a78`；本项在原开发工作树接续。

## 数据范围与权限

入口为财务角色的只读报表，租户只取当前认证上下文。每个来源先经过现有报销、事前申请或借款原轮次的完整财务字段读取权限，之后才能进入统计；管理员没有敏感字段豁免。拒绝读取的数据不计数、不返回其存在性或金额。报表明确标注“当前身份可读范围”，不能把局部可读结果称为租户全量。

按 UTC 提交日期选择报销轮次，默认近 30 天，最长 366 天；法人、部门取提交时原任职，类别取原费用行代码，组织变更不能重写历史分组。历史未记录的组织单独标为未知。重提为独立轮次，类别分组内一轮只计一次；跨类别的轮次计数不可相加得到总数，金额按实际明细分配。所有金额按币种分别展示，不进行当前汇率折算。

借款余额、计划额度执行和凭证/付款积压是生成报表时的可读存量，不能伪称所选日期末的历史余额。没有可用业务读取依据的外部资源不能借报表获得新的访问权；适用范围和缺失依据明确披露。查询及导出不调用外部网关、不触发付款或对账。

## 指标口径

- 提交至批准、批准至首次确认到账、提交至首次确认到账：只取有效的原始时间，P50/P90 使用 nearest-rank（排序后第 `ceil(p*n)` 个）。无样本为 null；待完成、不适用、缺失或矛盾时间单独计数。零应付不产生虚假的零秒到账。后续退回不将首次到账时间改成退回时间。
- 超标率为具有原制度例外的可读提交轮次 / 可读提交轮次；类别分组仅检查该类别的原行。核减率为该范围存在实际金额核减的轮次 / 可读提交轮次，核减金额为原本币申报额减当前核定额。退回率为 RETURNED / (APPROVED + RETURNED + REJECTED)，撤回、作废和在审不进入分母。退回原因沿原轮次 reason 汇总，缺失原因独立显示。
- 查验失败率按可读报销引用的发票、所选 UTC 日期内的真实查验任务计算；REJECTED / (SUCCEEDED + REJECTED)，UNAVAILABLE 和未完成分别展示。同一任务在总计或单个分组内只计一次，不能因为重提重复计算。
- 重复占用拦截分为已持久化预检结果和正式提交被拒绝两种实际尝试。同一提交幂等键/身份/正文只记一次；拒绝记录在原业务回滚后单独落库，不改变失败结果，也不扩大通用幂等器职责。新记录启用之前的提交拦截历史明确未知，不能补造为零。
- 借款余额取原余额聚合的 outstanding，预留仍属于未结清余额；账龄沿借款原法人时区的本地日期，逾期从到期日次日开始，分未逾期、1–30、31–60、61–90、90 天以上和日期未知，争议中的余额另列提示。不能用统一 UTC 日期改变原借款逾期规则。
- 事前执行率取已消费报销额 / 原批准额度，预留单列，不能当作实际执行；零分母为 null，允许真实超额执行率超过 100%。
- 凭证/付款按实际操作去重，FAILED 单列；UNKNOWN、RECONCILING、排队、处理中和其他停止状态分别展示，不把未知资金结果归为失败或已付款。

尝试指标只覆盖所选可读提交轮次：预检和提交拒绝按其原 `reportId/roundNo` 归属，允许计入该轮提交前补正版本的失败尝试，不扩展到尚未获授权的后续轮次或从未提交的私人草稿。法人、部门和类别筛选沿最终可读轮次，失败记录的原任职保留用于审计，不向查询者暴露其他草稿版本的明细。

同一原件的查验任务只看到该原件在可读轮次中最后一次提交时已存在的任务；任务之后才完成时展示为当时未完成，不借旧轮次泄漏后来私人验票结果。上述尝试的发生日期仍必须处于所选 UTC 范围。正式提交计数明确称为“已记录拒绝尝试”，存储故障日志不冒充完整审计记录。

借款本身没有费用类别，选择类别时借款余额和借款凭证/付款积压标为不适用；不能按后续报销的某一类别把整笔借款重复归入多个类别。事前计划按原批准行类别过滤，消费与预留仍来自该批准行的当前账本。

## 调用链与职责

调用方：财务报表页面 → 报表 GET 控制器 → 权限约束的只读查询 → 原审批轮次、费用/借款/事前快照、发票任务、凭证/付款记录与新提交拦截记录。

下游：既有 `ExpenseDraftService.read`、`ExpensePlanService.read`、`AdvanceRequestService.read` 保证完整字段读取边界；`SubmissionRoundRepository` 提供原任职/结论，财务仓储提供已保存事实。首次到账沿用 `JdbcPaymentOperationRepository.firstSuccessfulRevision`，不从当前操作更新时间猜测。

职责：指标运算放领域纯计算类型，跨来源和权限编排放报表查询服务；参数验证只在 HTTP 入口。正式提交拦截记录由费用入口协调，在幂等业务事务回滚后记录最小事实，不改通用幂等事务语义。新报表不建立第二套财务状态机。

受影响场景：财务只读统计、原轮次与重提归属、跨币种金额、未知历史、管理员敏感权限，以及失败重试/并发下的重复占用计数。既有业务写入结果、预算、会签、资源占用和原键成功回放保持原规则。
