## 调用链与职责

1. 流程进入固定的 `receiveTask`，由 `FlowableServiceTaskArrival` 读取原生流程实例上的租户、申请、轮次和表单上下文。
2. `ServiceTaskActivationService` 核对已发布定义及已安装契约，只投影节点明确映射的字段，与原审批事务一起写入队列。此时不请求外部服务。
3. `ServiceTaskOperationService` 先按根申请到子申请取得业务锁，再锁队列记录，领取原命令。网络请求由 `ServiceTaskWorker` 在领取事务提交后交给 `HttpServiceTaskGateway`。
4. 已确认的外部结果先独立保存。后续领取通过 `ServiceTaskWaitService` 核对原节点，再在同一事务内推进原生等待、保存申请及轮次、完成业务收尾、审计和通知，并登记推进回执。

状态判断和转换属于 `ServiceTaskOperation`；目录、数据库、HTTP 与流程之间的协调属于应用服务。服务结果不写入表单或流程变量，不能替代人工批准、预算冻结或财务凭证。

Flowable 会在顺序节点间复用 execution，因此队列唯一键包含租户、流程实例、execution 和节点。平台图不允许循环；连续服务节点必须各有自己的操作号。原节点回执不能消费下一个节点。

## 可信配置与固定输入

操作由部署配置 `agentflow.service-tasks.gateway` 声明，默认关闭。每个租户的声明包含操作键、版本、名称、标量参数、目标、凭据、启用状态和超时。设计数据只能引用确切契约及字段映射，不能提供 URL、Bean、脚本或结果变量。

- 契约限制参数数量、类型和 UTF-8 字节数；敏感源只能绑定声明为敏感的参数。隐藏、脱敏或不可读字段不能外发。
- 原命令固定租户、申请、轮次、定义版本及摘要、流程实例、execution、节点、契约和参数；规范摘要不依赖 Map 的迭代顺序。
- 目录版本只追加。相同租户、键和版本不能更换契约或目标；更新凭据和超时时长不改变原目标身份。
- 生产目标要求 HTTPS 和认证；仅数字回环地址支持 HTTP。本地无认证回环须显式启用。禁止 URL 用户信息、查询参数、片段和重定向。
- 凭据只保留在部署配置，不进入契约表、流程定义、命令、审计或错误分类。

`agentflow.service-tasks.worker-enabled` 控制后台调度，默认开启；没有服务节点时不产生外发。领取租约默认 90 秒，配置范围为 15–300 秒；单次 HTTP 超时范围为 1–60 秒。

## 设计、发布和模拟

`ADMIN`、`PROCESS_ADMIN` 通过以下只读接口读取当前租户已安装的契约，响应禁止缓存：

- `GET /api/v1/process-definitions/service-task-options`：按键升序分页，显示每个键的最新安装版本，包括停用版本。
- `GET /api/v1/process-definitions/service-task-options/{key}/versions`：按版本倒序分页。
- `GET /api/v1/process-definitions/service-task-options/{key}/versions/{version}`：读取确切版本；不存在时不回退。

目录返回操作键、版本、名称、契约摘要、参数和可用状态，不包含目标、目标摘要或凭据。版本及版本游标均为十进制文本，支持到 `9223372036854775807`；客户端不能转成浮点数。分页默认 30、最多 100；未知或重复查询参数拒绝。

`ServiceTaskBindings` 负责目录与字段模型之间的检查。草稿允许保留已安装但停用的原引用；发布、模拟及发起要求原操作当前可用。主流程发起和子流程实际激活都校验本次映射值，未选择的分支也检查，避免后续审批才发现必填参数缺失。子流程发布依赖检查包含其服务引用。

两个设计视图、撤销、模板导入导出和配置比较保留同一份原引用与映射。选择另一版本时必须重新配置来源；刷新目录和出现新版本不会自动替换。隐藏或脱敏源不可映射，受限源只能进入声明敏感的参数。画布的 `x`、`y` 只允许有界数字，不进入服务参数。

模拟使用测试数据校验原契约、字段和实际值，只计算路径，不生成命令、不产生外部调用。每条完成路径仍需人工审批依据。

## 按原轮次查看运行记录

申请详情的“服务运行”页签通过 `GET /api/v1/applications/{id}/rounds/{roundNo}/service-tasks` 读取记录。查询服务先复用申请详情授权，再读取同一事务快照中的原轮次、原发布定义和原操作；申请人、实际参与人和有权查看申请的管理员可读。仅有流程设计权限不代表能读取其他人的申请。

接口按不可变的创建时间和操作号分页，默认 25 条、最多 100 条；游标必须属于同一申请和轮次。没有进入服务节点的真实轮次返回空列表，不存在的轮次返回 404。未知、重复或非法查询参数返回 400，响应禁止缓存。查询不会领取任务、续租或调用接收方。

运行记录只返回节点名称、原契约名称及完整文本版本、操作编号、封闭状态、时间和配置可用性。不返回参数、目标、凭据、摘要或任意回执正文，管理员同样受此约束。旧名称取自原定义和原命令，不被当前同名配置覆盖。

页面区分外部操作结果与原流程推进：结果未知时提示按原号核对；成功但暂停时等待恢复；原轮次已结束时不会提示继续新轮次。服务完成仍不代替人工批准。账号、申请或轮次切换会取消读取并清除旧数据；读取失权、注销、迟到响应和翻页期间申请版本变化都有范围回归。

运行记录阶段通过 62 项 Java 和 39 项前端范围测试，OpenAPI 校验为 337 个操作、677 个 schema、123 份请求样例。固定安装包的三轮实际 HTTP 验收均先读到 `EXECUTING/PENDING`，强退重启后读到同一操作号的 `APPLIED/ADVANCED`；每轮恰好一次执行、一次原号查询，再由人工审批结束。测试数量与前一阶段存在重叠，不累加；Vue 模板测试不等于浏览器验收。

## 固定 HTTP 协议

协议版本为 1，只访问配置目标下的 `execute` 和 `query`，均使用 JSON POST。

- `execute` 发送 `protocolVersion`、`commandDigest` 和完整原 `command`；`Idempotency-Key` 为原操作 UUID。
- `query` 发送协议版本、租户、原操作号、原命令摘要、操作键和版本、契约摘要。查询不重发参数，也不使用执行幂等头。
- 响应必须回显协议版本、租户、操作键和版本、契约摘要，以及绑定原操作号和命令摘要的 observation。
- `APPLIED`、`REJECTED` 必须提供有界凭证和完成时间；`PENDING`、`NOT_FOUND` 不得伪造终态事实。`NOT_FOUND` 只允许出现在查询响应中。
- 请求上限 256 KiB，响应上限 16 KiB；整个响应读取受超时约束。重复 JSON 字段、未知字段、标量类型强转、尾随内容、错误 UTF-8 和身份不匹配均拒绝。

外部服务必须按原操作号持久保存摘要和结果，重复执行相同原命令不得重复产生副作用；同号异摘要须拒绝。平台不会用新操作号掩盖未知结果。受控回环测试只能验证本地协议，真实接收方的幂等和留存仍须企业联调证明。

## 暂停、停止和未知结果

| 情况 | 行为 |
| --- | --- |
| 首次待发且原轮次活动 | 领取执行 |
| 首次待发且暂停、配置停用 | 保留待发，无外发尝试 |
| 首次待发且原轮次已结束 | 取消未发送命令，标记原等待失效 |
| 执行超时、回执丢失、进程退出或领取过期 | 转为未知；先查询原号 |
| 查询确认原号不存在 | 使用同一个操作号、同一输入重新排队；重新发送前仍检查原等待 |
| 原轮次已停止但外部结果未知 | 继续查询原事实；确认后不再推进原流程 |
| 已成功但流程暂停 | 保存成功回执，恢复原等待后才推进；不再次执行 |
| 业务拒绝 | 保留拒绝终态，不自动通过或换号执行 |
| 引擎推进或通知失败 | 本次推进事务回滚；此前确认的外部回执保留，重试本地推进 |

调度退避只改变 `poll_at`，不增加外发尝试或改写业务事实。暂时停用操作可以继续查询其原目标；移除配置、全局关闭或改变目标后不能向其他地址追查旧命令。

## 数据与尚待完成内容

V106 增加可信目录安装锁、不可变契约目录、原命令与推进状态、连续修订四张表。激活发生在第一轮提交事务内，原轮次记录可能尚未插入，因此命令保留申请外键，领取时再核对已提交的实际轮次。

领域、公开入口、原生执行及相邻流程的范围回归和前端组件验证见本次证据。固定安装包已用独立 H2 文件库、真实 HTTP 和合成接收方验证目录到人工审批的实际链路；组件测试不等于真实浏览器验收。

重启测试暴露了 H2 文件库持久性缺口：领取事务已提交并产生外部效果后，立即终止进程曾丢失申请或领取状态。独立子进程测试复现了默认 500 ms 延迟窗口；关闭延迟后，新库可以通过，但已有库正常关闭并重开后仍复现了“未先查询就重复发送”。不能把同进程事务测试、单次成功恢复或只读配置断言当成完整证明。

进一步的纯 JDBC 复现将第二个缺口限定到已有文件空闲区块的复用：先创建并更新大块夹具形成空洞，正常关闭，重开后更新领取版本，提交后立即强退，恢复结果仍为旧版本。它不依赖 Spring、Flowable 或工作线程调度。正式回归先在候选 `WRITE_DELAY=0;ACCESS_MODE_DATA=rws` 下失败，排除了仅靠同步文件访问解决问题的假设。

默认数据源改为 `WRITE_DELAY=0;REUSE_SPACE=FALSE`，同时消除延迟提交窗口和区块复用路径；逻辑放在数据源配置层，不在工作线程中等待或补发命令。两组独立进程对照分别使用实际失败库副本和即时生成的碎片库，各通过 10 轮。最终 177 项 Java 范围测试通过，安装包默认配置的三轮强退恢复验收也已通过：每轮恰好执行一次、查询原号一次，保留原输入摘要，最后由人工审批完成流程。[H2 写入延迟定义](https://h2database.github.io/html/commands.html#set_write_delay)和[2.5.250 的区块复用配置说明](https://github.com/h2database/h2database/blob/version-2.5.250/h2/src/main/org/h2/engine/DbSettings.java)对应这两个设置。

禁用区块复用会增加 H2 文件增长速度，自定义 H2 文件 URL 必须保留上述设置。已有文件仍可打开；不会自动改写历史业务记录、删除旧库或整理文件。文件容量应纳入本地维护，长期运行与生产数据库仍按项目 PostgreSQL 部署方案验收。本阶段只验证应用进程强制退出，不扩展成断电或配套备份恢复结论。

可重复验收脚本仅启动自己的回环进程和合成接收方，在 `/fyoung/tmp` 新建独立目录，并直接使用安装包默认 H2 URL。每轮先正常关闭并重开已有库，再在合成效果已保存、执行回执尚未送达时强制终止应用；重启后必须查询原号、避免再次执行，并通过人工审批。脚本退出前停止自己创建的应用和接收方，结果、日志和文件库保留在输出目录。

```sh
python3 scripts/check-service-task-restart.py \
  --java "$JAVA_HOME/bin/java" \
  --jar agentflow-server/target/agentflow-server-0.1.0-SNAPSHOT.jar \
  --cycles 3
```

脚本不覆盖真实企业接收方、浏览器或 PostgreSQL 的验收。后续改变数据库版本或默认文件连接参数时，需要再次执行这组验收。
