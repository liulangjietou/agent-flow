# 原还款复核与真实退回

更新：2026-09-29。独立调整首先覆盖已确认借款还款的完整原件复核与全额真实退回，数据库新增 V56。V58 已扩展多笔部分退回，当前规则见 [部分退回](partial-repayment-returns.md)；下文验证数字保留 V56 阶段口径。企业资金系统和 ERP 仍通过配置接入；本地合成服务的结果不替代企业联调。

## 业务与职责

原还款保留收款流水及员工借款贷方分录。外部撤销、未核清或倒退版本使对应还款进入待核对，不能直接删除原还款或增加欠款。财务明确确认时有两种结果：

- `CONFIRMED`：当前原收款仍有效，原金额、流水和贷方分录一致，仅解除这笔还款的冻结。
- `RETURNED`：原收款已撤销，且已实际全额退回给原员工、ERP 已过账同额借款借方调整。第一次确认追加独立退回记录，增加同额未还款；以后核对同一退回不会重复记账。

仅收到撤销结论或不完整材料时为 `UNRESOLVED`，不能裁决。已确认退回不能再以 `CONFIRMED` 删除，也不能更换退款流水或借方分录。新的还款必须使用新的原收款，不得复用已经退回的旧收款再次冲减。

累计原收款减去累计已确认退回，得到净有效还款；实际放款始终等于报销冲销、净有效还款和未还款之和。原报销预留和已冲销记录保留。每笔还款冻结分别维护，复核一笔不会解除其他还款或原付款的冻结。旧版只有统一还款冻结标记的余额按全部原还款待复核恢复，不能在迁移中自动放行。

调用方为借款详情中的 `AdvanceRepaymentStatus` 与逐笔 `AdvanceRepaymentReview`。`AdvanceRepaymentReviewService` 编排原申请锁、权限、任务、余额、决定及审计；实体 `EmployeeAdvance` 负责逐笔冻结与余额状态变化，`AdvanceRepaymentResolution` 保留原件和独立决定。后台只读任务使用独立线程、90 秒持久租约和短数据库事务，外部调用在事务外执行。

本阶段仅确认外部已经发生的真实退回；不会向资金系统发退款命令或替 ERP 创建分录。原放款、付款凭证、报销凭证的真实退回和冲销仍是后续独立业务。原还款部分退回也不伪装为全额退回。

## 原件与权限

`advance-repayment-adjustment` 只读端口固定到原放款授权时的财务目标，请求包含已在本地入账的完整原还款。返回的汇总修订覆盖原收款、真实退款及借方分录；原收款自己的修订号独立保留。终态证据最多五分钟，并且不能比原收款当前证据更晚到期。

人工裁决采用当前完整证据，不允许低于任何已见汇总或原收款版本，也不能早于更晚观察。历史已见真实退回不能被后续有效还款结论抹除。已确认退回后，普通原收款查询接受一致且不倒退的 `REVERSED`；重新看到有效收款、不同原件或更旧版本仍会冻结。

所有动作要求原轮次完整财务字段可读、明确财务角色、原法人当前有效任职及非申请人身份。幂等回放之前再次授权。申请人可读原还款、独立退回和已确认决定，不能读取候选材料或发起裁决；管理员不增加旁路。原付款有争议时仍可核对已经发生的还款事实，但其独立付款冻结保持。

## HTTP 与持久化

统一前缀 `/api/v1/advance-requests/{id}/repayments/{repaymentId}`：

| 方法与路径 | 内容 |
| --- | --- |
| `GET /review` | 原件、净余额、已确认退回、最近决定及当前财务自己的候选。只接受可选 `roundNo`。 |
| `POST /review-checks` | 借款展示版本及核对说明；202 仅表示只读查询排队。 |
| `POST /resolutions` | 借款版本、原查询及其版本、展示结论、材料编号和说明；不接受员工、金额或目标。 |

V56 新增查询、查询修订、逐笔裁决和真实退回四张表。裁决绑定同租户原收款、已消费查询修订及实际借款余额修订；仓储重放相邻余额状态以确认决定确实对应本次变化。退款按原还款、原法人下资金流水及会计分录防重。余额、任务消费、决定和审计同事务保存，约束失败全部回滚。

页面分别显示累计原收款、已确认退回、净有效还款、报销冲销和未还款。查询和裁决分开确认，资金及分录金额只读。网络结果未知保留原幂等请求；身份、借款或轮次变化丢弃旧响应；读取或写入失去权限立即清空原件及表单。
