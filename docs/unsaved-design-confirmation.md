# 未保存流程修改的确认

流程设计器中有未保存的修改时，以下操作先显示应用内确认对话框。默认焦点位于“继续编辑”；取消不会保存、发布、复制或恢复请求，也不会替换当前图、表单和名称。

| 操作 | 确认后的行为 |
|---|---|
| 切换已保存流程 | 重新从当前列表查找原目标 ID，再替换编辑内容 |
| 新建流程 | 清空当前编辑内容，进入尚未保存的新草稿 |
| 复制流程模板 | 按原目标标识、名称和模板版本创建独立草稿 |
| 打开模板副本 | 读取原目标 ID，加载当前租户的副本 |
| 退出登录 | 按现有退出逻辑清除会话及编辑内容 |
| 恢复流程定义或模板复制请求 | 恢复原请求；结果仍需用户核对，不自动发布或提交 |

已保存的内容、只读发布版本无需放弃修改确认。复制已发布流程为新草稿仍保留原来的图与表单。页面关闭或刷新时的浏览器 `beforeunload` 保护继续保留，它与应用内导航确认承担不同职责。

## 交互与职责

`App.vue` 掌握编辑状态、原操作及会话，负责决定是否提示，并在实际执行前重新检查当前账号、租户、页面是否仍存在，以及操作各自的权限和写锁。恢复请求允许确认尚未明确结果的原操作，不会被普通写入锁拦住。

`UnsavedConfirmation` 只保管一个待答请求。再次请求不会覆盖原意图或共享其确认结果；每次答复关联独立编号，旧组件的迟到事件不能答复新请求。账号变化取消等待；页面卸载后，尚未恢复执行的 Promise 也不再放行操作。

`UnsavedConfirmationDialog.vue` 只处理呈现和键盘交互：

- “继续编辑”、Escape 和遮罩点击均取消。
- Tab 与 Shift+Tab 在两个按钮之间循环。
- 对话框位于页面背景之外；背景设置 `inert`，不能点击或通过键盘操作。
- 关闭后恢复触发控件的焦点；原控件已移除、禁用或不可交互时，将焦点交回工作区。

确认发生在执行动作之前，不改变服务端的租户隔离、乐观锁、权限或幂等协议。已经发送的请求继续按原请求恢复机制处理，不能用关闭对话框代表撤销服务端事务。

## 验证范围

执行 `npm run test:requests` 可验证确认状态的取消、重复意图、迟到答复、会话/锁变化和卸载边界。这些 Node 测试不挂载 Vue，不能代替浏览器的焦点和实际调用链检查。实际浏览器验收应覆盖上述六个入口、取消前后内容一致、恢复原请求以及窄屏布局。
