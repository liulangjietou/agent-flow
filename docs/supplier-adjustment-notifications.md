# 供应商应付调整通知

F17 的供应商应付调整准备、ERP 执行、人工裁决、安全结束及本地账务完成已接入通知与原编号详情。本阶段完成本地实现和范围验证，完整结果见 [阶段证据](evidence/supplier-adjustment-notifications-20261003.json)。F17 整体保持 OPEN。

## 调用链与事务

调用方是原申请财务入口和后台工作器。`SupplierAdjustmentPreparationService` 保存原银行、实际登记回款、原核销或前次调整、记账日期及财务人员；`SupplierAdjustmentService` 保存发送、原号查询和安全结束；`SupplierAdjustmentDisputeService` 保存具名裁决。这些应用服务在业务事实落库后发布同事务事件，通知服务仅投影持久事实。

ERP 调整成功先在独立事务提交。之后工作器重新读取银行原件，由 `SupplierAdjustmentCompletionService` 在另一个事务保存完成表、账本修订、资金分录及应付占用，并发布完成事件。通知失败与所在业务事务一起回滚；本地完成失败不会抹去此前已经提交的 ERP 成功，恢复继续使用原调整。

准备失败、依据变化、发送前复查不可用、结果未知、权威查无、争议和明确拒绝分别提示。正常排队、正常等待与主动查询保持安静。安全结束依赖实际保存的具名决定，明确拒绝本身不代替安全结束；结束前后操作版本相同时仍能通知实际结束。

## 原参与人及去重

接收人来自原申请人、本次准备的实际财务人员，安全结束还包括本次实际结束人员。当前有效人员及法人资格会在保存消息、外发领取与重试时复核。管理员身份不提供敏感字段旁路，消息中不复制金额、账户、入款流水、ERP 分录或指令摘要。

去重键为 `supplier-adjustment:<原准备及调整编号>:<事实种类>`。自动重读、重复回执和重复办理不会刷同类消息。已有本地完成凭据后的原号重查不会补发“本地尚未完成”的中间结果，即使原财务此前停用、后来恢复任职也是如此；首次 ERP 成功仍有独立通知。

## 消息详情

`GET /api/v1/notifications/{id}/supplier-adjustment-target` 只接受本人消息编号，拒绝替代调整或租户参数，成功响应禁止缓存。详情重新核对当前原申请轮次的字段权限，展示消息发生时的事实及该次准备、ERP 操作的当前状态。

本地完成按本次调整编号恢复实际 ERP、银行和回款账本修订，仓储重放原账本变化。后续追加资金、另一次调整以及原操作后来的争议都不能替换或抹去这份历史证明。旧失败准备和旧安全结束消息不能借用新调整的完成凭据。

读取不执行 ERP 查询、资金登记、账务完成或已读写入。页面仅提供重新读取和原轮次导航；身份切换、失权、超时、卸载和来源校验失败清除旧数据，迟到结果不能回填。

实际 Vue 组件、只读接口、原号业务流程和同事务故障恢复分别验证。固定安装包、浏览器、PostgreSQL 及真实企业财务系统仍需独立验收；当前阶段不能代替 F17 或全项目整体验收。
