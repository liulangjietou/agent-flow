# 分支覆盖、重叠与发布检查

流程设计器检查同一数字字段上的条件是否覆盖表单允许的输入，并给出可直接用于模拟的精确示例。错误和提醒有不同的发布行为：

| 情况 | 结果 | 发布行为 |
| --- | --- | --- |
| 存在可提交的输入，所有条件均不满足，且没有默认分支 | `BRANCH_COVERAGE_GAP`，提供示例值 | 阻止发布 |
| 多个非默认分支同时满足 | `BRANCH_OVERLAP`，提供按原顺序排列的连线标识与示例值 | 提醒，仍取首个匹配分支 |
| 条件跨字段、不是数字字段、没有表单契约，或超出分析预算，且没有默认分支 | `BRANCH_COVERAGE_UNPROVEN` | 提醒，需要设计者核对 |
| 存在默认分支 | 默认分支覆盖未匹配情况，仍检查可分析的重叠 | 不因遗漏阻断 |

例如 `amount <= 5000` 与 `amount > 8000` 没有覆盖 `6500`，需要补齐条件或添加默认分支。`amount <= 5000` 与 `amount >= 5000` 在 `5000` 重叠，执行顺序保持原样，不自动修改条件或重新排序。

## 领域规则

`BranchCoverageAnalyzer` 位于领域层。先完成结构和字段类型校验，再解析发布版本绑定的条件 AST。对同一 NUMBER 字段，比较式仅可能在其数值阈值发生真值变化；分析器检查各阈值点及相邻开区间，并使用原领域求值器计算每条分支。它支持同字段的比较、等于、不等于、存在性、括号、且/或和取反，不展开指数级的逻辑组合。

分析范围取自本版本表单的最小值、最大值与必填约束。必填字段不把缺失值当作可提交输入；选填字段额外检查未填写情况。`!(amount > 5000)` 对未填写值为 true，保持条件语言已有语义。

所有示例均符合平台 38 位有效数字、18 位小数上限，以字符串返回。开区间中点超限时，检查各允许小数位数的可表示格点；确实没有可提交数值时不产生错误。例如 `amount <= 0` 与 `amount >= 0.000000000000000001` 之间没有有效输入遗漏。

预算按“边界点/区间数量 × 比较项数量”计算，上限 250000 次比较估算。超限明确返回无法证明覆盖的提醒，不把未完成分析标为覆盖完整。每组相同的同时命中分支只返回一个数字示例，未填写另行区分；存在多个遗漏区间时，用一个数字反例即可证明覆盖不完整，不声称列举所有遗漏值。

## 保存、模拟和发布

- 草稿创建、更新与模板导入继续允许保存结构和类型正确但覆盖不完整的配置，以便逐步修改。模板导入不会自动发布。
- `POST /api/v1/process-definitions/validate` 保留 `errors` 字段，新增 `branchDiagnostics`。区间遗漏加入 `errors`，重叠和无法分析只进入诊断提醒。
- 示例模拟继续执行指定数据的真实条件语义。静态覆盖有遗漏时仍可模拟已覆盖输入；模拟不代替发布检查。
- 发布服务在事务内读取实际持久化图并重新检查。遗漏返回 `422 INVALID_DEFINITION` 及 `details.definitionErrors`，不分配发布事实、不部署引擎、不修改草稿 revision。
- 可发布的提醒随 `DefinitionPublication.ValidationSummary` 保存，新增 `BRANCH_COVERAGE` 检查标识。历史摘要没有此标识时不补造检查事实，提醒列表为空。
- 已发布版本和已启动实例保持原配置与分支顺序。新检查不会回写或重解释历史实例。

## 设计器交互

点击“校验流程”后，编辑停顿 450ms 自动重新检查；内容变化、切换流程/账号、离开设计器或关闭校验时，取消旧请求并清除旧结果。接口超时或错误不视为校验通过。错误节点标红，诊断可以定位条件节点和重叠连线。数字示例使用原字符串，不转 JS 浮点数。

发布确认窗口先展示当前检查结果和提醒，存在阻断错误或尚未取得检查结果时不能确认发布。正式提交仍重新校验。发布记录展示当时的检查范围和提醒。

可重复浏览器步骤：

1. 配置同一必填数字字段的 `<= 5000`、`> 8000` 两条分支，取消默认分支；校验应出现遗漏示例和红色条件节点。
2. 将第二条改为 `> 5000`，等待自动校验，错误应消失；改成 `>= 5000` 后只出现重叠提醒。
3. 将字段改成选填，检查未填写分支；增加 NOT_EXISTS 或默认分支后再次核对。
4. 快速连续修改表达式并切换流程，旧校验结果不得回填；打开发布确认应先展示当前提醒。
5. 确认发布后读取发布记录，提醒顺序与发布时一致；交换分支顺序发布新版本，已有实例仍按原版本执行。
