# 报销部分调整业务通知

部分调整的单侧准备、原预算差额、原挂账差额、资源执行、安全结束和争议裁决已接入消息中心。该阶段完成本地范围验证；F17 整体仍为 OPEN，当前已编号剩余任务仍为 34 项。详见[阶段证据](evidence/partial-expense-notifications-20261003.json)。

## 调用链与职责

人工部分调整入口和后台工作器分别调用准备、财务执行、资源执行、明确动作及裁决应用服务。领域继续决定可接受的业务状态；仓储验证原结算、规范化操作登记、连续修订和实际资源完成证明。应用服务在结果保存后发布 `ExpensePartialAdjustmentChanged`，站内消息与外发意向随业务事务一起提交或回滚。

准备读取失败与来源失效分别通知；正常排队、准备就绪、原系统处理中及主动原号查询保持安静。预算和挂账按各自原命令报告未知、查无、拒绝、到期、停止、争议及成功。任一侧成功都不能代替资源完成。资源受阻、实际完成、安全结束和具名争议裁决各有自己的事实来源。安全结束停止未执行命令时，不另外制造两侧失败消息。

## 原操作和读取边界

去重键为 `expense-partial-adjustment:<调整编号>:<来源类型>:<具体来源编号>:<事实>`。来源类型限于 PREPARATION、BUDGET、ACCRUAL、ADJUSTMENT、DISPUTE；准备、两侧命令、调整与裁决使用各自真实编号。来源类型必须与事实匹配，UUID 必须是规范形式。

两侧可以分别重新授权，因此只固定根调整编号不足以保护旧消息。读取预算、挂账及裁决消息时，沿连续修订找到**同一原操作最后所在的调整记录**，再核验该修订的规范化操作登记和完成证明。后来的替代命令不会换入旧消息。页面明确标注“原操作最后记录”，不会把历史修订声称为根调整当前状态。失败准备只返回原准备；裁决还须匹配数据库中的实际决定和原操作编号。

`GET /api/v1/notifications/{id}/expense-partial-adjustment-target` 固定本人原消息，核验原结算精确修订、申请归属、来源事实与发生时间。创建及外发领取复核当前人员及法人任职；详情再校验原轮次字段权限及独立财务资格，管理员身份不能绕过。接口拒绝查询参数、返回 `no-store`，不触发外部查询、调整、授权或已读写入。

消息详情只投影定位、状态、版本、时间、稳定问题分类、原观察和冲突观察、实际完成／结束及裁决关联。金额、账户、原财务快照、外部引用、人工证据正文与办理许可不会返回。
