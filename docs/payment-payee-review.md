# 本人收款账户复核与重新授权

本地实现日期：2026-09-29。适用于借款放款和报销付款；真实企业账户维护由原财务系统负责。

## 办理规则

原授权必须已作废、到期或安全结束，且仍是该业务轮次最新的授权，才能请求本人账户复核。已有执行、未知、查无、到账、退回或争议交易继续占用业务，不能通过复核绕开原资金处理。

财务登记读取意图后，后台向原目标读取同法人、同申请人的当前账户。读取成功为 `READY`，不生成新授权。财务看到脱敏账号和证据期限，明确选择“按复核账户授权”后，复核才与新授权原子绑定。出纳仍须单独选定出款账户并确认执行；登记执行和真正发送前继续读取两端账户，主数据再次变化会停止新发送。

一次读取证据最多有效五分钟，外部返回更短期限时采用更短期限。只能由请求复核的财务消费其最近一次 `READY` 结果，版本必须与页面相同。新的复核替代旧结果；过期、读取失败或来源变化必须重新登记复核。普通“按原批准账户授权”仍使用审批时冻结的账户。

## 调用与职责

| 环节 | 调用方与下游 | 约束 |
| --- | --- | --- |
| 登记读取 | 财务页面 → `FinancePaymentActions` → `PaymentPayeeReviewService` | 当前字段权限、法人任职、原业务锁、展示版本、读取意图与审计同事务；无外部 HTTP |
| 事务外读取 | `PaymentPayeeReviewWorker` → `PaymentAccountsPort.currentPayee` | 原租户及财务目标、同法人本人；领取和结果各自短事务 |
| 复核状态 | `PaymentPayeeReview` | 实体维护状态、租约、证据期限、单次消费和不可变条款 |
| 新授权 | 财务再次确认 → 原授权接口 | 最新复核、当前批准与挂账、新授权及证据消费同事务；前端不传账号或金额 |
| 执行与到账 | 付款来源、借款余额、费用核销、付款凭证 → `PaymentPayeeEvidence` | 按持久复核回溯到原批准账户，保留原金额、业务和批准轮次 |

`PaymentPayeeEvidence` 负责跨聚合证据读取，避免将仓储放进借款实体，也避免各个资金下游分别放宽“账户必须等于原批准账户”的条件。多次换账户时逐次核验已消费复核和已结束的旧授权。证据过期不抹去已签发授权的历史依据；当前账户可否执行另由发送前复查决定。

## 持久状态与接口

V52 新增 `payment_payee_review` 和修订表。输入引用原授权修订与凭证修订；新授权绑定具有租户外键和唯一约束。原 `PaymentAuthorization.Terms` 的字段和 JSON 保持不变，避免历史条款的文本比较失效。旧授权、原批准账户、原支付命令、原回执不回写。

`QUEUED → RUNNING → READY → CONSUMED` 是成功路径。读取异常为 `UNAVAILABLE`，外部明确拒绝为 `BLOCKED`，来源或人员不再有效为 `VOIDED`。超时租约回到原记录 `QUEUED`；旧领取结果不能覆盖新领取。失败不会自动无限重试账户系统。

- `POST /api/v1/payments/{id}/payee-reviews`：原授权版本、凭证版本、说明；202 只表示读取意图保存。
- `GET /api/v1/applications/{id}/payments`：当前财务自己的最近一次复核、掩码、期限和允许动作；申请人没有未授权复核数据。
- `POST /api/v1/applications/{id}/payments/authorizations`：可选的 `payeeReviewId` 与 `payeeReviewVersion` 必须成对，成功时只能消费一次。

所有写入沿用原幂等键和当前权限检查。未知结果恢复原请求，刷新不会自动发起复核或授权。

调度默认启用，可通过 `agentflow.payments.payee-review-worker-enabled=false` 暂停；读取租约 `payee-review-lease-seconds` 默认 90 秒，范围 15–300 秒；独立轮询间隔 `payee-review-poll-delay-ms` 默认 1000 毫秒。

## 验证记录

最小接口测试先确认旧版本返回 404。增加换账户后的付款至归档测试，复现旧下游仅接受原账户，造成银行成功结果无法在本地提交；修复后原批准保留，新账户授权能够完成核销和归档。

- 领域 29 项；H2 报销 55 项；H2 付款、升级和契约 41 项通过，范围之间存在重叠。
- PostgreSQL 91 项通过，包括迁移、并发单次消费、原文不变、权限、回滚、报销归档、借款余额及付款凭证。
- 前端 20 项与生产构建通过；OpenAPI 163 个操作、279 个 schema、53 个请求示例通过校验。

真实本地 HTTP 与浏览器验收使用隔离演示库和合成财务服务，实际 HTTP 19 项、页面复核及独立授权、到账和凭证已验证。升级前已备份验收库；窄屏检查没有水平溢出，已恢复尺寸。结果记录在 [验收证据](evidence/payment-payee-review-20260929.json)。企业员工账户服务及真实资金系统的业务语义需在目标环境验收。
