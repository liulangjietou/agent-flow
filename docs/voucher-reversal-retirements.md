# 冲销命令安全结束与重新准备

更新：2026-09-29。V63 已完成本地 PostgreSQL、真实应用 HTTP 与浏览器验收，财务集成使用回环合成服务。数据迁移、命令执行与权限验证不代替真实企业接口联调。

## 结束规则与职责

调用链为原凭证办理页面 → 当前独立财务和原轮次完整字段授权 → 锁定原申请、业务与凭证 → 领域核对冲销及原件 → 同事务保存结束依据、停止命令、释放占用并通知资金/结算领域。原命令、准备及全部修订继续保留。

只有两种依据允许结束：从未领取发送，或 ERP 绑定原命令明确返回过账前的期间关闭、法人不可用、科目不可用、授权拒绝。结果未知、查无、已受理、已过账和回执争议均不能结束；原件变化、原件未过账、已有冲销的失败原因也不能用于重新创建命令。发送、查询和结束共用原来源锁，领取与结束并发只有一方成功。

结束前必须重新查询同一原凭证仍有效过账，观察时间不早于冲销最后更新，且不超过五分钟。原件不能存在争议或已登记的独立冲销，当前停用绑定必须就是本次命令。财务只提交显示版本、材料编号和说明，不能自行声明未执行或填写 ERP 状态。

`VoucherReversalOperation` 判断执行状态是否能安全结束，`VoucherOperation` 只解除自己的指定绑定，`VoucherReversalRetirement` 固定两个聚合的前后修订及原件证据。应用服务负责人员、跨聚合锁、持久化和审计。借款领域只解除对应凭证冻结，其他凭证、付款、还款争议保持；报销恢复原结算前重新复核付款、批准和预算。任何一步失败都回滚，不重复消费发票、预算或借款资源。

## 持久化与公开办理

V63 在冲销操作上增加当前占用与结束时间，将原来永久唯一的原凭证约束改为“每个原凭证只有一个未结束命令”。升级只回填关系列，保留旧命令与状态 JSON。结束表通过同租户同原件外键，分别引用原件恢复前后、冲销停止前后的精确修订；原状态为失败时，失败回执和版本原样保存。从未发送的队列会停止为 `VOIDED / FINANCE_RETIRED`，不能再领取执行。

`POST /api/v1/applications/{id}/vouchers/{operationId}/reversal-execution/retirements` 支持幂等，回放之前重新检查当前财务权限。工作台读取只展示当前命令及完整结束历史，结束的候选不再冒充待授权候选。新命令仍需重新核验原件与期间，并由财务明确授权；旧命令不能通过查询、重发或新编号复活。

页面展示结束依据、原件版本与核对时间，要求材料、说明和再次确认。未知写入保留原路径、正文及幂等键，身份切换清除材料和迟到响应。凭证修订变化会通知所属借款/报销明细重读相关资金和结算，初次读取、同版本刷新及旧身份响应不会触发联动。

## 本地验证

领域相关 49 项、H2 重点服务端 25 项、PostgreSQL 服务端 150 项通过。后者包含费用提交与结算 95 项、借款与还款 38 项、公开契约 5 项、冲销网关 11 项、V63 迁移 1 项。前端凭证及借款范围 78 项、报销范围 25 项通过；这些范围与早期阶段测试有重叠。生产构建通过，保留原有大块打包提示。OpenAPI 为 182 个操作、344 个 schema、67 个样例，作者检查 777 个 Java 文件、1425 个命名类型，缺失和解析错误均为零。

浏览器验收暴露余额联动缺口：此前只刷新凭证面板，借款余额仍显示旧值。原测试仅覆盖面板自身，新增最小用例先失败（应通知一次，实际零次），再补充凭证变更事件和父明细刷新。实际第二次结束后无需手动刷新资金区域，可用余额从冻结的 0 恢复为原 300 元，未还款仍为 300 元。

V62→V63 升级前生成 618794 字节数据库备份，本阶段未执行恢复；26 张既有业务表升级前后保持数据。两轮通过的 HTTP 验收共 34 次请求（含登录），28 份业务响应符合契约；两次浏览器结束都支持原幂等回执恢复。原凭证持续有效过账，两笔独立命令各自在过账前拒绝，均保留历史，没有新的过账或银行交易。18 张不涉及本次修改的表全量保持；旧修订、原命令文件及 4 个附件原文保持。被办理的旧借款余额早于新增列表字段，保存时使用领域既定空集合和 false 默认值；金额与历史原文保持。
