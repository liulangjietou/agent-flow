# 会签加减签

当前已完成全员会签加减签的本地办理：权限与轮次、申请版本、具名审计、通知、幂等恢复、公开 API、页面和个人已办记录均已接通，实际 PostgreSQL、HTTP、浏览器及重启验收通过。财务长期验收服务保持原 V86 包；本功能使用独立的 V86 验收库和服务，没有新增迁移。完整证据见[加减签办理验收](evidence/countersign-membership-workflow-20260930.json)。

## 已采用的规则

- 仅对当前运行的全员会签节点增减人员。新人员必须由应用层按同租户当前审批目录复核，新增后形成一张真实必要待办，仍须实际同意。
- 本次操作人必须是当前任务的实际责任人。委派协助期间只允许回交，不能通过增减签改变原责任。
- 减签只能移除同节点其他尚未完成、且不在委派中的任务。保留操作人自己的审批责任，至少保留一张必要待办；已完成意见不能被删除或改写。
- 同一节点不能再次增加已有未决责任人或已完成审批的人。之前明确移除的人员可另行重新加入，产生新的任务编号，旧取消历史保留。
- 当前责任人数达到 100 后不再增加；已有大名单仍可依规则减签。最初目录解析名单和组织修订保持，显式变更另行记录。

## 调用链与职责

调用方是当前待办的“查看与增减会签人”入口。`CountersignMembershipController` 只处理严格请求、无查询参数、当前资格及幂等回放；`CountersignMembershipService` 负责角色与同租户组织资格、原责任人、实际轮次与发布定义绑定，锁定申请后再次授权，再编排引擎、版本、审计和通知。跨申请与引擎的原子性属于应用层，人员本身的约束仍在领域模型。

查询使用 `GET /api/v1/tasks/{taskId}/countersign-members`，变更使用独立的 `POST /api/v1/tasks/{taskId}/countersign-changes`。ADD 只接受 targetUser，REMOVE 只接受 targetTaskId；必须有 reason、expectedVersion 和原幂等键。申请、轮次、执行编号及人数均由服务端恢复，客户端不能覆盖。读写响应均为 `no-store`，当前角色已撤销时不能重放成功回执；原任务已结束但资格仍有效时可恢复同一结果。

`CountersignMembership` 根据实际未决任务和已完成责任人约束变更，不复制一套持久任务或投票状态。`FlowableCountersignRuntime` 位于引擎防腐层，定位当前任务的多实例父执行，核对逐人事实与原生计数，再调用当前项目 Flowable 7.2 的原生多实例增加或未完成删除接口。修改必须处于调用方事务中。

新增执行显式设置责任人，不重新解析原选人集合。删除采用未完成语义，取消记录进入引擎历史，不能增加已同意计数。适配器在写后再次核对作用域、初始快照、总数差额和已完成数；后段失败由外层事务整体回滚。新任务创建仍经过原期限监听器，原任务不会重新计时。

当前平台图禁止循环，尚未支持子流程，因此同一轮、同一节点的已完成历史可用于恢复本次责任。将来接通循环或可重复激活子流程前，必须先将历史范围绑定到具体激活实例，不能继续沿用这一假设。

加减签记录使用 `ADD_SIGNER`、`REMOVE_SIGNER`，包含实际目标任务、执行身份、变更前后人数和已有同意人数，不伪造批准意见。申请审计、管理员审计与本人已办记录可筛选。新增任务只通知新成员；取消消息引用被移除的旧任务，不包含原因、表单或整个名单。重新加入产生不同任务编号。新成员继续按当前节点的字段和附件权限读取，历史参与不延伸到重提后的新轮次。

页面提交必须明确选择及原因；取消不发送。成功后清除旧表单、重新读取任务版本与人数。结果未知保留原请求和原键，不自动重新提交；成功响应若不符合原操作身份也保留恢复入口。切换账号、任务或版本会取消旧名单读取，迟到响应不能回填。

## 当前验证

新增领域 7 项和真实引擎 7 项。H2 相关领域 7 项、服务端 51 项通过，涵盖既有全员会签、并行审批、委派和期限；独立 PostgreSQL 17.11 的相同领域 7 项、引擎 7 项通过，范围有重叠。PostgreSQL 实际保存 8 张申请、21 张历史任务及 2 条多实例取消记录，库版本为 V86。没有新增迁移，也没有替换长期验收服务。

底层验证覆盖先完成再加签、原快照保留、新增成员的必要审批、移除及重新加入、完成意见保留、完成任务和最后待办拒绝、委派回交、并行节点隔离、单人节点拒绝，以及外层失败时引擎任务和历史整体回滚。适配器拒绝无调用方事务的修改；对外授权由当前应用用例承担。底层阶段的历史证据见[增减签底层验证](evidence/countersign-membership-foundation-20260930.json)。

公开办理新增 17 项集成测试。H2 服务端相关 97 项通过；补齐个人已办查询后，最终 H2 接口、个人工作台、申请搜索及契约 42 项通过，PostgreSQL 领域 7 项和实际接口 17 项通过。前端相关 49 项、类型检查及构建通过；范围互有重叠，不合计为唯一用例数。验证包括两次同版本增员及增员与批准竞争、审计/消息中途失败整体回滚、目录停用、委派保护、下一轮权限隔离、新增期限独立计时以及未定义参数拒绝。

实际 HTTP 的 68 份 JSON 响应符合当前契约，2 次可读附件下载哈希一致；隐藏和脱敏附件仍拒绝下载。浏览器完成取消无写入、增加、移除、重新加入、三人分别批准、原始名单与意见展示、个人已办筛选。实际 500 CSS 像素下页面无横向溢出。一次在审重启保持两张待办、已完成意见、版本、审计与 3 份附件，随后继续办理；最终包再次重启保持两张已批准申请及旧记录，结束后的原加签请求仍回放同一回执。

验收中修复两处入口遗漏，均先有失败测试：写入时 busy 保护阻止原任务重新读取，改为先清除旧表单、结束写入阶段后读取；个人已办动作白名单缺少加减签，补齐查询、筛选和目标人员标签。
