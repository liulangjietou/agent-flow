# 移动端工作空间导航

650 CSS 像素及以下，页头显示“菜单”，点击打开带完整名称的导航抽屉；正文使用整屏宽度。更宽的视口保留侧栏，1050 像素及以下的折叠侧栏仍提供完整可访问名称和悬停说明。原深色导航、青绿色选中态及字体保持。

## 调用链与职责

`App.vue` 根据已认证账号计算 `canInspectSystem`、`canManageDefinitions`，将页面、待办数、会话状态传给 `WorkspaceNavigation`。桌面和抽屉共用 `workspaceNavigation.ts` 菜单配置，选择后回传现有 `page`；退出仍调用 App 原有未保存确认及注销链路。导航不发送审批命令，不修改角色、后端授权、DDD 领域模型或数据范围。

管理员入口继续要求 ADMIN；模板入口要求 ADMIN 或 PROCESS_ADMIN；普通账号可见原有工作区和只读流程入口。Agent 助理仍显示未接入，不以新导航暗示模型可用。

## 交互约定

- 抽屉使用原生模态 dialog，背景不可操作；打开时聚焦关闭按钮并锁定背景滚动。
- Tab / Shift+Tab 在可用按钮间循环，Escape、关闭按钮和遮罩可关闭，焦点返回菜单按钮。
- 选择页面先关闭抽屉，再进入原页面；相同入口也可收起抽屉。
- 退出先关闭抽屉，已有未保存确认随后显示。取消退出保留内容，焦点返回仍可见的菜单按钮。
- 菜单内部滚动，品牌、关闭和退出入口留在可见区域；窄屏触发、关闭、退出和条目均提供至少 44 像素的操作高度。
- 跨过 650 像素断点时关闭模态状态、释放滚动锁；从展开抽屉切到侧栏时聚焦当前页入口。
- 导航键盘事件不会传给设计器，避免菜单中按 Delete 等按键触发画布编辑。

## 缺陷复现与验证

原页面在 390 × 844 CSS 像素下，菜单文字被 CSS 隐藏，多个入口的可访问名称只有相同的 `↗`，普通用户难以区分。原菜单已经有独立滚动，未发现底部入口被永久遮挡。现有 Node 测试主要覆盖请求及状态逻辑，不挂载 Vue，也不验证响应式布局和可访问名称，因此本次使用真实浏览器复现与回归，不新增只比对菜单常量的单元测试。

可重复验证步骤：

1. 在独立本机演示环境登录 admin，实际回读视口为 390 × 844；打开菜单，核对所有菜单名称、分组、当前页及关闭/退出入口。
2. 关闭按钮上 Shift+Tab 应到退出，退出上 Tab 应回关闭；Escape 返回触发按钮，页面恢复滚动。点击遮罩不切换当前页。
3. 从待办选择合成申请，执行批准；另一份填写退回原因并确认退回，再从“我发起”核对两份结果。
4. 设计器关闭自动保存并修改名称，经导航退出；选择继续编辑应保留名称，再次退出并确认应回登录页。
5. 登录 alice，管理员和模板入口不出现，前一账号页面与菜单状态不残留。
6. 核对 320 像素布局，展开抽屉跨到 651 像素后应变为侧栏且没有滚动锁；再核对宽屏。

2026-09-24 实测：390 像素正文与页面宽度均为 390，详情宽 360；320 像素页面宽度为 320，抽屉宽/滚动宽均为 282，底部入口位于 740 像素视口内。651 像素断点、1280 与实际 1707 像素宽屏状态通过。ADMIN 与 alice 菜单、焦点循环、Escape、退出取消、跨断点切换、真实批准和退回均通过。

390/320 像素通过 Chromium 视口仿真、截图和键盘操作验证。浏览器常规尺寸工具因当前缩放实际返回 520 像素，鼠标打开、条目选择及遮罩关闭在该实际宽度验证。未将桌面浏览器结果计为 iOS / Android 真机、软键盘或触摸手势验收。
