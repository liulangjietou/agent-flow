# 供应商原 ERP 核销争议

领域规则、V79 持久裁决、权限接口及页面已实现，H2/PostgreSQL 接口与前端回归通过。实际验收服务仍运行 V78；接续原库升级、实际 HTTP、重启与浏览器验收，当前测试不代表真实 ERP 联调。

## 调用链与职责

调用方是可读取原采购轮次完整财务字段、当前法人任职有效的独立财务人员；原申请人及原付款出纳不能裁决。原核销查询先保存 ERP 事实，财务再针对展示版本明确决定。下游只恢复原核销的本地占用完成，不重新发送银行或 ERP 指令。

核销实体判断近期终态与历史凭证、余额是否一致，应用服务编排当前权限、原申请锁和审计，仓储原子保存相邻修订及具名决定。受影响场景包括 ERP 回执矛盾、原凭证或核销身份变化、成功后返回拒绝、证据过期、并发裁决及恢复后的本地完成。

## 采用规则

- 仅采用原指令最高外部修订的 `SETTLED` 或 `REJECTED`，观察时间五分钟到期后必须重新查询。
- 已确认核销后，采用成功结果必须保留完整原过账，包括核销号、凭证号、台账版本、前后余额及日期。
- 历史中出现成功或 `ALREADY_SETTLED` 提示，即使后来被其他争议候选覆盖，也不能裁决成安全拒绝。真实冲销需要独立调整。
- 普通查询与普通仓储更新均不能清除冲突。专用裁决必须保存独立办理人、外部对账引用、原因和裁决前后版本。
- V79 只新增决定表，两个外键约束原核销的相邻修订；并发只能成功一次，决定保存失败回滚状态及修订。
- 读取决定时重新核对关联修订和当时连续历史。外部纳秒时刻保留在原文中，关系列明确截断到微秒，避免数据库舍入改变核对依据。
- 原银行结果、ERP 已核销事实及既有本地完成各自保留。解除 ERP 争议不会覆盖银行争议或重复完成占用。

## 权限接口与页面

`GET /api/v1/supplier-settlements/{id}/dispute` 返回原核销、当前候选及历史决定。`POST /api/v1/supplier-settlements/{id}/dispute/resolutions` 仅接收展示版本、实际候选终态、外部对账凭据和原因；原号查询复用既有 `finance-actions` 的 `QUERY`。读取与写入回执均禁止缓存，写入及幂等回放前均重新检查当前独立财务资格和敏感字段读取权限。

裁决、原核销修订、审计和适用的本地占用完成共享事务。银行独立争议未解除时，ERP 裁决可以保存，但本地占用继续等待。采用拒绝不会自动结束原操作；后续明确安全结束仍保留决定。投影不返回内部台账标识、原始账户或命令摘要。

页面从每条已外发的原核销记录打开，分别展示原凭证、本次候选和累计前后余额。填写凭据和说明后明确确认；五分钟到期停止提交，身份变化清空旧信息，未知请求按原幂等键恢复。保存期间父面板禁止刷新卸载或切换核销记录，成功后重新读取结算。

新增六项接口工作流测试；H2 相关范围 41 项通过，PostgreSQL 工作流 35 项及同次独立 H2 契约 6 项通过。新增十二项前端测试，相关范围 51 项及生产构建通过。OpenAPI 验证通过（240 个操作、470 个 schema、87 个请求示例），原有 JSON 片段保持。错误查询参数的 400 映射遗漏由测试先失败，再修复，见[接口与页面证据](evidence/supplier-settlement-dispute-api-ui-20260930.json)。
