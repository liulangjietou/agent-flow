# 并行分支设计与运行

流程管理员可以在高级画布添加“并行网关”，把不同职责的审批同时展开，再等待全部分支完成后进入后续步骤。例如：主管、财务、法务分别审批，全部完成后进入最终审批。每条分支内仍可使用单人审批、全员会签和条件网关。

## 设计与编辑

1. 在流程管理中打开高级画布，从节点面板添加并行网关。
2. 拆分网关连接至少两条分支；每条分支最终接到同一并行汇合网关。
3. 汇合网关连接后续审批或结束节点。也可在一个网关先汇合、再拆分。
4. 配置各审批节点的审批人，使用自动布局、校验与模拟检查连接，填写发布说明后发布。

并行网关的出线全部执行，不配置条件或默认分支。需要条件选择时，在对应并行分支内加入条件网关，让互斥路径先合流，再以一条入线到达并行汇合点。[快速步骤](quick-parallel-designer.md)也已支持结构化并行图的展示和编辑，可自动生成配对网关，并在必要时保留条件汇合。下文 743 项 Java 测试等为最初高级画布阶段记录，快速模式的新增验收见链接。

节点与连线支持现有撤销、保存、版本复制、比较及模板文件导入导出。并行区域支持成对嵌套，汇合后才能离开区域；交叉汇合、缺分支、提前结束、普通节点直接汇合并行分支均阻止发布。这是平台当前支持的结构化范围，不表示支持全部合法 BPMN 图。

## 运行语义与 DDD 职责

- `DefinitionValidator` 在入口统一检查结构；`ParallelStructureValidator` 沿无环图传播分支归属，验证各汇合入口恰好覆盖对应拆分的全部分支。领域层不依赖 Flowable。
- `DefinitionSimulator` 在内存中模拟令牌到达与汇合，返回经过的节点、连线及条件决策。模拟编号是确定的遍历顺序，不承诺实际任务的完成先后，也不代办审批。
- `FlowableDefinitionDeploymentAdapter` 生成原生 `parallelGateway`；Flowable 创建并发执行并等待汇合。平台没有建立另一套持久化令牌或投票引擎。
- 各分支的批准继续使用申请版本、授权、事务、审计和幂等协议。只有全部分支完成才创建后续任务，整个流程结束才批准申请。任一退回、驳回或申请人撤回仍终止整轮，其余任务同时结束。
- 并发操作同一申请时，一方成功，冲突方整体回滚并按刷新后的版本重试；不会重复创建汇合后的任务或最终批准通知。

引擎的拆分、汇合及不计算并行出线条件的行为依据 [Flowable 并行网关文档](https://www.flowable.com/open-source/docs/bpmn/ch07b-BPMN-Constructs#parallel-gateway)。平台主动拒绝并行条件线，避免用户填写的条件被引擎忽略。

## 兼容与验收

没有新增数据库迁移，数据库版本仍为 V23。旧顺序、排他分支及全员会签定义保持原语义。新节点复用已存在的图类型；旧应用版本不能编辑或发布新增并行定义，运行回退时需要评估新增定义的使用范围。

2026-09-25 验证：完整 Java **743 项**（领域 190、服务端 553），前端 **255 项**，工具 **38 项**，类型检查、构建及作者检查通过。增加的领域用例覆盖嵌套、汇合后拆分、条件分支、错接和提前结束；真实 H2 引擎用例覆盖两种审批先后、退回/驳回、撤回重提、分支内会签及并发重试。

独立 PostgreSQL 验证了实际并行及嵌套审批、幂等回放、无关账号拒绝和轮次流程图；65 个 OpenAPI 操作的真实响应验证通过。Chrome 验证新增第三个审批分支、连接、自动布局、模拟、发布；服务端回读确认 8 个节点、9 条连线和 3 条并行分支，并运行至最终批准。

```bash
python3 scripts/check-parallel-gateways.py http://127.0.0.1:18180 --exercise
```

具体证据见 [本次验证记录](evidence/parallel-gateways-20260925.json)。企业组织、字段权限、财务、Agent、SLA 与其他高级流程仍按原范围推进；本功能通过验收不代表整个平台完成。
