# 整笔报销资源调整业务通知

F17 的整笔报销调整准备、预算冲正、资源恢复和安全结束通知已接通。本阶段完成本地实现及范围验证，F17 整体仍为 OPEN。完整记录见[阶段证据](evidence/expense-adjustment-notifications-20261003.json)。

## 调用链与职责

人工入口 `ExpenseResourceAdjustmentController` 与后台 `ExpenseResourceAdjustmentWorker` 调用准备、预算执行、资源执行和明确动作四个应用服务。领域继续约束原预算回执、独立财务授权、资源恢复和无副作用结束；仓储验证实际来源修订及完整反向资源明细。原状态保存后，由应用服务发布 `ExpenseAdjustmentChanged`，通知、外发意向与财务状态一并提交或回滚。

准备失败或来源失效分别通知。正常排队、读取就绪、原系统处理中及主动原号查询保持安静。预算未知、查无、拒绝、到期、发送停止、回执矛盾与实际冲正分别表达；预算冲正成功不等于资源已完成。资源受阻与实际完成有独立通知。明确安全结束先停止未发送命令，再保存结束证明，不额外制造一次预算停止异常。

## 原事实与权限

去重键为 `expense-adjustment:<原调整编号>:<事实种类>`。原准备、预算和资源共用该调整编号；不同事实分开，同类重复回执只通知一次。新准备不会替换旧消息。

`GET /api/v1/notifications/{id}/expense-adjustment-target` 固定本人原消息，核验原结算精确修订、原授权输入、同一操作历史和消息发生时刻。资源完成还要求实际持久反向明细，并展示首次完成修订。后续预算复核保留已发生的资源完成事实。

接收人取原申请人、实际发起财务；安全结束增加实际作出决定的财务。创建及外发领取复核当前人员与法人任职，详情进一步校验原轮次敏感字段和财务职责分离，管理员不能绕过。读取拒绝额外查询参数，返回 `no-store`，不触发外部查询、授权、恢复、结束或标记已读。

响应只含原来源定位、稳定状态、版本、时间、问题分类、预算观察与冲突观察，以及实际完成／结束的最小证明。金额、账户、外部引用、命令摘要、授权说明和办理许可不会进入消息详情。
