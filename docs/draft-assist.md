# 普通申请草稿建议

2026-10-02。普通根申请草稿建议已完成后台、页面、真实 HTTP／浏览器、在审副本升级和重启接续的本地验收。票据抽取、预检建议及结构化财务业务 Agent 入口仍未完成；本子项完成不代表 Agent 工作包关闭。

调用方是原申请人的申请详情页。模型适配器只返回建议；人工保存经 `DraftAssistService` 调用原 `ApprovalApplicationFacade.revise`，继续使用申请版本、表单契约和操作审计。涉及草稿、退回、撤回、并发编辑及旧结果复核，不更改审批决定入口。

## 输入与生成

- 仅普通、已保存且绑定版本化表单的根申请可生成；当前申请人须有编辑权。无表单旧申请及绑定专用财务业务的申请返回 `AGENT_DRAFT_UNSUPPORTED`，不会绕过对应业务服务写入。
- 生成要求由本人明确输入；已有内容默认不选。服务端按选择的字段标识读取已保存值，不接受客户端伪造来源正文。说明最长 8,000 字符，加上选定来源最多 64 项、64 KiB。
- 标题及可生成字段可作为目标。敏感字段、附件，以及含敏感或附件列的整张明细均排除；采纳不会丢失这些原有值。可发送 schema 只含业务字段约束，不含审批节点权限和路由配置。
- 每次授权固定原申请版本、实际来源与内容指纹、模型目的地指纹。排队和领取检查版本与目标；外发前再核对实际目标。模型请求不含租户、用户和申请标识。
- 草稿与既有审批摘要共用有界文本 HTTP 客户端，禁止重定向及工具执行，响应上限 256 KiB。每个建议目标唯一且必须符合冻结字段类型；来源须属于本次发送清单。额外动作、伪造来源、截断及非 JSON 结果不能成为可采纳建议。

## 人工采纳与记录

`QUEUED → RUNNING → COMPLETED / FAILED` 是模型执行；`COMPLETED → ADOPTED / DISMISSED` 是人工确认。生成完成不会改变申请。

原申请人可选择模型确实建议过的字段，并修改其值，再明确保存。未选择的字段保持；原模型值、证据及人工修订分别保留。申请正文、原修改审计、建议确认及幂等回执使用同一事务，任一保存失败均回滚。申请必须仍是生成时的可编辑版本；失效建议可以查看或放弃，不能覆盖新草稿。

管理员身份不替代原申请人权限。目录不返回正文，详情和来源只给原申请人；所有读取禁止缓存。成功写回执只含运行 ID、状态、运行版本及实际保存的申请版本。结果未知时必须保留原请求与幂等键恢复。

## 页面与结果未知恢复

原申请人在申请详情页使用草稿助手。输入目录展示实际模型目的地，已有来源默认不选；生成结果逐项显示模型原值、来源和可编辑的人工值，保存字段默认也不选。保存只发送明确勾选的目标，未选字段保持。

助手有未发送说明或未保存核对时，原表单保存、提交、撤回和普通关闭受互斥约束；清空助手输入仅放弃本地内容。每种读取独立取消和限时，身份切换立即清空私有数据，迟到响应不能回填。保存成功后的读取也有等待上限，避免原表单永久锁定。

成功回执须核对运行编号、状态、运行版本与实际保存的申请版本，才能清除原请求。丢失或不完整回执保留原字节和幂等键，恢复后按原申请与运行重读；不会将简短回执当成完整申请，更不会继续提交。申请在审时仅保留历史建议，不能生成或采纳旧建议。

运营页面的采纳率明确标为“审批摘要人工采纳率”，按所选提交轮次统计。草稿建议没有审批轮次，故不并入该指标，也不按申请号连接而重复累计。

## 队列与迁移

同申请最多一个活动生成。领取按申请、运行顺序加锁，模型 HTTP 在事务外执行。领取后通过持久租约限制进程间执行；过期执行结算为失败，晚到结果不能覆盖，系统不自动再次外发原内容。用户可重新明确发起一次新生成。

V99 新增 `agent_draft_assist_run` 与追加轨迹 `agent_draft_assist_transition`，包含同租户申请外键及状态／版本约束。它不改写旧申请、审批摘要及其发送授权，也不自动为历史申请生成内容。验收使用由非空 V98 数据复制的独立 V99 服务；原 V98 服务及源数据保持。升级前 228 张表的 3,778 行及三份文件保留，V99 新增两张表。

## 接口

统一前缀 `/api/v1/applications/{id}/draft-assist-runs`：

| 方法与子路径 | 行为 |
| --- | --- |
| GET `/input` | 当前可发送来源、可生成字段与真实模型目的地 |
| GET | 目录分页，`page` 从 0 开始、默认每页 20、最多 50 |
| GET `/{runId}` | 原始输入、模型建议及人工记录 |
| POST | 排队，202 只表示持久化成功 |
| POST `/{runId}/review` | 选择并保存草稿字段，或放弃建议 |

完整字段、错误响应、幂等与身份要求以 OpenAPI 为准。既有摘要领取资格失效时，任务查询在事务内部返回否定结果，防止权限异常将外层“记录执行失败”的事务一并回滚；真实读取和办理仍保持原权限判断。

本轮 59 项独立 Java 范围（领域 5、服务端 54）通过；其中 27 项在 PostgreSQL 重复通过，包含非空 V98→V99 升级。OpenAPI 302 个操作、602 个 schema、115 个请求示例校验通过。模型调用使用本地合成 HTTP 服务，尚未接入真实企业模型。

新增前端范围 114 项（含 18 项草稿建议测试）、类型检查和构建通过。254 份实际 HTTP／浏览器响应及 64 份成功请求符合契约，其中浏览器响应 26 份，无捕获缺口。真实页面完成部分人工采纳、旧版本阻断、原请求响应丢失恢复、21 条记录分页、500 CSS 像素和在审历史只读验证。

两次重启分别验证完整数据保持和原排队任务只新增一次模型调用；15 笔原待办在第二次重启后保持，随后其中一笔旧在审任务沿原实例实际批准。最终独立服务保留 230 张表、4,019 行和三份文件，原 V98 源库保持。演示认证在服务重启后重新登录，不将重新登录计为业务数据丢失。
