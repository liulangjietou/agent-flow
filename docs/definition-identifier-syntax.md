# 流程编号字符校验与旧草稿修正

数字开头的流程、节点或连线编号曾通过设计预检和草稿保存，直到发布时才由 Flowable 抛出 XML 编号格式异常。现在统一在结构校验中提前报告，写入口返回可修正的 422；已有草稿、已发布图和历史申请不自动改名。

这是 V02 最终版本验收下的已知缺陷修复，不新增独立待办编号，也不表示 V02 或全项目已经验收完成。证据见[本阶段验收索引](evidence/definition-identifier-syntax-20261003.json)。

## 调用链与职责

调用方为设计器、模板预检和定义 API。预检、创建、更新、发布通过 `DefinitionApplicationService` 使用同一 `DefinitionValidator`；模拟及内置模板也复用这个结构校验器。只有通过校验的写入才进入仓储和 `FlowableDefinitionDeploymentAdapter`。

本项目直接把原图编号用作 BPMN 编号，因此可发布编号是受限流程图的输入约束。规则放在共用结构校验层，保存与发布采用同一规则；实体构造和仓储恢复仍允许读取旧草稿，避免把历史错误变成不可读取的数据。

`DefinitionIdentifiers` 使用 Java 标准 XML Schema 校验 `NCName`，没有引入 Flowable 或第三方依赖，也不自行复制 Unicode 字符范围。Schema 为固定本地文本，禁止外部 DTD 和 Schema 访问；每次校验使用独立处理器，只传递文本事件，不将输入作为 XML 解析。标准依据为 [W3C NCName 定义](https://www.w3.org/TR/xmlschema-2/#NCName)。

原编号中的空格、制表符和换行直接拒绝，避免 XML 空白折叠改变身份。合法中文、重音字符、组合字符、下划线以及编号后续的数字、连字符和点号保持原样；校验不执行大小写折叠、Unicode 归一化或替换编号。

## 错误与修正

| 范围 | 预检错误 |
| --- | --- |
| 流程标识 | `INVALID_PROCESS_KEY:原标识` |
| 节点编号 | `INVALID_NODE_ID:原编号` |
| 连线编号 | `INVALID_EDGE_ID:原编号` |

预检仍以 HTTP 200 的 `errors` 返回问题。创建、更新和发布返回 422、`INVALID_DEFINITION` 及 `details.definitionErrors`。无流程标识的旧版图预检请求继续只检查图元素。编号重名的既有错误与检查保持。

界面显示中文原因及原定位编号；含冒号的非法编号不会被错误拆断。模板存在非法编号时阻止导入，保留已读取文件供修正，不自行生成替代编号。

节点或连线可通过定义更新接口明确修正编号与相应引用，再按新修订发布。已保存的流程标识仍不可修改；若流程标识本身非法，使用正确标识创建新草稿，旧草稿继续保留。被拒绝的发布和更新不会改变原图、版本或修订号，也不会生成半份发布记录。

## 复现与验证

原测试覆盖跨种类编号重名，缺少非法字符和真实发布的组合。先完成失败复现，再修改实现：

- 领域回归 26 项中，14 组非法编号被旧代码放行；涵盖数字开头、冒号、空白、斜杠、控制字符和非法起始字符。
- 接口回归 24 项中，6 项断言失败、2 项旧草稿发布抛出 Flowable 编号格式异常。合法 Unicode 编号可部署的用例保持通过。
- 前端新增提示断言先失败，修复后显示对应中文原因，并保留完整定位值。

最终 9 个 Java 测试类合计 106 项通过，覆盖编号、领域规则、定义预检、发布、真实引擎部署及服务任务公开入口。36 项前端范围测试、类型检查、生产构建和 OpenAPI 校验通过；OpenAPI 为 337 个操作、677 个 schema、123 份请求样例。范围测试不等于最终全项目门禁。

扩大回归还发现一条 W01 之前的过期断言：未配置服务节点仍被测试定义为“类型不受支持”。当前已支持可信服务任务，该断言改为“必须明确声明服务绑定”，并将 `ServiceTaskDefinitionTest` 加入本轮范围，保留未配置节点必须拒绝的业务要求。

固定安装包的实际升级验收使用独立 H2 文件库，共完成 42 次 HTTP 检查。旧包创建三类非法草稿、一份合法中文流程和一张在审申请；正常停止后升级为修复包，确认：

1. 三份旧草稿可读，预检返回准确错误，拒绝发布后内容和版本保持。
2. 明确修正节点、连线或使用新流程标识后，三份流程均成功发布；非法原流程标识没有被覆盖。
3. 新建及更新的非法编号返回 422，失败更新不改动已有草稿。
4. 旧在审申请保留同一人工任务编号，升级后完成批准，原已发布定义保持。

本轮没有执行真实浏览器交互或 PostgreSQL 补测；此前浏览器策略检查和 Docker 镜像层 I/O 的环境限制仍在。实际 HTTP 验收不替代这两项。临时实例均由验收脚本创建并停止，现有主工作区及保留运行环境没有被升级。
