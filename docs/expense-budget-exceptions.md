# F09 柔性预算例外审批

状态：本地实施中。依据原费用设计 §8.1 与 §9，沿用用户已授权的推荐规则和连续开发方式。本计划不更改真实企业配置，不推送远端。

## 业务规则

预算来源必须明确允许本次分摊申请例外。预检返回可选的柔性政策来源；没有该字段的历史协议保持刚性。预检成功只表示可以提交，不代表冻结成功。实际首次冻结或重提调整若明确拒绝并提供与原命令、柔性政策绑定的例外凭据，才可以由已发布定义的预算负责人审批。普通 `BUDGET_INSUFFICIENT` 保留自动退回；未知、超时和无效响应不生成例外授权或冻结事实。

新版费用模板设置独立 `BUDGET_REVIEW` 节点，位于财务审核之前的所有可达路径。该节点先等待当前冻结结果：已实际确认冻结时系统记明原操作依据并通过；明确需要柔性例外时才允许负责人作人工决定。它不能被普通相邻同人审批策略跳过，不能由纸件或财务节点兼任。无该节点的旧发布定义保持原行为；提交时发现柔性政策却缺少安全必经节点，整体拒绝，不能让单据进入无法办理的轮次。

人工同意与原生任务、审计、例外记录和新预算操作在一个本地事务中提交。新操作必须引用原拒绝操作、原命令摘要、外部政策与例外凭据、真实审批任务/操作者/审计号；金额、分摊、法人、申请人、期间和目标不能改变。原拒绝操作保持原样。新操作继续使用既有持久幂等和未知结果只查询规则，只有外部返回 `APPLIED` 才算预算冻结。

每轮只允许针对正式提交登记的原预算操作作一次人工例外授权；授权后的预算再次拒绝时保持财务阻断并退回补正，不自动循环生成审批或操作号。财务核减发生在预算确认后，后续调整若拒绝也沿用退回补正；新轮次重新预检和审批。撤回、退回、驳回、作废和关闭不复活旧授权，保留既有占用与释放规则。

预算节点首期使用现有单人决策语义；不接受会签、减签或多个预算节点引入不明确的部分授权。节点可绑定已有角色/组织选人规则，发起人回避、财务职责分离、转交/委派/有效代理和字段权限继续沿用原规则。任何身份都不能通过管理员权限直接查看被隐藏或脱敏的费用依据。

## 职责与链路

1. `ExpensePrecheckEvaluator` 调用 `BudgetPrecheckPort` / `GatewayBudgetPrecheck`，固定外部柔性政策来源；`ExpenseSubmissionService` 在原配置/资源/申请锁内复核，冻结原轮次与原预算操作。
2. `BudgetCommand`、`BudgetObservation` 和 `BudgetOperation` 保留金额、身份、摘要和操作状态约束。可选的新凭据只有完整且绑定当前上下文时合法；缺字段的旧 JSON 与旧摘要保持原样。
3. 新的费用预算例外聚合拥有待预算结果、无需例外、待人工、已授权及结束状态；独立 JDBC 存储关联现有原轮次、财务修订、预算操作及审计，不复制金额台账。
4. `ExpenseBudgetOutcomeHandler` 分流真正的柔性拒绝与原刚性退回。`FlowableTaskFacade` 的人工同意通过 `ExpenseApprovalService` 校验，并在同一事务记录授权和后续预算操作。
5. `ApprovalCompletionService` 组合专门的预算节点推进器。恢复 worker 只在原申请/业务锁中推进已满足条件的等待节点，扫描持久记录覆盖提交后崩溃或事件丢失；不在持锁事务访问外部服务。

异步结果不能成为普通表单可编辑的布尔路由字段：预算结果可能晚于提交及业务审批，因此按本轮原预算操作控制节点和财务守卫。所有人工决策、后台推进与生命周期动作保持申请优先的既有锁顺序。子流程祖先暂停/终止按原执行路径锁处理，不直接推进已暂停或过期流程。

## API 与页面

增加只读原轮次预算例外详情，复用费用明细授权和 `no-store`；明确区分旧未记录、等待冻结、无需例外、需负责人审批、已授权待外部确认、确认成功和拒绝。当前任务显示真实可操作性与阻断原因，隐藏不可用的批准入口不能替代服务端守卫。申请人、审批人可以核对冻结政策来源、原预算操作及人工依据；不提供客户端生成或修改外部授权的写入口。

定义设计器明确解释预算职责和外部确认要求，费用模板升级但不改写原发布版本。预检提示柔性政策只代表可以申请例外；审批同意后仍显示预算待确认。身份、单据或轮次切换清理迟到读取，未知写入沿用原键恢复。

## 验收

先覆盖旧 JSON/摘要、刚性不变、新凭据不完整/串单/串轮/错目标、预算未确认与再次拒绝、重复并发审批、原键恢复、事务回滚以及代理和敏感权限。实际引擎验证普通预算自动通过有审计、柔性不足必须人工审批且不能同人跳过、批准后预算未知时财务仍不可通过、撤回重提不复用授权、后台恢复与子流程暂停。

固定 V118 安装包建立非空旧在审及预算状态，再升级新包核对全部旧列；合成外部协议完成柔性授权、命令受理后强退、只查原号及独立数据库/附件/预算接收方恢复。前后包分别按各自 OpenAPI 校验，真实前端解析单独计数。浏览器和 PostgreSQL 既有环境边界保留，不能由 H2 或组件测试替代。
