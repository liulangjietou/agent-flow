# 申请作废

申请人可以作废自己的 `DRAFT`、`RETURNED` 或 `WITHDRAWN` 申请。作废后状态为 `CANCELLED`，不能再编辑、提交或重复作废；原内容、绑定流程版本和已经存在的审批轮次保留。审批中申请应先使用撤回，已批准、已驳回等终态不能通过作废改写结论。

本能力作用于当前普通审批申请。结构化报销、发票占用、预算冻结、借款冲销和付款授权尚未接入，因此没有声称完成财务资源释放或已批撤销。

## 使用与界面

从“我的草稿”或“我发起”打开申请详情，点击“作废申请”，核对不可重提的提示后确认。作废说明选填，最多 2000 字。表单必填项尚未填写不妨碍作废；已有未保存修改时必须先保存或明确重新加载，不能由作废操作偷偷保存、丢弃或提交编辑内容。

确认框打开后暂停表单编辑和重新提交。成功后详情只读并打开操作审计；草稿从“我的草稿”移出，在“我发起”中仍可按“已作废”查询。原审批参与人仍按已有参与权限查看历史，管理员没有代替申请人作废的权限。

网络中断或结果未确认时，继续沿用统一原请求恢复机制。正文、说明、版本和幂等键保持不变；恢复成功只呈现作废结果，不触发后续提交。用户刷新页面前会收到未确认请求提示，关闭页面后应先读取现态和审计。

## API 与 DDD

`POST /api/v1/applications/{id}/cancel`，要求认证、`Idempotency-Key`，正文示例：

```json
{"expectedVersion": 3, "comment": "申请计划已取消"}
```

成功返回 HTTP 200 与更新后的 Application。过期版本返回 409；非本人返回 403；跨租户或不存在返回 404；状态不允许返回 422。重复原请求回放首次响应，另一请求的版本仍必须实时校验。

调用链为 `ApplicationRecord → ApplicationController → ApprovalApplicationFacade → ApprovalApplicationService → Application`。申请聚合负责允许状态和版本变化；应用服务编排仓储 CAS 与 `CANCEL` 审计，接口负责说明长度和幂等。没有新增数据库表，也不直接删除或改写 Flowable 数据。

作废不产生新的提交轮次，不把已退回或已撤回的轮次改成 CANCELLED，不改变已有退回率分子或分母。申请审计记录操作者、时间、前后状态、申请版本、当时轮次与说明；可通过 `/audit?action=CANCEL` 筛选。

## 验证

领域回归覆盖三个允许状态、全部拒绝状态、版本竞争及终态不可重提。真实引擎集成验证申请人/租户隔离、重复请求、四并发同键、审计失败回滚，以及提交竞争：即使提交事务已经创建流程，后续申请 CAS 输给作废，流程和轮次也必须回滚。

运行时验证命令：

```bash
python3 scripts/check-application-cancellation.py http://127.0.0.1:8082
```

必须指定独立本机演示环境。脚本创建带随机前缀的合成数据，验证不完整草稿、退回、撤回、历史保留、同键并发、提交竞争及统计不变，并保留浏览器验收数据，不删除原记录。

本阶段 H2 与独立 PostgreSQL 均通过该脚本和全部 49 个接口契约。浏览器验证未保存保护、暂不作废、不完整草稿作废、终态只读、草稿列表移除、退回申请断网恢复、原审批意见保留以及只有一条作废审计。详细计数和升级证据见相邻文档 `32-申请作废阶段验收.md`。
