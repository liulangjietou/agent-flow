## 已确认规则

1. 发起申请时选择本次任职，并固定到该审批轮次，以此解析主管和部门负责人。
2. 申请人仅在草稿、退回、撤回时编辑内容；审批节点配置显隐、只读和脱敏，管理员同样受敏感字段约束。

## 调用链与职责

任职选择：申请表单／补正页面 → 本人有效任职只读查询 → 提交入口 → 组织服务验证归属和当前有效性 → 审批提交用例 → 不可变轮次快照与流程运行适配器。任职身份和名称取服务端事实，不能从表单正文或客户端显示标签恢复。静态选人的旧流程与无任职快照的旧轮次保留原有语义；动态选人必须取得明确任职上下文。

主管关系维护：组织管理员 → 任职主管／部门负责人配置 → 组织实体状态变更 → 同租户关系、环检测与审计事务。跨实体约束由组织应用服务编排。主管对应具体任职，避免主管本人多任职时再次猜测上下文。

动态选人：发布器输出受控规则 → 节点激活 → 组织解析服务以本轮固定任职为起点解析 → 冻结节点实际候选人。空结果、无效关系或缺失上下文不能跳过审批。已冻结候选与历史轮次不随组织修改改写，办理仍检查当前人员及身份角色资格。

字段权限：版本化流程／表单配置 → 已有申请级授权 → 应用查询层构造字段投影 → 申请详情、历史轮次及页面。持久化原文与引擎条件计算保留完整事实；对外读取必须使用授权投影。申请聚合继续维护可编辑状态，写入口拒绝越权字段修改。管理员不能绕过敏感字段限制。

## 任职选择和动态审批

`GET /api/v1/organization/my-appointments` 只返回当前身份在当前租户的有效任职，支持有界分页。发起和补正页面由申请人明确选择，即使只有一个选项也不自动代选。提交的 `initiatorAppointmentId` 经服务端核验后生成 `InitiatorContext`，保存人员、身份主体、法人、部门、岗位标识与名称，以及目录修订。同一快照写入提交轮次和引擎流程变量，未知提交结果恢复仍使用原任职及原幂等请求。

静态选人的既有流程允许未选择任职；含动态规则的定义在启动前要求有效任职，否则返回 `INITIATOR_APPOINTMENT_REQUIRED`。要求检查位于确认实际引擎定义来源之后，同标识、同版本的新租户定义不能影响原先绑定内置定义的申请，旧申请的来源恢复也沿用原轮次事实。他人、其他租户或失效任职返回 `INITIATOR_APPOINTMENT_UNAVAILABLE`。重新提交可选择另一有效任职，旧轮次名称和责任上下文保持不变。旧轮次没有上下文时明确显示未记录，不查询当前组织补写历史。

组织管理员通过独立关系入口维护直属主管和部门负责人，避免原有名称/启停更新意外清空关系。主管指向同法人下具体有效任职，拒绝任职或人员形成的循环；部门负责人必须任职于该部门。设置目标须具备有效审批资格，关系更新复核目录修订并追加审计；清空关系也使用显式请求。

设计器支持第 1–10 级主管和部门负责人，目录通过 `contextual: true` 标识，页面显示“按本轮任职解析”。这些规则发布时检查合法性，节点激活时以固定任职为起点读取当时组织关系并冻结候选名单。后续组织调整影响尚未激活的节点，不改写已生成的候选或历史轮次。缺少负责人、无效组织关系或无有效审批人时回滚推进，不能跳过人工审批。单人和全员会签共用该解析边界，办理仍检查身份角色和当前本地审批资格。

V27 增加可空 `initiator_context_json`；V28 增加任职主管、部门负责人引用，并使用包含租户的复合外键。旧记录保持空值，既有迁移不改写。

## 字段权限与读取边界

表单字段和明细列新增可选 `sensitive`、`nodeAccess`。敏感字段默认脱敏，其他字段默认只读；节点可明确配置 `READ_ONLY`、`MASKED` 或 `HIDDEN`。配置只能引用真实人工节点，删除节点后遗留规则须先清理，发布错误清单包含 `FIELD_PERMISSION_NODE_INVALID`。字段类型切换、模板导入导出和发布比较保留配置，旧表单未配置时延续原语义。

申请人读取自己的完整内容，修改仍仅限草稿、退回、撤回。其他身份先通过申请级授权，再按服务端节点参与事实生成展示副本：当前活跃节点优先，同轮无活跃节点时参考本人实际完成的节点；多个节点取更严格规则。没有节点证据时取缺省与已配置规则中更严格的结果，ADMIN 不额外获得读取原文的特权。

当前申请只有在审批中使用当前轮次的节点权限。退回、撤回后的补正内容不能沿用上一轮宽权限；历史轮次始终使用自己的表单、内容和流程实例。隐藏字段同时从返回 schema 和 payload 去除，脱敏字段统一返回“已脱敏”，不暴露原文长度、类型或是否填写；明细列逐列处理，整表脱敏不返回行数，全部列隐藏时移除该表。

`ApplicationFieldViews` 放在已经完成申请授权的查询边界，覆盖申请详情、旧列表和历史轮次；业务聚合、原始轮次和 Flowable 条件仍使用完整事实。审批节点只有办理动作，没有正文编辑入口。公共待办金额投影遇到任一节点受限的金额字段时不保存该金额，列表展示、金额筛选和计数共同避开受限值，不能通过筛选推断金额。

Agent 的模型原文和人工修订属于自由文本，不能可靠逐字段脱敏。看不到该轮完整表单输入的身份读取完整运行详情返回 `403 FORBIDDEN`；无正文的运行目录仍按原申请权限读取。真实模型生成、发送字段授权及人工复核写入仍未完成。申请摘要导出、通知、操作审计和轮次流程图未新增原始表单出口；标题、申请单号和人工填写的意见沿用原申请权限，不属于本次结构化字段策略。
