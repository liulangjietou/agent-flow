# 员工财务模板配套样例

报销、事前申请和借款三个模板共用 `employee-finance` v1 样例包。在模板中心选择任一模板，点击“查看配置与业务样例”，可以查看准备顺序、参数替换、配置和业务输入，也可以下载完整 JSON。读取和下载不创建流程或单据，不保存或发布财务配置。

资源位于 `agentflow-server/src/main/resources/process-template-examples/employee-finance.json`，接口为 `GET /api/v1/process-templates/{key}/financial-examples`，只允许 `ADMIN` 或 `PROCESS_ADMIN`。其他模板返回 404。目录中的 `companion` 提供包版本和样例数量，普通模板没有该属性。财务配置写入仍要求独立的 `FINANCE_CONFIG_ADMIN` 权限。

## 准备与执行

1. 在独立演示租户准备法人、申请人本次任职、主管、业务审批人与财务人员。把三个模板复制成独立草稿，绑定实际审批人，核对金额矩阵和财务复核阈值后发布。
2. 保存 `DEMO_OFFICE`、`DEMO_HOTEL` 类别。类别接口提交完整目录；已有类别必须保留，不得用样例覆盖。制度样例是办公费用允许规则和 T1 城市、G1 职级的每晚 500 元住宿规则。城市等级与职级仍由可信事实源提供。
3. 保存制度草稿并核对草稿、类别、当前生效三个版本再发布。发布会切换当前租户的整个制度集；样例不是可以不经核对直接追加到任意现有企业制度的补丁。
4. 按法人和 CNY 保存并发布科目映射。`SYNTHETIC.*` 是合成代码，银行选择键必须绑定真实付款账户标识；科目可用性继续由 ERP 判断。
5. `receiptOptions` 展示可信法人主数据的两种回执。`paperReceiptRequired=true` 时必须记录实际签收；为 `false` 时不登记纸件签收，模板中的收单节点仍需人工办理。申请人和模板复制请求不能覆盖该主数据字段。
6. 把 `bindings` 中的法人、日期、票据、借款资源、事前额度资源、城市和成本中心替换为本次演示事实。原样例日期固定用于展示，借款归还日必须晚于提交时法人的本地日期。
7. 各 `content` 从对应的专用业务创建入口提交。预检与提交使用实际返回的版本号、目标摘要、本次任职和预检编号，不填造审批结果、资金回执或查验结论。

费用类别、制度和映射的管理入口与版本规则分别见[费用制度配置](expense-configuration.md)及[科目映射管理](account-mapping-configuration.md)。具体接口以随安装包提供的 OpenAPI 为准。

## 十个业务样例

| 样例 | 输入及预期边界 |
|---|---|
| `plan-basic` | 800 元事前申请；批准并确认预算后才生成可核销额度 |
| `advance-basic` | 300 元借款；批准和实际放款分开，实付确认后才生成可冲销余额 |
| `expense-basic` | 80 元普通报销，不触发部门、分管负责人和财务复核分支 |
| `expense-over-standard` | 住宿 1 晚 650 元，对照 500 元标准，需理由及费用例外审批 |
| `expense-reduction` | 原申报 10,500 元核减为 9,500 元，默认 10,000 元复核阈值应读取核定金额 |
| `expense-finance-recheck` | 不核减的 10,500 元报销进入财务复核，财务节点不得自动跳过 |
| `expense-advance-offset` | 80 元报销选择 60 元已放款借款；结算前仅占用，确认后借款剩余 240 元、员工应付 20 元 |
| `expense-prior-plan` | 80 元报销引用已批准的事前第 1 行；先预留，成功结算后消费，原批准总额仍为 800 元 |
| `expense-invoice-owner` | 本人已上传并查验的 100 元票据由第一单占用 |
| `expense-invoice-duplicate` | 第二单使用同一票据，预检或提交重新核对时阻断，不覆盖第一单占用 |

`reductions` 是核减行样例，调用核减接口时放入请求的 `lines` 字段，并补当前申请与财务版本、原因枚举及说明。核减金额使用十进制字符串，币种取自本轮已冻结的本位币。未确认的预算调整仍会阻止最终财务批准。

## 证据与剩余范围

资源加载复用现有费用类别、制度、科目映射和三类业务内容契约，拒绝损坏配置、不平衡分摊、重复样例标识和错误核减金额类型。前端按账号与模板清理预览，迟到响应不能重新生成旧下载内容。

本阶段 55 条范围测试、13 份实际响应契约、三类浏览器下载与 390 像素布局均通过；安装包升级保留 245 张表、6,328 行与 9 个附件，见[配套包验证记录](evidence/financial-template-examples-20261003.json)。

样例文本中的预期结果是待执行的验收断言。F13 关闭还需要对照这些输入完成固定安装包的实际填报、预检、提交、审批、核减、原件占用及关联资源办理，详见[未完成任务清单](remaining-task-ledger.md)。项目分摊会签、柔性预算、自审批上溯、相邻业务节点去重仍按各自任务推进，不因提供配套数据而视为已实现。
