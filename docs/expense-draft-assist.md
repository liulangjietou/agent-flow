A03 仍为 OPEN。领域模型、受限模型协议、持久化、应用服务、后台工作器及六个 HTTP 操作已经接通。费用编辑页面尚未接入，固定安装包运行、配套恢复、浏览器及 PostgreSQL 验收仍待完成，不能据此认定用户端已经交付。

## 适用范围和保存链路

原始费用设计 §16 要求从行程生成费用行草稿，并推荐费用类别与分摊；补贴金额仍由规则计算。本阶段只面向 `ExpenseReport`，不把普通表单建议入口扩展到事前申请、借款或其他财务聚合。

费用保存沿用 `ExpenseEditor → ExpenseController → ExpenseAllowancePreparation → ExpenseDraftService`。补贴准备在事务外完成，保存时再验证申请版本、财务版本和规则计算结果。费用行必须有合法金额及完整分摊，助手不能为了保留半成品而绕过这些规则。

职责分配如下：

| 层 | 职责 |
| --- | --- |
| `ExpenseDraftAssistInputs` | 从本人财务目录投影明确选择的类别、当前法人下的成本中心和项目，并生成行程与目录来源摘要。 |
| `ExpenseDraftAssistRun` | 管理生成租约、原建议、人工逐项确认及稳定失败状态。 |
| `OpenAiCompatibleExpenseDraftModel` | 在事务外调用已有有界 HTTP 客户端，只解析限定的建议字段。 |
| `JdbcExpenseDraftAssistRepository` | 保存不可变上下文、状态和追加轨迹；不修改费用、补贴或审批聚合。 |
| `ExpenseDraftAssistPreparation` | 在事务外读取本人目录，生成发送预览，并按原有效期重新核对来源及目的地。 |
| `ExpenseDraftAssistService` | 校验归属及双版本，编排排队、领取、结果保存和人工选择；不依赖费用保存服务。 |
| `ExpenseDraftAssistWorker` | 在分离的事务之间复核目录并调用模型；已领取运行不自动重发。 |
| 后续费用页面 | 展示发送清单和逐项确认，将明确选择的内容带入未保存的费用编辑状态。 |

## 输入与输出约束

- 输入最多 20 段本人提供的行程，明确日期、城市和用途；每类所选目录最多 50 项，发送来源的 UTF-8 JSON 最多 64 KiB。
- 本地上下文保留原申请和财务双版本、报销类型、法人、目录版本及有效期、财务目的地摘要和模型目的地摘要。实际模型请求只包含选定来源，不自动发送申请标识、完整费用正文、账户或其他法人目录。
- 输出允许 0 至 50 行。没有可靠依据时可以明确返回空建议。
- 每行只能指定原行程编号、所选类别及其合法单位、说明、分摊百分比和证据引用。日期和城市来自原行程。
- 分摊必须引用所选成本中心及可选项目；比例为正、最多两位小数、合计 100，重复分摊对象被拒绝。
- 每行必须引用原行程和目录，来源标识与摘要精确匹配。额外的金额、补贴标准、日期、余额、发票及审批字段被拒绝。
- HTTP 客户端沿用禁止事务内请求、禁止工具及重定向、有界响应和重复 JSON 键拒绝的约束。

## 确认与持久化

`QUEUED → RUNNING → COMPLETED → CONFIRMED / DISMISSED`；执行失败进入 `FAILED`。版本固定为 1、2、3、4。

`CONFIRMED` 表示本人确认了建议，尚未保存报销。每行的新建行程、类别和分摊分别选择；行程是创建新行的必要选择，类别和分摊不随之默认采纳。原建议和证据完整保留，人工只选择原建议标识与字段组。

确认要求原双版本未变且目录未过期；历史建议仍可放弃。运行租约固定在第一次领取，过期结果不能覆盖稳定失败，也不能通过重新领取自动重发模型输入。

V108 新增 `agent_expense_draft_run` 和 `agent_expense_draft_transition`。归属外键绑定租户、报销单、申请和本人，财务版本外键指向原修订，活动唯一键限制同一报销单的并发执行。状态更新比较版本及原上下文，运行状态和追加轨迹在同一事务提交。恢复时核对索引列、租约和领域状态，不接受静默改写的绑定。

## 本人接口与来源复核

以下路径均以 `/api/v1/expense-reports/{id}/draft-assists` 开始，只允许原申请人访问。管理员身份本身不增加权限，幂等回放前也重新核对身份和单据归属。

| 方法及相对路径 | 行为 |
| --- | --- |
| `POST /preview` | 只读预览实际来源、模型目的地、目录原有效期及确认摘要，不调用模型。 |
| `POST /` | 重新准备目录，精确比较预览摘要后排队；202 只表示运行已创建。 |
| `GET /` | 按页返回本人当前报销单的运行索引。 |
| `GET /{runId}` | 返回原输入、建议、人工选择和本地时效检查结果。 |
| `POST /{runId}/confirm` | 重新读取当前目录并校验双版本，只记录所选行程、类别和分摊。 |
| `POST /{runId}/dismiss` | 放弃原建议；过期后仍可执行，不读取目录或调用模型。 |

排队请求带回原预览有效期、模型目的地摘要和完整确认摘要。重新读目录只用于核对，不延长已展示的有效期。实际模型发送前和人工确认前再次检查所选目录的权限、版本、名称及当前法人；变化要求重新预览生成。生成后申请或财务版本变化、进入审批、目录到期都会禁止确认。详情的 `canConfirm` 只反映当前本地检查，确认接口仍会读取真实目录。

排队、确认和放弃使用既有幂等事务执行器。外部目录准备在事务外完成，成功回放不再访问目录或模型；运行及轨迹写入失败会一起回滚。未知请求字段、额外金额字段、未知或重复查询参数均被拒绝。接口返回禁止缓存，模型原始正文不写入日志。
