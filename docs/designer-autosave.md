# 草稿自动保存与冲突恢复

流程设计器默认开启自动保存。修改内容后停顿 2 秒，保存当前草稿；新草稿需先填写流程标识和名称。可以关闭自动保存并继续使用“保存草稿”。自动保存不校验并发布、不发起申请，也不创建引擎部署。

## 用户行为

- 保存状态区显示等待、正在保存、已保存及确认时间、暂停和关闭状态。没有服务端定义 ID 的初始画布显示“首次修改后自动保存”，不能把未改动当作已落库。
- 保存期间可以继续编辑节点、连线、表单和流程名称。首次创建时锁定流程标识；切换流程、发布和其他写操作等待当前请求完成。
- 成功响应只确认本次发送的快照，保留后续输入、选中节点、焦点、画布视图及撤销栈。后续内容在下一次停顿后串行保存，使用最新确认的 revision。
- 首次保存后流程标识固定；撤销旧节点或表单编辑不会把已创建草稿的标识改回空值。创建前去除标识首尾空白，成功响应确认绑定的标识。
- 输入法组合、节点拖动、确认框、发布对话框和其他操作锁期间暂停计时。离开设计器取消未开始的自动保存；已经发送的请求照常确认。
- 已发布定义及无管理权限的用户不能自动保存；缩放、适应画布、选择节点和预览填写不产生定义保存。

## 并发编辑

自动保存与手动保存都使用现有 `expectedRevision`。服务端拒绝过期 revision 或已发布定义时，页面保留本地修改并暂停自动保存和发布，提供：

1. **另存为新草稿**：保留本地流程与表单，创建同 key 的独立草稿；不修改冲突的原资源，不自动发布。自动保存关闭时仍需手动保存这个新草稿。
2. **加载服务端版本**：先确认放弃本地修改，再读取服务器当时的最新版本；取消确认继续保留本地内容。

不自动合并两个管理员的图，也不提升 revision 后强行覆盖。关闭后再开启自动保存不会绕过冲突或失败暂停。

## 网络与失败恢复

所有保存继续经过 `PendingWrites`，原正文、路径和幂等键在未确认期间保持不变。网络错误、401、5xx 或响应无法解析时，停止自动重试并显示现有恢复入口。

同一编辑会话中恢复保存请求，只确认原快照；发送后继续输入的内容不丢失、不弹出放弃这些内容的确认框。有后续修改时继续暂停，提示用户手动保存后再恢复自动保存，因此点击“恢复”不会顺带提交新的内容。会话或设计已变化时，仍执行原有恢复确认与账号隔离。

确定的参数、schema 或其他保存错误同样暂停，修正后点击“保存草稿”，成功才恢复调度。若恢复原请求得到版本冲突，则进入同样的另存/加载流程。

当前检查点和未确认请求只在页面内存中保存，不写入浏览器持久存储。关闭、刷新或开发服务器热更新不能当作草稿恢复机制；页面离开警告仍保留。原有 localStorage 只记录已选择的定义 ID 与登录令牌。本功能没有交付离线草稿、跨设备协同或实时多人合并。

## 实现职责和验证

`DraftAutosave` 负责计时、串行化、会话代次和失败暂停。`App.vue` 负责界面准入、发送快照、保存确认和冲突选择。服务端领域对象继续负责草稿状态和版本不变量；应用服务与 JDBC/Flowable 适配器没有改动。

执行 `npm run test:requests` 与 `npm run build`。新增调度回归覆盖连续编辑合并、发送期间的新内容、取消准入、计时器执行前复核、冲突/校验/网络暂停、旧会话迟到响应和卸载清理。已有幂等、会话隔离、确认与发布测试继续运行。

浏览器验收需覆盖：首次自动创建、保存期间输入、保存后节点焦点/撤销、第二客户端抢先保存、另存副本、加载确认及取消、服务端成功后响应丢失与原键恢复、自动保存开关、空库初始状态、发布只读及窄屏。失败代理只放在独立验收环境，不改变正式服务行为。
