# 费用相邻重复审批：后端第一阶段

F12 仍为 OPEN。本页记录已接入的后端规则和阶段验证边界，不能代替设计器、模板或固定安装包的完整验收。

## 发布契约

费用流程开始节点显式配置 `expenseDuplicateApproval=AUTO_PASS_ADJACENT`，规则版本为 1。此版本还要求结构化费用表单和 `expenseSelfApproval=ESCALATE_SUPERVISOR`，复用提交轮次候选冻结、申请人排除及业务与财务职责分离。

没有新属性的已发布流程继续人工办理。当前内置费用模板仍为 v2，尚未默认启用 F12；设计器配置和新版模板是后续工作。

## 调用链与职责

1. 人工审批由 `FlowableTaskFacade` 锁定申请并复核办理资格，记录实际 assignee 后完成原生任务。定时、事件、服务任务及子审批推进也使用原申请锁和统一进度服务。
2. 新发布 BPMN 的固定监听器 `FlowableExpenseDuplicateTrace` 记录实际经过的顺序流和已完成任务的人员、动作。记录在原实例变量中，与引擎事务一起提交或回滚；监听器不操作申请聚合，也不自行完成下一个任务。
3. `ExpenseDuplicateApprovalPolicy` 根据已走连线倒查最近人工节点。发布图已经过无环验证，金额网关无需重新按变化后的金额计算。财务节点、子审批边界和多个不同的并行人工前驱不能作为唯一相邻业务责任。
4. `ApprovalCompletionService` 调用 `ExpenseDuplicateApprovalProgress`，核对原发布定义、申请及轮次，并重新检查当前人员资格和原职责约束，再编排原生完成、申请版本递增与审计。

因此，规则判断归费用领域，读取引擎路径归引擎适配层，跨任务、申请和审计的原子推进归应用服务。自动动作没有另建可放宽费用校验的入口。

## 自动通过条件与审计

前后节点均须是业务审批；来源节点的实际完成人员必须唯一，且与后一个任务唯一有效审批人相同。候选集合存在多人、会签分母大于 1、委派未归还或人员资格失效时，保留人工任务。上溯去重后只有一人的会签可以自动完成。

非相邻重复不跳过；财务签收、审核及复核始终保留人工任务。转交和代理以实际完成任务的人为依据，不能拿原角色或代理委托人代替实际人员。

每个自动动作增加一次申请版本，写入 `AUTO_PASSED_DUPLICATE`。审计 actor 为 `system:expense-duplicate-approval`，额外的 `duplicateApproval` 记录规则版本、发布定义及版本、前驱节点、源任务编号和人员。历史及运营审计支持按该动作筛选，现有说明栏展示来源及规则版本。审计失败会回滚原人工动作、自动动作、申请版本和引擎推进。

## 阶段验证

最小复现直接读取实际费用模板，保留原金额连线，使用 6,000 元单据。修改生产代码前，新策略用例停留在 `department`，未达到预期的 `receipt`；未启用策略的兼容用例通过。最早两轮失败来自合成金额、分摊和制度接口夹具，未计作产品失败证据。

范围验证包含规则边界、真实模板金额网关、旧版本保持人工、转交实际人员、单人会签、多候选保留人工、财务签收与审核不自动合并、原任务重复请求，以及审计异常的整体回滚。准确执行数量、源提交和终态见 [阶段证据](evidence/expense-duplicate-approval-backend-20261004.json)。
