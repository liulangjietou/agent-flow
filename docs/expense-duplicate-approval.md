# 费用相邻重复审批

F12 仍为 OPEN。后端、设计器、模板、异步接续和固定安装包的 H2 运行及恢复验收已通过，浏览器与 PostgreSQL 补验尚未完成。

## 发布契约

费用流程开始节点显式配置 `expenseDuplicateApproval=AUTO_PASS_ADJACENT`，规则版本为 1。此版本还要求结构化费用表单和 `expenseSelfApproval=ESCALATE_SUPERVISOR`，复用提交轮次候选冻结、申请人排除及业务与财务职责分离。

没有新属性的已发布流程继续人工办理。当前内置费用模板为 v3，开始节点默认启用此策略；v1/v2 旧副本不自动升级。配套样例包同步升到 v3，业务输入、金额条件和财务配置保持原值。

## 设计器与模板

快速和完整设计器使用同一设置组件，明确启用、关闭各保留一个撤销点。便携模板保留属性，版本比较提供具名说明。依赖的费用策略被移除后，已有重复审批设置不会被自动删除；界面保留原文并提示修正，后端发布校验仍拒绝依赖不完整的图。锁定版本和无管理权限的视图不可修改。

模拟页面仍显示经过的业务节点，并明确实际办理时才判断人员及职责；不把图上出现的节点全部解释成人工审批。

## 调用链与职责

1. 人工审批由 `FlowableTaskFacade` 锁定申请并复核办理资格，记录实际 assignee 后完成原生任务。定时、事件、服务任务及子审批推进也使用原申请锁和统一进度服务。
2. 新发布 BPMN 的固定监听器 `FlowableExpenseDuplicateTrace` 记录实际经过的顺序流和已完成任务的人员、动作。记录在原实例变量中，与引擎事务一起提交或回滚；监听器不操作申请聚合，也不自行完成下一个任务。
3. `ExpenseDuplicateApprovalPolicy` 根据已走连线倒查最近人工节点。发布图已经过无环验证，金额网关无需重新按变化后的金额计算。财务节点、子审批边界和多个不同的并行人工前驱不能作为唯一相邻业务责任。
4. `ApprovalCompletionService` 调用 `ExpenseDuplicateApprovalProgress`，核对原发布定义、申请及轮次，并重新检查当前人员资格和原职责约束，再编排原生完成、申请版本递增与审计。

因此，规则判断归费用领域，读取引擎路径归引擎适配层，跨任务、申请和审计的原子推进归应用服务。自动动作没有另建可放宽费用校验的入口。

## 自动通过条件与审计

前后节点均须是业务审批；来源节点的实际完成人员必须唯一，且与后一个任务唯一有效审批人相同。候选集合存在多人、会签分母大于 1、委派未归还或人员资格失效时，保留人工任务。上溯去重后只有一人的会签可以自动完成。

非相邻重复不跳过；财务签收、审核及复核始终保留人工任务。转交和代理以实际完成任务的人为依据，不能拿原角色或代理委托人代替实际人员。

每个自动动作增加一次申请版本，写入 `AUTO_PASSED_DUPLICATE`。审计 actor 为 `system:expense-duplicate-approval`，额外的 `duplicateApproval` 记录规则版本、发布定义及版本、前驱节点、源任务编号和人员。历史及运营审计支持按该动作筛选，现有说明栏展示来源及规则版本。审计失败会回滚原人工动作、自动动作、申请版本和引擎推进。

## 阶段验证

最小复现直接读取实际费用模板，保留原金额连线，使用 6,000 元单据。修改生产代码前，新策略用例停留在 `department`，未达到预期的 `receipt`；未启用策略的兼容用例通过。最早两轮失败来自合成金额、分摊和制度接口夹具，未计作产品失败证据。

范围验证包含规则边界、真实模板金额网关、旧版本保持人工、转交实际人员、单人会签、多候选保留人工、财务签收与审核不自动合并、原任务重复请求，以及审计异常的整体回滚。后端第一阶段执行数量、源提交和终态见[后端证据](evidence/expense-duplicate-approval-backend-20261004.json)。

设计器、模板和原生专项阶段通过 102 项 Java、67 项前端测试，以及类型、契约和生产构建检查。原生流程验证了代理实际人员、定时等待接续、并行分支自动通过后汇合业务保留人工、并发重复请求与两个连续自动节点。模板原金额条件、表单权限、场景和配套业务配置保持一致。固定服务器 JAR 与前端目录已留存；设计器和模板阶段见[本阶段证据](evidence/expense-duplicate-approval-ui-template-20261004.json)。

事件与服务任务接续阶段通过 65 项 Java 范围回归（其中新增 2 项组合场景），无失败或跳过。实际费用模板在主管审批后进入原生等待，故意在自动审批审计写入后抛错，验证任务、申请版本、路径依据和审计一起回滚；服务任务已确认的远端回执保留，重试只恢复本地推进，合成 HTTP 服务仍只有一次效果。两种接续都保留原主管任务作为自动审批来源，财务签收仍需人工办理。该阶段没有修改生产代码；见[异步接续证据](evidence/expense-duplicate-approval-event-service-20261004.json)。

固定安装包通过 v2 到 v3 非空升级、旧版人工语义、新版并发自动通过、撤回重提、两次强退与独立恢复。253 张表、789 行、1,981 条结构语句及自动审批来源已核对，257 份响应和 53 份请求契约通过；见[运行说明](expense-duplicate-approval-runtime.md)和[运行证据](evidence/expense-duplicate-approval-runtime-20261004.json)。
