# 原产品目标与当前缺口核对

更新：2026-10-01。以相邻项目文档 `doc/04-产品化与开箱即用目标.md` 的能力矩阵为基线，结合用户随后授权的[实施方案](remaining-implementation-plan.md)核对。这里只记录已经找到依据的缺口和明确调整；尚未完成全部需求的证据映射，不能据此宣布全量本地开发结束。

## 已确认仍有本地工作

| 原目标 | 当前事实 | 后续工作 |
| --- | --- | --- |
| §3.A、§6：新租户初始化向导，建立租户／法人／管理员／日历／渠道并记录审计 | `FirstWorkflowController` 只有读取流程运行进度的接口；[首次引导](first-workflow-guide.md)明确没有企业初始化。组织、日历和通知各自的管理能力已存在，首次使用页面仍是复制、发布、提交、批准的引导 | 实现并验收初始化编排及页面，复用既有组织、日历和通知用例；企业身份授权仍以可信配置／IdP 为依据，不能由浏览器自授租户或角色 |
| §2、§3.C、§5：组织代理、职责分离和表单字段关系选人 | `LocalOrganizationDirectory` 和 `OrganizationAssigneeResolver` 只解析指定人员、组织成员、所选任职主管及部门负责人；没有代理期限、通用自审批／职责冲突策略或表单关系解析。现有单笔委派和财务专用控制不能替代这些规则；[选人说明](designer-assignees.md)亦明确代理与职责分离未接入 | 增加明确的代理范围／有效期、职责冲突规则及字段关系选人，覆盖发布、实际候选快照、转交、历史和审计；保留既有已发布语义 |
| §5、§7：Agent 草稿、票据抽取和预检建议 | `AssistRunController` 的生成入口要求当前审批待办，`AssistInput`／`AssistRun` 只承载审批摘要及人工复核；没有草稿生成或票据抽取入口。已完成的财务规则预检与摘要不能算作这些 Agent 能力 | 在各真实业务入口增加有来源、明确外发范围和人工确认的建议能力；实际模型质量另验收 |
| §2、§3.G、§5：组织同步和电子签适配 | 当前组织入口为可信管理员 CRUD，本地目录不创建身份或授予系统角色；未发现外部组织同步用例或电子签业务端口。OIDC 认证与事件 HMAC 验签分别属于身份和消息完整性，不是这两项集成 | 开发可审计的组织同步与电子签业务接入；先完成本地协议和失败恢复验证，再按企业提供的源系统与签署服务联调 |

以上四类仍含本地开发，不能归因于缺少企业密钥而整体停止。2026-10-01 进一步检查上述调用链后，将先前尚未判定的组织与 Agent 条目确认为缺口，并补列组织同步／电子签。它们来自原目标，不是本次新增产品要求。其余原目标的全量代码和证据映射仍在接续，不把未核对条目算作完成。

## 已明确的范围调整

- 原目标提到受策略控制的批量批准；用户随后授权的实施方案明确“不提供批量批准”。现有安全批量领取／释放按该方案验收，不再把批量批准追加为默认开发任务。
- 原目标允许 DMN／受限表达式中的实现选择；已使用白名单条件规则，不能仅因没有 DMN 就判断规则功能缺失。
- 附件已按用户确认的单机持久目录实施。对象存储是另一种部署适配，不把当前单机实现误报为未完成附件。

## 仍需实际环境的三类工作

1. 企业 IM 账号、应用权限、SMTP／TLS 和最终递送。
2. 实际财务制度、预算／ERP／银行／发票服务及回执对账。
3. 企业模型／IdP、目标安装升级和配套恢复、容量告警、远端 PR／CI。

当前至少七类剩余事项：以上四类含本地开发的工作和三类企业验收／交付。类别包含不同大小的任务，不能据此计算完成百分比；详细开发项随全量证据核对继续补齐。
