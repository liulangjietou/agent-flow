# 流程设计器审批人配置

人工审批节点可选择指定账号或审批角色。选择账号后，任务直接指派给该账号；选择角色后，由当前有效成员中的一人处理。角色人数来自当前身份源，不代表会签人数。当前使用演示身份目录，尚未接入组织负责人、直属上级、代理时段和职责分离规则。

## 使用

1. 以流程管理员登录，在流程管理中打开草稿并选择人工审批节点。
2. 在右侧“审批人”中选择“指定审批人”或“审批角色”分组下的选项。画布同步显示所选账号或角色，修改支持撤销、重做及自动保存。
3. 点击“校验流程”。匹配不到有效审批人的节点会显示中文错误，可点击“定位”回到该节点。
4. 填写变更说明后发布。服务端重新核对身份目录，通过后才保存发布版本、部署流程并记录发布事实。

目录加载失败会禁用选择并清除旧名单，保留已保存的规则供核对，可点击“重试读取审批人”。已有但当前无法匹配的规则不会被静默清空；可先保存草稿，修正后再发布。刷新目录本身不会修改草稿。

## 契约与职责

`GET /api/v1/process-definitions/assignee-options` 要求 `ADMIN` 或 `PROCESS_ADMIN`，返回当前租户规则数组，响应为 `Cache-Control: no-store`。未认证返回 401，普通账号返回 403。示例：

```json
[
  {"rule": "user:bob", "label": "bob", "memberCount": 1},
  {"rule": "role:FINANCE", "label": "FINANCE", "memberCount": 2}
]
```

`rule` 仍写入既有的 `graph.nodes[].properties.assigneeRule`，没有另建任务或审批人状态表，也没有数据库迁移。

领域校验器负责节点、图结构和字面量规则安全。流程定义上下文通过 `DefinitionAssigneeDirectory` 端口读取身份源，`DefinitionApplicationService` 编排目录复核。当前 `AuthService` 适配器与登录、任务接收人和通知受众共享有效账号与角色来源；领域模块不依赖认证实现或 Flowable。

管理员调用 `/process-definitions/validate` 时同时检查身份目录。普通账号仍可校验图结构，但不获得账号是否存在的探测能力。发布时所有人工审批节点均须有有效成员，包括本次测试数据未经过的分支；这是设计有效性检查，不是一次路径模拟。

发布检查失败返回 `422 INVALID_DEFINITION`，`details.definitionErrors` 包含 `ASSIGNEE_NOT_AVAILABLE:节点标识`，草稿不变、不分配发布版本、不部署、不新增发布记录。成功请求的原幂等键仍回放原结果。身份源异常不会按“有人审批”降级。

发布仅核对当时的身份源。后续组织变更、任务激活时审批人快照、SoD 和历史角色成员追踪尚未实现。新版本改变审批人不重写旧版本或在途申请，任务操作仍按实时任务归属授权。

## 验证

在独立的本机演示库运行，脚本创建随机记录并保留全部数据：

```bash
python3 scripts/check-definition-assignees.py http://127.0.0.1:8082 --exercise
```

覆盖目录认证与权限、真实人数、不存在用户/角色的发布拦截、草稿保持不变、指定账号审批、其他审批人不得处理、V1 指定账号/V2 角色分配的在途隔离、发布幂等回放和最终批准状态。末尾保留一个审批人失效的草稿供浏览器修正验收。

自动测试覆盖目录成员在校验后消失时再次拒绝发布、未配置身份源和跨租户目录为空，以及 UI 请求取消、迟到结果、失败重试和认证只读请求。完整门禁见根目录 README。
