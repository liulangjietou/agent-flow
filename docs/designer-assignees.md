# 流程设计器审批人配置

人工审批节点可选择指定账号或审批角色。选择账号后，任务直接指派给该账号；选择角色后，单人模式由一名成员处理，全员会签模式为节点激活时的每位有效成员创建待办。人数是当前目录结果，实际名单在会签节点激活时固定；规则详见[全员会签](all-countersign.md)。未启用本地目录时使用演示身份目录；管理员显式启用后，选人目录切换为[本地人员、部门和岗位](local-organization.md)，即使为空也不回退到演示账号。还可选择本轮发起任职的第 1–10 级主管或部门负责人，详见[动态规则及验收](organization-context-and-field-permissions.md)。代理时段和职责分离规则仍未接入。

## 使用

1. 以流程管理员登录，在流程管理中打开草稿并选择人工审批节点。
2. 在右侧“审批人”中选择“指定审批人”或“组织与审批角色”分组下的选项。画布同步显示所选账号或角色，修改支持撤销、重做及自动保存。
3. 点击“校验流程”。匹配不到有效审批人的节点会显示中文错误，可点击“定位”回到该节点。
4. 填写变更说明后发布。服务端重新核对身份目录，通过后才保存发布版本、部署流程并记录发布事实。

目录加载失败会禁用选择并清除旧名单，保留已保存的规则供核对，可点击“重试读取审批人”。已有但当前无法匹配的规则不会被静默清空；可先保存草稿，修正后再发布。刷新目录本身不会修改草稿。

## 契约与职责

`GET /api/v1/process-definitions/assignee-options` 要求 `ADMIN` 或 `PROCESS_ADMIN`，返回当前租户规则数组，响应为 `Cache-Control: no-store`。未认证返回 401，普通账号返回 403。示例：

```json
[
  {"rule": "user:bob", "label": "bob", "memberCount": 1},
  {"rule": "role:FINANCE", "label": "FINANCE", "memberCount": 2}
]
```

`rule` 仍写入既有的 `graph.nodes[].properties.assigneeRule`，没有另建任务状态表。本地目录使用 V26 的组织表；规则引用本地人员或组织的不透明标识，登录主体不会拼入执行表达式。

动态选项增加 `contextual: true`，`memberCount: 0` 表示尚未取得本轮任职，页面显示“按本轮任职解析”，允许选择。规则仅支持 `role:ORG_SUPERVISOR_1` 至 `role:ORG_SUPERVISOR_10` 和 `role:ORG_DEPARTMENT_HEAD`；发布时验证受控规则本身，不能据此声称实际申请一定有审批人。静态选项仍按真实人数校验。

领域校验器负责节点、图结构和字面量规则安全。流程定义上下文通过 `DefinitionAssigneeDirectory` 端口读取身份源，`DefinitionApplicationService` 编排目录复核。`LocalOrganizationDirectory` 适配本地选人和任务接收人端口，未初始化的租户才回退到 `AuthService` 演示目录。OIDC 继续提供认证身份与系统角色，本地审批资格不会授予角色；领域模块不依赖认证实现或 Flowable。

管理员调用 `/process-definitions/validate` 时同时检查身份目录。普通账号仍可校验图结构，但不获得账号是否存在的探测能力。发布时所有静态选人人工节点均须有有效成员，包括本次测试数据未经过的分支；这是设计有效性检查。动态规则要求申请提交时提供有效任职，并在实际节点激活时检查组织关系，空结果回滚推进。

发布检查失败返回 `422 INVALID_DEFINITION`，`details.definitionErrors` 包含 `ASSIGNEE_NOT_AVAILABLE:节点标识`，草稿不变、不分配发布版本、不部署、不新增发布记录。成功请求的原幂等键仍回放原结果。身份源异常不会按“有人审批”降级。

发布核对当时的目录。ALL 节点激活时固定成员；本地组织规则的 SINGLE 节点也冻结初始候选账号，演示角色规则继续沿用原解析方式。目录后续变更不重写已保存的候选快照；人员停用或取消审批资格会阻止其后续待办读取与办理。新版本不重写旧版本或在途申请。外部组织同步与职责分离尚未实现，快照和验收边界见[本地组织记录](local-organization.md)。

## 验证

以下脚本覆盖演示身份目录，须在未启用本地目录的独立本机演示库运行；它创建随机记录并保留全部数据。本地目录及 OIDC 的验收见[组织记录](local-organization.md)。

```bash
python3 scripts/check-definition-assignees.py http://127.0.0.1:8082 --exercise
```

覆盖目录认证与权限、真实人数、不存在用户/角色的发布拦截、草稿保持不变、指定账号审批、其他审批人不得处理、V1 指定账号/V2 角色分配的在途隔离、发布幂等回放和最终批准状态。末尾保留一个审批人失效的草稿供浏览器修正验收。

自动测试覆盖目录成员在校验后消失时再次拒绝发布、未配置身份源和跨租户目录为空，以及 UI 请求取消、迟到结果、失败重试和认证只读请求。完整门禁见根目录 README。
