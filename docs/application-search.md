# 管理员申请检索

ADMIN 在“申请记录”中按标题/业务单号、当前状态、流程标识及版本、申请人账号和创建日期检索当前租户的申请。结果先加载 30 条，点击“加载更多申请”读取后续页面；不会把已加载数量显示为全库总数。

查询后可[生成 Excel 摘要](application-export.md)，包含本次筛选的全部匹配记录，独立于页面已加载条数；超过 10,000 份时整次拒绝。修改筛选后旧文件失效，需重新查询和生成。

原来的管理员清单读取全部申请正文，并逐份构造聚合；新页面只读取有界摘要，打开记录时再通过原申请详情接口授权读取。普通用户的可访问申请路径与个人工作台保持原有权限。PROCESS_ADMIN 只拥有流程管理权限，不因此获得租户全部申请检索权。

## API

`GET /api/v1/operations/applications`，要求认证主体具有 ADMIN，响应禁止共享缓存。

| 参数 | 规则 |
|---|---|
| q | 标题或业务单号包含匹配，不区分大小写，最多 100 字符；`%`、`_`、`!` 按字面量处理 |
| status | 申请当前状态，省略或空值表示全部 |
| processKey | 精确流程标识，最多 128 字符 |
| definitionVersion | 正整数，最大 2147483647；必须同时指定 processKey |
| applicant | 精确申请人账号，最多 128 字符 |
| from / to | UTC 创建日期 `YYYY-MM-DD`，包含首尾两天；省略时不限制该侧日期 |
| limit | 默认 30，范围 1—100 |
| cursor | 上一次相同查询返回的 nextCursor，绑定租户、账号、角色和全部筛选条件 |

返回 `items` 和可选 `nextCursor`。摘要包含标识、标题、业务单号、流程及版本、申请人、状态、轮次和创建/更新时间，不返回 payload、formSchema、审批意见或引擎定义标识。未知参数、错误日期、无效游标等返回 `400 INVALID_APPLICATION_QUERY`；无认证返回 401，非 ADMIN 返回 403。客户端不能通过 tenantId 或排序参数绕过固定查询边界。

按 `created_at DESC, id DESC` 排序。创建时间不随修改或审批改变，同时间记录通过唯一 ID 翻页，不使用 offset。查询不是跨页冻结快照：审批状态及匹配条件可能在两次读取间变化，新建的较新记录要重新查询才能看到。每页为一次只读 SQL，没有额外全库 COUNT 或逐申请引擎查询。

## UI 与 DDD

筛选修改后需点击“查询申请”才生效；页面提示仍展示上次结果，并暂停加载更多。非法日期范围清除旧结果并提示修正，首次查询失败清除旧结果，追加失败保留已读页面并允许原游标重试。账号切换、页面卸载、后续新查询会取消旧请求，迟到成功或失败不能回填。

`ApplicationSearch → ApplicationSearchController → ApplicationSearchPort → JdbcApplicationSearchAdapter`。查询端口描述业务摘要与筛选，不修改聚合；Controller 负责管理员权限及参数校验，JDBC 负责 SQL 与时间转换。V15 仅增加租户创建时间索引，不改写业务记录或已发布迁移。
