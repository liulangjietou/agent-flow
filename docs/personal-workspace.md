# 个人工作台

“我发起”“我的草稿”“已办记录”从当前登录账号查询真实业务记录，支持标题、单号和流程标识搜索、状态或动作筛选、加载更多及打开详情。

## 业务口径

- **我发起**：当前租户中 `created_by` 等于当前用户的申请，覆盖草稿、审批中、退回、撤回、驳回、批准及作废等状态。管理员在这里也只看本人发起的申请。
- **我的草稿**：上述范围中状态为 `DRAFT` 的申请。已退回、已撤回仍从“我发起”继续填写。保存修改后列表刷新；提交或作废成功后离开草稿列表。
- **已办记录**：本人实际执行的 `APPROVE`、`RETURN`、`REJECT`、`TRANSFER`、`DELEGATE`、`RESOLVE` 审计事实，每个动作一行。同一申请多次办理可出现多行；认领、释放、流程因他人操作而结束均不冒充办理。回交时申请仍在审批中，后续最终决定不改写该办理事实。

已办显示操作当时的动作、时间、节点、轮次、意见、接收人和办理后状态，同时显示申请当前状态。标题、单号和流程信息来自申请当前记录；历史表单与历史标题请打开详情的提交轮次查看。缺失的历史办理结果显示“未记录”。

原“申请记录”入口仍按照发起人、参与者与管理员权限返回可访问记录。新入口没有改变申请写权限。真实历史办理者通过审计事实保留申请读取权限，转交后的指派人变化不会抹掉其参与关系；认领后释放不因此获得永久历史办理权限。

## 分层与链路

页面 `WorkspaceRecords` → `api` → `WorkspaceController` → `WorkspaceReadPort` → `JdbcWorkspaceReadAdapter`。

只读投影与申请聚合分开：查询不加载或修改聚合，不读取列表不需要的表单正文，不依赖 Flowable 内部表。HTTP 入口统一校验筛选；基础设施层绑定当前 Actor 的租户和用户，用参数化 SQL 返回所需列。

详情仍经 `ApprovalApplicationFacade` 与现有聚合服务授权。应用层组合现有引擎参与者端口与审计参与者端口；这是第二个实际参与事实来源，不复制引擎数据，也不重构申请状态规则。

任务操作 → 申请/引擎状态变更 → `JdbcTaskAuditAdapter` 在同一事务内写入原审计正文和 `actor_id` 查询列。事务失败时查询列与原审计共同回滚，不产生虚假已办。

## 查询契约

| 接口 | 可用参数 |
|---|---|
| `GET /api/v1/workspace/applications` | `view=started/drafts`（默认 started）、`q`、`status`、`limit`、`cursor` |
| `GET /api/v1/workspace/handled` | `q`、`action`、`limit`、`cursor` |

返回 `{items, nextCursor?}`，末页省略空游标。默认每页 30，最大 100；非法参数、超界限制、其他账号或筛选条件的游标返回 `400 / INVALID_WORKSPACE_QUERY`。`q` 最多 100 字，按字面量包含匹配，`%`、`_` 和 `!` 不作为查询通配符。身份来自会话，不接受传入用户或租户作为筛选条件。

申请按创建时间及 UUID 倒序；已办按审计时间及 UUID 倒序。游标同时包含时间和唯一 ID，绑定租户、用户、视图与筛选条件；服务端读取多一行判断下一页。同时间记录不遗漏。分页期间没有数据库快照锁，新写入或状态变化需要刷新首页看到。

前端在切换账号、视图、筛选和刷新时清空旧结果并取消旧请求；迟到成功和失败均不回填。加载更多失败保留已读记录与原游标，重试不跳页。12 秒超时显示重试提示；列表读取不生成幂等写请求。

## V10 升级

Java Flyway 迁移 `V10__Index_personal_workspace` 新增 `audit_event.actor_id`、操作人时间索引和申请归属时间索引。原 V1–V9 文件不变。

旧事件只有在 Task 聚合、明确关联同租户现存申请、动作列属于办理集合、正文动作与申请 ID 均和列一致、存在合法长度的非空操作人时才回填。缺少关联、缺少操作人、损坏 JSON、动作矛盾及跨租户引用均保留原状。只更新新列，不修改原正文、时间、动作或其他业务记录。更早的缺失关联事件仍可由原单申请历史读取链路解析，不推测放入全局已办。

Java 迁移使用固定校验和标记；发布后实现应保持不可变，后续变更必须新建迁移。

## 验证

后端 `PersonalWorkspaceIntegrationTest` 覆盖归属/租户隔离、转交后的参与权限、三类决定、认领释放与撤回排除、同时间双键分页、游标上下文和字面量搜索；`WorkspaceMigrationTest` 覆盖 V9 升级与所有旧列保持；既有 `LifecycleAuditIntegrationTest` 补充事务失败不留下操作人索引的断言。

前端 `workspace.test.mjs` 覆盖切换账号/筛选的迟到响应、分页重试、重复点击、末页省略游标与只读认证请求。完整命令见 README。

独立验收环境运行：

```bash
python3 scripts/check-personal-workspace.py http://127.0.0.1:8082
```

脚本创建随机前缀的流程、申请和真实办理记录，验证 30+6 分页、32 份草稿、4 类办理、权限和字段边界；保留全部验收数据。不要把脚本的新增数据当作真实业务数据。
