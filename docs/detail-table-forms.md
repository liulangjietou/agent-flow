# 重复明细表单

流程设计器支持“重复明细”填写类型。每个明细字段配置列名、标识、类型、必填和基础约束；列可以增删及调整顺序。申请人可以增删、排序明细行，审批人和历史轮次以表格读取。数字继续保存原始十进制字符串，布尔值保存为 boolean，不转换为浮点数或显示文本。

## 配置和数据

```json
{
  "schemaVersion": 2,
  "fields": [{
    "key": "items", "label": "物品明细", "type": "TABLE", "required": true,
    "maxRows": 50,
    "columns": [
      {"key": "name", "label": "名称", "type": "TEXT", "required": true},
      {"key": "quantity", "label": "数量", "type": "NUMBER", "required": true, "minimum": "0"}
    ]
  }]
}
```

填写值为 `{"items":[{"name":"显示器","quantity":"0002.00"},{"name":"键盘","quantity":"3"}]}`。列可使用 TEXT、TEXTAREA、NUMBER、DATE、SELECT、BOOLEAN，不支持嵌套 TABLE。字段配置随定义版本发布，模板文件导入导出保留全部列配置，定义比较识别列配置和 maxRows 的变化。

格式版本 1 继续支持原六类字段；首次选择 TABLE 时设计器提升到格式版本 2。格式版本不同于流程业务版本。已提交申请和退回后重提继续绑定原定义版本，后来发布的新列配置不会改写旧申请。

## 校验与快照

- 每个表单最多 50 个顶层字段；每个明细 1—20 列。maxRows 可配置 1—100，未配置时按 50 行限制，读取历史配置不补写默认值。
- 整份填写最多 2000 个明细单元格，按实际行数 × 配置列数累计。这是输入技术边界，不是性能容量承诺。
- 草稿允许缺少必填值，但已有值必须满足类型、约束和字段白名单。提交时，必填明细须至少一行，每行必填列须完整。
- 明细 null、缺失、空数组表示未填写；空字符串、非数组值、非对象行均拒绝。未知列不会静默删除。
- 错误使用 `items[0].quantity` 定位第一行的 quantity；非法行用 `items[0]`。超限返回 TOO_MANY_ROWS / TOO_MANY_CELLS。填写、增删或排序后清除旧位置错误，下次校验重新定位。
- 申请聚合和 SubmissionRound 共用 PayloadSnapshot 深拷贝并冻结嵌套对象、列表，外部引用不能绕过版本号修改内容。保留 null、false、行序和数字字符串写法。
- TABLE 仅支持 EXISTS / NOT_EXISTS 路由，空数组为未填写。明细列不能直接作为顶层条件字段，不支持求和或逐行条件。

## 调用链和职责

`FormSchemaEditor → 严格 JSON 入口 → FormSchema` 保存不可变定义。入口负责 JSON 类型及属性白名单；表单值对象负责列结构、范围和填写规则。`FormFields → Application → PayloadSnapshot` 负责填写与聚合快照；提交应用服务仍协调原轮次仓储与 Flowable。模拟器和 Flowable 使用同一领域字段类型和存在性语义，没有引入另一套路由计算。

`DetailTableValue` 只按绑定版本渲染只读表格；`roundComparison` 使用各轮自己的列名称及选项解释原值。权限继续复用现有申请详情、待办和轮次接口。没有新增数据库迁移或明细专用授权。
