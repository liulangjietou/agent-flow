# 借款还款复核通知

独立还款复核的查询、人工裁决和原消息详情属于 F17 的一个交付阶段。F17 整体仍为 OPEN；其他异常分支核对和固定安装包验收继续推进。

## 调用链与责任

财务从原借款的已登记还款发起复核，后台工作器只读取原收款与实际退回依据。`AdvanceRepaymentReviewService` 比较已登记还款、历次外部原件和已接受退回；领域查询保存本次比较结论，借款实体负责冻结与明确裁决后的余额变更。通知服务只投影已保存事实，不替代任何财务决定。

服务保存查询后发布 `AdvanceRepaymentReviewChanged`；明确裁决先保存借款修订、查询消费和具名决定，再发布事件。最小站内通知、外发意向与原财务事务一起提交；通知失败时查询、冻结或裁决一起回滚。

## 原查询比较结论

原还款复核和原放款退回查询新增可空 `reviewRequired`。应用服务完成跨历史比较后，在本次 CHECKED 修订首次保存前固定结论；同一次查询不能改写已确定的比较结果，RESOLVED 修订保留原值。旧 JSON 缺失字段时为 `null`，保留旧消息读取语义，不反推过去未保存的比较结论；无需新增 SQL 表结构。

这个事实解决两种实际缺陷：外部仍显示 CONFIRMED，却与既有退回登记矛盾时，必须通知重新核对；再次查询已经接受过的相同退回且比较一致时，不能再通知“等待登记”。外部状态与本地登记是否一致由应用服务判断，通知文案不会仅凭外部状态推断。

通知区分 UNAVAILABLE、SOURCE_CHANGED、UNRESOLVED、RETURN_REVIEW、REVIEW_REQUIRED 和 RESOLVED。正常一致复查保持安静。查询不会自动增加欠款、冲销历史退回或解除已有冻结；解除冻结仍需要财务消费新鲜原件，形成明确决定。

## 身份、历史与详情

`GET /api/v1/notifications/{id}/repayment-review-target` 固定原查询、原还款和原申请轮次，不接受额外查询参数。消息接收人仅为原申请人和本次实际发起复核的财务，创建及外发领取重新核验当前人员与法人任职。详情还校验原轮次字段权限；管理员角色不能绕过。

访问服务核对已登记原还款及原放款身份。裁决按自身编号恢复被消费查询的相邻修订和借款的相邻修订，再重放领域变更，确认这是该次查询真正形成的决定。后续查询、余额变化或另一轮裁决不会替换旧消息的依据。旧待核对消息只可显示自身查询后来产生的决定。

去重键为 `repayment-review:<原查询编号>:<事实种类>`。重复事件及 HTTP 原键回放不重复通知。响应使用 `no-store`，不包括金额、账户、资金流水、证明正文和办理许可，读取不会标记已读或重新查询外部服务。

页面分别显示当时消息事实、原查询、外部观察和实际裁决，只提供重新读取与原轮次导航。身份变化、失权、超时和卸载会清除旧内容并阻止迟到响应；历史时间戳保留浏览器毫秒截断边界。
